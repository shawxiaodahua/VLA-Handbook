# 无机器人本体的手持采集接口工程专题 / Robot-Free Collection Interfaces Engineering Brief

> 整理日期：2026-10-25。观察窗口：2026-04-25 至 2026-10-25；窗口外项目以旧基础另标（outside_window）。本文核验公开材料（arXiv 摘要/HTML、项目页、Hugging Face 数据卡、GitHub README、厂商新闻），未下载大数据集、未运行复现实验。所有项目均为阅读/接入研究卡，不冒充逐篇完整复现笔记。

## 核心结论

先区分原始观测、重建轨迹、动作标签和机器人实际执行。手持设备记录到的轨迹，还要经过坐标、时间和控制接口核验；“无线”“便携”本身不证明可直接用于目标机器人。不同路线采用视觉惯性、LiDAR、环视相机或其他追踪方式，双臂系统还应检验相对位姿与共同时间基准。下面按这些工程问题阅读，而不预设某一方案普遍最好。代码、硬件与数据的开放状态分别记录。

```
手持/头戴采集 ──► 离线SLAM位姿 ──► 动作标签(相对EE+夹爪宽度)
      │                                   │
      ├─ 传感一致性: 触发时钟/相机几何/力通道
      ▼                                   ▼
 数据质量过滤(静态规则/主动校验) ──► 策略训练 ──► 真机部署(机器人状态/控制器)
```

## 路线比较（按工程问题）

| 工程问题 | UMI 系（UMI/UMI-3D/MV-UMI/HiFi-UMI） | 力/接触增强（UMI-FT/BRIDGE） | 引导与校验（RoboPocket/EgoGuide） | 双臂/全身（KIW） | 平台化（Grabette/Orbbec） |
|---|---|---|---|---|---|
| 位姿记录 | 单目惯性 SLAM；UMI-3D 换 LiDAR-惯性 | 同 UMI 系 | RoboPocket 主动校验；EgoGuide 腕+头同步 | 360° 相机前后镜组合 | RTAB-MAP / 厂商多设备同步 |
| 候选动作表示（仍需控制映射） | 相对 EE 位姿+连续夹爪宽度 | BRIDGE 相对 EE+绝对宽度，horizon 24 | 同上 | 双臂工具位姿 | 导出 LeRobot 格式 |
| 采集/部署传感一致性 | 相机几何保真；部署无 SLAM 输入 | 逐项核对采集与执行端的力通道 | EgoGuide 头显固定安装 | 工具端单相机 | 共享时钟同步 |
| 夹爪控制 | fiducial 测宽 | 六轴力/力矩（UMI-FT）；磁传感器（BRIDGE） | 旋转传感器/几何匹配 | 工具夹持 | 电机夹爪 Gripette |
| 接触/全身 | 无显式接触模块 | BRIDGE 接触段部分遥操作 | 无 | loco-manipulation 采集 | 无 |

## 项目卡片

<a id="p-umi"></a>
### UMI

日期 2024-02-15，窗口外旧基础（outside_window），非新首发。机制：触发式手持 3D 打印平行软指夹爪，仅以腕部 GoPro（155° 鱼眼）为传感与记录设备；基于 ORB-SLAM3 的惯性-单目 SLAM 联合视觉与惯性约束恢复米制尺度位姿，夹爪指宽经 fiducial 标记连续跟踪。监督信号为 SLAM 后处理位姿与连续宽度，非机器人控制器执行量。边界：论文开源声明仅针对硬件与软件系统，数据集是否公开及许可未声明；评估含人工判定成功与人工监督终止，非全自动评测。接入检查：到项目网站核实数据集/处理脚本是否实际发布及许可，确认 SLAM 低纹理失败率与过滤口径，核对硬件 BoM 与相机型号。来源：[arXiv 2402.10329](https://arxiv.org/abs/2402.10329)。

<a id="p-umi-ft"></a>
### UMI-FT

日期 2026-01-15，窗口外（outside_window），旧基础另标。机制：每指装 CoinFT 六轴力/力矩传感器，同时采集 RGB、深度、位姿与指级力旋量；主 RGB 与位姿 60Hz、超广角 10Hz、深度 30Hz、力传感器 360Hz，策略输入最近 32 帧力读数、输出位置/抓取力/刚度。监督信号为力/力矩标签，采集端存在而部署端的力通道一致性需单独核实。边界：人类手持采集、当前有线连接；三任务演示数 275/200/200，另有 630 条野外场景仅用于特定任务；未见表数据下载页与许可。接入检查：核对项目页是否提供数据下载与许可，确认力传感器标定模型与训练标签是否随代码开放。来源：[arXiv 2601.09988](https://arxiv.org/abs/2601.09988)。

<a id="p-umi-3d"></a>
### UMI-3D

日期 2026-04-15，窗口外（outside_window）。机制：在腕持夹爪集成 LiDAR+相机，以 LiDAR-惯性 SLAM 替代单目视觉 SLAM；STM32 产生 1Hz PPS 与 20Hz 相机触发，LiDAR 10Hz、相机 20Hz 统一入 rosbag，数据打包为含 RGB、末端位姿、旋转与夹爪状态的 Zarr。监督信号为多模态同步后的位姿与夹爪状态。边界：策略推理主要仍用视觉输入，作者自述 3D 感知未充分利用；单臂配置，未支持双臂协调；数据可下载性未在来源确认。接入检查：访问项目页确认 BOM/固件/标定代码是否真开源，核实 LiDAR-相机外参标定脚本与 Zarr 转换工具。来源：[arXiv 2604.14089](https://arxiv.org/abs/2604.14089)。

<a id="p-mv-umi"></a>
### MV-UMI

日期 2025-09-23，窗口外（outside_window）。机制：在腕部第一视角外增加第三人称 Intel RealSense D455，用 SAM-2 分割并以静态背景参考帧修复移除人类演示者；动作标签从腕部 egocentric MP4 经 ORB-SLAM3 与 IMU 估计，夹爪宽度由 ArUco 标记间距测得。监督信号为去除演示者后的第三人称视图与 SLAM 位姿。边界：47% 提升为三任务子任务平均，非通用结论；第三人称相机未做形式化标定，属设计取舍；数据集许可未说明。接入检查：核对项目页代码与数据集是否实际可获取并分别确认许可，核查第三人称相机时间同步与分割修复在部署端的实时性。来源：[arXiv 2509.18757](https://arxiv.org/abs/2509.18757)。

<a id="p-robopocket"></a>
### RoboPocket

日期 2026-03-05（v1/v2），v3 为 2026-10-19，窗口内更新、首发在窗口外。机制：手持夹爪几何匹配 Robotiq 2F-85 并以预压扭簧近似被动自适应指；主动校验把低纹理异常轨迹比例从 30% 降至 0%（异常定义为超过 1m 定位漂移或 5cm 轨迹跳变），纠偏数据由人手持采集、策略云端推理、机器人纠偏时不执行策略。监督信号为人类介导的近似 on-policy 数据。边界：纠偏数据分布为人类介导，作者明确不等同于机器人执行 DAgger 的状态分布；未声明代码/APP/硬件公开。接入检查：确认代码/硬件 BOM 公开及许可，核对单设备 2.8mm 精度在非常规刚性固定下是否复现。来源：[arXiv 2603.05504](https://arxiv.org/abs/2603.05504)。

<a id="p-egoguide"></a>
### EgoGuide

日期 2026-06-12，窗口内（in_window）。机制：采集接口同步记录腕部与头/自我中心观测，并联接在线视觉-几何数据质量引导；硬件基于开源 exUMI，夹爪旋转传感器测开度，腕部鱼眼由 Raspberry Pi 直采，各模态经 UDP 同步、头显 72Hz、控制器 20Hz，跨模态同步在 20ms 内；静态过滤丢弃约 2%–5% episode。监督信号为同步多视角观测加质量引导。边界：代码与数据发布状态在给定原文未明确；GERP 自我中心相机部署时固定安装而非主动头动；20 trials/policy 且作者自述未大量调参。接入检查：核对项目页是否实际提供硬件文件、采集脚本与数据集及各自许可，确认 20ms 同步与端到端延迟可复现。来源：[arXiv 2606.14665](https://arxiv.org/abs/2606.14665)。

<a id="p-bridge"></a>
### BRIDGE

日期 2026-06-25，窗口内（in_window）。机制：区分手持只记录观测动作与遥操作直接记录控制器期望动作的差异；仅对基础手持策略失败的接触段采集部分遥操作示教，形成状态门控专家。DM-UMI 用在线 SLAM 相机提供 6-DoF 位姿、磁位置传感器测夹爪宽度，动作空间用相对末端位姿与绝对夹爪宽度、horizon 24，目标动作 100Hz 插值后送 1kHz 笛卡尔阻抗控制器。监督信号为接触段期望动作。边界：未提供数据集下载、数据许可或代码仓库信息；CC BY 4.0 仅为论文许可。接入检查：核对 DM-UMI 离线/在线位姿估计一致性、support 数据标注方式与开源计划。来源：[arXiv 2606.26603](https://arxiv.org/abs/2606.26603)。

<a id="p-kiw"></a>
### KIW

日期 2026-09-19，窗口内（in_window）。机制：工具上唯一传感器为零售 Insta360 X5，工具端无额外电子或计算；用前后镜 360° 相机组合做双臂同体定位，六段双臂录制中仅 0.1% 查询帧定位失败（仅前镜跨手对齐在 24.8% 帧失败），对标记物参照平移 ATE 中位数约 4.31/4.48mm；语音命令起止录制。监督信号为 360° 相机重建的双臂工具位姿。边界：硬件与软件标注为未来计划（will be fully open-sourced），当前下载可用性与许可未确认；评估仅六段双臂录制，规模小。接入检查：核对项目页是否已发布硬件文件、重建代码与许可，确认前/后镜标定与音频同步可按自备相机复现。来源：[arXiv 2609.22809](https://arxiv.org/abs/2609.22809)。

<a id="p-grabette"></a>
### Grabette

博客页面日期 2026-07-21，不据此认定项目首发。机制：受 UMI 启发的手持夹爪加鱼眼相机野外记录，单一共享时钟同步观察相机、跟踪相机（含 IMU）与夹爪编码器；处理管线用 RTAB-MAP 做 SLAM 并校验轨迹无跳变或丢失跟踪，再转 LeRobot 格式；BOM 约 490€，配电机夹爪 Gripette 约 120€。监督信号为 SLAM 恢复轨迹与编码器值。边界：采集由人手完成非机器人自主；示例策略评测未给具体指标；评论区指出电子 BOM 曾不可公开访问，硬件完全开源状态待核；数据许可未明确。接入检查：核对博客脚注的 GitHub/HF Space/数据集 URL 可访问性、数据集许可与 SLAM 失败剔除规则。来源：[Hugging Face 博客](https://huggingface.co/blog/grabette)。

<a id="p-grabette-repository"></a>
### GRABETTE（仓库）

仓库可见日期 2026-06-08，不据此认定项目首发。机制：采集设备同步记录相机与深度流（OAK-D SR 另含 IMU），用 SLAM 恢复相机轨迹并导出 LeRobot 数据集，管线与具体机器人无关；提供手持、夹爪电机与头戴式（WIP）三种组件。监督信号为 SLAM 轨迹与编码器数据。边界：README 仅描述工具链，未说明任何已发布数据集内容或规模；头戴设备标注 WIP；数据许可未说明，仅代码 Apache-2.0。接入检查：核对导出的 LeRobot 数据集字段（相机内外参、动作空间定义、时间同步方式）与 SLAM 精度评估方式。来源：[GitHub 仓库](https://github.com/pollen-robotics/grabette)。

<a id="p-orbbec-robot-free-hardware"></a>
### Orbbec Robot-Free Hardware

官方页面日期 2026-08-05，不据此认定硬件首发。机制：硬件厂商平台围绕 EGO、UMI、WristCam 覆盖第一人称、手-物交互与腕部近场采集；Dual-Ego 原型配双 200 万像素鱼眼、同步精度 1ms 内、六轴 IMU 最高 1000Hz、重 200g，提供微秒级时钟同步与帧级对齐多设备触发能力，EGO RGB-D 结合原生深度与 LingBot-Depth 增强改善透明反射物体深度。边界：为展会新闻非数据集发布，未提供数据/标注/采集规模，测量为厂商宣称未第三方核验。接入检查：核实 Dual-Ego 与 EGO/WristCam 实际交付状态、多设备同步稳定性与 UMI 夹具兼容性。来源：[Orbbec 新闻](https://www.orbbec.com/news/scaling-real-world-data-for-physical-ai-orbbec-showcases-robot-free-data-collection-hardware-platform-at-roscon-jp-2026/)。

<a id="p-hifi-umi"></a>
### HiFi-UMI

日期 2026-07-28，窗口内（in_window）。机制：所有传感器由单一共享 GPIO 外触发驱动，实现微秒级跨相机/IMU/编码器同步；自述约 3mm 工作空间局部末端执行器精度、无需外部跟踪设施；发布 HiFi-UMI-2K 子集（2000 小时，源自超过 20000 小时、4.32M+ episode、480+ 场景语料），含六路视频、夹爪状态、子任务边界与质量元数据。监督信号为硬件同步多传感器数据加绝对下一状态动作目标。边界：完整 20000 小时语料是否可获取未确认；zero-robot post-training 结论仅覆盖四个桌面双臂任务与三个骨干；保真度未做消融。接入检查：下载清单核对每回合字段与许可文件，确认绝对动作是否需转为目标控制器相对动作。来源：[arXiv 2607.25895](https://arxiv.org/abs/2607.25895)。

<a id="p-hifi-umi-dataset"></a>
### HiFi-UMI-2K（数据集）

日期未知（undated），不冒充新首发。机制：Hugging Face 数据卡可访问，含数据预览与 LeRobot v3 式目录；所有相机、IMU、编码器与夹爪信号共享 GPIO 硬件触发，跨传感器偏移低于 40µs；存储 action 为绝对下一状态目标，valid.frame 为 false 的帧仍保留于 Parquet 与视频以保持对齐。监督信号为绝对下一状态目标。边界：98% 重建/重放成功率与 3mm 精度为页面自述非本文独立测量；策略成功率对比为特定设置非通用保证；未给代码仓库，代码许可 unknown。接入检查：核对每任务 episode 数与 valid.frame 过滤比例，确认绝对动作到相对动作的转换。来源：[Hugging Face 数据集](https://huggingface.co/datasets/simple-world-lab/HiFi-UMI-2K)。

## 最小对照试验设计（本文建议，未运行）

- **目的**：区分位姿记录误差、动作标签误差与传感一致性缺失对部署成功率的影响。
- **输入**：同一批任务、同操作者，分别用单目惯性 SLAM 与 LiDAR-惯性 SLAM 两种追踪采集各 N 条（N 值落地后按统计功效定），保持夹爪与相机几何一致。
- **对照**：A 组离线位姿标签；B 组在相同坐标约定下比较重建标签与目标机器人实测状态；若候选方案确有力/触觉通道，再设计 C/D 模态对照，并在训练与部署中一致处理缺失输入。
- **输出**：每组位姿漂移分布、动作标签与控制器执行量偏差、部署成功率与失败模式分类。
- **停止/复核条件**：若任一组位姿漂移超出自定工程容忍带（先标定后固定，不预设通用阈值）则停止该组训练并复核标定与触发时钟；若在线与离线位姿偏差导致动作分布显著偏移则复查 SLAM 配置与过滤口径；所有数值须来自本次实测，不以来源页面自述替代。

## 下一步值得跟踪的问题

1. HiFi-UMI 完整语料与代码是否实际发布，绝对动作到相对动作的官方转换工具是否提供。
2. KIW 的开源计划是否落地为可下载的硬件文件、重建代码与数据许可。
3. BRIDGE 的接触段专家标注与数据集是否公开，离线/在线位姿一致性有无量化。
4. EgoGuide 与 RoboPocket 是否提供代码/硬件 BOM，纠偏数据的分布偏移有无后续量化。
5. Grabette 数据集许可与 SLAM 失败剔除规则，以及 Orbbec 平台量产交付与第三方同步核验。
6. 各系统采集端力/触觉通道在部署端的缺失如何系统性量化与补偿。
