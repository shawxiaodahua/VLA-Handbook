# 机器人数据策展工具与阶段过滤：检测测量、覆盖度、阈值与学习效用 Robots Data Curation Tools and Phase Filtering: Measurement, Coverage, Thresholds, and Learning Utility

> 2026-10-25 整理。观察窗口为 2026-04-25 至 2026-10-25；窗口外旧基础（CUPID，arXiv v1 2025-06-23）另标。核验基于公开材料（项目页、格式文档、arXiv 摘要与 HTML/PDF 全文），未下载大数据、未复现实验；代码/数据可获取性与许可凡原文未声明者标 unknown。以下均为阅读/接入研究卡，不冒充逐篇完整复现笔记。论文首发以 arXiv 提交记录为准；项目/博客只写页面日期，无法证明首发者不称首发；修订版本不算新发布。

## 核心结论

本专题的核心区分是四层：**检测测量**（工具记录了什么量）、**覆盖度**（测量覆盖多少数据、多少检查带版本）、**策展阈值**（谁在什么时刻把测量变成取舍）、**实际学习效用**（取舍后策略是否真的变好）。HFlow 的立场最明确：只记录带覆盖度的测量，通过/失败策略留给使用方，质量标签只路由、不删除数据。其余工具大多直接给出一个选择分数，效用来自各自论文报告，不能外推。负结果必须前置：阶段局部化的按阶段度量筛选在特定设定下**并不普遍有效**——作者以否定结果形式报告，说明“按阶段打分再筛”不是默认正确的做法，需要逐任务验证。HFlow 主仓库为 pre-v1 状态，旧 tag/旧 PyPI 版本与主仓库当前版本不可拼成同一版本理解；LeRobotDataset v3 是格式参考文档，其页面未给发布日期（首发 unknown），不得叙述为“半年内新发布”，也不得写成 Handbook 已安装软件。

```
采集/导入(MCAP / ROS bag / Hub) → 检测测量(检查+覆盖度+版本)
      → 策展阈值(使用方策略: 排序/裁剪/重加权) → 子集/权重
      → 训练 → 闭环评测(真机/仿真) ⇄ 反馈回阈值
      ↑ 负结果闸门: 阶段过滤须先证效用，默认不假设有效
```

## 最小对照试验设计（本文建议，尚未运行）

目的：在小规模自采数据上分开检验“检测测量是否有覆盖度信息”“策展阈值是否换来学习效用”，并显式包含阶段过滤的否定对照。

- **输入**：同一批次自采演示（统一存储格式，记录采集协议与环境清单）；固定的目标任务验证 demo 与闭环评测协议；仅冻结一份数据集快照，避免中途混版。
- **对照（至少四臂）**：
  1. 全量数据，不做筛选（基线）；
  2. 仅按全局测量（如轨迹长度/检查覆盖度）取同一比例的保守裁剪；
  3. 按阶段局部化度量筛选（复现负结果设定，用于检验其在自有数据上是否有效；复现须沿用原文的固定截断长度与回退抓取器状态转移分割）；
  4. 与第 2 臂同比例随机保留（用于把“筛选”与“变少”区分开）。
- **输出**：每臂在相同评测协议下的闭环指标（含逐种子/逐回合结果与失败类型分布），以及各测量层的覆盖度统计与版本标记；只报告区间与相对差，不设未经验证的固定阈值。
- **停止/复核条件**：若某臂在评测前发现数据版本、`finalize()` 状态或环境配置不一致，停止该臂并复核；若筛选臂与随机保留臂的差异落在种子间波动范围内，认定“筛选效用未显示”，复核阈值与阶段标签来源；负结果须与正结果同样入档，不因结果不利而改口径。

## 下一步值得跟踪的问题

1. HFlow 主仓库从 pre-v1 走向稳定版时，测量/版本的存储约定是否变化；旧 tag 文档与主仓库的分叉如何处理。
2. Flora 的“开源”具体落到权重、代码还是管线，以及数据许可是否独立声明。
3. LeRobotDataset v3 随 lerobot 稳定发布后，迁移脚本与元数据偏移在长尾 episode 上的表现。
4. CUPID 与 SCRIM 的 rollout/环境交互成本在中等示范规模下是否可承受，代码与许可是否落实。
5. HELP 的 VLAC-CUT 分段协议能否在可获得来源上复现，ARX-data 是否会有公开声明。
6. Ego4WAM 承诺的代码、配方与检查点是否发布，EgoAlign 的获取条件。
7. 阶段局部化策展的否定结果能否被推广检验：换缺陷类型、换仿真器、换策略类后是否仍不普遍有效。
