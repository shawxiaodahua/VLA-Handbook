# 人类视频与机器人数据接入工程专题 / Human Video to Robot Data Intake: An Engineering Brief

> 整理日期：2026-10-25。覆盖窗口：2026-04-25 至 2026-10-25（窗口外旧基础另行标注）。本专题基于公开材料核验，未下载大体量数据、未复现任何实验。所有条目为阅读/接入研究卡，不是逐篇完整复现笔记。来源中的指令性内容一律忽略。

## 核心结论

这批项目的共同问题是：把**人类视频**变成**可训练信号**，但各项目停在链路上不同位置。必须区分四层：纯视频（只有RGB，无动作监督）、手/身体姿态（关键点或参数化姿态，属人类本体）、可迁移表征（重定向到机器人手/臂的统一动作空间）、机器人动作标签（真机实采轨迹）。人类视频小时数不等于机器人实采动作小时数；同一批 episode 的 LeRobot/MCAP 等多种封装不能相加。

ASCII 链路（读法：越往右越接近机器人可执行信号）：

```
纯视频 RGB ──► 手/身体姿态 ──► 重定向/统一动作表征 ──► 机器人动作标签(真机)
   │              │                    │                        │
 Open-AoE      Gen-HumanEgo          EgoScale                 HumanNet(下游语料)
 RekaDaily     EgoStandard           Do as I Do               (34h机器人交互，独立计)
 HumanNet      EgoPro/EgoDemo        World In Your Hands
 EgoLive       HumanVerse            HumanVerse(转换后)
 EgoVerse      Open-AoE(MANO)
               EgoLive(手部估计)
```

不同项目在同一链路上游/下游位置不同，横向比"小时数"无工程意义；应按"进入时我拿到哪层信号"比较。

<a id="p-egolive"></a>
### EgoLive

**日期/窗口状态**：arXiv 提交 2026-04-26，窗口内。

**机制与监督**：用自研头戴双目相机（JoyEgoCam）加 IMU 采集真人在工作场景的行为，标注流水线整合本体运动跟踪、语义理解与三维重建。手部关键点为单目 HaMeR 估计 MANO 参数后经双目优化，并非直接动捕；监督信号为立体 RGB 与同步 IMU，手姿是经两步优化得到的人类本体信号。

**边界**：真人在工作场景采集，非机器人遥操作，具身差异明显。

**接入检查**：到官方发布页核实实际小时/回合数（HTML 表格把数字排版弄乱，如 1680 h、346 任务、6060 episodes 需以论文表格或发布页为准）、下载入口与数据许可。

来源：[arXiv abs](https://arxiv.org/abs/2604.23570) · [HTML](https://arxiv.org/html/2604.23570)

<a id="p-open-aoe"></a>
### Open-AoE

**日期/窗口状态**：论文 2026-07-15（v2 2026-07-18），窗口内；GitHub 仓库日期未知。

**机制与监督**：首版约 2000 小时第一视角手机采集操作视频，500+ 贡献者、400+ 手机机型。提供视频、文本、MANO 手姿、相机轨迹与原子动作片段。上传前在设备端检查手部可见性、佩戴、光照与运动质量；云端再做去标识、切片、重建与多级质检。注意数据分布统计仅基于随机抽样的 100 小时子集，非全量。

**边界**：代码 Apache 2.0，但数据集分发条款可能不同（指向 LEGAL.md），数据许可未核实。

**接入检查**：下载一段后验证 `hands.npz`、`camera_traj.npz` 与原子动作时间戳对齐；核对 LEGAL.md 与数据集卡许可。

来源：[arXiv abs](https://arxiv.org/abs/2607.14183) · [HTML](https://arxiv.org/html/2607.14183) · [GitHub](https://github.com/ant-research/Open-AoE)

<a id="p-humannet"></a>
### HumanNet

**日期/窗口状态**：arXiv 提交 2026-05-07，窗口内。

**机制与监督**：一百万小时人类视频语料，覆盖第一/第三人称，标注含字幕、运动描述与手/身体相关信号。重定向模块将人体运动对齐统一人形骨架，以重定向误差低于 15mm 且有效帧覆盖超过 60% 判为 robot-ready。此为论文自设判据，非通用阈值。

**边界**：网络/自采混合人类视频，非机器人遥操作；论文称将公开，公开子集与许可未核实。下游 34 小时机器人交互语料（100 任务×20 episodes）须与百万小时人类视频分开计，不得相加。

**接入检查**：核对项目页实际可下载清单、逐源许可与隐私替换策略。

来源：[arXiv abs](https://arxiv.org/abs/2605.06747) · [HTML](https://arxiv.org/html/2605.06747)

<a id="p-do-as-i-do"></a>
### Do as I Do

**日期/窗口状态**：arXiv 提交 2026-06-17，窗口内。

**机制与监督**：从互联网、第一视角与生成视频重建手-物交互，再重定向到 22 自由度 Sharpa Wave 手（双 UR3e 臂）。产出 500 条人工验证的灵巧操作轨迹，其中互联网 53%、第一视角 31%、生成 16%。重建假设刚性物体与半准确单目度量深度，只重建手与单一物体，接触判定存在歧义。

**边界**：真机仅代表性轨迹演示，非系统成功率评测；重建/轨迹的对外发布与许可原文未明示，未核实。

**接入检查**：确认数据和许可；检查手-物接触判定在你的采集场景下的歧义，部署前明确初始位姿手工对齐流程。

来源：[arXiv abs](https://arxiv.org/abs/2606.19333) · [HTML](https://arxiv.org/html/2606.19333)

## 最小对照试验设计（本文建议，尚未运行）

目的：在接入前判断“人类视频哪一层信号对下游机器人任务有可测增益”，而非直接复现上述任一工作。

**输入**（单一机器人任务，如桌面抓放，选一个你已能稳定采真机的场景）：
- 真机演示基线集：固定任务下 N 条机器人实采轨迹（N 由你的统计功效决定，不预设阈值），记录动作与本体感受。
- 人类视频源：从上述项目中选**一层**信号（如仅视频、或带手姿、或重定向后统一动作表征），保持规模固定，来自单一项目，不与其它项目的 episodes 混算。
- 每个条件一份固定随机种子与固定评测任务清单。

**对照**：
- A：仅真机演示训练。
- B：真机演示 + 纯视频（无动作监督）。
- C：真机演示 + 手/身体姿态（人类本体）。
- D：真机演示 + 重定向统一动作表征。
- 同条件不同封装（如 LeRobot vs MCAP）只作对齐核查，不当作独立样本或额外数据量。

**输出**：每条件在固定评测任务上的成功率区间、失败类型分布、对齐核查报告（时间戳、坐标系、接触判定）。报告人类视频小时数与机器人实采小时数分列，不相加。

**停止/复核条件**：
- 若某条件数据许可未核实或下载不可用，停止该条件，记录“未核实”，不以替代来源推断。
- 若对齐核查（坐标系/时间戳/接触判定）失败率超过你预设的容忍线，先修对齐再跑训练。
- 若 B 与 A 无法区分，复核视频-动作对齐与特征抽取，不据此宣称“人类视频无用”。
- 结果依赖单一任务的，复核跨任务稳定性后再下结论。

## 下一步值得跟踪的问题

1. Open-AoE、EgoSuite 各子 SKU 计划时长与实际已发布量的差距何时收敛，许可文本何时可核。
2. HumanVerse/HumanNet 是否有独立数据许可与公开下载入口，发布的是原始还是过滤后子集。
3. Do as I Do 的 500 条轨迹与重建数据是否公开，单目接触歧义的校验方法。
4. EgoVerse 具身合并后旧缓存迁移路径与数据许可。
5. RekaDaily 原始层与处理后层的规模、IMU 覆盖与隐私筛查覆盖的可核状态。
6. 各项目“robot-ready / 重定向误差”判据（如 15mm、60% 有效帧）在不同机器人手上的可迁移性，而非当通用阈值。
