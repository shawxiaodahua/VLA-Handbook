# 合成机器人数据引擎工程专题 / Synthetic Robot Data Engines: An Engineering Brief

> 2026-10-25 整理。覆盖 2026-04-25 至 2026-10-25 窗口内的公开材料；窗口外旧基础另标。核验基于公开摘要/HTML/数据集页面与官方 PDF 交叉核对，未下载大数据、未复现实验、未逐篇完整复现。所有项目均为阅读/接入研究卡。文中数字仅取来源明确陈述且条件完整处；发布状态与许可只写来源可见事实，未知即写 unknown。

## 核心结论

这批工作共享一条链路：原视频/人类示教 → 视觉编辑/动作映射/仿真执行/质量筛选 → 合成集 → 真机检验。但“合成”在不同项目里含义不同：视觉编辑产物（RoboEdit、Mirror Learning、Ego2Robot、HuRo）、仿真接触/执行产物（Dex-X、OASIS、EmbodiedSmith、DREAM）、世界模型渲染（GRAIL、OSCAR），以及物理采集人手示教后的重定向（AdvDex、NVIDIA V2D）。采集路线是并列的：可以是人手视频/穿戴采集，也可以是仿真内遥操作或资产条件生成，并非“人类手套→手持接口→仿真”的必经串联。场景数、重定向构型数、合成小时数都不是独立实采小时，不能互换口径。代码/数据发布状态在可见来源中多为 unknown，论文许可不等于数据许可。仅少数项目给出真机闭环结果（HuRo、RoboEdit、Dex-X、GRAIL、DREAM、OASIS、AdvDex），且多为单平台、自报、无独立复现。

```
并列采集路线：
  A 人手视频/穿戴采集 ──▶ 重定向+视觉替换/编辑 ──┐
  B 仿真内遥操作/规划执行 ──▶ 状态回放+渲染 ──────┼─▶ 质量筛选 ──▶ 合成集 ──▶ 真机检验
  C 资产/场景条件生成 + 世界模型 rollout ─────────┘
        │                    │                      │
   来源许可?           伪影/遮挡/物理近似        丢弃比例不透明、单平台/自报
```

## 路线比较

| 工程问题 | 视觉编辑/重定向派 (Ego2Robot, HuRo, RoboEdit, Mirror Learning, AdvDex, V2D) | 仿真接触/执行派 (Dex-X, OASIS, EmbodiedSmith, DREAM) | 世界模型派 (GRAIL, OSCAR) |
|---|---|---|---|
| 监督信号来源 | 视频帧+重定向动作/IDM 动作 | 仿真状态、接触力、规划器动作 | 世界模型渲染+跟踪策略 |
| 主要失真 | 遮挡伪影、深度歧义、本体差异 | 仿真-真机差距、物理近似 | 外观不一致、丢弃比例 |
| 真机证据 | HuRo、RoboEdit 有真机结果；AdvDex 单平台 | Dex-X 零样本、DREAM/OASIS 真机 | GRAIL 自报成功率 |
| 发布状态 | 多 unknown；V2D CC-BY-4.0 已标 | 多 unknown | 多 unknown |

### Ego2Robot
<a id="p-ego2robot"></a>

日期 2026-08-03（arXiv 首发，in_window）。机制：把手部姿态重定向为平行夹爪末端轨迹并做时间平滑，每条样本含合成视频帧、相机系 EEF 动作、相机参数与文本指令；四源 ego 共约 1,940 小时，经 15 种构型与三层质量筛选（管线内部 IK/自碰撞/动作离群、统计、VLM 一致性）产出 18,561 小时合成数据。监督信号是重定向 EEF 轨迹，非真机实采。边界：丢弃手指精细 articulation，仅支持平行夹爪，重遮挡下修补可能产生伪影。接入检查：到项目页核实合成数据是否对外发布、公开/内部子集比例、四数据集再分发条款与逐帧有效性掩码。[arXiv](https://arxiv.org/abs/2608.02580)

### HuRo

<a id="p-huro"></a>

日期 2026-09-09（arXiv 首发，v5 2026-09-25 修订，in_window）。机制：把五个人类视频源机器化为约 63 万 episode、1.42 亿处理帧的预训练数据；五源审计中仅 55.2% 轨迹无检测到的非抓取自接触，作者明示这些轨迹是预训练监督而非可执行演示。监督信号为视觉+运动学动作，无力/触觉。四个真机任务上全量预训练报告四任务平均总体完成 51.5%→80.3%、四任务平均 OOD 完成 34.9%→72.2%（ID 平均 68.1%→88.4%），自报，单机器人实例 ALLEX，OpenArm 为附录扩展。边界：不含力/触觉，自接触诊断表明不可直接当真机演示复用。接入检查：核对项目网站是否真提供数据/代码、适用许可与原人类视频源再分发条款，并确认自接触诊断是否随数据卡发布；论文未在可见正文给出项目网站数据/代码许可，不能从 arXiv 许可推断。[arXiv](https://arxiv.org/abs/2609.10706)

### RoboEdit

<a id="p-roboedit"></a>

日期 2026-08-19 首发（HTML v4 2026-10-17 修订，in_window）。机制：从五个公开手-物数据集取 24,197 段人类片段，经单目手部重建、深度尺度校正后重定向到 7 种构型，构成 174,547 对、逾 14.1M 成对帧——拆分为 145,459 真实场景对 + 29,088 合成场景增强对，后者源人类片段与真实对相同；机器人视频为编辑/渲染产物，物理合理性由深度正则与物理优化近似。监督信号为对齐的人/机器人视频对与 3D 状态标签。边界：非真实执行，深度歧义与接触丢失风险仍在。接入检查：核实 RoboEdit-14M 是否公开下载、公开子集是否只含可再分发部分、逐片段许可与 3D 标签是否随数据发布；真实对与合成对再分发条款可能不同。[arXiv](https://arxiv.org/abs/2608.18948)

### Mirror Learning

<a id="p-mirror-learning"></a>

日期 2026-07-30（in_window）。机制：微调视频扩散模型做第三人称到学习者视角的变换（不假设已知相对位姿或显式几何），再以逆动力学模型推断学习者控制空间动作；CARLA 仿真配对数据正文称约 2.2 万对保留（附录总数 21,966 段；初始生成约 37,000 对后过滤）。监督信号为视角变换帧+IDM 动作。边界：策略评测为自驾驶开环 minADE5，非机器人操作；Minecraft 为真实玩家但仅用于 MVM 定性；真实数据不足 20 场景仅零样本定性。代码/数据/检查点声明录用后发布，当前为规划状态。接入检查：确认发布物是否含 IDM 与 MVM 权重、CARLA 配对数据是否含动作标签，“约一半价值”是否仅在开环指标成立。[arXiv](https://arxiv.org/abs/2607.28737)

### AdvDex

<a id="p-advdex"></a>

日期 2026-08-14（in_window）。机制：OmniShare 含逾 10 万条轨迹、500+ 任务、700+ 物体；作者称跨五个真实域，本次未逐域核对；采集手套含 29 个磁旋转编码器与霍尔触觉阵列，系统微秒级同步；预训练混合 OmniShare、VITRA-1M 与 OXE 子集（5:4:1，OXE 子集具体规模/筛选原文未给）。监督信号为手部运动学与法向接触力——注意与光学触觉、标定力矩、sEMG 不同。边界：动作空间未建模本体动力学，真机仅单台 Paxini Tora 配 19 自由度 DexH13 手、1,000 条示教、五任务、每任务 20 trials，作者自述为局限。接入检查：确认 OmniShare 是否开放申请、触觉与运动学时间戳格式、JAAS 掩码槽位训练期处理。[arXiv](https://arxiv.org/abs/2608.14028)

### Dex-X

<a id="p-dex-x"></a>

日期 2026-09-07 首发（v3 2026-10-01 修订，in_window）。机制：以仿真接触动力学作“触觉补全引擎”，教师策略接收五指指尖接触力标量（平均降噪），学生策略在真实 Franka FR3 配 Sharpa Wave 手上零样本 sim-to-real 执行、无真机微调，但部署仍依赖重定向运动参考与任务条件——注意仿真触觉不是实采触觉。监督信号为仿真接触力+动作。边界：触觉仅五指指尖力标量，不含压力/剪切/滑移，15 个接触位置通道默认置零；训练全在仿真，人类视频数量未在可见正文量化；原文附录另有 Sharpa HA4 称谓。接入检查：核对项目页是否实际提供数据/代码、合成触觉力的仿真到真机尺度一致性、人类视频源与数量是否公开。[arXiv](https://arxiv.org/abs/2609.07747)

### GRAIL

<a id="p-grail"></a>

日期 2026-06-03（in_window）。机制：依赖三维资产、仿真就绪场景与商用视频世界模型生成人形序列，产出逾 2 万条覆盖拾取、全身操作、坐姿与地形通过；训练以 PPO 进行，轨迹为世界模型生成而非物理遥操作。监督信号为生成序列+PPO 策略。真机自报已见物体拾取 84%、未见物体拾取 80%、爬楼梯 90%（Unitree G1 + OAK-D）。边界：严重遮挡/快动/外观不一致时重建质量下降并丢弃相当比例序列；跨具身未验证。接入检查：确认项目页是否发布生成管线代码、序列数据及许可，核对真机评测回合数与随机化条件。[arXiv](https://arxiv.org/abs/2606.05160)

### OSCAR

<a id="p-oscar"></a>

日期 2026-06-03（in_window）。机制：生成式世界模型与合成评测环境，训练数据来自既有公开数据集；从 2,165,359 个源视频过滤后保留 180,657 个回合（180,657 为过滤后 episode 数），四个过滤机制为长度、静态相机、有意义动作、骨架可见性，语义去重先 SigLIP 相似度再轨迹 RMS 确认；条件表示为二维骨架渲染（可渲染机械臂或 MANO）。监督信号为动作条件视频。边界：不是新增实采；受标定与运动学标注质量限制，仅用 2B 骨干；虚拟评测用 GPT-5 打分，与人标签一致率 78/100，存在少报成功偏差。接入检查：核对 OSCAR 自产数据/检查点与代码的具体许可，确认第三方数据集许可能否覆盖再分发混合体。[arXiv](https://arxiv.org/abs/2606.04463)

### EmbodiedSmith

<a id="p-embodiedsmith"></a>

日期 2026-10-06（v1，in_window）。机制：仿真中执行并记录时间对齐的视觉观测、本体状态、物体状态、控制动作与阶段标注；仅满足任务成功判据且通过轨迹完整性检查的 episode 进入示教集，失败 episode 留作诊断。定量基准在 Isaac Sim 6.0.1 以 30Hz 物理与渲染步长运行（该 30Hz 不等于策略控制频率）；策略对比为两组等时长均为 20 小时：clean=20 小时固定布局，mixed=10 小时固定+10 小时随机化布局。监督信号为筛选后仿真轨迹。边界：可变形配置为简化程序化表示、释放后恢复不完整为已知限制；真机仅示教展示。接入检查：核对生成示教与资产库是否公开、许可为何、30Hz 记录与训练时间轴对齐方式、失败诊断是否单独发布。[arXiv](https://arxiv.org/abs/2610.07969)

### DREAM

<a id="p-dream"></a>

日期 2026-08-29（v1，in_window）。机制：在重建仿真中开环执行 TAMP 规划，检测器在夹爪闭合未取得物体时中止；TAMP 源轨迹通过 rubric 的记为时间索引轨迹，增强试验仅在终局判据触发并通过离线物理合理性过滤后接受；每步存语言指令、渲染 RGB、机器人状态与动作标签，写为 LeRobot 格式；仿真复用同一相机模型。监督信号为规划器动作标签。边界：场景限近似静态桌面与刚体，可变形/关节体/接触丰富任务为未来工作；视频来自商品手持相机扫描而非机器人执行。接入检查：核对 LeRobot 数据是否实际发布、公开子集与许可、增强接受率与判据校验是否经人审。真机评测为每策略每任务 15 次、留出物体配置。[arXiv](https://arxiv.org/abs/2608.29078)

### OASIS

<a id="p-oasis"></a>

日期 2026-06-07（in_window）。机制：两阶段解耦——遥操作时只记录机器人与物体状态序列，再离线重放渲染，每条轨迹渲染到 20 个环境（随机化后的渲染副本数，不是 20 条独立实采轨迹）以平衡性能与开销；部署为 29 自由度 Unitree G1，高层规划器 25Hz 输出 32 步动作块，低层控制器以 50Hz 执行该块。监督信号为仿真状态序列+渲染观测。边界：数据全部在仿真采集，未给出数据规模绝对数值；随机化全部关闭时策略几乎完全无法迁移，说明迁移强依赖随机化配置。接入检查：确认仿真数据总量与渲染帧数口径、是否有公开子集、零样本评测随机种子与成功判定标准。[arXiv](https://arxiv.org/abs/2606.08548)

### NVIDIA V2D

<a id="p-nvidia-v2d"></a>

日期 2026-08-01（页面标注，版本 0.1，in_window；页面日期不等于论文首发）。机制：数据集含将人示教重定向到双臂 Sharpa 机器人手的样本，以及模仿原人示教的机器人执行 episode；基础人示教来自 TACO 双手机-物数据集，采集与标注方法均标为合成。页面标注 1,215 条运动序列、121,500 个机器人 episode、1,215 个运动 Parquet、总存储 924.8 GB，均为页面自报、未逐条下载校验，viewer 曾报 JobManagerCrashedError；许可 CC-BY-4.0；仓库无独立代码链接，代码许可 unknown。边界：查看器崩溃仅见预览，未验证逐条可用性与 schema 一致性；两类子集的 task 计数未给出。接入检查：核对重定向运动与机器人执行两类子集 task 计数、逐条可用性、下载后 schema 与预览是否一致。[Hugging Face](https://huggingface.co/datasets/nvidia/video-to-data-robot-dexterity-task-library-and-dataset)

## 可执行的最小对照试验设计（本文建议，未运行）

- **输入**：同一小批任务（建议 3–5 个刚体桌面拾放，含一个遮挡变体）；同一基座策略与训练预算；四条数据臂——A 少量真机示教（对照基线）、B 视觉编辑合成（如 RoboEdit/Mirror 式）、C 仿真接触/规划合成（如 DREAM/EmbodiedSmith 式）、D 重定向人手采集（如 AdvDex/V2D 式）。所有合成臂先做许可与逐条可用性核验。
- **对照**：A vs B/C/D 分别配对；合成臂内按“视觉编辑 vs 仿真接触 vs 重定向”分组；每条臂记录来源片段许可状态与筛选丢弃比例。
- **输出**：真机成功率（固定回合数、留出物体配置、固定随机种子）、OOD 变体成功率、失败类型分布（遮挡/接触/抓取滑移）、每有效小时成本。
- **停止/复核条件**：若任一合成臂的丢弃比例或来源许可无法核实，暂停该臂；若真机差距在遮挡变体上系统性放大，复核视觉伪影归因；若仿真接触臂真机力尺度不一致，复核触觉标定后再比较。

## 下一步值得跟踪的问题

1. 各项目代码/数据/检查点的实际发布状态与独立数据许可，尤其论文许可与数据许可的分离。
2. 合成小时数、成对帧数、场景/构型数的口径统一，避免与独立实采小时混用。
3. 筛选丢弃比例的透明报告及其对数据分布的影响。
4. 仿真接触力到真机的尺度一致性与跨具身迁移证据。
5. 真机评测的回合数、随机化与独立复现日志。
