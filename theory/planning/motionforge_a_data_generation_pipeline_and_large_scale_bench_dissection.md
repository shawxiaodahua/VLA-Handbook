## 1. 核心架構/方法總覽 (Overview / Architecture)

MotionForge 不是单一模型，而是「**基准 + 数据生成管线**」两部分，构建在 Isaac Sim 之上，仿真时钟固定 120 Hz。

### 1.2 关键机制 (Key Mechanism)

- **复用 Skill 而非任意低层控制**：预言机只调用预定义可复用技能（target tracking / grasping / pushing / pulling / placing），避免每个任务写一份专属控制逻辑，降低实现差异造成的噪声。
- **自适应预言机而非轨迹回放**：预言机持续跟踪目标 6D 位姿、生成 Pre-Interaction Pose、在交互条件满足时执行技能，而非重放固定轨迹——这样才能在动态环境中"跟着物体走"。
- **两步自动化闭环**：构建 → 校验 → 失败归类（interaction failure / pre-grasp failure / execution timeout / other）→ 反馈修订 → 重跑，直到通过。
- **任务长时程的操作性定义**（不是拿时长当难度代理）：满足其一即算长时程——(i) 参考执行 > 8 s 且包含 ≥ 2 个有序技能原语；或 (ii) > 20 s（无论技能数）。8 s 阈值取自 DOM 长时程子集平均时长。结果：**17 长时程 / 23 短时程**。
- **因果运动标注**：只对"被交互目标物"的非因果/因果运动做标注（非因果 = 缺乏可辨识且物理合理的场景内因；因果 = 可归因于显式驱动或物理过程）。MotionForge 因果运动比 R_causal = 1（全覆盖），DOMINO 与 PhysMani-Bench 大量目标运动是脚本化运动学命令、无可辨识场景内因。

⚡ **Eureka Moment**：**把"环境在策略推理期间是否继续演化"变成评测协议的一等维度**——用 R1（解耦、独立演化的 120 Hz 仿真时钟）替代传统的 R3（推理时冻结环境），使模型的原生推理延迟直接转化为 obs→act 时间差与失败，从而暴露被"冻结环境评测"系统性掩盖的实时性缺陷。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
动态操作的成功 = P(动作在"到达时"仍然对物体有效) ≈ f(推理延迟, 物体速度, 动作预测精度)
```

基准本身没有训练损失，其"数学核心"是**评测定义**——因子化域偏移与实时协议的形式化。

**目标**：给定固定任务语义 T，衡量策略在单因子/联合因子分布偏移下的鲁棒性，并把推理延迟显式计入成功判据。

**形式化**（用代码块，非 LaTeX）：

```
任务实例:    τ = (T, v, o, b, l)
              T = 任务语义与交互目标 (评测时固定)
              v = 运动速度  o = 被操作物体  b = 场景背景  l = 光照条件

偏移因子集:  S ⊆ { Speed, Object, Background, Lighting }
              |S| = 1  → 单因子 OOD (隔离单一变化的影响)
              |S| = 4  → 联合 OOD  (四因子同时偏移)

单任务成功率: SR_t = (1/50) · Σ_{s=0}^{49} success(t, s)
场景族分数:   对族内任务取平均
总体分数:     对全部 40 个任务做宏平均 (macro-average)
```

**变量说明**：

| 符号 | 含义 | 备注 |
|------|------|------|
| T | 任务语义/交互目标 | 域偏移时保持不动 |
| v, o, b, l | 速度/物体/背景/光照 | 独立扰动轴 |
| S | 被偏移的因子子集 | 决定 OOD 类型 |
| s | 随机种子 {0,…,49} | 跨方法共享同一 seed 集 |
| SR_t | 任务 t 成功率 | 50 次 rollout，每 seed 一次 |

**因果运动比**（用于跨基准对比运动真实性）：

```
R_causal = N_causal / N_dyn
  N_causal = 交互目标物具有因果运动的动态任务数
  N_dyn    = 全部被标注的动态任务数
```

**直觉**：这套定义把"泛化"拆成可隔离、可组合的四个轴，并把"实时性"从工程噪声升格为语义组成部分——因为当 |S|=4 且环境在推理时继续演化，模型面对的不是"换个背景"而是"换个世界且世界还在动"。

> 符号与本文/相关文档保持一致：T 为任务语义，v/o/b/l 依次为速度/物体/背景/光照，S 为偏移因子子集。

## 3. 带数字走一遍：玩具例子 (Worked Example)

设想一个 CM（Circular Motion）族任务：夹取一个绕中心旋转的杯子，训练速度 = Level 2。

**Step 1 — 设定**：仿真时钟 120 Hz；动作以 30 Hz 定义、重采样到 120 Hz；默认执行长度 H_exec = 16 → 每次开环执行 16/30 ≈ 0.53 s 的动作。

**Step 2 — 延迟注入**：设某策略原生推理延迟 L = 79.99 ms（X-VLA 实测值）。R1 下环境不暂停：从取观察那一刻到动作真正作用到仿真，物体已多转/多移动了约 L 对应的角度。若物体角速度较慢（Level 1），这段位移小，任务仍可挽回；若在 Level 3（快于训练速度），同 80 ms 内的位移更大 → 抓取点错位。

**Step 3 — 冻结 vs 不冻结**：把同一策略切到 R3（推理时冻结环境），obs→act 的时间差被清零，相当于把物体"按住"等模型。论文实测：**冻结环境使平均成功率相对 R1 提升 21.7–27.5 个百分点**。这个差值就是"实时性"被 R1 显式暴露出来的代价。

**Step 4 — 联合偏移的乘法效应**：单因子下 X-VLA 在 Object OOD 上 13.20%、Background OOD 15.80%、Speed OOD 19.05%；但要四个轴一起偏移（Joint OOD），其总体成功率掉到 **5.85%**（全部被测方法中的最高值）。也就是说，单轴鲁棒性并不叠加成联合鲁棒性——这是本基准最刺眼的诊断数字。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 仿真时钟 | 120 Hz 固定 | 环境演化粒度细，任何推理延迟都被如实放大为状态偏差 |
| 动作表示 | 10-D: a = [p, r_6D, g] | 绝对末端位姿 + 夹爪指令；跨方法统一便于受控对比 |
| 动作频率 | 30 Hz 定义 → 重采样 120 Hz | 重采样引入相位对齐细节，长 H_exec 时开环漂移累积 |
| 默认执行长度 | H_exec = 16 | 反馈频率 vs 开环时长权衡；最优值依策略而异（ACT/GR00T→16, X-VLA→32） |
| 缓存策略 | 推理时缓存动作继续执行，新 chunk 返回后替换剩余缓存，**不做延迟截断** | 不人为掩盖延迟；延迟越大，被替换的"过期动作"越多 |
| 观测 | 全局/前置 320×240 + 腕部 160×160 | 多视角；DP 额外用原生两步时序输入 |
| 训练预算 | 50 演示/任务（共 2K），80K 步 × batch 32 = 2.56M 样本 | 跨架构受控对比；每策略每场景族 10 任务 500 演示，共 4 模型 |

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 系统隔离"光照/物体/背景/速度"单轴偏移对策略的影响，并给出联合偏移下的合成效应。
- 用 R1 协议把真实推理延迟纳入成功判据，暴露被冻结评测掩盖的实时性缺陷。

**不能做 / 失败模式**：
- **联合域偏移**是普遍崩塌点：所有被测策略在 |S|=4 时大幅掉点，最优仅 5.85%，且方法排名相对 in-domain 发生改变。
- **高速运动**单向变难：多数策略在慢于训练速度（Level 1）保持甚至提升，快于训练速度（Level 3）则普遍下降——慢速放宽了时间裕度，快速压缩了闭环修正窗口并放大延迟/预测误差。
- **未见过动态目标物**（Object OOD）对所有策略都是硬伤，仅 X-VLA 基本不变（可能存在底座效应，需注意）。
- **世界模型式策略**（FastWAM）在实时协议下表现最差——预测表征无法在延迟内转化为动作。

### 6.1 隐含假设 (Hidden Assumptions)

- **仿真即真实**：全部结论出自 Isaac Sim，未做 sim-to-real 验证；仿真物理与真实接触/摩擦/光照的差异未被评估。
- **单平台**：统一在单一机械臂 + 10-D 末端位姿动作空间下评测，"泛化到移动/双臂/人形"未被验证（论文未来工作也承认要扩展到真机移动操作）。
- **固定训练预算的公平性**：50 演示/任务是为受控对比而设，可能对数据饥饿型大模型不利，"大模型更差"的结论需限定在此预算下解读。
- **in-domain 训练分布是各场景族 10 任务各 500 演示**，跨族不共享——方法排名是否能迁移到联合训练设置未知。
- **冻结环境增益 21.7–27.5 pp** 用 ACT/X-VLA/GR00T 在 FC/CM 上测得，未证明该增益对所有策略/场景族一致。

## 7. 与相关工作对比 (Comparison)

| 基准 | 长时程任务 | 运动模式 | 任务数 | 联合OOD | 实时协议 | 因果运动 |
|------|-----------|---------|--------|---------|----------|----------|
| DOM (DynamicVLA) | 1/3 | 1 | 3 | 部分 | R2 | ✓ |
| DOMINO | 0/35 | 3 | 35 | ✗ | R3 | ✗ |
| PhysMani-Bench | 0/8 | 3 | 8 | ✗ | R3 | 部分 |
| **MotionForge** | **17/40** | **11** | **40** | **✓** | **R1** | **✓** |

（RT 协议：R1 基准控制的、模型无关的实时协议，环境独立于策略推理演化；R2 粗粒度异步步进；R3 step-synchronous 冻结环境。表格来自论文 Table I，采用统一任务族标注协议。）

**与基线策略对比**：ACT（任务专用）在 in-domain 领先但 OOD 脆弱；大型预训练通用策略（X-VLA/GR00T）对光照/背景更鲁棒，但联合偏移仍崩；世界模型 FastWAM 在实时约束下最弱。

**面试 Tip**：被问"动态操作为什么难"，一句话答——**难的往往不是预测物体去哪，而是"等你算完，物体已经到了下一个状态"**；MotionForge 的价值就是把这句话变成一个可复现、可隔离的评测维度（R1 vs R3 差 21.7–27.5 pp）。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做动态/移动物体抓取、需要选评测集或复现 baseline 的研究者；
  2. 关心 VLA 实时推理-执行闭环、想量化"延迟代价"的系统工程师；
  3. 需要动态操作演示数据（~20K episodes）做训练/预训练的数据团队。
- **建議章節路徑**：先讀 §III-D（解耦实时协议 R1/R2/R3，理解本文灵魂）→ 再看 §III-C（因子化 OOD 定义）→ 再看 §IV（数据生成管线：Coding/Examine Agent + 校验闭环）→ §V-B/§V-C/§V-D（ID/Joint OOD/时序分析结果）→ 可跳 §II Related Work（除 Table I 对比外信息密度低）。
- **不值得精讀的理由**：若你不做机器人学习、或已熟悉 DOM/DOMINO/PhysMani 系列与 LIBERO-Plus 之类的鲁棒性基准，读摘要 + Table II/III 两个数字（ID 最强 22.20% / Joint 5.85%）即可抓住全部要害。
