## 1. 核心架構/方法總覽 (Overview / Architecture)

CMP 是一條**離線、黑盒、策略無關**的資產投毒管線。輸入一個良性資產 `A=(V,C)`，輸出一個視覺網格不變、碰撞網格被篡改的投毒資產 `A'=(V,C')`。

### 1.1 系統對比概覽 (System Component Comparison)

| 模塊 | 輸入 | 輸出 | 時序/頻率 | 備註 |
|------|------|------|-----------|------|
| 手柄選取 (FPS) | 視覺網格 V | k 個均勻分佈的手柄 H | 一次性 | 固定搜索空間維度 k×3 |
| 變形算子 D_θ (RBF) | 手柄位移 θ、V | 平滑變形後網格 D_θ(V) | 每候選 | 不直接改碰撞網格，而是改「視覺網格的副本」 |
| 凸分解 | D_θ(V) | 候選碰撞網格 C' | 每候選 | 保證滿足物理引擎的凸性等約束 |
| 策略無關代理 (scripted proxy) | C'、C | 估計 Stealth、Harm | 每候選 | 用腳本化抓取，不訓練策略 |
| 黑盒優化器 (CMA-ES) | 一群候選的分數 | 更新的搜索分佈 | 每輪 | 目標非可微（離散成功/失敗） |
| 資產打包 | 最優 θ | 投毒資產 A' | 一次性 | 視覺網格/紋理/物理參數全不動 |

### 1.2 關鍵機制 (Key Mechanism)

- **為什麼不直接改碰撞網格？** 物理引擎對碰撞網格有嚴格幾何要求（如凸性），直接改容易讓仿真崩潰、暴露痕跡。所以作者改「視覺網格的副本」，再走凸分解生成 C'——既能變形，又保持物理合法。
- **為什麼用 RBF + 手柄？** 頂點動輒上萬，直接優化不可行且易產生尖刺/不連續。用少量手柄（k 個）承載位移、RBF 把位移平滑傳播到全網格，搜索空間降到 k×3，且形狀始終「像同一個物體」。
- **為什麼用腳本代理而非策略？** 威脅模型是嚴格黑盒——攻擊者不知道受害者的策略類型/參數，無法查詢也無法造替代品。且每候選都重訓策略成本爆炸。所以用「採樣抓取位姿 + 固定動作序列」的腳本代理做**排序信號**。
- **為什麼攻擊「接觸建立」這一步？** 幾乎所有操作（抓取、打開抽屜、插入）都以穩定接觸為前提。攻擊接觸建立，就能跨下游任務泛化。

⚡ **Eureka Moment**：**仿真裡「視覺」與「物理」是兩套幾何，而安全和評測只看其中一套——攻擊者只要動另一套，就能在受害者毫無感知的情況下，把一個「仿真滿分」的策略變成真機災難。**

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
ASR(C') = Stealth(C') × Harm(C')
```

**先給目標**：攻擊者要找一個投毒碰撞網格 C'，同時最大化「仿真裡別露餡」與「真機上要出事」。
**再給公式**（原文 Eq.1–3）：

```
ASR(C')  = |S(C') \ S(C)| / M                  # 攻擊成功率
ASR(C')  = Stealth(C') × Harm(C')              # 分解
Stealth(C') = |S(C')| / M                      # 仿真中成功的比例
Harm(C')    = |S(C') \ S(C)| / |S(C')|         # 成功中在良性幾何下失敗的比例
```

**變量說明**：

| 符號 | 含義 |
|------|------|
| E(G) | 由幾何 G 決定物理的環境 |
| C' | 投毒碰撞網格；C 為良性碰撞網格；R 為真機真實幾何 |
| π' | 用投毒資產訓練出的策略 |
| S(G) | π' 在 E(G) 中成功的執行集合 |
| M | 配對執行的次數（同一初始位姿，兩環境配對） |
| θ ∈ ℝ^{k×3} | k 個手柄的位移，優化變量 |
| τ | 平均手柄位移預算（限制形狀漂移） |

**約束**（Eq.4）：
```
d̄(θ) = (1/k) · Σ_m ‖θ_m‖₂ ≤ τ
```
**直覺**：目標函數是一個**乘積**，所以兩頭都不能塌。想只求 harm？那會把仿真任務直接搞崩，Stealth→0，開發者一眼看出訓練失敗棄用；想只求 stealth？太保守的變形在真機上又沒影響（見 §5.5 ablation：去掉 stealth 項後 PSSR 直接 0）。攻擊的精髓全在這個「刀尖上跳舞」的平衡。

> 符號與原文保持一致：`S(C') \ S(C)` 表示在 C' 下成功、但在 C 下失敗的執行集合（差集）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

用一個抓取杯子的抽象例子走完一個候選的評分（配對執行 M=100 個初始位姿）：

| 階段 | 條件 | 結果 | 計算 |
|------|------|------|------|
| Phase 1 | 在投毒環境 E(C') 執行 | 100 次裡 90 次成功 | Stealth = 90/100 = **0.90** |
| Phase 2 | 把那 90 次成功放到良性環境 E(C) 重跑 | 只有 30 次成功，60 次失敗 | Harm = 60/90 = **0.667** |
| 合成 | — | — | ASR = 0.90 × 0.667 = **0.60** |

對比兩個極端候選：
- **太激進**：變形過猛，Phase 1 只剩 10 次成功 → Stealth=0.10，即便 Harm=1.0，ASR 也只有 0.10（開發者會直接棄用）。
- **太保守**：Phase 1 有 99 次成功，但這些在良性環境下 95 次也成功 → Harm=4/99≈0.04，ASR≈0.04（真機沒影響）。

CMA-ES 就是沿著 θ 梯度自由地爬，把 ASR 從隨機初值逐步推到高值。實測搜索很快：Task 1 平均 **12.33** 輪就到達最終最佳 ASR 的一半（預算 50 輪），抽屜任務更是只用了 **4** 輪。

| 跨訓練框架 | RSL-RL / RL-Games / SKRL 均有效（Drop 26–28 pp） | 不綁定特定 RL 框架 |
| 觀測通道 | 開發者**只能看到 PSSR**，看不到 BSR/BSSR | 受害者缺少判斷「這個成功率是否正常」的基準——這是攻擊能潛伏的根本原因 |

一句話：**這是供應鏈攻擊的經典形狀——攻擊者改的是「上游資產」，受害者承擔的是「下游安全」**。和軟件供應鏈投毒（npm/PyPI）唯一的差別，是這裡的「惡意代碼」是一套幾何。

| 任務 | 內容 | 主指標 |

**指標定義**：BSR（良性策略在良性仿真成功率，開發者看不到的參照）、PSSR（投毒策略在投毒仿真的成功率＝開發者唯一可見＝stealth）、BSSR（投毒策略在良性仿真的成功率＝harm 代理）、Drop = BSR − BSSR。

**主要結果**：

| 任務 | BSR | PSSR | BSSR | Drop (pp) | Iter@50% |
|------|-----|------|------|-----------|----------|
| Task 1（9 物體平均） | 88.57% | **89.09%** | 32.48%* | **56.09** | 12.33 |
| Task 2（抽屜） | 100.00% | **100.00%** | 0.00% | **100.00** | 4 |
| Task 3（方塊） | 100.00% | **82.65%** | 73.68% | **26.32** | 8 |

> *Task 1 的 BSSR 是 9 物體均值推算；表 1 逐物體 Drop 從 mug 的 21.72 pp 到 sugar box 的 83.45 pp。

**關鍵補充證據**：
- **多資產策略**：投毒單一物體時，對角線（被投毒物）平均 Drop 42.6 pp，非對角線（其他物）僅 4.9 pp → 攻擊**目標特異**，不會整體崩盤而暴露。
- **真機驗證**（Franka + 3D 列印物體，3 物體 × 20 位姿 × 3 重複 = 360 次試驗）：良性策略平均 BRSR 93.33%，投毒策略平均 PRSR 僅 31.67%，**真機 Drop 平均 61.67 pp**。96.67% 的條件三次重複結果一致。
- **代理有效性**：腳本代理 ASR 與訓練後 PSSR−BSSR 的 Spearman 相關為 **1.00**（三物體），Stealth 相關 0.70–1.00 → 代理可靠做排序信號。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做什麼**：
- 只改碰撞網格即可，視覺網格/紋理/物理參數全不動 → **現有資產審查（惡意軟件/版權/格式）完全失明**。
- 跨物體、跨任務、跨機器人、跨訓練框架、跨仿真器均保持效果。
- 在真機上實測有效，且失敗表現「像普通 sim-to-real 誤差」而非明顯篡改 → 難歸因。

**不能做什麼 / 失效場景**：
- **無接觸任務**（如導航）無效——沒有接觸就沒有碰撞幾何可投毒。
- **純真機數據訓練**的策略不受影響（投毒需經仿真）。
- Task 3 這類**幾何簡單物體**抗性高（Drop 僅 26.32 pp）——簡單形狀對形狀失配更寬容。
- 攻擊效果**物體依賴**：mug 只有 21.72 pp，sugar box 高達 83.45 pp。
- 未在「原生材料全閉環部署」上驗證（真機實驗用 3D 列印物 + 受控協議，靠已知位姿規避常規 sim-to-real 干擾）。

### 6.1 隱含假設 (Hidden Assumptions)

1. **「良性仿真 ≈ 真機」這一替代成立**：優化時用 E(C) 代替不可及的 E(R)。這正是整個 sim-to-real 範式的隱含前提，但真機材料/摩擦/接觸動力學與仿真仍可能有系統偏差。
2. **開發者無法判斷 PSSR 是否「正常」**：攻擊成立的核心。若開發者有良性基準或獨立評測，攻擊會大打折扣。
3. **資產供應鏈是投递通道**：假設開發者會從公開平台下載第三方資產並直接用其碰撞網格（平台/開發者實踐確實傾向如此，但非普適）。
4. **攻擊者能預測操作原語**：mug 會被抓、抽屜會被拉——對非常規/未知任務的資產，原語預測可能失敗。
5. **防禦評估覆蓋有限**：只測了 4 種幾何統計特徵 + 3 個 VLM，且都是**非自適應攻擊者**（未針對檢測器優化），因此「防禦無效」的結論是**保守下界**。

- **不值得精讀的理由**：如果你不做機器人學習、不涉及仿真資產或安全評測，讀摘要 + §7 防禦結論即可——它不提出新模型或新表徵方法，價值全在「攻擊面 + 安全警示」。
