## 1. 核心架构/方法总览 (Overview / Architecture)

SafeHarness 不是一個新模型，而是一層**包在被凍結策略外面的決策框架**。它的關鍵設計是「把任務沿接觸事件切段」：每一段 = 一段自由空間路線（route）+ 一個接觸動作（contact），安全約束也切成兩半，分別由兩個 harness 負責。

### 1.1 系统对比概览 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 頻率/時序 | 訓練/推理 |
|------|------|------|-----------|-----------|
| 視覺 grounding（SAM-3） | RGB 觀測影像 | 目標 & 障礙物的 bounding box | 每 phase 一次 | 凍結預訓練模型，無微調 |
| ❶ Obstacle-aware route planning | grounded box + 任務語言 | waypoint 折線（polyline） | 每 phase：plan→verify→execute，可反覆重規劃 | 全推理，無梯度 |
| 路線驗證器（LLM 之外） | 候選路線 + box（含 gripper，必要時含 payload） | 通過/拒絕 | 每次送出動作前 | 確定性幾何判斷 |
| ❷ Obstacle-aware contact execution | 接觸目標 + 相鄰障礙物 | 接觸側向、腕部朝向 | 每次接觸（pick / place 各一次） | 離散 argmax，無梯度 |
| 凍結 VLA（π0.5） | 接觸階段的觀測 | 動作 | 僅在 contact-rich 階段接手 | 完全凍結，不改權重 |
| 技能記憶（skill memory） | 成功經驗 | 可複用原語 | 跨任務 | 無訓練 |

### 1.2 关键机制 (Key Mechanism)

- **沿接觸事件切段**：coding agent 天然把任務組成「可呼叫技能 + 運動原語」，最自然的切口就是接觸事件。每個 phase 都跑一次 plan–verify–execute，長時程任務靠「多跑幾個 phase」覆蓋，而不是靠一個更長的計畫。
- **規劃與執行的成本不對稱**：計畫可以自由修改，但已發出的動作無法召回。所以**錯誤要在它還是文字的時候就攔下**——驗證必須發生在動作之前。
- **驗證器在 LLM 之外**：模型只負責「提議」路線，是否真的不碰障礙物由外部幾何檢查判定；侵入 box 就退回重規劃，直到通過才放行。
- **規劃按 phase 重啟**：物體一旦被抓進夾爪，手臂+物體成為一體，所需的淨空隨之改變——「空夾爪過得去」不等於「負載過得去」。

⚡ **Eureka Moment**：**把必須跨數百步成立的不變式，從「第 0 步寫下的一句話（prompt）」搬到「第 N 步仍會重新執行的無狀態工具（harness）」**。安全不是模型能力問題，而是「約束住在哪裡」的問題。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
安全 = 一個在 LLM 之外、每步重新施加的位置不變式，而非 prompt 裡的一句约束
```

**目标**：在有障礙物的場景中，同時最大化「完成任務」與「不碰障礙物」——即一個帶硬約束的最優化：

```
max_π  E[ 1{ goal ∧ no_collision } ]
s.t.   ∀t ∈ [0,T]:  vole( G_t ∪ P_t ) ∩ O = ∅        ← 全程不變式 (invariant)
```

**兩個子約束**（互不蘊含，必須同時成立才算安全）：

```
① 路線約束 (route)：   ∀ w ∈ polyline(R):  box( G ∪ P , w ) ∩ box(O) = ∅
② 接觸約束 (contact)：  d* = argmax_{ d ∈ A }  clearance(d)
                        A = { d : clearance(d) ≥ 0 }        （A 為可行接近方向集）
```

**變量說明**：

| 符號 | 含義 |
|------|------|
| G_t | 夾爪在 t 時刻佔據的體積 |
| P_t | 被搬運物體（空手時為空集） |
| O | 障礙物（本文為單一軸對齊 bounding box） |
| R | 一個 phase 的路線（waypoint 折線） |
| d | 接觸的接近方向；clearance(d) 為該方向下夾爪與障礙物的淨空 |
| TSR / CAR | 任務成功率 / 避障率 |

**兩個評測量的定義**：

```
TSR = (1/N) Σ_i  1{ goal_i 達成 }
CAR = (1/N) Σ_i  1{ max_t ‖ pos_O(t) − pos_O(0) ‖ ≤ 11 mm }
```

**直觉**：① 路線是「長條狀掃掠」，繞得開，所以用「逐段與 box 求交」來驗證；② 接觸是「錨定在目標上的小體積掃掠」，繞不開，只能改**從哪一側接近**。把兩者分開建模，正是因為它們對障礙物的風險方式不同。

> 符号与本文/相关文档保持一致：路線驗證在論文中不給解析式，僅描述為「在 LLM 之外對 obstacle box 的幾何檢查」；上式的 box 相交表達是本文方法語義的等價重述，非原文逐字公式。

## 3. 带数字走一遍：玩具例子 (Worked Example)

在 2D 俯視平面（單位：公尺）上，夾爪近似為半徑 r = 0.04 的圓。障礙物 box O = x∈[0.30, 0.50], y∈[0.10, 0.30]。起點 S=(0.10, 0.20)，目標 T=(0.65, 0.20)。安全評分門檻：障礙物位移 > 11 mm 即判碰撞。

**候選 A（直線最短路線）**：S→T 為 y=0.20 的水平線。中點 (0.40, 0.20) 落在 box 內部，且距最近邊界 = min(0.20−0.10, 0.30−0.20) = 0.10 > 0。

```
驗證：box 侵入 → 判 A 侵入深度 0.10 m  → 拒絕 → 退回重規劃
```

**候選 B（繞行折線）**：waypoints = [(0.10,0.20), (0.25,0.05), (0.55,0.05), (0.65,0.20)]。

1. 段 (0.10,0.20)→(0.25,0.05)：x 範圍 < 0.30，不與 box 的 x 投影重疊 → 淨空充足。
2. 段 (0.25,0.05)→(0.55,0.05)：y=0.05，與 box 下緣 y=0.10 的距離 = 0.05。
3. 段 (0.55,0.05)→(0.65,0.20)：x 範圍 > 0.50 → 不重疊。

```
最小淨空 = 0.05 m
扣除夾爪半徑 r = 0.04 → 幾何餘量 = 0.05 − 0.04 = 0.01 m > 0  → 通過驗證
```

於是 B 放行、被執行；若執行中夾爪因物理約束卡在 (0.25,0.05) 附近，則**停機並從該姿態重新規劃**——這正是「執行時重規劃」觸發點。

**接觸步驟**：假設 pick 目標緊鄰 box 的 +y 側。adjacency test 命中 → 在四個候選接近方向中，逐一計算 clearance：

```
方向 +y（正對障礙物）： clearance < 0 → 排除
方向 +x / −x / −y：     clearance ≥ 0 → 可行
d* = argmax clearance = −y（離障礙物最遠的一側）
```

若四個方向都不可行，則腕部轉向使「開口軸與障礙物相切」，再垂直下放 payload，杜絕任何朝障礙物的橫向運動。

## 5. 数据与评测 (Data & Eval)

- **基準**：SafeLIBERO——從 LIBERO-Spatial / Goal / Object / Long 四個 suite 各取 4 個代表性任務，各加一個障礙物（moka pot、收納箱、牛奶盒、酒瓶、馬克杯、書）。**任務語言從不提及障礙物。**
- **兩個難度層級**：
  - Level I：障礙物緊鄰目標物 → 干擾抓取/放置（對應 ❷ 接觸約束）。
  - Level II：障礙物遠離目標但位於自然搬運路徑上 → 干擾路線（對應 ❶ 路線約束）。
- **規模**：全部 32 個任務（4 suite × 4 任務 × 2 層），每任務 10 個 seed。
- **指標**：TSR（任務成功率）與 CAR（避障率）；位移以官方 SafeLIBERO 評分器判定，**障礙物任一時刻位移 > 11 mm 即判碰撞**。
- **對照**：π0.5、OpenVLA-OFT、前 SOTA AEGIS（π0.5 + 屏障函數安全層）；主幹 LLM 為 GPT-5.5 / GPT-6-astra，grounding 用 SAM-3，凍結策略與技能記憶沿用 Harness VLA 原版**完全不動**。

**主要結果（作者提供的數字，見論文 Table 1 / 摘要）**：

| 方法 | TSR (%) | CAR (%) | 說明 |
|------|---------|---------|------|
| π0.5（凍結策略） | 57.8 | 17.1 | 會完成任務但常碰障礙物 |
| AEGIS（屏障層包裹 π0.5） | 接近凍結策略 | 68.9 | 事後否決動作，Long 上成功率反而低於其包裹的策略 |
| Model-only agent | 6.0 | 50.0 | CAR 無意義（早早失敗＝什麼都沒碰到） |
| **SafeHarness（GPT-6-astra）** | **71.9** | **87.5** | 作者稱超越前 SOTA 6.5% 與 27.0%，相對同 agent 無 harness 為 2.3× / 1.5× |

> 註：摘要的「超越前 SOTA 6.5% / 27.0%」與表內可得數字（AEGIS CAR 68.9、π0.5 TSR 57.8）之間的對應關係在 HTML 正文中未逐格展開，**待補 citation/待核對 Table 1 完整值**。

**消融重點（Table 2，定住 32 場景僅換 planner 輸入）**：
- Model-only → Model+Skills：GPT-6 下任務成功提升約 5 倍，但避障僅 +9 點。
- Model+Skills 的較弱 planner 約 3/10 集保持淨空，甚至低於「早早失敗」的無技能 agent——**能力本身不會變成安全，反而是能力才讓這個基準會扣分的碰撞成為可能**。
- 模型規模的提升幾乎全落在 Level I（CAR 18.8 → 69.0）；Level II 僅 +6 點安全卻倒貼約 13 點成功——因為「從哪一側接近」是局部決策（單視角可判），而「路線」是長時程決策（沒有事前檢視就無從改進）。
- 加上 harness 後，兩個 planner 的成功率都 +40 點以上，兩層 CAR 都 ≥ 85，且**兩 planner 的差距被抹平**——安全成為 harness 的性質而非模型的性質。殘餘代價落在 Level II 的成功率（64.0 vs 76.0；62.5 vs 81.2），最可能是驗證後的繞行讓 episode 變長、撞上固定步數預算。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 在單障礙物的桌面操作中，把「任務成功」與「不碰障礙物」從互相拉扯變成同時上升（TSR 與 CAR 同漲）。
- 在接觸-rich 階段（抓取/放置緊鄰障礙物）選擇遠離障礙物的接近側，避免「路線乾淨但最後一碰撞上」的典型失敗。
- 用同一套無狀態工具在不同 LLM 骨幹間遷移，降低對 planner 能力的依賴。

**不能做什么 / 失败模式**：
- **仍非零碰撞**：論文自述「大約每 8 集中仍有 1 集推移障礙物」。
- **長路線的殘餘成本**：繞行使 Level II 成功率仍低於 Level I。
- **多障礙場景未覆蓋**：只建模單一軸對齊 box。
- **末端依賴**：接觸側測試是為並聯夾爪調的。
- **grounding 依賴**：分割失敗時表現為「路線被拒」而非「碰撞」，因此魯棒但可能頻繁重規劃、拖慢速度。
- **評測侷限**：全在模擬器，真機未驗證。

### 6.1 隐含假设 (Hidden Assumptions)

1. **單一障礙物 + 軸對齊 box 足以代表「安全」**：真實桌面常有透明/可形變/多個障礙物，box 近似會低估風險。
2. **「不碰障礙物」＝安全**：論文把 safety 操作化為「障礙物位移 ≤ 11 mm」，未涵蓋力/扭矩上限、人員接近、動態障礙物等其他安全維度（作者在 Discussion 中預期同一機制可外推到工作空間/力矩限制，但未實證）。
3. **驗證器只查一個條件**：即「路線是否與障礙物求交」，且建立在**近似測量**的場景上；其他物理約束不在其範圍，故仍需執行期停機重規劃兜底。
4. **grounding 品質直接決定上限**：整個安全保證建立在 SAM-3 的 box 之上。
5. **凍結策略「夠好」**：π0.5 承擔所有 contact-rich 動作，harness 不改善其抓取成功率。

| π0.5 / OpenVLA-OFT | 端到端操作 | VLA 網路 | 需機器人資料訓練/微調 | 通用操作，無安全約束目標 |
| RRT / CHOMP / TrajOpt | 自由空間路線 | 取樣/優化規劃器 | 無學習（解析） | 已知碰撞模型的路線認證；不回頭重規劃 |
| CBF 安全濾波器（AEGIS 一類） | 運行時最小改動動作 | 策略下游濾波 | 無學習 | 否決違規動作，但無法提議更好的路線/側向 |
| Harness VLA（本文 base） | 免訓練操作 | agent loop + 凍結 VLA + 技能記憶 | 無機器人專屬訓練 | 自由空間用 IK 原語、contact-rich 才交 VLA |
| **SafeHarness（本文）** | **免訓練 + 安全** | **Harness VLA + 兩個障礙感知外殼** | **無梯度、無訓練** | **單障礙物桌面操作，安全為一等公民** |

**面試 Tip**：被問到「為什麼不直接微調一個更安全的 VLA / 加個安全濾波器就好？」——一句話答：*濾波器只能否決，不能提議；微調改的是模型先驗，改不掉長上下文裡的約束漂移。SafeHarness 的洞見是——把不變式放在「產生動作的決策」裡（規劃階段就限定可行集），而不是放在「動作產生之後」去減法。*

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**多模態具身 agent / coding-agent for robotics** 的研究者——§3 的方法切分與 §3.4 的長上下文診斷是可複用的設計語言。
  2. 要評估「把安全機制遷移到新機器人平台」可行性的工程師——§4 消融與 Limitations 直接給出遷移成本的清單。
  3. 關心 **LLM 長上下文約束漂移**（lost-in-the-middle、instruction drift）的人——§3.4 把語言模型的老問題搬到了具身場景。
- **建議章節路徑**：先讀 §1 Introduction（問題動機與三點貢獻）→ 再看 §3.2 / §3.3（兩個 harness 的具體機制）→ 然後 §4.3 消融（失敗根因與 harness 增益的證據）→ 可跳 §2 Related Work（除安全控制那一小節外信息密度較低）。
- **不值得精讀的理由**：若你不做機器人學習、或已熟悉 harness/coding-agent 範式，讀摘要 + §1 的三點貢獻即可；本文的價值在「問題的提出方式」與「安全職責的擺放位置」，而非新的網路或損失函數。
