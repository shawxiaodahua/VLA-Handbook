## 1. 核心架構/方法總覽 (Overview / Architecture)

CAPEX = **C**alibrated **A**daptive **P**lanning through **EX**perience Collection。整條管線每 20 Hz 跑低階控制，但基礎模型只在稀疏決策點被呼叫，且**參數完全冷凍、每次呼叫無狀態**（stateless）。跨 episode 的影響力只能透過顯式的經驗狀態 `Γ_e` 傳遞。

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 頻率/時序 | 訓練? |
|------|------|------|-----------|-------|
| 低階執行器 (executor) | 已承諾的 waypoint 序列 | 關節/夾爪動作 | 20 Hz 伺服；每 waypoint ≤10 cm | 否（OSC 控制器）|
| VLM 計劃器 π（冷凍） | 指令 ℓ、觀測 o_t、近期動作 m_t、已 ground 的點 L_t、經驗 Γ_e | 一段 waypoint 計劃 P_t（≤24 個）或 base 移動 | 稀疏決策點；≤80 決策/episode | **否（凍結）** |
| 校正器 (calibrator) w_e | 8 維特徵 φ_k（見 §2） | 校正後到達概率 p̂_k | 每 episode 開始前重擬合一次 | 是（MAP 邏輯回歸，輕量）|
| 經驗摘要 M_e | 過去所有嘗試記錄 | 相位可靠度骨架 B_e + ≤2 個舊成功 episode R_e | 每 episode 前更新 | 否（非參數化、有界）|
| 下游學生策略 | CAPEX 產出的成功軌跡 D_ours | 動作 | 離線訓練 | 是（DP / ACT）|

### 1.2 關鍵機制 (Key Mechanism)

- **Waypoint 介面**：不逐小步問模型，而是一次讓模型給一段「時序延展」的 waypoint 計劃，把昂貴的語義—空間推理與低頻控制解耦。
- **自監督可達標籤**：每個被執行的 waypoint 由執行器自動產生二值標籤 y_k（到達=1；停滯/接觸停止/超時=0）。**不需要任何人工標註或留存監督**。
- **置信度校正**：模型自報的 q_k 嚴重失準（見 §4），於是用執行結果重新擬合一個邏輯回歸，得到校準後的 p̂_k。
- **自適應執行長度**：執行「第一個低於閾值 τ 的 waypoint 之前」的最長前綴，之後回觀測、重新規劃。
- **有界經驗**：不管收集多久，送進 VLM 的上下文最多 8 條相位可靠度 + 2 個成功參考；系統 prompt 從首集的 9.8k 字元升到最多 17.7k 字元後封頂。

⚡ **Eureka Moment**：VLM 自報的置信度幾乎沒用（94.9% 的 waypoint 都自報 ≥0.8、且從不低於 0.5），但**機器人自己的執行結果可以自監督地把它校正到可用**（ECE 0.24→0.05、AUROC 0.57→0.75）——於是「一次執行多長計劃」從此有了一個可靠訊號，這才是把推理呼叫頻率降下來的鑰匙。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
每次「成功示教」的成本  J = E[C] / P(S=1)      ← 越低越好
```

即：把「單次嘗試更便宜」與「更多嘗試能成功」一起算進去的綜合效率。CAPEX 的增益主要來自**後者**（把更多嘗試變成可用示教），而非單純讓每次嘗試更便宜（論文 §4.2）。

### 2.1 問題設定與成本目標

```
episode:  ξ_e = (s_i, a_i)_{i<T_e}
成功指示: S_e = 1[ Succ_ℓ(s_{T_e}) ]
資料集:   D_ours = { ξ_e : S_e = 1 }
                                              (式 1)

成本目標: J = E[C] / P(S=1) = E[N]·c̄ / P(S=1)
          其中 c̄ = E[C] / E[N]
                                              (式 2)
```

| 符號 | 含義 |
|------|------|
| N | 單次嘗試中的 API 請求數 |
| C | 該次嘗試的 list-price 總成本 |
| c̄ | 以呼叫次數加權的平均每次請求成本 |
| J | 每次成功示教的成本（**評測指標**，不是被直接優化的目標）|

> 作者明確聲明：J 只是評估指標；方法本身不直接優化 J。

### 2.2 置信度校正（核心）

目標：把模型自報的機率 q_k，校正成「實際會到達」的機率 p̂_k。

```
特徵:       φ_k  (8 維，見下表)
校正機率:   p̂_k = σ( w_eᵀ φ_k )                         (式 5)
擬合:       w_e = argmin Σ_{(φ,y)∈Y_e} [ log(1+e^{wᵀφ}) − y·wᵀφ ]
                   + ½·‖w − w_0‖₂²                       (式 6)
先驗均值:   w_0 = (0, 1, 0, …, 0)ᵀ                        (式 7)
```

直覺：`logit(q_k)` 是特徵向量中**第 2 個分量**，先驗 w_0 把它對應的權重設為 1，其餘為 0——這意味著**在還沒有任何執行數據時，校正器等於恆等映射 p̂_k = q_k**。也就是說，CAPEX 是「以模型自報置信度為起點、用執行結果逐步修正」，而不是一開始就推翻它。

**8 維特徵 φ_k（論文 Table 4）**：

| j | 特徵 | 定義 |
|---|------|------|
| 0 | bias | 1 |
| 1 | stated log-odds | logit(q_k) |
| 2 | gripper closed after k | {0,1} |
| 3 | gripper phase | min(γ_k, 4)/4（γ_k = 迄今夾爪指令數）|
| 4 | leg length | ‖x_k − x_{k−1}‖ / 10 |
| 5 | vertical leg | (x_k − x_{k−1})_z / 10 |
| 6 | 距上一個 located 點 | min(‖x_k − x^loc‖, 40)/20 |
| 7 | 在計劃中的位置 | min(k, 4)/4 |

### 2.3 自適應執行長度

```
n_t = min( { k ∈ {2,…,K_t} : p̂_k < τ } ∪ {K_t+1} ) − 1,   τ = 0.5   (式 8)
```

- 第一個 waypoint **永遠執行**（保證每次決策至少拿到 1 個標籤）。
- 一旦某個後續 waypoint 的 p̂_k < 0.5，它與其後的尾段**被延後**（不是排隊執行），機器人取得新觀測後請 VLM 重新規劃。
- τ 是可調參數，反映「頻繁重規劃」與「執行不可靠 waypoint」之間的取捨。

### 2.4 有界經驗狀態

```
Γ_e = ( w_e , M_e ),      M_e = ( B_e , R_e )        (式 9)
```

| 分量 | 內容 | 作用通道 |
|------|------|----------|
| w_e | 校正器權重 | 決定「計劃執行多遠」|
| B_e | 相位級可靠度骨架（≤8 相位，純文字，無座標）| 影響「VLM 提什麼計劃」|
| R_e | 最多 2 個過去成功 episode（含初始觀測、grounded 點、waypoint 序列、執行結果）| 影響「VLM 提什麼計劃」|

> 符號與本文/相關文檔保持一致：σ 為 logistic 函數；q_k 為模型自報機率；p̂_k 為校正後到達機率；τ 為承諾閾值。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設 VLM 對某次決策提出一段 **3 個 waypoint** 的計劃（K_t = 3），自報置信度 q = [0.95, 0.90, 0.70]，並給出前 3 維特徵（其餘用簡化值），我們想算「執行多少個」。

**Step 1 — 沒有執行數據時（w_e = w_0 = (0,1,0,…,0)）**

```
p̂_k = σ( 1 · logit(q_k) ) = q_k
→ p̂ = [0.95, 0.90, 0.70]，全部 ≥ τ = 0.5
→ n_t = min({k≥2 : p̂_k<0.5} ∪ {4}) − 1 = (4) − 1 = 3
→ 執行全部 3 個 waypoint
```

這解釋了論文的觀測：**空記憶時計劃截斷率只有 0.4%**——幾乎永遠整段執行。

**Step 2 — 累積執行數據後（w_e 被重新擬合）**

假設 MAP 擬合出的權重（示意值，非論文實數）：
```
w_e ≈ [−0.50,  0.80,  −0.30,  −0.40,  −0.60,  −0.20,  −0.10,  −0.50]
```
對第 3 個 waypoint（較晚、腿部動作較長、離 located 點遠）取示意特徵：
```
φ_3 = [1, logit(0.70)=0.847, 0, 0.25, 0.50, 0.30, 0.10, 0.75]
```

計算：
```
w_eᵀφ_3 = −0.50
         + 0.80×0.847 = +0.678
         + (−0.40)×0.25 = −0.100
         + (−0.60)×0.50 = −0.300
         + (−0.20)×0.30 = −0.060
         + (−0.10)×0.10 = −0.010
         + (−0.50)×0.75 = −0.375
       ≈ −0.667
p̂_3 = σ(−0.667) ≈ 0.339  <  τ = 0.5
```
→ 第 3 個 waypoint 被截斷，`n_t = 2`，只執行前 2 個，然後回觀測、重新規劃。

## 4. 工程視角 (Engineering View)

| 工程維度 | 具體數字 / 約束 | 工程含義 |
|----------|-----------------|----------|
| 控制頻率 | 低階執行 20 Hz；VLM 僅稀疏決策 | 模型延遲不直接耦合控制迴路 |
| 每次 waypoint 位移 | ≤10 cm；到達判定 8 mm & 0.08 rad | 太長易撞、太短呼叫變多 |
| 計劃長度 | ≤24 waypoints；τ = 0.5 | 一次推理可攤薄到多次動作 |
| 每次決策工具輪數 | ≤6 輪（含 locate_pixel）| 限制單次模型延遲上界 |
| Episode 上限 | 地平線 H、80 決策、$25 API 成本 | 硬性成本熔斷 |
| 校準器 | 8 維邏輯回歸，每 episode 重擬合一次 | 極輕量，與 LLM 成本相比可忽略 |
| 上下文預算 | 系統 prompt 9.8k → 最多 17.7k 字元（base 臂 3.9k）| 記憶增長不導致上下文無界 |
| 上下文組件 | 3×512×512 RGB（左右外視 + 手腕）；不含物體 pose | 模型只能從像素+工具拿幾何 |
| 參考選擇 | 最多 2 個、來自不同初始狀態的成功 episode | 提供策略範例 + 相對 grounded 點的幾何 |
| 成本單價 | 每百萬 token：$10 新輸入 / $1 快取 / $12.5 快取寫 / $50 輸出 | 輸出（含推理 token）是主要成本源 |

**部署邊界**：整套方法**不更新模型權重**，因此可以對「封閉 API 的前沿模型」直接套用；代價是能力上限被底層模型鎖死（見 §6）。校正器是唯一的學習組件，且訓練信號零人工成本——這讓它適合 7×24 自動化採集迴路。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 在 RoboCasa 與**實機 YAM / Franka**上自主採集示教（YAM：45%→95% 成功率）。
- 用「已成功」的跨 episode 經驗提升採集效率（記憶 vs 清空：185/341 vs 162/341，p=0.027）。
- 用零人工標註的執行結果校正置信度（8,458 waypoints；ECE 0.24→0.05）。
- 產出的數據可訓練出逼近人類示教的下游策略。

**不能做 / 失敗模式**：

| 失敗模式 | 證據 | 原因 |
|----------|------|------|
| 無法補足底層 visuomotor 能力 | Qwen3.8-27B：Base 0/360 → CAPEX 只有 5/350 (1.4%) | 方法只改「怎麼用」模型，不擴展其能力 |
| 純失敗經驗有害 | 只有失敗先前嘗試時：14/67 → 7/67（p=0.09）| 沒有成功範例時，經驗提供不了有效先驗 |
| 增益集中在「已有一次成功」後 | 有成功經驗：54.0%→65.0%（p=0.0016）| 經驗要靠成功軌跡才能遷移到新初始狀態 |
| 目標不針對下游學習價值 | 作者自述：current objective prioritizes successful demos | 只追求「成功」而非「提升學生策略」 |
| 實機仍需人工 | 需人工重置場景 + 成功判定 | 尚未自動化 reset / eval / 任務選擇 |
| 跨任務遷移未解 | 作者列為 open direction | 經驗目前限同任務 |

### 6.1 隱含假設 (Hidden Assumptions)

1. **初始狀態來自官方人類示教**——360 個 starts 是人類示範重現，因此預設了「人類可行」的狀態分佈；對抗性/自生成初始狀態下的表現未驗證。
2. **存在可靠的成功判定器 Succ_ℓ**——自動採集依賴一個能判斷任務成功的 oracle；實機上這一步仍靠人。
3. **執行器的 reach/stall 標籤可信**——整套自監督信號建立在低階執行器「到達/停滯」報告的正確性上；若執行器誤報，校正器會被污染。
4. **相位切分（以夾爪事件分段）可跨 episode 匹配**——B_e 的可靠性依賴這個分割假設在長時程任務上成立。
5. **8 維特徵足以刻畫「到達可能性」**——特徵是人工設計的（腿部長度、相位、距 located 點距離等），未做特徵搜索。
6. **冷凍模型不會被廢棄**——方法綁定特定前沿模型的行為；模型下線/升級會重置所有累積經驗。

## 7. 與相關工作對比 (Comparison)

| 方法 | 關注點 | 架構 | 訓練方式 | 適用場景 |
|------|--------|------|----------|----------|
| 人類遙操作 | 直接產生示教 | 人操作 | 無（人工）| 通用但要人工成本 |
| MimicGen 等 | 放大稀疏示教 | 軌跡變換 | 無 | 已有少量示教 |
| Manipulate-Anything | 自動示教生成 | VLM 拆解 + **獨立抓取/運動規劃模組** | 無 | 桌面操作，需外掛模組 |
| Agent-as-Policy | 前沿 VLM 直接當策略 | VLM agent + 工具 | 無 | 度量 wall-clock/token/cost |
| **CAPEX（本文）** | **降低示教採集成本** | 冷凍 VLM + **waypoint 計劃 + 自監督校準的承諾執行 + 有界經驗** | 只訓練輕量校正器 | 同任務重複採集，可上實機 |

**差異定位**：與 Manipulate-Anything 不同，CAPEX 讓通用多模態模型**直接輸出幾何動作**、以閉環執行；與 Agent-as-Policy 同處「前沿模型直接控制」的賽道，但把**反覆推理的推論成本**當成核心瓶頸來解。

🎤 **面試 Tip**：被問到 CAPEX 時，一句話抓住它——「它不是讓模型更強，而是用機器人的執行結果去校準模型自報的置信度，決定『一次執行多長』，把前沿模型的推理呼叫頻率降下來」。接著補一句它的邊界：「所以它只在模型本身已具備 visuomotor 能力時有效，Qwen 骨幹幾乎採不到數據。」

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 正在評估「用前沿 VLM/Agent 做機器人示教採集」的研究者——特別是關心成本與可擴展性的人。
  2. 要決定是否把此類採集流程搬到自己機械人平台（雙臂/單臂）的工程師。
  3. 做 imitation learning 資料管線、關注「自動數據 vs 人類數據下游價值」的人。
- **建議章節路徑**：先讀 §3.2（校準與自適應執行，本文最核心）→ 再看 §4.3（學習自經驗的消融與校準前後對比）→ §4.4/§4.5（下游策略與實機結果）→ 可跳 §2 的相關工作細節（只在需要定位時回看）。
- **不值得精讀的理由**：如果你不做機器人學習、或已熟悉 action-chunking / adaptive-horizon 這條線，讀摘要＋本筆記的 §1.2、§2.2、§6 即可掌握要點。若要複現，務必注意：物理實驗仍依賴人工重置與成功判定，且需要一個具備閉環 visuomotor 能力的模型骨幹。
