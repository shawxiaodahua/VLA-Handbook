## 1. 核心架构/方法总览 (Overview / Architecture)

CAPEX = **C**alibrated **A**daptive **P**lanning through **EX**perience Collection。整条管线每 20 Hz 跑低阶控制，但基础模型只在稀疏决策点被调用，且**参数完全冷冻、每次调用无状态**（stateless）。跨 episode 的影响力只能通过显式的经验状态 `Γ_e` 传递。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练? |
|------|------|------|-----------|-------|
| 低阶执行器 (executor) | 已承诺的 waypoint 序列 | 关节/夹爪动作 | 20 Hz 伺服；每 waypoint ≤10 cm | 否（OSC 控制器）|
| VLM 计划器 π（冷冻） | 指令 ℓ、观测 o_t、近期动作 m_t、已 ground 的点 L_t、经验 Γ_e | 一段 waypoint 计划 P_t（≤24 个）或 base 移动 | 稀疏决策点；≤80 决策/episode | **否（冻结）** |
| 校正器 (calibrator) w_e | 8 维特征 φ_k（见 §2） | 校正后到达概率 p̂_k | 每 episode 开始前重拟合一次 | 是（MAP 逻辑回归，轻量）|
| 经验摘要 M_e | 过去所有尝试记录 | 相位可靠度骨架 B_e + ≤2 个旧成功 episode R_e | 每 episode 前更新 | 否（非参数化、有界）|
| 下游学生策略 | CAPEX 产出的成功轨迹 D_ours | 动作 | 离线训练 | 是（DP / ACT）|

### 1.2 关键机制 (Key Mechanism)

- **Waypoint 接口**：不逐小步问模型，而是一次让模型给一段“时序延展”的 waypoint 计划，把昂贵的语义—空间推理与低频控制解耦。
- **自监督可达标签**：每个被执行的 waypoint 由执行器自动产生二值标签 y_k（到达=1；停滞/接触停止/超时=0）。**不需要任何人工标注或留存监督**。
- **置信度校正**：模型自报的 q_k 严重失准（见 §4），于是用执行结果重新拟合一个逻辑回归，得到校准后的 p̂_k。
- **自适应执行长度**：执行“第一个低于阈值 τ 的 waypoint 之前”的最长前缀，之后回观测、重新规划。
- **有界经验**：不管收集多久，送进 VLM 的上下文最多 8 条相位可靠度 + 2 个成功参考；系统 prompt 从首集的 9.8k 字符升到最多 17.7k 字符后封顶。

⚡ **Eureka Moment**：VLM 自报的置信度几乎没用（94.9% 的 waypoint 都自报 ≥0.8、且从不低于 0.5），但**机器人自己的执行结果可以自监督地把它校正到可用**（ECE 0.24→0.05、AUROC 0.57→0.75）——于是“一次执行多长计划”从此有了一个可靠信号，这才是把推理调用频率降下来的钥匙。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
每次“成功示教”的成本  J = E[C] / P(S=1)      ← 越低越好
```

即：把“单次尝试更便宜”与“更多尝试能成功”一起算进去的综合效率。CAPEX 的增益主要来自**后者**（把更多尝试变成可用示教），而非单纯让每次尝试更便宜（论文 §4.2）。

### 2.1 问题设定与成本目标

```
episode:  ξ_e = (s_i, a_i)_{i<T_e}
成功指示: S_e = 1[ Succ_ℓ(s_{T_e}) ]
数据集:   D_ours = { ξ_e : S_e = 1 }
                                              (式 1)

成本目标: J = E[C] / P(S=1) = E[N]·c̄ / P(S=1)
          其中 c̄ = E[C] / E[N]
                                              (式 2)
```

| 符号 | 含义 |
|------|------|
| N | 单次尝试中的 API 请求数 |
| C | 该次尝试的 list-price 总成本 |
| c̄ | 以调用次数加权的平均每次请求成本 |
| J | 每次成功示教的成本（**评测指标**，不是被直接优化的目标）|

> 作者明确声明：J 只是评估指标；方法本身不直接优化 J。

### 2.2 置信度校正（核心）

目标：把模型自报的概率 q_k，校正成“实际会到达”的概率 p̂_k。

```
特征:       φ_k  (8 维，见下表)
校正概率:   p̂_k = σ( w_eᵀ φ_k )                         (式 5)
拟合:       w_e = argmin Σ_{(φ,y)∈Y_e} [ log(1+e^{wᵀφ}) − y·wᵀφ ]
                   + ½·‖w − w_0‖₂²                       (式 6)
先验均值:   w_0 = (0, 1, 0, …, 0)ᵀ                        (式 7)
```

直觉：`logit(q_k)` 是特征向量中**第 2 个分量**，先验 w_0 把它对应的权重设为 1，其余为 0——这意味着**在还没有任何执行数据时，校正器等于恒等映射 p̂_k = q_k**。也就是说，CAPEX 是“以模型自报置信度为起点、用执行结果逐步修正”，而不是一开始就推翻它。

**8 维特征 φ_k（论文 Table 4）**：

| j | 特征 | 定义 |
|---|------|------|
| 0 | bias | 1 |
| 1 | stated log-odds | logit(q_k) |
| 2 | gripper closed after k | {0,1} |
| 3 | gripper phase | min(γ_k, 4)/4（γ_k = 迄今夹爪指令数）|
| 4 | leg length | ‖x_k − x_{k−1}‖ / 10 |
| 5 | vertical leg | (x_k − x_{k−1})_z / 10 |
| 6 | 距上一个 located 点 | min(‖x_k − x^loc‖, 40)/20 |
| 7 | 在计划中的位置 | min(k, 4)/4 |

### 2.3 自适应执行长度

```
n_t = min( { k ∈ {2,…,K_t} : p̂_k < τ } ∪ {K_t+1} ) − 1,   τ = 0.5   (式 8)
```

- 第一个 waypoint **永远执行**（保证每次决策至少拿到 1 个标签）。
- 一旦某个后续 waypoint 的 p̂_k < 0.5，它与之后的尾段**被延后**（不是排队执行），机器人取得新观测后请 VLM 重新规划。
- τ 是可调参数，反映“频繁重规划”与“执行不可靠 waypoint”之间的取舍。

### 2.4 有界经验状态

```
Γ_e = ( w_e , M_e ),      M_e = ( B_e , R_e )        (式 9)
```

| 分量 | 内容 | 作用通道 |
|------|------|----------|
| w_e | 校正器权重 | 决定“计划执行多远”|
| B_e | 相位级可靠度骨架（≤8 相位，纯文本，无坐标）| 影响“VLM 提什么计划”|
| R_e | 最多 2 个过去成功 episode（含初始观测、grounded 点、waypoint 序列、执行结果）| 影响“VLM 提什么计划”|

> 符号与本文/相关文档保持一致：σ 为 logistic 函数；q_k 为模型自报概率；p̂_k 为校正后到达概率；τ 为承诺阈值。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设 VLM 对某次决策提出一段 **3 个 waypoint** 的计划（K_t = 3），自报置信度 q = [0.95, 0.90, 0.70]，并给出前 3 维特征（其余用简化值），我们想算“执行多少个”。

**Step 1 — 没有执行数据时（w_e = w_0 = (0,1,0,…,0)）**

```
p̂_k = σ( 1 · logit(q_k) ) = q_k
→ p̂ = [0.95, 0.90, 0.70]，全部 ≥ τ = 0.5
→ n_t = min({k≥2 : p̂_k<0.5} ∪ {4}) − 1 = (4) − 1 = 3
→ 执行全部 3 个 waypoint
```

这解释了论文的观测：**空记忆时计划截断率只有 0.4%**——几乎永远整段执行。

**Step 2 — 累积执行数据后（w_e 被重新拟合）**

假设 MAP 拟合出的权重（示意值，非论文实数）：
```
w_e ≈ [−0.50,  0.80,  −0.30,  −0.40,  −0.60,  −0.20,  −0.10,  −0.50]
```
对第 3 个 waypoint（较晚、腿部动作较长、离 located 点远）取示意特征：
```
φ_3 = [1, logit(0.70)=0.847, 0, 0.25, 0.50, 0.30, 0.10, 0.75]
```

计算：
```
w_eᵀφ_3 = −0.50
         + 0.80×0.847 = +0.678
         + (−0.40)×0.25 = −0.100
         + (−0.60)×0.50 = −0.300
         + (−0.20)×0.30 = −0.060
         + (−0.10)×0.10 = −0.010
         + (−0.50)×0.75 = −0.375
       ≈ −0.667
p̂_3 = σ(−0.667) ≈ 0.339  <  τ = 0.5
```
→ 第 3 个 waypoint 被截断，`n_t = 2`，只执行前 2 个，然后回观测、重新规划。

## 4. 工程视角 (Engineering View)

| 工程维度 | 具体数字 / 约束 | 工程含义 |
|----------|-----------------|----------|
| 控制频率 | 低阶执行 20 Hz；VLM 仅稀疏决策 | 模型延迟不直接耦合控制回路 |
| 每次 waypoint 位移 | ≤10 cm；到达判定 8 mm & 0.08 rad | 太长易撞、太短调用变多 |
| 计划长度 | ≤24 waypoints；τ = 0.5 | 一次推理可摊薄到多次动作 |
| 每次决策工具轮数 | ≤6 轮（含 locate_pixel）| 限制单次模型延迟上界 |
| Episode 上限 | 地平线 H、80 决策、$25 API 成本 | 硬性成本熔断 |
| 校准器 | 8 维逻辑回归，每 episode 重拟合一次 | 极轻量，与 LLM 成本相比可忽略 |
| 上下文预算 | 系统 prompt 9.8k → 最多 17.7k 字符（base 臂 3.9k）| 记忆增长不导致上下文无界 |
| 上下文组件 | 3×512×512 RGB（左右外视 + 手腕）；不含物体 pose | 模型只能从像素+工具拿几何 |
| 参考选择 | 最多 2 个、来自不同初始状态的成功 episode | 提供策略范例 + 相对 grounded 点的几何 |
| 成本单价 | 每百万 token：$10 新输入 / $1 缓存 / $12.5 缓存写 / $50 输出 | 输出（含推理 token）是主要成本源 |

**部署边界**：整套方法**不更新模型权重**，因此可以对“封闭 API 的前沿模型”直接套用；代价是能力上限被底层模型锁死（见 §6）。校准器是唯一的学习组件，且训练信号零人工成本——这让它适合 7×24 自动化采集回路。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 在 RoboCasa 与**实机 YAM / Franka**上自主采集示教（YAM：45%→95% 成功率）。
- 用“已成功”的跨 episode 经验提升采集效率（记忆 vs 清空：185/341 vs 162/341，p=0.027）。
- 用零人工标注的执行结果校正置信度（8,458 waypoints；ECE 0.24→0.05）。
- 产出的数据可训练出逼近人类示教的下游策略。

**不能做 / 失败模式**：

| 失败模式 | 证据 | 原因 |
|----------|------|------|
| 无法补足底层 visuomotor 能力 | Qwen3.8-27B：Base 0/360 → CAPEX 只有 5/350 (1.4%) | 方法只改“怎么用”模型，不扩展其能力 |
| 纯失败经验有害 | 只有失败先前尝试时：14/67 → 7/67（p=0.09）| 没有成功范例时，经验提供不了有效先验 |
| 增益集中在“已有一次成功”后 | 有成功经验：54.0%→65.0%（p=0.0016）| 经验要靠成功轨迹才能迁移到新初始状态 |
| 目标不针对下游学习价值 | 作者自述：current objective prioritizes successful demos | 只追求“成功”而非“提升学生策略” |
| 实机仍需人工 | 需人工重置场景 + 成功判定 | 尚未自动化 reset / eval / 任务选择 |
| 跨任务迁移未解 | 作者列为 open direction | 经验目前限同任务 |

### 6.1 隐含假设 (Hidden Assumptions)

1. **初始状态来自官方人类示教**——360 个 starts 是人类示范重现，因此预设了“人类可行”的状态分布；对抗性/自生成初始状态下的表现未验证。
2. **存在可靠的成功判定器 Succ_ℓ**——自动采集依赖一个能判断任务成功的 oracle；实机上这一步仍靠人。
3. **执行器的 reach/stall 标签可信**——整套自监督信号建立在低阶执行器“到达/停滞”报告的正确性上；若执行器误报，校正器会被污染。
4. **相位切分（以夹爪事件分段）可跨 episode 匹配**——B_e 的可靠性依赖这个分割假设在长时程任务上成立。
5. **8 维特征足以刻画“到达可能性”**——特征是人工设计的（腿部长度、相位、距 located 点距离等），未做特征搜索。
6. **冷冻模型不会被废弃**——方法绑定特定前沿模型的行为；模型下线/升级会重置所有累积经验。

## 7. 与相关工作对比 (Comparison)

| 方法 | 关注点 | 架构 | 训练方式 | 适用场景 |
|------|--------|------|----------|----------|
| 人类遥操作 | 直接产生示教 | 人操作 | 无（人工）| 通用但要人工成本 |
| MimicGen 等 | 放大稀疏示教 | 轨迹变换 | 无 | 已有少量示教 |
| Manipulate-Anything | 自动示教生成 | VLM 拆解 + **独立抓取/运动规划模块** | 无 | 桌面操作，需外挂模块 |
| Agent-as-Policy | 前沿 VLM 直接当策略 | VLM agent + 工具 | 无 | 度量 wall-clock/token/cost |
| **CAPEX（本文）** | **降低示教采集成本** | 冷冻 VLM + **waypoint 计划 + 自监督校准的承诺执行 + 有界经验** | 只训练轻量校正器 | 同任务重复采集，可上实机 |

**差异定位**：与 Manipulate-Anything 不同，CAPEX 让通用多模态模型**直接输出几何动作**、以闭环执行；与 Agent-as-Policy 同处“前沿模型直接控制”的赛道，但把**反复推理的推论成本**当成核心瓶颈来解。

🎤 **面试 Tip**：被问到 CAPEX 时，一句话抓住它——“它不是让模型更强，而是用机器人的执行结果去校准模型自报的置信度，决定‘一次执行多长’，把前沿模型的推理调用频率降下来”。接着补一句它的边界：“所以它只在模型本身已具备 visuomotor 能力时有效，Qwen 骨干几乎采不到数据。”

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1. 正在评估“用前沿 VLM/Agent 做机器人示教采集”的研究者——特别是关心成本与可扩展性的人。
  2. 要决定是否把此类采集流程搬到自己机器平台（双臂/单臂）的工程师。
  3. 做 imitation learning 数据管线、关注“自动数据 vs 人类数据下游价值”的人。
- **建议章节路径**：先读 §3.2（校准与自适应执行，本文最核心）→ 再看 §4.3（学习自经验的消融与校准前后对比）→ §4.4/§4.5（下游策略与实机结果）→ 可跳 §2 的相关工作细节（只在需要定位时回看）。
- **不值得精读的理由**：如果你不做机器人学习、或已熟悉 action-chunking / adaptive-horizon 这条线，读摘要＋本笔记的 §1.2、§2.2、§6 即可掌握要点。若要复现，务必注意：物理实验仍依赖人工重置与成功判定，且需要一个具备闭环 visuomotor 能力的模型骨干。

## 9. Pulsar 系统洞察 (Pulsar System Insight)

把这篇放回 Pulsar 的两条追踪线看，有两个交叉点值得记：

- **对 VLA 线（触觉 + VLA）**：CAPEX 的“执行结果自监督标签”恰好在**接触丰富（contact-rich）场景**最有意义——它的 y_k 失败定义直接就是“stall / contact stop / timeout”。这意味着若要迁移到触觉方向，最自然的切口是把触觉信号接进校正器的 8 维特征（目前全是几何/夹爪/相位特征，**没有任何力/触觉维度**），用触觉预测“这一步会不会 contact stop”。这是一条明确的空白。
- **对 AI App 线（Agent + UI）**：CAPEX 本质上是一个 **tool-use agent**（工具仅 `act` / `locate_pixel`），其设计与 agent 工程高度同构——**有界上下文**（≤8 相位 + 2 参考，prompt 封顶 17.7k 字符）、**有界记忆**、**置信度闸控的动作承诺**（p̂_k < τ 才回退重规划）。它的“经验状态 Γ_e”就是一份 skill library + 反思摘要的具体实现。
- **跨领域共同抽象**：“何时该推理、推理前能承诺多远”——这既是 VLM 机器人控制的核心瓶颈，也是 agentic LLM 系统决定“何时调用工具 vs 直接行动”的同一类问题。值得作为一条共用模式持续追踪。
