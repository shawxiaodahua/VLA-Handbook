### 1.2 关键机制 (Key Mechanism)

- **两个目标挂在一个骨干上，而不是训两个模型**。平滑头要的是「相邻采样帧之间最多差一个 γ」，尖锐头要的是「错误开始那一刻的阶跃」，两者的最优 γ 互相冲突。作者在 §4 明说：在所有试过的 γ 下，单头都服务不了这两个消费者，所以拆成两个头、共享骨干，代价只是多 33k 参数。
- **必须因果，且窗口长度是个反直觉的旋钮**。机械臂周期性进出视野、夹爪反复开合，单帧分不清「出错」和「正常周期运动」，所以要历史；但双向编码器不能在线使用，所以用三角 mask，训练与推理同构。早期单头实验用 32 帧（16 s），双头部署砍到 16 帧（8 s）：长窗会把价值平滑到半窗尺度，对 V_mc 有利，却会磨掉 V_bin 需要的错误起点。窗口长度在 {8,16,32,64} 上扫过，是影响最大的一项。
- **标注宏化（macro-labeling）**。人工只标两件事：失败 episode 里「第几个阶段出错」、以及每个错误区间的起止。逐帧连续值由公式展开，标注成本不随帧数增长。
- **干预信号免费扩监督**。遥操作台本来就逐帧记录 operator 是否在接管。这个 flag 不能直接当标签（它是滞后指标，且接管期间的帧是人的动作），所以前移 λ=1.5 s、并把模糊的起跑带排除出二值损失。

⚡ **Eureka Moment**：失败 episode 的前缀不该被标成 0——那段观测与成功 episode 的前缀在视觉上不可区分，强行归零等于教网络「干净的观测预示着失败」。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
失败 episode 的逐帧价值 = 成功曲线走到失败阶段为止，然后从那个峰值继续按同一速率衰减
```

**目标**：为平滑头定义逐帧回归目标 v_k ∈ [0,1]，为尖锐头定义逐帧二分类目标；两者都由宏观标注展开。

**成功 episode 的曲线**：

```
v_k = γ^(N−1−k),    k ∈ {0,…,N−1}
```

**失败 episode 的阶段感知曲线**：

```
v_k = γ^(N−1−k)                        k ≤ k_fail
v_k = γ^(N−1−k_fail) · γ^(k−k_fail)    k > k_fail

其中  k_fail = floor( (s_fail / N_s) · N )
```

**尖锐二值目标**：

```
v_bin(k) = 0   落在任一人工标注错误区间内（含接管派生的前移区间）
v_bin(k) = 1   其余
```

**优势与后训练权重**：

```
A_t = V_mc(t + H_A) − V_mc(t)
w_t = clip( e^(A_t / β), 0.1, 9 )
```

| 符号 | 含义 | 本文取值 / 说明 |
|------|------|----------------|
| N | 采样帧数 | 2 Hz 下 73 s episode ≈ 146 帧 |
| k | 采样索引 | 0…N−1 |
| γ | 折扣 | 0.99（按采样帧计） |
| N_s | 任务阶段数 | 6（三明治：底包 / 肉饼 / 芝士 / 番茄 / 生菜 / 顶包） |
| s_fail | 失败前已完成的阶段数 | 人工标注 |
| k_fail | 失败阶段起始帧 | 把每个阶段近似为等长时间份额 |
| λ | 干预前置量 | 1.5 s |
| H_A | 优势视野 | 50 帧 |
| β | AWR 温度 | 0.3 |
| α₊ | 检测损失正样本权重 | clip(n₀/n₁, 0.1, 10) |

**直觉**：三个设计点各有对口的下游消费者。

1. **连续性**。式 (1) 在 k_fail 处严格连续（前缀末值 = 衰减初值），因此不要求网络在光学上连续的画面上拟合出一个阶跃。对比方案 B「cliff」没有 t=0 的泄漏，却要拟合阶跃，作者报告它会以「cliff 前的振荡」形式浮出水面。
2. **非单调**。rollout 可以「好 → 坏 → 好」，价值也就必须能先降后升；只会计数的进度时钟做不到这件事。干预期间 V_mc 目标被乘上一个梯形（从 1 线性降到下限 0.2，保持到接管中点，再线性回升到释放时回到 1），重叠的下降取最小值。
3. **指数形状对优势估计有意义**。若标签是线性的，A_t 在成功段上是常数，无法区分「真在推进」和「原地滑行」；指数形式下 V 的增量随剩余步数放大，优势自然分层。

> 论文对此的表述是「标签形状本身让验证 loss 变动约 4 倍」；Table 1 的实测是 0.00051 对 0.00178–0.00202，即 3.5–4 倍区间。作者同时明确：每个方案是拿自己的目标打分的，所以这些数比较的是**可学习性**，不是准确率。

## 3. 带数字走一遍：玩具例子 (Worked Example)

> ⚠️ 以下数值是我按论文公式（式 1）自行设定的**假设场景**并手动验算，不是论文的实验结果。参数取论文公开值：γ = 0.99、2 Hz 采样。

**设定**：一个 50 s 的 episode → N = 100 帧；任务 4 个阶段（N_s = 4）；失败发生在已完成 2 个阶段之后（s_fail = 2）。则

```
k_fail = floor((2 / 4) × 100) = 50
```

**步骤 1 — 成功曲线**

```
k=0  :  v = 0.99^99  = 0.370
k=50 :  v = 0.99^49  = 0.611
k=99 :  v = 0.99^0   = 1.000
```

**步骤 2 — 失败曲线**

```
k ≤ 50 :  v_k = 0.99^(99−k)            → k=50 处 0.611
k = 51 :  v = 0.611 × 0.99            = 0.605
k = 99 :  v = 0.611 × 0.99^49         = 0.611 × 0.611 = 0.374
```

连续性检查：k=50 时前缀给出 0.611，衰减支从 0.611 起步，无跳变 ✓

**步骤 3 — 与朴素 MC 对比**

朴素 MC 把整个失败 episode 的所有帧都设为 0。于是 k=0 处，成功 episode 的目标是 0.370、失败 episode 是 0.000，而这两帧的观测在视觉上几乎一致。网络只能靠「细微到不可见的早期线索」去拟合这个差，正是作者说的「教模型用干净观测预测失败」。

**步骤 4 — 与方案 A（outcome-scaled）对比**

方案 A 把前缀整段乘以 c = s_fail/N_s = 0.5：

```
v_0 = 0.5 × 0.370 = 0.185
```

而成功 episode 的 v_0 = 0.370。也就是说，在任何可见线索出现之前，t=0 的两个目标就已经差了 2 倍——这是「结果泄漏到起点」的量化版本。

**步骤 5 — 优势与权重（H_A = 50 帧）**

```
成功段：  A_t = V(t)·( γ^(−H_A) − 1 ) = V(t) × (1.653 − 1) = 0.653·V(t)

t=0  :  A = 0.370 × 0.653 = 0.242  →  w = e^(0.242/0.3) = 2.24
t=49 :  A = 0.605 × 0.653 = 0.395  →  w = e^(0.395/0.3) = 3.73
```

若改用线性标签 V(t) = t/N，则 A_t = 50/100 = 0.5 恒定，w 处处相同——后训练权重退化为均匀采样。这一步把论文「指数 vs 线性的差别下游才显形」的说法落成了可算的数字。

| Mean subtask ↑ | 0.88 | 0.91 | 0.94 | **0.96** |
| Clean subtasks ↑ | 82% | 88% | 88% | **92%** |
| Catastrophic subtasks ↓ | 10 | 7 | **2** | **2** |
| Repeat-picks ↓ | 0 | 4 | 0 | 0 |
| Median duration ↓ | 1:16 | **1:15** | 1:21 | 1:22 |

> ⚠️ 数字对不齐的地方要点出来：摘要与结论写「70% → 85%」，这个 70% 是 IWR 对照组的数，不是无 HIL 基线；Table 2 里 π0.5 无 HIL 是 65%。汇报时应以表格为准。

两个 critic 权重到达同一 headline，路径不同：vf-mask 抬起地板（番茄 0.82→0.97、生菜 0.82→0.95，且在更难的第二个三明治 60%→90%），vf-awr 抬高天花板（番茄生菜满分、平均子任务 0.96）但在芝士上更吃力、第二个三明治掉到 80%。**重复抓取**是最干净的信号：这个反射在纯 flag 路线上（更多纠错数据、双倍回放比例、去 pause 帧）都没消失，两个 critic 权重下都不再出现。作者解释为 critic 在梯度上削掉了「重复抓取前的低价值漂移」，同时保留教会恢复动作的接管帧（w 下限 9）。代价是中位时长变长（1:16 → 1:21/1:22）。

作者对 A/B 的自评是 **suggestive rather than established**：n=20 下完成率差异落在噪声内（Fisher exact p=0.45），多行 headline 其实追踪的是同样那 3 个多完成的三明治，四列来自不同时段、配料摆位未受控。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：

- 在**一次前向传播**里同时给出平滑进度（喂优势估计）与尖锐失败概率（喂告警），且因果 mask 保证训练与在线推理同构。
- 在**不新增人工标注**的前提下扩检测监督：利用遥操作台已有的 intervention flag，AP 从 0.38 提到 0.82、AUROC 0.69→0.94、接管前检出 35%→95%、中位领先 1.2 s→2.4 s。
- 作为**训练权重**使用：两种 critic 派生权重都把完成率从对照组的 70% 抬到 85%，并让重复抓取归零。
- 对**量化鲁棒**：bf16 下 AUROC/AP/领先时间几乎不变。

**不能做 / 做不好**：

- **滞后**。作者自述预测比真实失败晚数秒，量级约为因果历史窗口的一半（8 s 窗口 → 数秒）。这决定了它只能做告警与数据筛选，做不了毫秒级安全拦截。
- **仍依赖人工标注失败阶段**。Appendix 试了 Gemma-4-26B 当阶段标注器，MAE 0.21（占 episode 比例），高于作者判定的可用线 0.10。所以「宏标注便宜」里的「哪个阶段出错」这一环还没有自动化。
- **没有外部失败检测器作为 baseline**。SAFE / AHA / I-FailSense / StepEval 都只在 related work 里被定性讨论，没有在同工位同数据上跑数。
- **跨任务泛化无证据**。单任务、单工位（六阶段三明治），作者明写「最想做出的跨任务声明尚无支撑」。
- **闭环收益未超噪声**。n=20、p=0.45，且任务是更容易被「三次额外成功」主导的小样本。
- **速度与完成度的权衡**没被讨论：完成率上去了，但中位时长变长。

### 6.1 隐含假设 (Hidden Assumptions)

1. **阶段等长假设**。k_fail = floor((s_fail/N_s)·N) 把每个阶段近似为 episode 的等长时间份额。真实三明治工位里「放生菜」和「放底包」耗时未必相当，这个近似会给 k_fail 引入系统性偏移。论文未量化这个误差。
2. **γ 与采样率强耦合**。γ = 0.99 是**按采样帧**计的，2 Hz 下等于每帧只衰减 1%、146 帧累计到 0.23。若采样率换成 10 Hz，同一 γ 会让曲线形状完全变形。论文没有讨论这个超参的可迁移性。
3. **干预 flag ≈ 状态变坏的可靠代理**。它假设操作员的接管时机反映真实失败、且延迟大致恒定（所以可以用固定 λ=1.5 s 前移）。不同操作员的反应习惯差异未被建模。
4. **冻结 DINOv3 特征可迁移到本站**。作者明确说「没测过 fine-tune」，即迁移性只是未被证伪，不是被验证。
5. **留出集独立性**。检测评测的真值由 intervention flag 派生，构成轻度循环；只有领先时间不受此影响。
6. **A/B 的隔离性**。四列来自不同 session，配料摆位未受控；作者靠「两个不同 critic 权重给出同样结论」来间接支撑。
7. **单一任务代表整类问题**。全部结论建立在一个六阶段、固定顺序的装配任务上。

## 7. 与相关工作对比 (Comparison)

| 方法 | 关注点 | 监督层级 | 索引方式 | 部署时可读 | 训练成本 / 接入方式 |
|------|--------|----------|----------|-----------|---------------------|
| SAFE / AHA / I-FailSense / StepEval | VLA 失败检测 | episode 级或子任务级 | — | 多为事后判定 | 独立检测器，需失败标注 |
| Hi Robot / SayCan / HG-DAgger | 层级或交互式纠错 | 语言 supervisor 路由 | — | 有路由无标定进度 | 需语言标注 / 人在环 |
| π*0.6 / RECAP | critic 驱动的策略后训练 | 逐时间步价值 | 距完成的剩余步数 | RECAP 的 indicator 不在运行时被 operator 读取 | 需 on-policy rollout + 遥操作干预 |
| **ValueFormer（本文）** | 标签形状 + 双头 critic | **逐帧、双信号** | **任务阶段** | **运行时直接出告警** | 3.46M 参数、作者称 3 分钟级；复用已有 intervention flag |

与 RECAP 的两点关键差异（作者自陈）：其一，RECAP 把优势阈值化成二值 indicator 去条件化策略，本文保留优势幅值，所以同一个连续 critic 既能供软权重（vf-awr）又能供硬 mask（vf-mask），还能在部署时逐帧读出来报警；其二，RECAP 的价值按「到完成的步数」索引，本文按「任务阶段」索引——后者让「放了四个配料后崩溃」和「第一个阶段就崩溃」在目标上不再同形。

🎤 **面试 Tip**：被问「怎么监控一个正在跑的 VLA 是不是在出错」，一句话答——**加一个轻量 critic 即可，但成败在标签形状**：失败 episode 的前缀必须沿用成功曲线、只在失败阶段之后衰减，否则网络学到的是「干净观测预示失败」，检测器在正常 rollout 上就会误报。

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1. 在真实产线 / 工位上部署 VLA、需要在线失败检测、早停或数据筛选的工程团队——重点看 §2.1、§2.3、§3.2 和 Appendix A。
  2. 做 offline critic、advantage-weighted regression、post-training data weighting 的研究者——重点看 §3.3、Table 2 和 Appendix A 的权重细节。
  3. 想把「宏标注展开成逐帧监督」这套思路搬到别的任务（装配、分拣、移动操作）的人——重点看 §2.1 的标签构造与 §4 的局限性。
- **建议章节路径**：先读 §2.1（标签形状，这是全文核心）→ 再看 §2.3 + §3.2（干预信号为什么能用、用了之后涨多少）→ 然后 §3.3 + Table 2（闭环，注意 n=20 的噪声声明）→ 最后 Appendix A（超参与损失细节）。§1 的 related work 与 §7 的对比可以略读，因为本文并未在同一实验台上与这些方法跑数。
- **不值得精读的理由**：如果你不做真实机器人学习、或只关心 VLA 主干网络结构创新，读摘要与 §2.1 就够——这篇的贡献是标签设计与一个外挂 critic，主干完全冻结、未做任何改动；如果你已经熟悉 offline RL 的价值函数设计，本文的增量主要是「按阶段索引 + 前缀不置零」这两点，其余是工程配方。
