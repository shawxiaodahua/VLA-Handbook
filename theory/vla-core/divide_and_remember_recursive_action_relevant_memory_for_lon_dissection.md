💡 **X-Ray 开场**
长时序机器人任务里，机器人常常"看不到"决定动作的关键信息——比如刚才视频里它抓方块的手势。这篇论文问：那到底该从历史里记住什么？作者的答案是：记住那些"当前观测没有、但动作依赖"的信息，形式化为最大化条件互信息。实现上他们用一个小选择器递归地从历史 token 里挑出 top-K（默认 64 个），一个选择器管整段历史。结论很硬：在 16 个长时序任务的 RoboMME 上，它把无记忆策略从 17.9% 拉到 38.6%，真机 40 次试验成功 35 次。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练 / 推理差异 |
|------|------|------|----------------|
| 冻结 SigLIP 编码器 | 历史帧 patch | 历史 token ℋ_t | 训练 / 推理一致，均冻结 |
| 选择器 f_ψ | 2K 个候选 token | top-K token | 训练加 Gumbel 噪声探索；推理性确定性 top-K |
| 递归合成 ℳ_ψ | 任意 token 跨度 | ≤K 的 token 子集 | 训练与部署对同一前缀构造同一棵树，无离线-在线错配 |
| π0.5 骨干 (Gemma VLM + action expert) | o_t + 记忆 m_t | 动作块（chunk 20，执行 16）| 流匹配动作损失联合微调 |

记忆注入方式：所有 memory 方法都通过 adaptive LayerNorm 把记忆调制进 action expert，action 特征对记忆 token 做 cross-attention（论文 Figure 3b）。

### 1.2 关键机制 (Key Mechanism)

- **视记忆为预算化 token 选择**：记忆 M 是从历史 token 到"至多 K 个 token 子集"的映射，目标是在预算内最大化条件互信息。
- **递归分治**：全历史的 top-K 选择被分解为对 2K 个 token 的 top-K 子问题，逐层向上合并，固定尺寸的轻量选择器即可支撑无界历史。
- **共享选择器**：所有递归节点共用一个 f_ψ，捕捉每个块通用的选择规则，参数与历史长度无关。
- **保持预训练 token 空间**：记忆是历史 token 的直接子集，因此被记住的事实能"原样读回"（保留空间细节），不像隐式记忆那样压进新的稠密潜空间。

⚡ **Eureka Moment**：不该由人来设计"记什么"，而应直接优化 I(a_t; m_t | o_t)——即"当前观测之外、动作仍然依赖"的那部分互信息，且在 VLA 预训练 token 空间内做离散 top-K 选择即可实现。

### 1.3 信息流/架构图 (Flow / Diagram)
```
历史 token ℋ_t
   │  递归合并（每层: 2K → top-K）
   ▼
[leaf 对]──f_ψ──▶ 保留 K
[leaf 对]──f_ψ──▶ 保留 K     ──┐
                              ├─合并 2K ─f_ψ─▶ 保留 K ... 直到根
[leaf 对]──f_ψ──▶ 保留 K     ──┘
   ▼
根节点 m_t (≤ K = 64 token)
   │  通过 attention mask 注入
   ▼
π0.5 action expert  ──▶ 动作块 chunk
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：
```
M* = argmax_M  I(a_t ; M(h_t) | o_t)
```

目标：找到把历史压缩成记忆的映射 M，使其保留"对动作有用、且当前观测 o_t 未包含"的信息。
公式（条件互信息的链式分解）：
```
I(a_t ; h_t | o_t) = I(a_t ; m_t | o_t) + I(a_t ; h_t | o_t, m_t)
```
变量说明：

| 符号 | 含义 |
|------|------|
| a_t | t 时刻动作 |
| o_t | 当前观测 |
| h_t | 到 t 为止的历史（观测-动作对序列）|
| m_t = M(h_t) | 记忆；历史的（策略充分）统计量 |
| K | 记忆预算（token 上限），主实验 K = 64 |

直觉：等式左边由任务固定，因此最大化右边第一项等价于最小化被丢弃的信息 I(a_t; h_t | o_t, m_t)。

把可优化项展开（用策略 π_θ 作变分下界）：
```
I(a_t ; m_t | o_t) = H(a_t | o_t) − H(a_t | o_t, m_t)
                   = E_D[ log p(a_t | o_t, m_t) ] + H(a_t | o_t)
                  ≥ E_D[ log π_θ(a_t | o_t, m_t) ] + H(a_t | o_t)
```
其中 H(a_t | o_t) 由数据固定，故训练目标就是最小化策略负对数似然（π0.5 实际用流匹配损失作为其代理）。这给出统一视角：感知记忆（按像素变化选帧）实际在最大化 H(o_k | o_t)，它是 I(a_t; o_k | o_t) 的松上界；隐式记忆通过变分下界优化同一目标，但损失了预训练 token 的空间保真度。

选择器的离散 top-K 用直通门控（straight-through）训练：
```
g_i^hard = 1[ s_i > ρ ]                        # 硬选择
g_i^soft = σ( (s_i − ρ) / τ )                  # sigmoid 松弛，τ 为温度
g_i      = sg( g_i^hard − g_i^soft ) + g_i^soft # 前向硬选，反向软梯度
```
其中 ρ 是第 K 与第 K+1 大得分之间的（detach 的）中点，sg 表示 stop-gradient。

## 3. 带数字走一遍：玩具例子 (Worked Example)

设 K = 2，历史共 8 个 token，记为 t1..t8（从左到右为时间序）。

```
第 0 层: 跨度为 4 的两个块
  块A = {t1,t2,t3,t4}  --f_ψ--> 保留 {t2,t3}
  块B = {t5,t6,t7,t8}  --f_ψ--> 保留 {t6,t7}
第 1 层: 合并 {t2,t3,t6,t7}（2K = 4 个）--f_ψ--> 保留 {t3,t6}
根输出: m_t = {t3, t6}     (≤ K = 2)
```

对比启发式：假设 t7 是"打光变化"帧（像素变化大但动作无关），t3 是"抓手势"帧（当前观测看不到但决定动作）。
- 按像素变化最大选（感知记忆）可能选中 t7 ⇒ 预算浪费在无关信息上。
- D&R 按 I(a; m | o) 目标打分，选择器会把 t3 的分数推高（保留 t3 能提高动作似然），于是选到 {t3, t6} ⇒ 关键事实被读回。
- 若把动作 token 放进候选池，策略可能"抄"上一动作（因果混淆），所以候选只保留 patch token。

## 4. 工程视角 (Engineering View)

| 关注点 | 事实与工程含义 |
|------|----------------|
| 计算量 | 预算 64→512 token，D&R 成功率最高而单次前向 TFLOPs 基本持平；递归只对幸存 token 重新打分，算力花在"高价值 token"上 |
| 训练时间 | D&R 80k 步约 20 小时；隐式记忆 RB-VLA 每步循环更新 belief，无法在时间维并行，约 10 天 |
| 部署 | 记忆是 token 子集，可原样读回；无离线-在线错配（训练/部署对同一前缀构造同一棵树）|
| 候选池 | 选择器在 \|ℋ\| 个候选 token 上工作（每 16 帧均匀采样 1 帧、每帧 16 个池化 patch），与历史长度解耦；池 128→1024 扫描显示帧类事实在 512 达峰（47.5%），1024 反降到 36.2% |
| 预算 | 64→512：256 时趋平（50.1%），512 微降（46.4%），作者归因于大预算需更多训练步（80k 步尚未收敛）|

## 5. 数据与评测 (Data & Eval)

- **基准**：RoboMME（Dai et al., ICML 2026）——16 个长时序操作任务，按功能分 6 类：Motion-Centric / Time-Sensitive / Short-Horizon Video / Long-Horizon Video / Dynamic Scene-Change / Event-Salient。
- **训练**：全部 16 任务多任务训练；SigLIP 冻结，Gemma VLM + action expert + 记忆参数用流匹配损失微调；预测动作块 20、执行前 16；80k 步、batch 64。
- **评测协议**：所有记忆方法统一 64 token 预算，仅"填什么"不同；每任务 50 episode（共 800），训练无关 seed，最大 horizon 1300 步；对最后 3 个 checkpoint × 3 个 seed 取平均。
- **主要结果**（论文 Table 1 / Table 7）：
  - 四套件平均成功率：**D&R 38.6%** > HAMLET 32.2% > FrameSamp 27.9% > 无记忆 π0.5 17.9%
  - 帧类事实（Motion-Centric、长短视频）：D&R 增益最大；Long-Horizon Video 上 D&R 是唯一超过无记忆策略的方法（31.7% vs 28.5%）
  - 状态类事实（Time-Sensitive 等）：隐式记忆 HAMLET 领先（39.3% vs D&R 31.3%）
- **真机**（论文 Table 2）：PutBottles / TrackCube / RepickCube / DrawPattern，D&R 35/40 成功，FrameSamp 22/40，π0.5 3/40；PutBottles 最长约 4 分钟。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 帧类事实检索：从视频阶段（300 步前）保留关键手势 / 位姿；MoveCube 中保留了抓取手势。
- 多任务一致增益：四套件全部提升，覆盖四种记忆需求（跨重复事件累积计数、跟踪被遮挡物体、回指早前时刻、复现演示序列）。

**不能做 / 受限**：
- 状态类事实（BinFill 逐次计数、流逝时间、动态场景）：D&R 只能与隐式记忆打平，在 StopCube、ButtonUnmask 上落后——因为它是"存快照"，需要从快照重建运行状态。
- InsertPeg：所有方法 ≤ 3.3%（无记忆 1.6%），论文归因于插入精度问题而非记忆（rollout 已到正确的一端与正确的侧面）。

### 6.1 隐含假设 (Hidden Assumptions)

- 记忆只需"策略充分"（policy-sufficient），不需预测未来观测 / 奖励——消融 D&R+pred 显示加世界模型预测损失无增益；但这与"未来需新观测去消歧"的任务设定相关，未涵盖主动感知场景。
- 历史信息可由均匀采样的候选池代表（每 16 帧取 1 帧）；极短时间内的高频关键事件可能被采样漏掉。
- 多任务统一训练下，记忆模块可能收敛到"跨任务共性知识"，导致冗余——作者已在 limitations 中承认。
- 评测与部署都假设可控的相机 / 光照条件；真机实验加了"人中途介入"和感知噪声，但仍限于桌面单臂操作，泛化到双臂 / 移动 / 人形未验证。
