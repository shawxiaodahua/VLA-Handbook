### 1.2 关键机制

- **双表示分离视觉与物理**：3DGS 只负责「看起来真」，SuGaR 抽出的 mesh 负责碰撞、容器发现和导航分析。这是整条流水线能自动化的前提——高斯点云无法直接做接触。
- **容器发现不依赖语义标注**：估地板平面 → 保留朝上的 mesh 区域 → 用基于机器人几何的全局高度/面积阈值筛 → 用 3D 位置和法线做 HDBSCAN 聚类 → 按几何范围、表面稳定性、高度合并过滤。论文强调这能发现 non-tabletop 表面。
- **可达性作为任务可行性过滤器**：先算 navmesh，再要求某个站立点周围 0.70 m 水平半径内至少有 6 个候选放置采样点，之后才做物体稳定、抓取过滤和 oracle 执行可行性检查。
- **特权 oracle 替代遥操作**：缓存物体局部对跖抓取候选 → 变换到当前稳定位姿 → 排序可行腕/基座配置 → 贪心规划器在离散动作网格上选平移与偏航 → 控制器伺服预抓取、下降、闭合、提升；失败则回滚快照换下一个候选。
- **两阶段 SFT 的分工**：Stage 1 是「同场景粗适配」（Office1k）或「多场景广适配」（Multi1k），Stage 2 才用用户自己的物体做个性化。论文的关键发现是起点选择比什么都重要。

⚡ **Eureka Moment**：把「个性化」重新定义为**同场景的数据扩增问题**——论文在指定场景用约 500 条 Stage 2 oracle 演示做个性化，但 Stage 1 同场景与多场景数据的效果需分别评估；其中一个跨场景个性化配置出现退化（Office1k Stage 1 在 Office 上 40.0%，经 Conference 个性化后掉到 15.0%）。

## 2. 数学核心

📌 **Napkin Formula**（一行抓住本质）：

```
68,021 条成功演示 ÷ 60 demos/(A40·GPU·hour) ≈ 1,133.7 A40 GPU 小时；273.46 是记录控制小时，不是 GPU 小时。62.5% 是 Office 任务库仿真聚合成功率；63.9% 是真机 12 任务子集成功率（该子集仿真为 66.7%）
```

**目标**：在只有特权仿真数据、没有任何真实遥操作的条件下，让策略在用户场景的指定容器上完成指定物体的拾取。

**核心损失**（论文 §III-D，条件流匹配）：

```
x_t = t·a + (1 - t)·ε,   ε ~ N(0, I),   t ∈ [0, 1]

L_FM = E_{a, ε, t}[ || v_θ(x_t, o, t) - (a - ε) ||₂² ]
```

**可达性判据**（论文 §III-B，几何规则而非学习）：

```
keep(stand_point) ⇔ |{ p ∈ placement_samples : ||p_xy - stand_xy||₂ ≤ 0.70 m }| ≥ 6
```

**动作空间**（10 维 Stretch 向量）：

```
a = [Δq_arm, 0, Δq_lift, 0, 0, Δθ_wrist, g, τ, Δx_base, Δθ_base]
```

| 符号 | 含义 |
|------|------|
| `a` | ground-truth 动作块，H × d_a |
| `x_t` | 噪声与真值之间的线性插值点 |
| `v_θ(x_t, o, t)` | 以观测 `o` 和时间 `t` 为条件的预测速度场 |
| `g, τ` | 夹爪命令与终止命令 |
| `0.70 m` | 机器人水平可达半径（论文给定常数） |

**直觉**：训练目标是把噪声推向 oracle 动作块；在部署时从噪声积分出动作块，再一次性执行。真正决定成败的不是这个损失，而是喂给它的演示是否落在「这个场景的某个可行容器上」——这正是 Stage 1 数据源选择的实验要回答的问题。

## 3. 带数字走一遍：玩具例子

> 以下 A、B 两组数字为**我的验算**，用论文给出的统计量互相校验；C 组是**假设场景**，标注为假设。

**A. 演示吞吐的自洽性（验算）**
论文：68,021 条成功演示 = 273.46 记录控制小时。
```
273.46 h × 3600 / 68,021 ≈ 14.47 s / 条
```
再乘以论文假设的 24 配置/对 × 473,712 候选对：
```
473,712 × 24 = 11,369,088 个候选任务
11,369,088 × 14.47 s ≈ 1.645e8 s ≈ 45,700 h
```
与论文「约 45,700 小时」吻合。这说明论文的 68,021 条只是潜在任务空间的很小一部分（论文自述因存储限制约做了 100× 下采样）。

**B. 「一个 epoch」的语义（我的核验，非论文结论）**
```
Stage 1 Office1k：39,489 步 × 64 = 2,527,296 个样本 / 1,024 条轨迹 ≈ 2,468 样本/轨迹
Stage 2 Office  ：15,963 步 × 64 = 1,021,632 个样本 / 504 条轨迹  ≈ 2,027 样本/轨迹
```
若「epoch」按完整回合计，这两个数字对不上。合理解释是 epoch 定义在**动作块/时间窗**层面，而非回合层面。论文没有明说，这是一个需要向作者确认的点。

**C. 可达性过滤的假设演算（假设，非论文数据）**
设某容器表面采样 40 个放置点，机器人候选站立点 S1、S2：
```
S1：0.70 m 内有 11 个点 → 11 ≥ 6 → 保留
S2：0.70 m 内有 4 个点  → 4 < 6  → 丢弃
```
这条规则的工程含义是：它把「基座朝向、机械臂伸展、动态可达」全部压成了一个水平圆盘近似，代价是可能误杀一些实际可达但需要特定朝向的配置。

## 6. 能力与失败模式

**能做**
- 建筑尺度（中位 104.87 m²）捕获 → 自动发现 852 个容器 → 6.8 万条无遥操作演示。
- 用户只需 20–30 分钟手扫 + 每个目标物体一张图和尺寸。
- 同场景个性化后，真机成功率与仿真接近（63.9% vs 66.7%），且策略排序保持一致。

**不能做 / 明显短板**
- **任务族极窄**：只有 receptacle-local pickup，没有长程移动操作、铰接物体、开关门、放置到指定位置后的交付验证。
- **跨场景个性化有害**：错场景 Stage 2 让 Office1k Stage 1 从 40.0% 掉到 15.0%；六个跨场景对比全部低于同场景。
- **OOD 容器掉点大**：从 62.5%/47.5% 掉到 22–33%。
- **统计功效有限**：真机 36 次试验/策略、OOD 每桌 18 次试验/策略（两桌合计 36 次/策略）、单机器人单场景，未报告多种子方差。
- **成功谓词偏弱**：只看目标抬升，不检验稳定抓持、运输或放置。

### 6.1 隐含假设

1. **0% 的归因是混合的**：论文说 π₀.₅ base 为 0.0% 是因为「没接触过 Stretch 本体或本文动作空间」——这同时包含**本体/动作空间适配**和**场景适配**两个变量，论文用 Stage 1 一并解决，但没有拆开消融。
2. **扫描即真值**：假设 3DGS + SuGaR mesh 的几何足以支撑碰撞与可达判定，未量化重建误差对任务可行性的影响。
3. **部署时容器几何不变**：用户场景里的架子/台面在部署时与扫描时一致，物体也摆在同一批容器上。
4. **可达性是可分离的圆盘**：用 0.70 m 水平半径 + ≥6 个采样点近似可达，忽略基座朝向、关节限位与动态避障。
5. **特权 oracle 的成功可迁移**：oracle 用特权位姿规划出的轨迹，被认为对策略学习有代表性；但真机接触「更宽容」（夹爪柔顺 + 橡胶指面摩擦高于仿真接触模型）这一点说明 sim-to-real 的部分成功来自物理容差，而非仿真完全准确。
6. **演示规模=覆盖度**：Table III 中 24 任务/物体是「足够覆盖」的经验结论，来自 4 个物体、最多 4 个容器的消融，外推到 852 个容器的场景未验证。
7. **公开数据状态未核实**：论文仅写「接收后公开数据集」，未提供可核验的仓库地址；仅凭这份论文不能判断目前是否已经公开，复现前需另行核实。
