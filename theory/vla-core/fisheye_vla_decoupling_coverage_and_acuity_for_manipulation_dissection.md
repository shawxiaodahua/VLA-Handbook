💡 **X-Ray 开场**
传统做法把"看得广"和"看得清"绑在两块硬件上——前视相机管全局，腕部相机管近景。这篇问了一个反直觉的问题：如果只给你**一颗鱼眼**，把有限的视觉预算（像素/token）花在哪里最值？作者用"同一段录像重渲染"的受控实验证明：**花在末端执行器（手）周围最值**——一只手一路就吃掉了大部分收益。对 VLA 研究者意味着：观测接口本身是可优化的一等公民，不必靠加相机解决。

### 1.2 关键机制 (Key Mechanism)

- **为什么鱼眼而不是普通广角**：理想等距模型下 ρ = f·θ，径向角采样密度恒定，全局与边缘的角分辨率一致；而直线相机 ρ = f·tanθ 在 θ→90° 时发散，有限像面覆盖不了整个半球。所以鱼眼能让 crop 在大角范围内移动而径向采样可比。
- **为什么是"渲染"而不是"裁剪"**：crop 不是直接抠像素块，而是用标定镜头模型做**逆透视采样**——裁剪与畸变校正一步完成，输出的是预训练编码器认识的透视图像，避免先整流整张全景再抠图。
- **为什么一只手一路（而非动态选一只手）**：实验显示双手静止时"仅凭运动无法选出该看哪只手"（37 个窗口的 oracle 仍有 2.427 mm 增益），每手一路直接绕过"选哪只手"这个额外决策。
- **为什么要速度前瞻**：模仿人类"看在前、抓在后"（anticipatory gaze），crop 中心预测到手的前方 τ·v 处，避免伸手时前方细节被裁掉。

⚡ **Eureka Moment**：**覆盖度与锐度不该被硬件绑定——用一颗鱼眼的广角覆盖，再用"按手位姿重渲染的透视 crop"把锐度动态投放到交互点，且实验证明这个投放规则（手为中心）能被离线"重渲染"预先测量出来。** 换句话说：观测接口的设计可以像超参一样被 A/B 出来。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
一颗鱼眼：ρ = f·θ（等距，密度恒定）  vs  直线：ρ = f·tanθ（θ→90° 发散）
```

**先给目标**：在固定视觉预算下，从单张广角图中抽出"最有用的局部透视细节"喂给预训练 VLA。

**再给公式**（全部用纯文本/代码块表达）：

```
# 1) 逆透视渲染：输出像素 u → 物理光线 → 源图像素
r_η(u) = normalize(U_η · A_η^{-1} · ū)      # 虚拟相机内参 A_η、朝向 U_η
m_tj(u) = P_κ( r_ηtj(u) )                    # 标定投影 P_κ：光线→源像素
C_tj(u) = I_t( m_tj(u) )                     # 双线性采样取色，裁剪+去畸变一步完成

# 2) 焦距跟踪与前瞻
p_tj     = Π_κ,j( R_tj, x_tj )               # 当前 EE 位姿 → 图像中心
x̂_tj     = x_tj + τ · v_tj                    # 因果后向差分速度 v，前瞻间隔 τ
α_tj     = 1 + β · clip( ‖v_tj‖ / v_ref, 0, 1 )   # 速度越大视野越宽
f_tj     = f_0,tj / sqrt(α_tj)               # 局部焦距随速度收缩

# 3) 球面射线位置编码
h̃ = h + e(r),  e(r) = W2 · σ( W1 · γ(r) )    # γ：单位光线 + L 阶 Fourier 特征
```

| 变量 | 含义 | 本文取值 |
|------|------|------|
| τ | 运动前瞻间隔 | 0.5 s |
| β | 视野扩展系数 | 0.5（视野最多放大 1.5×） |
| v_ref | 参考速度（经验高分位） | 0.204 m/s |
| L | 射线 Fourier 频带数 | 4 |
| n | 局部 crop 数（手数） | 2 |
| token | 每图 14×14 patch | 256 token/图；全局+2局部=768 |

**直觉**：等距投影让"角分辨率"在中心与边缘一致，所以 crop 可以在大角度范围里平移而不损失径向采样——这是"能从一张图里到处取清晰局部"的几何前提。射线编码则解决 crop **移动时坐标漂移**的问题：把 token 绑定到"它来自哪个物理方向"而非"它在图上的 (x,y)"，于是同一个方向无论出现在全局还是局部 crop，都拿到一致的射线特征。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设单手末端速度 ‖v_tj‖ = 0.204 m/s（恰为 v_ref），τ = 0.5 s，β = 0.5：

1. **前瞻**：x̂ = x + 0.5 × 0.204 = 手前方 **10.2 cm** 处。crop 中心落在手的运动方向前方，而不是手上。
2. **视野扩展**：clip(0.204/0.204, 0, 1) = 1 → α = 1 + 0.5×1 = **1.5**。
3. **焦距收缩**：f = f_0 / sqrt(1.5) = f_0 / 1.225 ≈ **0.816·f_0**，即局部视野面积放大约 1.5×。手越快，看得越广、越"糊"，以容忍前瞻误差。

**离线分配的算账（Round 2，端点误差下降 mm）**：

```
global-only          基线 = 0
+ 随机方向 crop       0.458 mm
+ 1 个 EE crop        1.339 mm   → 与随机的点估计差 0.881 mm
+ 第 2 个 EE crop     再 +0.175 mm [0.007, 0.346] → 累计 1.514 mm
全候选参考(full ref)  1.637 mm
两 crop / 参考 ≈ 1.514 / 1.637 ≈ 92.5%
```

结论：**方向对了比多塞一张图更重要**（EE vs 随机 0.881 mm > 随机 crop 本身的 0.458 mm）；而两手各一路几乎吃满候选池收益（~92.5%）。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 推理延迟 | RTX 5090 中位 **87 ms** | 其中渲染仅 1.3 ms → crop 生成几乎免费，瓶颈在策略前向 |
| 渲染成本 | 1.3 ms | 逆透视采样是纯几何 + 双线性，可放到 CPU/轻量 GPU |
| token 预算 | 全局+2局部 = **768**，与前视+双腕持平 | 不靠"看得更多"，靠"看得更对"，预算中性 |
| 训练步数 | 每任务 300 条演示、20,000 步、batch 12、单张 RTX PRO 6000 | 训练成本与常规 VLA 相当 |
| 控制频率 | 30 Hz 采样/执行，30 步动作块 | 87 ms 延迟 < 33 ms/步 × 30，需注意 chunk 执行与推理异步 |
| 视野动态 | 局部面积最多 1.5× | 用"分辨率换鲁棒"，遮挡/快速运动时更宽容 |

**工程含义**：这套接口可以**在不新增硬件**的前提下替换"前视+双腕"——省掉两条腕部线束与安装位，代价是引入**标定依赖**（位置靠离线拟合的手眼映射 Π_κ,j，方向靠 P_κ^{-1} 反投影源光线）。任何标定漂移都会直接把 crop 放偏。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 单固定相机覆盖扩展到 **180×100 cm** 桌面（R3 达 82%），目标超出前视/腕视覆盖仍可完成。
- 支撑货架抬升放置/取回与传送带动态搬运（同一多任务策略）。
- 复用同一渲染规则做人类手持演示收集（UMI 风格），减少采集与部署的视觉域差。

**不能做 / 风险**：
- **共享光心无法去遮挡**：crop 只是从同一光心重采样，不产生新视差 → 遮挡场景无解（作者明说）。
- **强标定依赖**：位姿投影靠离线拟合，标定转移（新相机/新布局）是未解问题。
- **仅桌面级验证**：固定底座双臂 + 桌面/货架/传送带，未验证移动平台、人形、多机器人。
- **离线-在线不一致的隐患**：物体中心 crop 离线对比包含 0，但闭环中优于随机（45.3% vs 33.3%）→ 离线端点误差是否足以代表在线成功率存疑。
- **人类预训练引入额外数据与优化开销**。

### 6.1 隐含假设 (Hidden Assumptions)

1. **手眼标定长期稳定**：Π_κ,j 与 P_κ 全流程不漂移——真实部署中相机震动/温漂未讨论。
2. **末端可达即"值得看"**：以 EE 为中心的先验在给定任务族成立，但需长程、多物体、大量遮挡任务才知是否普适。
3. **π0.5 底座足够强**：收益可能部分来自底座对透视 crop 的适应性，换底座未验证。
4. **渲染像素分布≈物理相机像素分布**：鱼眼重采样的透视 crop 与真实腕相机成像的域差（Fisheye3R 报告过此类 mismatch）被作者认为存在但未量化隔离。
5. **速度前瞻能代表未来交互点**：τ=0.5 s 固定，快速变向/急停场景未单独评估。
