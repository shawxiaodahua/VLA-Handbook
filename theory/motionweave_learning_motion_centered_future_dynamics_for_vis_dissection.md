## 1. 核心架構/方法總覽 (Overview / Architecture)

MotionWeave 的骨幹是 **InternVL3-2B**（語言側為 Qwen2.5 系列解碼器），動作頭是一個 **12 層、768 維、12 頭的 DiT**，用 flow matching 生成長度 H=4 的動作塊。在此之上疊兩個模組：**Action-Induced Motion Grounder (AIMG)** 與 **Horizon Residual Composer (HRC)**。

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 時序角色 | 訓練/推理差異 |
|------|------|------|----------|---------------|
| InternVL3-2B (VLM) | 當前 RGB `I_t`（224×224）、指令 `l`、動作 query 佔位 `A_0` | 視覺 token `V`（N_v=256，16×16 網格）、動作 token `A` | 單幀前向 | 訓練/推理相同（全參數微調） |
| Proprio Encoder | 本體感覺 `S_t` | 本體嵌入 `P` | 單幀前向，**不進語言模型** | 相同 |
| **AIMG** | `A`、`V`、`P` | 交互 token `M`、空間注意力 `α`（H×N_v） | 生成按 horizon 索引的 query | 訓練：`α` 受遮罩 KL 監督；推理：遮罩分支移除 |
| **HRC** | `M`、`A`、`P` | 運動接地後的動作 token `A'` | 相鄰 horizon 差分 → 注入動作 | 相同（純前向） |
| Action DiT | `A'`、`P`、含噪動作塊、擴散步 τ | 4 步動作塊 `â_{t:t+H-1}` | 10 步推理去噪 | 相同 |
| Robot-arm Mask (RoboEngine) | 未來幀 `I_{t+1..t+H}` | 逐 horizon 二值遮罩 → 目標分佈 `μ_h` | **僅訓練** | 推理時完全移除 |

### 1.2 關鍵機制 (Key Mechanism)

- **為什麼用 horizon-specific query，而不是共享全局特徵**：動作塊從共享全局特徵解碼時，不同時間步拿到的是同質的視覺證據，缺少「這個時間步該看哪裡」的對應。AIMG 為每個未來步 `h` 造一個 query，讓不同步各自去當前視覺 token 上取證。
- **為什麼監督用「手臂遮罩」而不是像素重建**：手臂遮罩天然抑制靜態背景、紋理、無關外觀，把容量集中在「會動的區域」。遮罩由 RoboEngine 離線渲染，無需人工標註。
- **為什麼 HRC 用「差分」**：相鄰 horizon 交互表徵之差不僅去除靜態成分，還直接編碼運動的**方向與幅度**——這正是「動作會造成什麼變化」的最小充分信號。
- **為什麼是「相減」殘差**：`A' = A - g ⊙ ΔA`，讓每個動作 query 只吸收與自己時間步相關的運動增量，而非覆寫原有控制先驗；門控 `g` 由本體感覺調節注入強度。

⚡ **Eureka Moment**：把「未來視覺監督」重新定義為 **「對每個動作步定位當前畫面中即將改變的區域，並用相鄰步之差編碼其運動」**——世界模型的作用不是想像畫面，而是引導注意力找對「會動的地方」。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
L_total = L_act + λ · L_motion,   λ = 0.05
（動作去噪損失 + 運動接地的 KL 正則；未來幀只在 L_motion 裡出現）
```

### 2.1 AIMG：按 horizon 生成 query 並在視覺 token 上取證

```
q_h = e_h + Mean(Proj_a(A)) + Proj_p(P)                     # (2)

α_{h,n} = softmax_n( q_hᵀ · Proj_v(v_n) / sqrt(d_m) )       # (3)

m_h = LN( q_h + Σ_{n=1..N_v} α_{h,n} · Proj_v(v_n) )        # (4)
```

- `h = 1..H`：未來動作步索引；`e_h` 為可學習的 horizon 嵌入。
- `A ∈ R^(N_a×D)`：動作 token；`P`：本體嵌入；`V = {v_n}`：N_v=256 個視覺 token。
- `α ∈ R^(H×N_v)`：每個 horizon 對 256 個視覺位置的注意力（即「這一步會動哪裡」）。
- `M = [m_1,...,m_H]`：逐 horizon 的交互表徵，全部來自**當前觀測**，靠 `e_h` 區分不同未來步。

**關鍵**：`m_h` 不預測未來畫面，只是把「與第 h 步動作相關的當前視覺證據」聚合出來。監督信號 `μ_h` 來自第 h 個未來幀的手臂遮罩。

### 2.2 HRC：相鄰 horizon 差分 → 門控殘差注入

```
Δm_h = m_h - m_{h-1},   m_0 := m_1   (故 Δm_1 = 0)          # (5)

U = MHA( Proj_m(ΔM),  Proj_a(A),  Proj_a(A) )               # (6)

ΔA = Proj_o(U),   g = σ(Proj_g(P))                          # (7)

A' = A - g ⊙ ΔA                                             # (8)
```

- `ΔM = [Δm_1,...,Δm_H]`：運動差分序列（方向 + 幅度）。
- 交叉注意力中，**差分當 query、動作 token 當 key/value**——每個局部運動線索去「探詢」需要被修正的動作 query。
- `g ∈ (0,1)`：由本體感覺調節的注入強度門。
- `A'`：運動接地後的動作 token，送給 Action DiT。

> 符號與本文一致：`H`=動作塊長度（=4），`N_v`=視覺 token 數（=256），`d_m`=運動空間維度（AIMG hidden=512）。

### 2.3 訓練目標

```
L_motion = (1 / (H · log N_v)) · Σ_{h=1..H} KL( μ_h ‖ α_h )   # (9)

L_total  = L_act + 0.05 · L_motion                            # (10)
```

- `μ_h`：第 h 個未來幀手臂遮罩 → 下採樣到 16×16 → 平滑 → 歸一化成空間分佈。
- `KL(μ_h‖α_h)`：懲罰注意力落在手臂區域之外的質量；除以 `log N_v`（均勻分佈熵）做歸一化，使損失與 token 數無關。
- `L_act`：flow-matching 動作去噪損失。

**直覺**：本體感覺 `P` 同時出現在 horizon query（2）與殘差門（7）——它既是「當前姿態告訴模型該看哪」，也是「當前姿態決定運動修正要多強」。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

為了好算，把 16×16=256 個視覺 token 縮到 **2×2=4 個 token**，動作塊 H=2。假設手臂在第 1 步移動到 token 3 區域，第 2 步移動到 token 4 區域。

**① 遮罩目標分佈**（由未來幀手臂遮罩歸一化）：

```
μ_1 = [0.05, 0.05, 0.80, 0.10]     # 第 1 步：主要落在 token 3
μ_2 = [0.05, 0.05, 0.10, 0.80]     # 第 2 步：主要落在 token 4
```

**② AIMG 學到的注意力**（softmax 後，不會正好是 0/1）：

```
α_1 = [0.10, 0.10, 0.70, 0.10]
α_2 = [0.05, 0.10, 0.15, 0.70]
```

**③ 逐 horizon KL**（自然對數）：

```
KL(μ_1‖α_1) = 0.05·ln(0.05/0.10) + 0.05·ln(0.05/0.10)
            + 0.80·ln(0.80/0.70) + 0.10·ln(0.10/0.10)
            = -0.0347 -0.0347 + 0.1068 + 0
            ≈ 0.0375

KL(μ_2‖α_2) = 0.05·ln(0.05/0.05) + 0.05·ln(0.05/0.10)
            + 0.10·ln(0.10/0.15) + 0.80·ln(0.80/0.70)
            = 0 -0.0347 -0.0405 + 0.1068
            ≈ 0.0316
```

**④ 歸一化的運動損失**：

```
L_motion = (1 / (H · log N_v)) · (0.0375 + 0.0316)
         = (1 / (2 · ln 4)) · 0.0691
         = 0.0691 / 2.7726
         ≈ 0.0249
```

**⑤ HRC 差分行進**（把交互表徵降維成 2 維示意）：

```
m_1 = [0.50, 0.10]
m_2 = [0.60, 0.40]
Δm_2 = m_2 - m_1 = [0.10, 0.30]      # 第 2 維變化更大 → 該步運動幅度更大
```

若門控 `g = 0.3`、交叉注意力給出 `ΔA_2 = [0.2, 0.5]`，則：

```
A'_2 = A_2 - 0.3 ⊙ [0.2, 0.5] = A_2 - [0.06, 0.15]
```

即第 2 步的動作 token 被「往下、往右」微調了 0.06 / 0.15——**修正量隨該步運動差分的大小而變**，且被本體感覺門控縮放。這就是一個可計算的閉環：遮罩 → 注意力 → 差分 → 動作修正。

## 4. 工程視角 (Engineering View)

| 面向 | 數值 / 事實 | 工程含義 |
|------|-------------|----------|
| 動作塊長度 | H=4（每次輸出 4 步） | horizon query 數峰值也剛好是 4，一一對應；H 變大時 query 需同步增長（見 §6 假設） |
| 視覺 token | N_v=256（16×16） | AIMG 注意力矩陣 H×N_v = 4×256；遮罩必須對齊到同一 16×16 網格，否則 KL 監督失效 |
| DiT 去噪 | 訓練 100 擴散步 / 推理 10 步 | 推理延遲主要來自 DiT 去噪 + VLM 前向 |
| 重規劃 | 每執行 2 步重規劃一次 | 高頻重規劃放大了推理成本，故「不重建未來幀」的省算力很關鍵 |
| 推理額外開銷 | 移除遮罩渲染 / KL 分支，僅保留 AIMG+HRC 兩個輕量模組 | 相比 DreamVLA 類「預測未來幀」的方案，推理不做圖像解碼，模組邊界乾淨 |
| 訓練成本 | 2× A40 48GB，FSDP 全分片 + 梯度檢查點，20k 步，全局 batch 16，lr 1e-5 | 2B VLM 全參數微調；單機可復現但需注意 FSDP 顯存 |
| 前置依賴 | RoboEngine 離線生成手臂遮罩（128×128 → 下採樣 16×16） | **訓練資料管線多一環**：需先跑分割模型產生 mask cache，推理時不需 |

**模組邊界**：AIMG/HRC 插在 VLM 動作 token 與 Action DiT 之間，屬於「動作頭前置」的改動，不改 VLM 主幹結構，理論上可移植到其它 VLM+DiT 的 VLA 骨幹。**部署約束**：遮罩工具鏈（RoboEngine）只提供仿真/視頻分割接口，真機資料能否低成本產生手臂遮罩是落地前提。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 在仿真機械臂操作（抓取/裝配/長程放置）上，用「運動接地」替代「未來幀重建」，取得超過 π0 與多個世界模型基線的成功率。
- 提升**持續交互**類任務的成功率（Disassemble、Shelf Place 增益最大）。
- 推理時不做未來重建，只輸出動作塊——架構上省掉圖像解碼。

**不能做 / 未驗證**：
- **只在 MetaWorld 仿真、單臂、單視角 224×224 上驗證**：無真機實驗，作者在結論中明確把真機泛化列為 future work。
- **無觸覺 / 無力反饋**：只有 RGB + 本體感覺，接觸豐富任務未覆蓋。
- **非雙臂 / 非人形 / 非移動平台**：模型與評測均為單臂桌面操作。
- **目標位移短時可能倒退**：Pick Place 上輸給 π0，說明運動中心監督在「全局特徵已足夠」的場景未必有增益。
- **未測分佈外任務 / 新硬體**：作者自陳「unseen tasks and hardware platforms」待驗證。

### 6.1 隱含假設 (Hidden Assumptions)

| 假設 | 為何可能不成立 |
|------|----------------|
| **「機器人手臂區域」≈「感興趣的運動」** | 遮罩只覆蓋機械臂，被手臂推動/帶動的**物件運動**未被顯式監督。對「移動物件」為主的任務，監督信號可能不完整 |
| 未來手臂遮罩可離線、低成本獲得 | 依賴 RoboEngine 渲染仿真遮罩；真機資料需換成視頻分割工具，成本與可靠性未驗證 |
| horizon query 數應等於動作塊長度 H | 峰值在 4、與 H=4 對齊；加大 H 時 query 數與顯存/冗餘的權衡未知 |
| 16×16 視覺網格能穩定承載運動定位 | 遮罩、注意力、VLM 三者必須嚴格對齊同一網格，網格變動會破壞 KL 監督 |
| MetaWorld 成功率能外推到真機 | 仿真無噪聲、無執行抖動、無視角/外觀漂移；結論中的真機泛化仍待驗證 |
| 「整體未來觀測演化」是浪費容量 | 論文未提供「物件運動被忽略」對比實驗，屬推斷性論證 |

## 7. 與相關工作對比 (Comparison)

| 方法 | 關注點 | 動態監督形式 | 推理是否重建未來 | 適用場景 |
|------|--------|--------------|------------------|----------|
| **π0** | 直接從全局特徵回歸動作 | 無（僅稀疏動作監督） | 否 | 通用真機（flow model） |
| **WorldVLA** | 自回歸動作-世界模型 | 顯式重建未來幀 | 是（重） | 需要世界模型的生成式控制 |
| **DreamVLA** | 綜合世界知識「夢」出未來 | 顯式稠密想像未來場景 | 是（重） | 長程、需想像的任務 |
| **WoG** | 條件空間中的世界建模 | 隱式引導 | 部分 | 動作生成引導 |
| **Fast-WAM** | 測試時免想像的世界-動作模型 | 免測試時想像 | 否 | 高效 WAM |
| **MotionWeave（本文）** | **逐時間步的局部運動定位** | **手臂遮罩 KL 監督注意力 + 相鄰差分** | **否（僅訓練用未來幀）** | 仿真單臂操作；持續交互任務 |

**面試 Tip**：被問到「世界模型對 VLA 到底有沒有用、該怎麼監督」時，一句話答：**「關鍵不是要不要想像未來，而是要不要把監督信號投影到『與控制相關的運動』上——MotionWeave 的證據是：把監督從重建未來幀換成逐 horizon 的手臂區域遮罩，在 MetaWorld 上把平均成功率從 66.7% 拉到 75.3%（+8.6），且推理不重建未來。」** 補一句局限：只在仿真、單臂、6 任務驗證，真機與物件運動監督仍是空白。

## 8. 精讀建議 (Reading Guide)

**值得精讀原文的人**：
- 正在做 **VLA + 世界模型 / 動作塊生成**的研究者——想找「動態監督怎麼設計才不浪費容量」的具體做法。
- 需要評估「把世界模型監督換成運動接地」能否遷移到自有資料/平台的工程師——重點看遮罩資料管線（RoboEngine）與 AIMG/HRC 的模組邊界。
- 研究注意力監督 / 可解釋定位的人——AIMG 的 KL 遮罩監督是一個乾淨的「用未來資訊塑造當前注意力」範式。

- 先讀 §2.2 AIMG + §2.4 訓練目標（公式 2-4、9-10，抓住核心）。
