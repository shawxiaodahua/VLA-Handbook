## 1. 核心架構/方法總覽 (Overview / Architecture)

PhysicsLENS 不是一個生成模型，而是一個**數據集 + 基準 + 自動診斷管線**。它要驗證的核心假說：模型可能只靠視覺先驗生成合理動作，而沒有真正把文本裡的物理屬性「落地」——作者稱之為 **physical property blindness（物理屬性盲區）**。

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 頻率/時序 | 訓練/推理差異 |
|------|------|------|-----------|----------------|
| 場景構建 | 11 個公開機器人數據集的起始幀 + 日誌任務 | 結構化場景/動作描述 | 離線一次性 | GPT-4o 起草 + 作者審核 |

| Reporting | 合併證據 | 每段視頻輸出時間窗、物件、違規型別、置信度、簡短解釋 |

### 1.2 關鍵機制 (Key Mechanism)

- **匹配對（matched pairs）是整個設計的心臟**：同一初始幀、同一任務指令，只把「場景描述」從「與幀一致」換成「與幀衝突的隱藏屬性」。這樣一來，唯一的自變量就是文本屬性——干擾變量（視覺場景、任務、幀質量）被固定住。
- **可觀測 / 不可觀測二分**：可觀測條件下 prompt 與幀暗示的物理一致（模型靠視覺先驗就能做對）；不可觀測條件下 prompt 陳述一個幀裡看不出來的屬性（如「普通茶壺裡的液體像糖漿一樣黏稠」）。模型若只看外觀，就會倒出水一樣的流體。
- **兩條評估軌道**：人類軌道（P/A/H 三軸 + 違規標籤）與自動軌道（4 階段管線）。自動軌道刻意把「運動測量」與「針對性 VLM 提問」配對，因為單獨的 VLM 額判不可靠。
- **P 與 H 必須分開報告**：作者強調二者會互相背離（見 §6），因此不合成單一分數。

⚡ **Eureka Moment**：物理世界模型的「像樣」和「聽話」是兩個正交的問題——一段視頻可以 P 高 H 低（看起來對但忽略屬性），也可以 H 高 P 低（體現了屬性卻穿模）；基準必須把這兩個軸拆開來測。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
Grounded ⟺ (P ≥ 3) ∧ (H ≥ 3)     # 合理且落地，兩軸都要過
```

先給目標，再給公式，再給變量說明，最後給直覺。

**目標**：量化「生成模型是否真的服從文本指定的（隱藏）物理屬性」，並與「單純看起來合理」區分開。

**① 物理屬性盲區率（Property Blindness Rate）**：

```
Blindness = |{ P ≥ 3 ∧ H ≤ 2 }| / |{ P ≥ 3 }|
          = 34 / 47 ≈ 72.3%          # 不可觀測視頻中，被判 plausible 卻沒落地屬性的比例
```

**② 匹配對差異（Matched-pair Delta）**：同幀同任務，只換屬性描述。

```
Δ_i = P_unobs,i − P_obs,i          # 第 i 個場景的合理性變化（unobservable 減 observable）
Δ̄   = mean_i Δ_i ≈ −0.28 點         # 29 個場景池化；p = 0.085，方向一致但不顯著
```

**③ 排序一致性（AUC，自動評估器用）**：

```
AUC = P( score(正例) > score(負例) )   # 0.5 = 隨機猜, 1.0 = 完美排序
```

| 符號 | 含義 |
|------|------|
| P | physical plausibility，可見物理合理性，∈{1,2,3,4}，P≥3 記為 mostly/fully plausible |
| A | task completion，任務是否完成，∈{0,1} |
| H | hidden-property adherence，是否體現所述隱藏屬性，∈{1,2,3,4}，H≥3 記為 mostly/fully following |
| Δ̄ | 池化匹配對合理性差；負值表示「說出隱藏屬性」使合理性略降 |
| AUC | 自動分數與人類判斷的排序一致度 |

> 符號與本文/相關文檔保持一致：P/A/H 沿用論文 §3.3 定義；Δ、AUC 沿用論文 §4.2、§4.4。

**直覺**：如果模型真的「懂」物理，把屬性寫進 prompt 應該讓它的輸出更正確、因此更合理；但實驗顯示「說出來」只讓合理性掉 0.28 點且不顯著——意味著模型根本沒在聽 prompt 裡的屬性，只是在畫它視覺上認得的畫面。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

場景：**糖漿茶壺**（論文 Figure 2 / Figure 6a 的典型例子）。

- 起始幀：一個普通茶壺，液體外觀像水。
- observable prompt：「把壺裡的茶倒進杯子。」
- unobservable prompt：「把壺裡像糖漿一樣黏稠的茶倒進杯子。」

四個生成模型各出一段，人類標註（假設值，用於演示計算閉環）：

```
模型          P   H   是否 plausible(P≥3)   是否落地(H≥3)
Wan 2.2       4   1   ✓                    ✗   ← 倒得像水，但畫面最好看
Cosmos 3 Nano 3   1   ✓                    ✗
Hunyuan 1.5   3   2   ✓                    ✗
MAGI 4.5B     3   1   ✓                    ✗
```

- 這段場景貢獻：plausible 計數 +4，其中未落地 +4 → 全部「盲區」。
- 若與 observable 版同場景比較（假設 observable 平均 P̄_obs = 3.75，unobservable 平均 P̄_unobs = 3.5）：
  ```
  Δ = 3.5 − 3.75 = −0.25 點     # 說出「黏稠」只讓合理性微微下降
  ```
- 把 29 個場景的 Δ 池化：40 個場景下降、26 個上升，平均 −0.28 點，p=0.085。

再算全局盲區率（論文報告的實數）：

```
plausible 的不可觀測視頻:        47 段
其中未落地屬性(H≤2):             34 段
Blindness = 34 / 47              ≈ 72.3%
（去掉 MAGI: 13 / 26 = 50%）
```

反向也成立：28 段落地屬性（H≥3）的視頻裡有 15 段反而**不合理**（P≤2）——體現了屬性卻違反別的物理（例如矽膠疏水桌面上，玻璃杯沒被接觸卻移動了）。

## 5. 數據與評測 (Data & Eval)

- **規模**：110 個 prompt（80 可觀測 + 30 匹配的不可觀測變體）；439 段生成視頻 = 320 observable + 119 unobservable；>400 條人類標註。
- **來源**：80 個起始幀取自 11 個公開機器人數據集，覆蓋人形、雙臂、單臂、移動機械臂。每幀顯示機器人與固體物件/液體交互前的場景。
- **不可觀測屬性（30 個場景，4 類任務相關屬性）**：

| 屬性 | 任務 | 場景數 |
|------|------|--------|
| 黏度 viscosity | 傾倒 pouring | 10 |
| 表面條件 surface condition | 擦拭 wiping | 8 |
| 彈性 elasticity | 可變形物件 | 7 |
| 質量 mass | 推動 pushing | 5 |

- **生成模型**：Wan 2.2、Cosmos 3 Nano、HunyuanVideo 1.5、MAGI 4.5B Distill，跨擴散、自回歸、world/action foundation 三類範式。Hunyuan 有 1 個 prompt 沒生成可用視頻，故貢獻 109 段（含 29 不可觀測），其餘各 110 段。
- **標註**：P∈{1,2,3,4}、A∈{0,1}、H∈{1,2,3,4}（H 僅對不可觀測評）；P<4 時須描述違規並從 8 類標籤中勾選（7 個物理域 + contact，分析時 contact 併入 collision）。
- **評測**：自動評估器用 10 個 open-weight VLM（7 個家族）+ Stage1/2 信號，報告 AUC。完整評估器：plausibility 0.72、task completion 0.81、violation detection 0.73、hidden-property adherence 0.71。

> ⚠️ 統計功效提示：每 prompt–模型只生成 1 段，無法估計種子方差；作者明確說結果「characterize these generated clips」而非跨種子泛化。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 分離「物理合理性」與「屬性落地」，並用匹配對把屬性作為唯一自變量。
- 用運動測量 + 針對性 VLM 提問提升與人類判斷的一致性（比單純問「這視頻合理嗎」好得多：Qwen3-VL-32B 在可觀測上 0.55→0.75）。
- 局部化違規並給出證據（時間窗、物件、違規型別、置信度）。

**不能做 / 失敗模式**：
- **屬性落地判斷不可靠**：最佳單 VLM 的 adherence AUC 僅 0.57；即便加信号也只到 0.70，接近 signals-only（0.69）與 generator identity（0.68）——「是否服從某個具體隱藏屬性」仍是未解問題。
- **違規歸因很弱**：不同違規家族間的 attribution AUC 多在 0.53–0.58（流體例外 0.82）；66% 有違規的視頻含多種類型，讓「歸為單一家族」格外困難。
- **流體族反而被信號拉低**：加 signals 對 momentum 無提升、對 fluid 甚至下降。
- **合理的假陽性陷阱**：幾乎靜止的視頻會被判為 plausible（MAGI 機械臂常近乎不動），因為「沒動就沒穿模」。
- **「完成任務」與「物理正確」分離**：A 可以為 1 而 P 很低；反之亦然。

### 6.1 隱含假設 (Hidden Assumptions)

- **每 prompt 單次生成**：假設單次樣本足以代表該模型行為——但生成噪聲可能主導差異，作者自己也承認需靠聚合分析匹配對。
- **「可觀測」的定義**：假設初始幀確實能決定可見物理屬性；若某屬性其實可從細節推斷，二分就不乾淨。
- **屬性集合有限**：只測黏度、表面、彈性、質量四類（30 個不可觀測場景），對「因果性 causality」等域的不可觀測測試缺失。
- **描述由 GPT-4o 起草**：場景/動作描述用 GPT-4o 生成再由作者審核——假設 GPT-4o 的措辭不會系統性引入對某些屬性的偏置。
- **人類標註一致性未充分報告**：8 類違規標籤的可選項與標註者分配在附錄，主文未給標註者間一致性指標。
- **VLM 判據近隨機**：作者自己指出多數 VLM 在直覺物理測試上接近隨機——即「加 VLM」的收益很大程度來自信號而非推理。

🎤 **面試 Tip**：被問到「怎麼評一個機器人視頻世界模型好不好」時，答：**物理合理性和屬性落地是兩個正交軸**——同一段視頻可以 P 高 H 低（好看但忽略指令）或 H 高 P 低（聽話但穿模）；正確做法是用「同幀同任務、只換屬性描述」的匹配對把兩者分開測。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 正在做**機器人視頻世界模型 / 生成式模擬器**、想用它做 RL 或規劃的研究者（可靠性評估直接相關）；
  2. 想復用「匹配對」評測範式到其他模態（如動作、觸覺）的評估方法論工程師；
  3. 做 **VLM-as-judge** 的人——§4.4 對「為什麼要測量+提問」有直接的經驗證據。
- **建議章節路徑**：先讀 §1 + §3.1（理解可觀測/不可觀測與匹配對）→ 再看 §4.1–4.2（核心發現與數字）→ 工程落地看 §3.4 管線 → 可跳 §2 相關工作（除非要寫 related work）與附錄標註細節。
- **不值得精讀的理由**：如果你只關心生成畫質指標、或你的 pipeline 不用生成視頻當環境、或已熟悉 VideoPhy/WorldModelBench 系列，讀摘要 + §4.1 的那個 34/47 就夠了。
