### 1.2 关键机制 (Key Mechanism)

- **为什么用 VAE 潜空间而非直接 54 维？** 灵巧手动作空间"高维但强结构"——手指构型受生物姿态协同约束，真正有效的变化维度远低于 20。VAE 从协调整体运动中学到的 9 维潜空间，正好是"协调的手部动作流形"。
- **为什么在潜空间做残差 RL？** 原始 40 维关节空间的探索是"逐关节乱动"，样本效率极低；潜空间残差把探索限制在**协调动作**上（实验证明这是 raw-space 残差失败的关键）。
- **为什么 DAgger 接管前要回滚？** 接管瞬间人手势 ≠ 机器手当前姿态，直接切换会产生命令跳变，且最初那段"手势对齐"动作会被误当成"错误恢复"数据污染监督。作者把"姿态同步"与"任务恢复"彻底分离。

⚡ **Eureka Moment**：**把"手部动作的潜表示"做成三阶段共享的同一个接口**——同一个冻结的 codec 既给 SFT 提供监督目标、又给 DAgger 提供编解码、还给 residual RL 提供低维探索空间。zero residual 精确恢复参考策略，让 RL 成为"可回退的增量"而非"重写"。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
z = π_sft(o) + Δz     ⇒     q_cmd = q + D(z; q)
π_ref 与 D 冻结；Δz = 0 时精确恢复参考策略 —— RL 只是"可回退的修正项"
```

### 2.1 Step 1 — Codec 损失（加权时序 Huber + KL）

```
L_codec = Σ_{k=0}^{2} λ_k · L_WH^(k)  +  β_KL · KL( N(μ,σ²) ‖ N(0,I) )
λ = (λ0, λ1, λ2) = (1, 0.2, 0.05)
```

其中 `Δ^k` 是 k 阶时间差分：`Δ^1x_t = x_{t+1} - x_t`，`Δ^2x_t = x_{t+2} - 2x_{t+1} + x_t`；
误差 `e^(k)_{t,j} = (Δ^k â_hand)_{t,j} - (Δ^k a_hand)_{t,j}`（在标准化后的相对动作空间计算）。
`L_WH^(k)` 是逐关节加权 Huber 惩罚：

```
ℓ_τ(e) = (1/2)e²            , |e| ≤ τ_Huber
       = τ·(|e| - (1/2)τ)   , |e| > τ_Huber     (τ_Huber = 1)
```

| 变量 | 含义 |
|------|------|
| `a_hand ∈ R^{H×20}` | 相对块起点的手部动作（`q^hand,cmd − q0^hand`） |
| `λ_k` | k 阶时间差分的权重：k=0 保位置，k=1,2 保帧间运动及其变化 |
| `w_j` | 关节权重：拇指/食指/中指 = 1，无名指/小指 = 0.5 |
| `β_KL` | KL 权重；前 4000 步为 0，再用 4000 步线性升到 3e-4 |

**直觉**：Huber 的二次支对典型重建误差敏感，线性支防止异质语料里偶发大偏差主导更新；KL 项固定潜尺度并防止后验方差塌缩——这对 Step 4 加入潜扰动很重要。

### 2.2 Step 2 — SFT 损失（潜空间流匹配 + 解码动作监督）

```
L_sft = E[ λ_arm·‖(v_ω − u)^arm‖² + λ_lat·‖(v_ω − u)^hand‖² ]
      + λ_dec·E‖ â_hand − a_hand ‖²
λ_arm = 1.0,  λ_lat = 0.25,  λ_dec = 0.75
```

- 流匹配：`x_{t_flow} = t_flow·ε + (1−t_flow)·z`（`ε~N(0,I)`），目标向量场 `u = ε − z`，一步干净估计 `ẑ = x_{t_flow} − t_flow·v_ω`。
- 因为手部 decoder 非线性，**潜空间等大误差可能对应不同关节空间误差**，所以额外加 `λ_dec` 项，梯度穿过冻结的手部 decoder 回传。

### 2.3 Step 3 — DAgger 接管平滑（命令混合）

```
q^hand,cmd_t = (1 − α_s)·q_hold + α_s·q^teleop_t
α_s = min{ s / τ_b , 1 },   τ_b = 2 s
```

`q_hold` = 接管前最后发出的手命令，`q^teleop_t` = 操作员实时命令，`s` = 混合已耗时。`α_s = 0` 起始、`α_s = 1` 完成。记录的是**操作员实时命令**（不是发给机器人的混合命令）。

### 2.4 Step 4 — Latent Residual RL

```
c_{i,d} = b_d^c · tanh([f_θ(h_rl, q, z_ref)]_{i,d})   , 1 ≤ i ≤ C ;  0 for i > C
Δz_{i,d} = Σ_{j=1}^{i} c_{j,d}   (arm 维度, 累积)
         = c_{i,d}               (hand latent 维度, 逐帧直接)
z = z_ref + ( m_task ⊙ Δz )
q_cmd = q + D(z; q)          (q broadcast 到 H 帧)
```

TD3 clipped double-Q 目标（chunk 级时序，每步跨 C=25 帧）：

```
y_t = r_t + (1 − d_t)·γ^C · min_{i∈{1,2}} Q_{φ̄_i}( h_rl', q', z_ref' + Δz' )
```

Actor 损失：

```
− β_q · Q_{φ1}(h_rl, q, z_ref+Δz)
+ β_{Δz} · R_{Δz}(Δz)                       ← 残差幅度正则
+ β_s · S(z_ref + Δz)                       ← 时序平滑正则

R_{Δz}(Δz) = ‖Δz‖_F² = Σ_i Σ_d (Δz_{i,d})²
S(z) = 1/(H−2) · Σ_i ‖ z_{i+2} − 2·z_{i+1} + z_i ‖²
```

| 变量 | 含义 |
|------|------|
| `h_rl ∈ R^2048` | 冻结 backbone 前缀读出的 RL-token 观测表示 |
| `b_d^c` | 每帧修正上限：arm 维度用 `b_arm^c`，hand latent 维度用 `b_hand^c` |
| `m_task ∈ {0,1}^32` | 任务特定的残差掩码（broadcast 到 H 帧） |
| actor 输出层 tanh head **零初始化** | 训练起点 `Δz = 0`，保证不破坏参考策略 |
| 奖励 | `r_T = −1`（失败终点）/ `0`（成功及其它），只给每回合终止 chunk |

> 符号与本文一致：`q ∈ R^54` 是块起始关节状态，`C=25` 是每个策略查询后执行的帧数。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

**A. DAgger 接管混合（连续性的可算闭环）**

设接管前机器人手张开命令 `q_hold = [0.0]²⁰`，操作员实时握拳命令 `q_teleop = [1.0]²⁰`，`τ_b = 2 s`，控制频率 30 Hz ⇒ 混合跨 `2×30 = 60` 帧。

```
帧 1  : α = 1/60 ≈ 0.017 → q_cmd ≈ 0.017
帧 30 : α = 30/60 = 0.5  → q_cmd = 0.500
帧 60 : α = 1.0          → q_cmd = 1.000   (混合完成)
```

命令从 0 平滑过渡到 1.0，**无阶跃**。对照速率上限：`q̇_max = π/18 ≈ 0.1745 rad/帧`（30 Hz ⇒ ≈ 5.24 rad/s）。每帧增量 1.0/60 ≈ 0.0167 rad，远低于 0.1745，说明 2 s 混合天然安全。而若直接切换（Δ=1.0 rad 单帧），会**超速率上限 5.7 倍**并被限幅截断——这正是要平滑的原因。

**B. 潜残差探索的维度缩减**

手臂维度（14 维）残差是**累积增量** `Δz_{i,d} = Σ_{j=1}^{i} c_{j,d}`（保证连续性）；手部潜维度（18 维）是**逐帧直接** `Δz_{i,d} = c_{i,d}`。整个在线 RL 只需在这 32 维潜空间搜索，而非原始 54 维关节空间——论文报告 raw-space 残差在 3000 次 transition 内只到 80%/50%，而潜残差到 100%/100%。

**C. 参数量账本（为什么说 RL 便宜）**

```
全部模块:        4.18 B
推理部署:        3.76 B  (VLA + 手解码器 + RL-token 编码器 + actor)
在线 RL 可训:    3.23 M  = 0.08%   (ChunkActor 1.21M + 双 critic 2.02M)
SFT/DAgger 微调: 3.35 B  (12 h / run, 8×H20)
```

## 4. 工程視角 (Engineering View)

| 维度 | 数值 / 含义 |
|------|-------------|
| 控制频率 | 30 Hz，关节位置控制；记录 3 路相机 + 关节命令/状态均 30 Hz |
| Chunk 结构 | 预测视野 `H = 32`；每 chunk 只执行前 `C = 25` 帧（≈ 0.83 s），再取新观测（同步推理解码） |

**工程含义**：整套设计的重心在"边界"——动作空间边界（潜空间）、接管边界（平滑混合）、安全边界（三重限幅）。真正上真机跑 RL 的训练量被压到极小，这是它能落地的前提。

## 5. 數據與評測 (Data & Eval)

**Codec 训练语料**（三源）：
1. 内部遥操作语料 ≈ **3800 万帧/手**（同族机器人，多任务）；
2. VITRA-1M 人体手轨迹（第一视角视频重建并 retarget 到 20-DoF 手）；
3. 任务示范集（每任务 200 回合）——**仅用初始 200 条，排除后续 DAgger/RL 数据**。

**五个真机任务**（同一支马克笔，由易到难）：

| 任务 | 成功判据 | 达到 100% 的路径 |
|------|----------|------------------|
| Pick Up Marker | 完全提起并稳定抓握 | SFT → DAgger |
| Remove Marker Cap | 左手续分离笔帽且不掉落 | SFT → DAgger |
| Write on Paper | 写出完整单词 "WUJI" 且保持笔尖接触 | SFT → DAgger |
| Transfer Marker between Hands | 右手→左手稳定抓握并卡在右食指/中指间 | SFT → DAgger → **latent residual RL** |
| Rotate Marker in Hand | 手中旋转不掉落，笔尖朝下结束 | SFT → **latent residual RL**（无法接管，物理状态不可回滚） |

**关键数字**：
- 每任务示范起点 200 条；SFT 微调 30k 步；DAgger 每轮 50 条修正，`α_new = 0.5`。
- Transfer：10% → **65%**（第 1 轮 50 条修正）→ **70%**（第 2 轮）→ **100%**（RL）。
- Rotate：**50%**（SFT）→ **100%**（RL，100 回合内达成）。
- 真机 RL 收敛：Rotate 100 回合 / Transfer 150 回合达到 100%；raw-space 残差 3000 transitions 后仅 80% / 50%。
- 算子工时：Transfer **9.7 人·时**、Rotate **5.2 人·时** 得到 100% 策略；同预算下无-RL 基线仅 ≈75%（SFT+DAgger）与 ≈55%（SFT）。RL 每 100 rollout 回合约 **1.2 人·时**。
- 评测设置：每任务 20 次试验，人工复位，光照近似恒定，初始位姿在采集分布内变动。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做什么**
- 把开源 π0.5 高效适配到**双臂 + 20-DoF 手**的具体下游技能，5 个原子任务全部 20/20。
- 潜残差 RL 产生**参考策略从未出现过的纠错行为**：重新抓握（regrasping）、维持接触、从早期错误中恢复。
- 在随机初始位姿 + 外扰下展现了超出名义评测条件的鲁棒性（作者称"疑似"来自学到的纠错响应，而非偶然扰动）。

**不能做什么 / 失败模式**
- **强依赖基线能力**：参考策略成功率 < ≈20% 时残差 RL 几乎无效；> ≈50% 才稳定有用。作者明确指出 50% 是否普适尚未验证。
- **只覆盖原子任务（≈30 s 内）**，不做长程技能组合、不做场景级泛化（光照/物体/初始分布仅局部变化）。
- **单平台**：实验仅在天机 7-DoF 臂 + 无極 20-DoF 手 + 3 相机上验证，未跨本体验证。
- **接管依赖**：Rotate 因物理状态无法回滚，禁用 DAgger，只能退回 SFT + RL。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设 20-DoF 手存在低维姿态协同**，且 9 维足以保留任务相关运动——作者用重建误差 + "9 维不损失模仿性能"间接支持，但未直接验证"9 维对 RL 最优"。
- **假设 32-D 接口足够**：9-D/手 是按 π0.5 的 32-D 上限倒推（14 臂 + 18 手），作者承认没把"接口约束"与"潜在维度对 RL 的影响"解耦。
- **假设成功判据可由操作员客观核验**（每任务自定义 success criterion，人工判定）。
- **假设遥操作語料与目标平台同族**，未验证跨厂商硬件迁移。

## 7. 與相關工作對比 (Comparison)

| 方法 | 关注点 | 动作空间 | 学习方式 | 适用场景 |
|------|--------|----------|----------|----------|
| **本文** | 高 DoF 手后训练全流程 | 手部 **VAE 潜空间**（共享接口） | SFT + DAgger + latent residual TD3 | 真机灵巧原子任务 |
| HandITL (Li et al. 2026b) | 接管跳变 | 相对手 retargeting + 共享臂控制 | 人在环干预 | 灵巧 VLA 修正 |
| DexHiL (Han et al. 2026) | 人在环框架 | 集成遥操作接口 | 干预感知采样 | 灵巧 VLA 后训练 |
| RL Token (Xu et al. 2026) | 在线 RL 起跳 | 冻结 VLA + 小 actor-critic | 在线 actor-critic | 通用 VLA 在线 RL |
| BORA (Chen et al. 2026) | 离线+在线残差 | 动作残差 | 离线 critic + 在线残差 | 真机灵巧 VLA |
| π0.6* / RECAP (Amin et al. 2025) | 经验驱动策略改进 | advantage-conditioned | 离线 RL | 通用 VLA |
| DSRL (Wagenmaker et al. 2025) | 冻结扩散策略 | **噪声潜空间**转向 | 潜空间 RL | 扩散/流策略 |
| ZPRL (Yu et al. 2026) | 观测侧瓶颈 | 信息瓶颈扰动 | 潜空间 RL | 冻结动作生成器 |

**与 HandITL 的关键差异**：本文**保留绝对手命令接口**（让示范、修正、策略输出共享同一动作语义），代价是接管时会产生跳变——于是用回滚+对齐+2s 混合来"修"接口，而非像 HandITL 那样改用相对 retargeting 来"绕"接口。

> **面试 Tip**：被问到"为什么残差 RL 要在潜空间而不是关节空间做"，一句话答案——**潜空间由记录的协调运动学得，把在线探索限制在'整只手协调动作'的流形上，消掉大量无结构的逐关节自由度**；实验里这正是 raw-space 残差失败而 latent 残差成功的核心（Transfer 70%→100% vs 70%→80%）。
