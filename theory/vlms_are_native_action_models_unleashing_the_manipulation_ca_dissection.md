## 1. 核心架构/方法总览 (Overview / Architecture)

EASG 把「模块化基础模型操作」与「端到端 VLA」两种范式的优点缝在一起：前者能零样本但依赖外部规划器、不可端到端训练；后者可端到端训练但动作接口必须由机器人数据从头学。EASG 的想法是——**保留 VLM 的原生输出接口（文本），只把动作空间的语义显式喂给 VLM**。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理差异 |
|------|------|------|----------------|
| 动作空间接地 G_t | 当前机器人状态、相机标定、腕部 RGB-D | 投影后的动作坐标系可视化 + 度量深度 M_t + 语言语义 P_t | 推理期确定性计算，无需训练 |
| VLM 策略（原生解码） | 观测 I_t + 语言指令 l + G_t | 文本动作串 y_t | 零样本直接用预训练权重；微调时用标准自回归交叉熵 |
| 语法约束解码 (GCD) | VLM 每步 logits | 合法动作格式的 token | 推理期掩码，不改变词表与生成过程 |
| 几何/运动学执行 | Δp^A, Δω^A, g_t | 目标位姿 T_t^{B,*} → 关节命令 q*_t | 确定性（外参变换 + IK），与模型解耦 |

关键在于：**VLM 只负责「在该动作帧下，往哪个方向、走多远、转多少」**，机器人相关的坐标变换与逆运动学全部交给确定性几何模块处理。动作空间与「本体」解耦，因此天然可跨本体。

### 1.2 关键机制 (Key Mechanism)

- **接地三要素 G_t = (V_t, M_t, P_t)**：
  - V_t：把 TCP 中心动作帧的原点与三根轴投影到腕部相机图像（π(K·...)），让 VLM「看见」坐标系；
  - M_t：用对齐深度估计沿动作帧 z 轴到最近可见表面的距离，提供**度量尺度**，避免 VLM 从纯 RGB 猜物理距离；
  - P_t：用自然语言写清动作参数化、单位与输出格式。
- **原生文本动作**：不新增动作 token、不训练动作头。动作被序列化成 `state | v_x,v_y,v_z,d | r_x,r_y,r_z,θ | gripper`，每个标量带显式正负号、保留两位小数。翻译与旋转用「单位方向 + 长度/角度」分解，方向向量执行前做单位球投影。
- **同一接口零样本 + 微调**：同一字符串格式既用于零样本执行，也用于机器人轨迹的标准 CE 微调。微调不会改变接口，只是让模型在这个接口上更准。

⚡ **Eureka Moment**：THE 关键洞见是——**动作接口的正确性比动作模块的容量更重要**。把连续动作空间的语义直接「画」进 VLM 的可视上下文、用其原生文本接口输出，就能解锁预训练里早已存在的空间推理能力，而无需机器人数据从头教它「动作是什么」。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
G_t = (V_t, M_t, P_t)        # 把动作空间的「原点/朝向/尺度/语义」显式摆到 VLM 面前
```

先给**目标**：让预训练 VLM 在自身感知上下文里，直接生成可执行的连续机器人动作，无需动作预训练。再给**公式**（全部用代码块，避免 LaTeX）：

```
接地定义:
    G_t = (V_t, M_t, P_t)
    V_t : 动作帧原点与三轴在腕部相机图像的投影
    M_t : 沿动作帧 z 轴到最近可见表面的度量距离
    P_t : 动作参数化与输出格式的语言描述

动作定义（均在接地动作帧 F_At 下表达）:
    a_t = (Δp^A_t, Δω^A_t, g_t, s_t)
    Δp^A_t ∈ R^3 (增量平移),  Δω^A_t ∈ R^3 (轴-角增量旋转)
    g_t (夹爪命令),  s_t (任务完成标志)

坐标变换到基座系:
    Δp^B_t = R_At^B · Δp^A_t
    Δω^B_t = R_At^B · Δω^A_t
    p_t^{B,*} = p_t^B + Δp^B_t
    R_t^{B,*} = Exp([Δω^B_t]_×) · R_t^B
    q*_t = IK(T_t^{B,*}; q_t)

文本动作参数化:
    Δp^A_t = d_t · v^A_t,   ‖v^A_t‖_2 = 1,  d_t 单位 cm
    Δω^A_t = θ_t · r^A_t,   ‖r^A_t‖_2 = 1,  θ_t 单位度

微调损失（与语言建模同构）:
    L_CE = -Σ_{k=1}^{N} log p_θ(y*_k | y*_{<k}, I, G, l)

语法约束解码:
    z̃_k(v) = z_k(v)  若 v ∈ V_G(y_<k)
    z̃_k(v) = -inf      否则
    生成从 softmax(z̃_k) 逐步自回归
```

**变量说明**：

| 符号 | 含义 | 备注 |
|------|------|------|
| F_At | 第 t 步的接地动作帧 | 原点锚定当前 TCP，轴向定义 VLM 表达平移/旋转的方向 |
| d_t | 平移长度（cm） | 由 VLM 生成，非负 |
| v^A_t | 平移单位方向 | 生成后投影到单位球满足约束 |
| θ_t, r^A_t | 旋转角（度）与单位轴 | 同上 |
| V_G(y_<k) | 前缀 y_<k 后合法的 token 集合 | 由确定性动作语法定义 |
| Exp, [·]_× | 指数映射 / 反对称矩阵 | 把轴-角转为旋转矩阵 |

**直觉**：这套设计的数学核心其实只有一句话——**把「VLM 已具备的空间推理」与「机器人真实动作空间」之间的语义鸿沟，用一组显式的几何+语言接地填平**。平移用「方向×长度」、旋转用「轴×角」分解，是为了让每个数字都落在 VLM 预训练见过的、有物理直觉的区间里（单位向量 + 厘米 + 度），并且每个标量都能用原生词表里的普通 token 表示。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以论文给出的真实输出串为例，走一遍「抓黄瓜」的一步：

```
y_t = 0 | +0.40, -0.10, +0.91, +6.00 | +0.00, +0.00, +1.00, -45.00 | +1.00
```

拆解闭环：

1. **解析字段**：`state=0`（未完成）｜平移 `(v_x,v_y,v_z,d) = (0.40,-0.10,0.91, 6.00cm)`｜旋转 `(r_x,r_y,r_z,θ) = (0,0,1, -45.00°)`｜夹爪 `gripper=+1.00`（张开）。
2. **单位化方向**：‖v‖₂ = √(0.40² + 0.10² + 0.91²) = √(0.16+0.01+0.8281) = √0.9981 ≈ 0.999，已近似单位球，投影后 v ≈ (0.400,-0.100,0.911)。
3. **算增量平移**：Δp^A = d·v = 6.00 × (0.400,-0.100,0.911) ≈ (2.40, -0.60, 5.47) cm——即在这个接地动作帧里，主要沿 z 推进约 5.5cm、x 方向偏移 2.4cm。
4. **算增量旋转**：Δω^A = θ·r = (-45.00°) × (0,0,1)，即绕该帧 z 轴转 −45°。
5. **转基座系**：Δp^B = R_At^B·Δp^A，Δω^B = R_At^B·Δω^A（R_At^B 由机器人状态+标定确定）。
6. **目标位姿**：p^{B,*} = p^B + Δp^B；R^{B,*} = Exp([Δω^B]_×)·R^B。
7. **执行**：q* = IK(T^{B,*}; q)，下发关节命令，重观测进入下一步。

这个例子里，VLM 只需要「知道」往 x 正、z 正推 6 厘米、绕 z 负转 45°、张开夹爪；它**不需要**知道基座在哪、相机外参是多少——这些都在确定性模块里。所谓「可计算的闭环」，就是把一个自由形态的抓取任务，降解成一连串「在可视坐标系里报数」的过程。

## 4. 工程视角 (Engineering View)

- **动作粒度/控制频率**：每一步只输出**增量**（Δp, Δω），是逐步闭环而非长动作块预测。闭环意味着误差不会像开环动作块那样积累，但也意味着推理延迟直接决定控制频率。
- **推理延迟**：一个动作串约 40 个字符级别 token，用自回归逐 token 解码；带 thinking 时还要额外生成推理 token。Table 7 显示 thinking 对成功率影响巨大（79.4% vs 11.7%），这意味着**要性能就得付推理预算**——延迟/吞吐与成功率之间是一个硬 trade-off，论文把它显式称为「reasoning budget」。
- **上下文成本**：memory（历史动作）对长时序任务有互补增益（Table 7 中 1.3 折毛巾：w/ memory 33.3% vs w/o 20.0%），但会增长上下文长度，进一步抬高延迟。
- **精度/量化误差**：所有标量保留两位小数并显式正负号，方向向量执行前投影到单位球——把「连续动作」自然离散化到文本可表达的精度，本身是一种量化；论文未给出该量化对精度的系统分析，属待补。
- **部署约束**：需要标定好的腕部 RGB-D + 外部相机与机器人运动学模型（在仿真里可去掉深度）。跨本体时，因为动作接口在末端位姿空间而非关节空间，换机器人主要换的是外参与 IK，模型本身不变（Table 6：UR3 63.9% → Flexiv 62.2%）。
- **内存/算力**：27B VLM 需大显存；0.8B 微调后即可在 LIBERO 上打平多个 VLA 基线（Table 5），说明「小模型 + 好接口」在仿真里很划算。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 零样本抓取/放置/简单铰接操作（Group 1），并对物体位置、位姿、颜色变化鲁棒。
- 微调后在可变形、精密、长时序任务上有竞争力（Group 2）。
- 跨本体迁移（UR3 → Flexiv），接口不变。

**不能做/易失败**：
- **零样本不覆盖复杂任务**：作者明说 Group 2 任务零样本普遍失败，必须微调。
- **高度依赖 thinking**：去掉 thinking，零样本平均从 79.4% → 11.7%（带 memory 时）/ 8.9%（不带 memory 时），说明「不推理就基本不会动」（Table 7）。
- **可变形任务仍是弱项**：叠毛巾零样本仅 33.3%（Table 4）。
- **规模红利有上限**：27B→397B 收益有限（Figure 5），暗示单靠堆规模不能兜底。
- **模态依赖**：真机需要深度/标定；仿真里去掉深度（用与 VLA 相同观测）虽仍可训，但真机零样本强依赖度量深度（Table 8）。

### 6.1 隐含假设 (Hidden Assumptions)

作者默认成立、但未充分验证的前提：
- **相机外参与手眼标定是准的**：动作帧投影与坐标变换都建立在标定正确之上，标定漂移会直接污染接地，论文未做标定误差敏感性实验。
- **深度传感器在操作场景下足够可靠**：M_t 依赖沿 z 轴的最近可见表面距离；对反光/透明/细结构物体是否稳定未讨论。
- **「最近可见表面」= 有意义的操作接触面**：对镂空、多层遮挡场景，该假设可能失效。
- **原生文本接口的数值精度足够**：两位小数量化 + 单位球投影对精密任务（套环）的影响未量化。
- **单帧动作帧足以承载长时序语义**：memory 有帮助但增益有限，长时序的「计划」究竟存在哪、是否可靠，仍是开放问题。

| 模块化基础模型（Code as Policies/VoxPoser/CoPa/ReKep） | 零样本操作 | 中间表示（程序/3D 值图/约束） | 无需动作预训练 | 零样本，但依赖外部规划器、不能端到端 |
| WAM/视频策略（Cosmos Policy, World Action Models） | 未来视觉先验 | 生成未来帧再推动作 | 视频生成模型微调 | 推理成本高，视觉预测误差会传导 |
| **EASG（本文）** | 显式动作空间接地 | **VLM 原生文本串** | 零样本直接用；可同一接口微调 | 单臂桌面操作，跨本体友好 |

同系列/同期对比看，EASG 与「Actions as Language」(ICLR 2026) 思路最接近（把动作当语言微调 VLM），但 EASG 更强调**显式几何接地**（动作帧投影 + 度量深度 + 语法约束解码），并证明零样本即可用；与 VLA 相比，它把「学动作语义」的负担从数据搬到了接口设计。

💡 **面试 Tip**：被问到「EASG 和 VLA 的本质区别」时，一句话答——**VLA 让模型从数据里学动作语义，EASG 把动作语义直接显式喂给模型（画在视野里 + 写成文本），因此零样本可用且可跨本体；代价是强依赖标定/深度和推理预算。**
