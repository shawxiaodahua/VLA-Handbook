💡 **X-Ray 开场**

一个机器人看着桌上摆的方块，转身去拿了别的东西，回来之后还得记得方块原来是什么颜色——这就是「记忆」。现有 VLA 策略大多只看最近一两帧画面，于是**它到底靠不靠记忆做事，根本没法测**。这篇论文造了 90 个「故意把线索藏起来」的操作任务，再加一个能量化「线索消失与需要动作之间隔了多久」的指标，第一次给 VLA 的记忆能力配上一把一致的尺子。对研究者意味着：以后比较「有没有记忆模块」终于有公共靶场。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 组件 | 内容 | 输入/输出 | 频率/时序 | 训练/推理差异 |
|------|------|-----------|-----------|----------------|
| 视觉观测 | 顶视 RGB + 腕部 RGB | 各 128×128×3 | 每环境步 | 训练/推理同接口 |
| 本体感知 | 7 维（末端位置+RPY+夹爪）| 7-D 向量 | 每环境步 | π0.5 基线会把 proprio 离散化进文本 prompt |
| 动作 | 7 维 delta 末端位姿 + 夹爪 | pd_ee_delta_pose | 10 Hz | 基线把 7 维 pad 到 32 维，open-loop 一次执行 8 步 chunk |
| 语言 | 指令指定目标与记忆操作 | 文本 | 每 episode | 30 个模板覆盖 90 任务；多数任务家族内共享 |
| 任务/数据 | 90 任务 / 26 家族 / 10 记忆类 | RLDS + LeRobotDataset v3 | 回合 25–2160 步 | 22,500 episodes，6,306,953 timesteps，175.2 小时（10 Hz）|
| 评测 | 固定 seed、50-episode/task 默认、success_once | 布尔成功 | 每 episode | 基线用更小预算（20 episode/task）|

### 1.2 关键机制 (Key Mechanism)

- **线索消失机制（cue hiding）**：绝大多数任务在动作依赖的线索上做「呈现 → 隐藏/遮挡 → 动作」的结构，强制策略在信息不可见后仍能行动；10 个 reactive control 故意保持线索可见，作为对照。
- **参数化难度**：26 个任务家族通过变体改动「干扰物数量、需记住的条目数、演示序列长度、延迟」等因子，语义难度与时序难度分开调节（但作者声明**并非完全交叉的因子设计**）。
- **信息缺口（information gap）**：从环境 phase 边界提取「线索最后可见 → 需要线索的动作 phase 开始」的间隔，而不是从策略实际动作时刻反推。固定相位定时给出常数 gap，reset 采样给出分布（报 median + IQR）。
- **两套发布格式**：RLDS（含每步 reward，287.4 GiB）与 LeRobotDataset v3（25.9 GiB，AV1 视频，**不含每步 reward**）。

⚡ **Eureka Moment**：**「回合时长」≠「记忆需求」**——一个很长但每一步都局部可见的任务根本不需要记忆，而一个很短的任务却可能依赖一个早已消失的线索；因此评测记忆必须显式控制「记什么、记多久」，而不能只看 episode 有多长。

### 1.3 信息流/架构图 (Flow / Diagram)

```
   指令(语言) ─┐
               ▼
   ┌──────────────────────────────┐
   │  Phase A: 呈现线索 (cue)       │   ← 顶视/腕部 RGB + proprio
   │  e.g. 看到方块颜色              │
   └──────────────┬───────────────┘
                  │  线索消失（hide/occlude）
                  ▼
   ┌──────────────────────────────┐
   │  Phase B: 信息缺口 (gap)       │   ← 线索确证缺席的区间（可测）
   └──────────────┬───────────────┘
                  ▼
   ┌──────────────────────────────┐
   │  Phase C: 依赖线索的动作        │   ← 必须"回忆"才能正确
   │  e.g. 选出同色方块              │
   └──────────────┬───────────────┘
                  ▼
         success_once: 任务条件在任一步成立即记成功
```

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
信息缺口  gap = t_start(Phase_C) − t_last_visible(cue)
记忆基准判定：若 gap > 观测窗口 W，则固定上下文策略「按构造」不可能仅靠当前帧解决
```

**目标**：给任务贴一个不依赖任何具体策略的记忆难度标签。

**公式（gap 与阈值判据）**：

```
gap_i = t_start(phase_cue_dependent_i) − t_end(phase_cue_visible_i)

统计量：对于 reset 采样的任务，报告 median_gap 与 IQR
阈值参考：28 个任务的 median gap > 16（= 调查中最宽的固定观测窗口，按控制率折帧）
```

**变量说明**：

| 符号 | 含义 | 来源 |
|------|------|------|
| gap | 线索确证缺席的区间 | 环境 phase 边界（非策略动作时刻）|
| W | 固定上下文窗口 | 调查中 RT-1=6、Octo=2、RoboVLMs=16 帧 |
| 16 | 最宽固定窗口参考值 | 论文 §5.1 |
| k | 离散选择任务的候选数 | 用于 chance floor 分析 |
| 1/k | 线索无关的均匀随机选择成功率 | 论文 §5.2 |

**直觉**：gap 只统计「线索**可证明**不在」的那段，所以它是记忆需求的**下界**——15 个任务 gap=0（看一消失就要动作），它们仍然需要记忆；反过来 gap>0 也不代表策略一定失败，因为相关性观测、具身策略或显式记忆可能绕开它。因此作者强调这把尺子**不是**「窗口大小的禁令」，而是任务结构的显式描述。

> 符号与本文/相关文档保持一致：W=观测窗口；gap=信息缺口；success_once=任一步成功即记。

## 3. 带数字走一遍：玩具例子 (Worked Example)

设想一个简化任务 RememberColor：面前 3 个候选方块，指令「记住被指出的方块颜色，之后选出同色方块」。

- **Phase A（线索呈现）**：第 0–40 步可见目标方块。
- **Phase B（缺口）**：第 40 步线索被遮挡，直到第 120 步才允许动作 → gap = 120 − 40 = 80 步，在 10 Hz 下约 8 秒。
- **判定**：80 > 16（最宽固定窗口），因此只看当前帧的策略**按构造**无法获得颜色信息。

现在看 chance floor 怎么算（论文 §5.2 的真实设定）：对 7 个「k 个等概率候选」任务，线索无关的均匀猜测成功率 = 1/k。

```
基线实测：33 / 140 episodes 成功 ≈ 0.236
均匀猜测期望：35.3 成功（= 对每个任务的 1/k 求和）
标准差：≈ 5.1
→ 33 与 35.3 相差远小于 1 个标准差
→ 没有任何任务超出其选择参考值 1 个标准误
→ 结论：在这小子集上"没有清晰证据表明模型是根据线索做选择"
```

这个闭环很重要：它说明**0.211 的成功率可能大量来自「猜 + 有效操作」而非记忆**——正是 chance floor 才能揭穿这一点。

## 4. 工程视角 (Engineering View)

| 维度 | 数值/约束 | 工程含义 |
|------|-----------|----------|
| 控制频率 | 10 Hz（pd_ee_delta_pose）| 16 帧窗口仅≈1.6 秒上下文；gap 动辄数百步，说明普通 VLA 上下文远不够 |
| 回合长度 | 25–2160 步（Short/Medium/Long）| 长回合 ≠ 高记忆需求，部署时要分开评估 |
| 观测分辨率 | 策略输入 128×128（基线 resize 到 224×224）| 视觉前端处理的算力与延迟需匹配 10 Hz |
| 动作 chunk | 基线 open-loop 8 步 | 盲目开环会把记忆失败与运动误差混淆；per-task 成功率偏移可达 0.650 |
| 数据体积 | RLDS 287.4 GiB vs LeRobot 25.9 GiB | LeRobot 便于 CI/训练，但**无每步 reward**，需 RL 训练必须用 RLDS |
| 仿真并行 | ManiSkill 3 GPU 并行 | 可大规模 rollouts；但环境全为仿真，真机迁移未测 |
| 演示采集 | 250 episode/task；PPO(34)+运动规划(56) | oracle 成功率 1.000 是**过滤后的**，不代表无条件可靠性；缺失败恢复数据 |

工程结论：这套东西适合作为**离线评测靶场**与**模仿/RL 微调数据源**，但别把它当「真机部署就绪度」证据，也别指望它直接告诉你某个记忆模块是否收敛——它只提供一致的比较条件。

## 5. 数据与评测 (Data & Eval)

- **任务规模**：90 个语言条件任务，26 个家族，10 类记忆（身份/位置、集合、有序序列、跟踪、待完成意图、已完成动作等）。类别分配依发布 manifest。
- **时序分层**：Short/Medium/Long 按回合上限分组；回合含观测、等待与运动执行，**本身不是保留时长的度量**。
- **信息缺口覆盖**：70 个任务可测 gap，其中 28 个 median gap > 16；10 个 reactive control（线索可见）；10 个任务的保留区间依赖到达某状态，无法仅从相位定时确定。
- **评测协议**：固定 episode seed、默认 50 episode/task、success_once。
- **参考基线**：π0.5 从公开 pi05_base 全量微调。训练用 14 个任务、3,500 LeRobot episodes、798,296 timesteps（7 类记忆，占发布 timesteps 的 12.7%），**不是全基准的代表样本**；Temporal/Negative/Checklist 未评测。评测 checkpoint 139,999，每任务 20 episode，seed 与训练不相交。
- **结果**：平均任务成功 **0.211±0.044**（Table 3）；随机动作在全部 90 任务 4,500 episodes 中仅 1 次成功（地面很硬）。
- **关联分析（均在已评测子集内）**：9 个可测 gap 任务均成功 0.167 vs 5 个任务 0.290（置换检验 p=0.209，不显著）；gap 与成功的 Spearman ρ=0.161（p=0.673）；3 个 Long-split 任务 1/60=0.017 vs 其余 11 任务 58/220=0.264（单侧置换 p=0.008）。
- **架构参考（来自 μVLA，非同源同训练）**：OpenVLA-OFT 加 64-token 循环记忆后，5 个训练任务 0.42→0.84，18 个 held-out 任务 0.07→0.23。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：作为一致靶场比较不同记忆设计（循环状态、经验检索、视觉-文本多尺度记忆）；提供稠密奖励供 RL 微调；提供 25.9 GiB（LeRobot）与 287.4 GiB（RLDS）两种 CDN 友好/训练友好格式。

**不能/需谨慎**：
- 基线 0.211 只描述**一个模型 × 一种训练与评测协议**，作者反复强调它**不是记忆-free 策略的上限**。
- Long-split 低成功率**原因未定**：该子集只含唯一的 Capacity 与 Sequential 任务及一个 Procedural 任务，时长与「复现集合/顺序/轨迹」耦合；且 8 步 open-loop chunking 是独立混淆因子。
- gap 只刻画**显式信息缺口**，无法排除捷径；也未做密集的延迟扫描；TimedTransfer 测的是**计时追踪**而非隐藏视觉线索的回忆。
- 全部为仿真，采集依赖特权状态 PPO/运动规划，**无人类演示**，迁移到物理机器人未被测量。
- 指令集限于 80 个任务共享指令且**无 held-out 释义**，因此结论是关于任务执行，**不是语言泛化**。

### 6.1 隐含假设 (Hidden Assumptions)

1. **仿真的记忆难度≈真机记忆难度**：作者未验证 sim-to-real 的记忆保真度。
2. **相位定时能代表保留需求**：gap 只数「确证缺席」的区间，作者承认它**低估**了成功策略实际需要的保留时长（如 Spatial/Procedural 的零 gap 任务）。
3. **oracle 演示可直接支持模仿学习**：成功率 1.000 是被过滤后的；过滤掉失败意味着数据里**没有恢复行为**，学出的策略遇到自身误差易进入分布外状态。
4. **14 任务子集能代表全基准**：作者自己否认（非代表性采样），所以 §5.4 的关联分析只在小子集内成立。
5. **k 候选的 chance floor 假设「选中后执行必然成功」**：这是解析参考，不是学到的基线。
