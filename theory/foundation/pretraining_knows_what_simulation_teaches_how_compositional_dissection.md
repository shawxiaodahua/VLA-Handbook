## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 模块 | 输入 | 输出 | 时序/频率 | 训练/推理差异 |
|------|------|------|-----------|----------------|
| 预训练 VLM（Qwen 3.6 27B） | 指令、三路 RGB、SAM 3.1 感知读数、历史对话、todo | 计划、工具调用 | 回合制；每轮一次工具调用 | 预训练后，GRPO 用 LoRA（rank 64）适配；推理用 vLLM；来源未说明 SFT 使用 LoRA |
| 工具 harness | 工具调用参数 | 验证通过/拒绝、错误原因 | 每轮 | 仿真/真机同一套；非法调用拒绝，不裁剪 |
| 感知 SAM 3.1 | 相机流、`change_query` | mask、编号框、3D centroid/height/axes | 连续异步 | 现成模型，不训练；仿真不读特权位姿 |
| 运动控制器 | 绝对末端位姿 + 夹爪开合 | Cartesian 路径、IK、五类 outcome | 每次 `move_to` 执行到静止 | 非学习模块；仿真/真机后端切换 |
| 训练管线 | 仿真 episode | SFT traces、GRPO 更新 | 640 episodes/batch；每 episode ≤50 turns | 只用仿真；无真机训练数据 |

论文称 27B 为“small”，是相对 frontier 万亿参数模型；27B 本身仍是较大模型。

### 1.2 关键机制

- **What/how 分工**：Qwen 3.6 27B 的预训练提供世界理解、语言和推理；40 个仿真任务只教运动，不教任务语义。
- **Harness 是抽象层**：模型看到的观测和动作格式在仿真与真机一致；换机器人只换声明式 embodiment 描述和底层后端。
- **绝对位姿，不是 action chunk**：`move_to` 给工具中心点的绝对位置（米）和完整朝向；`set_gripper` 给 0–1 开合。没有 grasp macro、approach primitive、关节角序列或动作 chunk。
- **无教师自蒸馏**：SFT 数据来自模型自己的成功 rollout；先用短 GRPO 热身，再对困难任务做 prefix-tree search，最多约 1,000 leaves/task。
- **密集奖励阶梯**：成功奖励 5.0 减长度惩罚；部分奖励上限 0.9，避免二值奖励在零成功率任务上无梯度。
- **拒绝而非裁剪**：非法 `move_to` 被 harness 拒绝并返回原因，模型可重试；控制器报告 reached/short/incomplete/not attempted/unknown。
- **记忆是对话 + todo，不是固定视觉窗口**：`update_todo` 写短计划，后续每个观测重复；旧轮次会被丢弃。论文没有报告统一的历史帧窗口，也没有未来帧预测或 action chunk。

⚡ **Eureka Moment**

把“运动控制”降维成语言模型可学的工具调用，把“任务语义”留给预训练；仿真只补 how，不补 what。真正关键的不是 27B，而是**同一套绝对位姿工具接口**让仿真中学的运动能零样本搬到真机和新机器人。

## 2. 数学核心

📌 **Napkin Formula**

```text
π_θ(a_t | o_t, h_t) = 工具调用
r_partial ≤ 0.9；r_success = 5.0 - λ·T
```

先给目标：在仿真中最大化任务成功，同时用部分奖励给“接近、抓取、抬起、运输”等中间进展提供梯度。再给奖励阶梯：

| 阶段 | 奖励 | 条件 |
|------|------|------|
| approach | 最多 0.2 | 按夹爪指尖到物体距离的缩小比例 |
| grasp | 0.2 | 成功夹住 |
| lift | 最多再 0.55 | 按抬升高度，最高 8 cm |
| transport | 把总分抬到最多 0.9 | 按到目标的距离缩小比例 |
| success | 5.0 减长度惩罚 | 任务完成；长度惩罚系数 λ 论文未给具体值 |

> 论文没有明确 success 项与 partial 项是否相加；本文不把 5.9 当作总奖励，只按原文说“成功项 5.0 减长度惩罚，部分项上限 0.9”。

GRPO 侧，论文只说明采用 Dr. GRPO 风格，**不做标准差归一化，也不做 per-sequence 长度归一化**；按文字可还原为组内相对优势：

```text
A_i = r_i - mean(r_1..r_G)   # 按论文文字还原，非论文原式
```

变量说明：

| 符号 | 含义 |
|------|------|
| θ | LoRA 参数（GRPO 阶段 rank 64） |
| o_t | 当前观测：三路 RGB + 感知读数 + 工具位姿 + 剩余步数预算 |
| h_t | 对话历史 + `update_todo` 计划 |
| a_t | 一个工具调用，不是连续动作向量 |
| T | 回合数；每 episode 最多 50 turns |
| λ | 长度惩罚系数，论文未给具体值 |
| r_partial | 部分奖励，上限 0.9 |

**时序口径（重要）**：以下公式是通用时间约定，不是 ZAP 的实验设置。

```text
均匀间隔 K 帧：首末跨度 = (K-1)·Δt
从当前参考 t 预测 t+1..t+H：终点距 t = H·Δt
```

ZAP 没有 K 帧历史窗口、没有 H 步未来帧预测、没有 action chunk。每轮观测是当前三路图像与感知读数；历史是对话上下文，旧轮次可被丢弃；`update_todo` 是短程计划记忆。`move_to` 是绝对末端位姿目标，控制器执行到静止。**不能把连续未来 chunk 的预测区间当作历史上下文或记忆窗口，也不能把某一次设置的步长/chunk 长度写成所有实验共有的记忆窗口。**

直觉：成功奖励 5.0 必须远高于部分奖励 0.9，否则模型会满足于“接近但没完成”。论文明确说这是设计奖励时的指导原则。

### 3.2 奖励阶梯验算（假设数值）

假设一个 pick-and-place 任务：

```text
approach 100%           → 0.2
grasp                   → 0.2
lift 4 cm / 8 cm        → 0.55 × 0.5 = 0.275
subtotal                = 0.675
transport 100%          → 抬到上限 0.9（+0.225）
```

这是**假设数值，仅用于验算奖励阶梯，不是论文实验**。它说明：部分进展最多 0.9，成功项 5.0 明显占主导；如果 λ 太大，模型可能偏向少回合但未完成，论文没有给 λ 的具体值，不能反推。

## 4. 工程视角

### 4.1 延迟、回合与成本

| 指标 | ZAP | GPT-6 Astra |
|------|-----|-------------|
| 每任务时间 | 146 ± 83 s | 397 ± 159 s |
| 回合数 | 21.9 ± 10.9 | 19.4 ± 8.0 |
| 每回合时间 | 6.2 ± 4.5 s | 19.0 ± 8.6 s |

论文写“3× faster、17× cheaper”。按表中均值粗算：146/397≈0.37，约 2.7×；4.87/0.29≈16.8，约 17×。四舍五入/表述差异不影响结论方向，但工程上应按 2.7–3× 理解延迟收益。作者称两者回合数相近，增益主要来自更快的模型响应；ZAP 用 vLLM 单张 B300 服务，价格 7.10 USD/hour，带 2-token MTP head。

### 4.2 上下文与 token 预算

- 最大序列长度 127k tokens；单 episode 最多 50 turns。
- 9 轮真实 episode 已用 118,985 input tokens，说明**上下文成本是主要工程矛盾**，不是控制频率。
- `update_todo` 在每个后续观测中重复，旧轮次被丢弃；这是短程计划记忆，不是长期视觉记忆。
- 工程含义：需要 prompt caching、旧轮次裁剪、todo 压缩、早停；否则 token 成本会随回合数快速增长。
- ZAP 是回合制高层策略，不跑固定控制频率；底层控制器负责 Cartesian 路径和 IK，执行到静止。

### 4.3 控制栈与 embodiment 抽象

- `move_to` 用绝对位置（米）和三个朝向角：slot yaw ψ、tilt τ、tilt direction φ。τ=0° 是自上而下，τ=90° 是水平；这套参数避开欧拉角在水平工具附近的奇异。
- harness 先做 tilt 范围、工作空间等校验；非法调用拒绝，不裁剪。控制器再解直线 Cartesian 路径和密集 IK，报告五类 outcome。
- 换机器人只换声明式 embodiment 描述和底层后端：YAM 双臂 2×6 DoF，Franka 单臂 1×7 DoF。论文的 Franka 结果是**仿真零样本**，不是真实 Franka。
- 没有力/触觉反馈；夹爪只有开合和 stall 检测。任务集中在准静态桌面操作。

### 4.4 评测不确定性（我的条件性分析）

真实评测每个模型 30 次试验（10 任务 × 3 次）。ZAP 29/30 = 96.7%。按 Wilson 95% 区间粗算约 83.3%–99.4%（不是论文给出的置信区间）。这意味着“与 GPT-6 Astra 打平”在 30 次样本下是合理观察，但不足以支撑很小的任务级差异；Per-task 表也显示两者都是 29/30，只是失败任务不同：ZAP 在“白板笔放进杯子”2/3，GPT-6 Astra 在“罐头食品装箱”2/3。

| 新物体/新目标 | 试管插入架、换孔指令 | 定性 episode，未给成功率 |
| 新策略 | 空中双臂交接 | 定性 episode，未给成功率 |
| 复杂推理 | 井字棋画 X、国际象棋 mate in one | 定性 episode，未给成功率 |
| 新 embodiment | 仿真 Franka 55.9% | 定量，但仅仿真 |
| 真实任务打平 frontier | 29/30 vs 29/30 | 定量，但 n=30 |
| 语言/空间/计数 | “behind the bowl”“exactly 3 bananas”3/3 | 每任务仅 3 次试验 |

论文的“组合泛化”主张主要落在：简单仿真运动 + 预训练语义，组合出新物体、新目标、新策略、新机器人。最有力的定量证据是仿真 Franka 迁移和真实 10 任务；最有趣但最弱的是试管、交接、井字棋、象棋——这些是定性展示，不能当作稳定成功率。

### 6.2 不能做什么/没证明什么

- **真实 Franka 未测**：55.9% 是仿真单臂 Franka；真实机器人只有双臂 YAM。
- **动态/接触丰富/可变形物体未测**：任务集中在准静态桌面拾放、堆叠、重定向；没有力控、没有高速动态。
- **ZAP 自身失败分类不足**：论文详细分析的是 MolmoAct2 的失败，不是 ZAP 的失败；ZAP 唯一非满分真实任务是白板笔 2/3，但没有解释。
- **感知依赖强**：SAM 3.1 + 标定深度；试管孔在放置瞬间被遮挡，模型靠策略完成，但没有遮挡鲁棒性统计。
- **harness 是强混杂因素**：同一个 GPT-6 Astra 在本 harness 96.7%，在 Robocurve harness 36.7%。这说明“模型能力”与“观测/动作接口”强耦合，不能只比模型名。
- **奖励塑形未消融**：部分奖励数值是人工整体选择，论文明确说没有 ablation；换任务族可能需要重设计。
- **非法动作仍有 3%**：加惩罚后“无工具调用”从 4% 降到 0%，“非法运动”从 34% 降到 3%；不是零。
- **长程记忆有限**：最多 50 turns；`update_todo` 是短计划；旧轮次会被丢弃；没有长期视觉记忆。

### 6.3 隐含假设（Hidden Assumptions）

1. 预训练 VLM 已经具备足够的语义/空间/计数知识；论文没有跨 VLM 家族消融，不能证明“任何 VLM 都能这样”。
2. 绝对末端位姿 + 可靠 IK + 标定深度是可用的；不是所有机器人平台都能提供这种接口。
3. 40 个简单仿真任务覆盖了目标任务的运动基元；对动态、接触丰富、可变形任务没有保证。
4. 真实评测 30 次试验足以支撑“匹配 GPT-6 Astra”；论文没有给置信区间，读者应自行保守解读。
5. “无真机数据”指 ZAP 训练阶段；论文没有详细说明预训练数据是否含机器人数据，不能扩大为“预训练也零机器人数据”。
6. 记忆是对话 + todo，不是固定帧窗口；也没有未来帧预测。不要把 action chunk 的长度当成记忆窗口。
7. 感知不做跨相机融合，由模型自己判断同一物体；分割/标定错误会沿工具调用传播。

## 7. 与相关工作对比

### 7.1 四种范式

| 范式 | 语义来源 | 运动来源 | 动作表示 | 真机数据 | 泛化 | 延迟/成本 |
|------|----------|----------|----------|----------|------|-----------|
| VLA/WAM | 预训练 VLM + 机器人动作数据 | 机器人动作数据 | 关节/末端/chunk | 不必然；需要机器人动作数据（仿真或真机） | 受动作数据分布限制 | 快、便宜 |
| Code as Policies | LLM 写程序 | 感知/控制 API | 程序 | 不需要运动学习 | 脚本外易碎 | 快、便宜 |
| Frontier agent | frontier LLM | 工具调用，未学运动 | 工具调用 | 不需要 | 广 | 慢、贵 |
| ZAP | 预训练 VLM | 纯仿真 SFT+GRPO | 绝对末端位姿工具调用 | **零真机训练数据** | 新物体/目标/策略/embodiment | 快、便宜 |

ZAP 的差异不是“更大的模型”，而是**把运动降成工具调用**：VLA 用机器人动作数据同时学 what 和 how；ZAP 把 how 放进仿真，把 what 留给预训练。

### 7.2 与紧凑 agent 对比

| 方法 | 规模 | 教师/数据 | 训练 | 动作接口 | 评测 |
|------|------|-----------|------|----------|------|
| Guava | 4B | 蒸馏 frontier teacher | GRPO 两个任务 | 物体引用 grasp/align 工具 | 重组已学 grasp/place/push |
| RACaP | 8B | 蒸馏 frontier ReAct | 进化 policy API | API 调用 | 高效部署 |
| Robo-Harness K1 | 9B | 蒸馏 | 学生策略 | 工具 | 仅仿真 |
| ZAP 27B | 27B | **无教师**，自挖掘成功 | SFT + GRPO，40 个仿真任务 | 绝对末端位姿 + 夹爪 | 真实 YAM + 仿真 Franka |
| ZAP 9B（消融） | 9B | **无教师**，自挖掘成功 | SFT + GRPO，单独单臂 Franka 仿真任务（4.6k mined examples） | 绝对末端位姿 + 夹爪 | 仅仿真 Franka |

面试 Tip：如果被问“ZAP 和 VLA 的区别”，一句话答——**VLA 用机器人动作数据同时学 what 和 how；ZAP 把 how 降成仿真里的绝对位姿工具调用，what 留给预训练，所以不需要真机动作数据，但依赖高质量仿真和工具接口。**

## 8. 精读建议

- **值得精读原文的人**：
  - 做 VLA/agent 混合路线，想知道“预训练语义 + 仿真运动”能否拆开的研究者；
  - 要评估 sim-to-real 工具接口、绝对位姿动作空间、harness 设计的工程师；
  - 关注组合泛化评测，尤其是新物体/新目标/新策略/新 embodiment 的读者。

- **建议章节路径**：
  先读 §3.1（harness 与五工具）→ §3.2（奖励阶梯与 GRPO）→ §4.2（真实 10 任务与延迟/成本）→ §5（定性组合泛化）→ Appendix A/B（接口与一轮真实 episode）。Appendix E 的扩展相关工作可最后扫读。

- **不值得精读的理由**：
  如果你只关心低层控制、动态操作、接触丰富任务，或需要大规模真实机器人数据验证，这篇距离中等；读摘要和 §4.2 即可。它的强项是“准静态桌面 + 工具接口 + 零真机训练数据”，不是通用机器人基础模型。
