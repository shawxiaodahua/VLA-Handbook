### 1.2 关键机制 (Key Mechanism)

Embodied-R1.5 的核心设计围绕三个互补的能力维度，它们构成从感知到决策到执行的递进推理链：

1. **具身认知与空间推理**（4 个子维度）
   - 空间关系理解：物体相对方位、支撑关系、包含关系、遮挡
   - 度量空间推理：距离估计、物体大小判断、空间容纳性
   - 3D 场景感知：单目深度估计、跨视角几何推理、视频帧间空间一致性
   - 物体与场景认知：机器人视角的场景理解，区分目标与障碍物

2. **具身规划与修正**（5 个子维度）
   - 长程任务分解：将语言指令分解为结构化子任务序列
   - 下一步规划：执行中根据当前进度和观测生成原子动作指令
   - 过程检测：判断子任务是否完成
   - 错误定位：识别失败的具体原因（执行/规划视角）
   - 错误修正：生成具体的纠正建议（重规划或回退重试）

3. **具身定位与指向**（4 种类型）
   - REG（指代表达 grounding）：自然语言 → 物体坐标
   - RRG（区域指代 grounding）：如"能放盘子的空区域"
   - OFG（物体功能 grounding）：定位物体的功能部位（壶嘴、把手、按钮）
   - VTG（视觉轨迹生成）：生成操作轨迹的有序点序列，支持对象流和末端执行器流

⚡ **Eureka Moment**：在本文测试的设置中，更强的具身推理底座能在没有大规模动作预训练的情况下适配出有竞争力的 VLA；这是数据使用路径的经验性证据，不是动作预训练已普遍无用的证明。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（两阶段训练的文字示意，并非一个同时优化的总损失）：

```
阶段 1：SFT，优化因果语言建模损失
阶段 2：RFT，采用带裁剪的策略优化与 KL-in-reward（β = 0.01）
```

SFT 建立多任务基础能力，随后 RFT 用可验证奖励继续训练；实际裁剪目标、奖励处理与超参数以论文 §4 为准。

**关键创新在优势函数的归一化方式**：

```
A_i = (R_i - μ_group) / (σ_batch + ε)
```

与传统 GRPO 使用组内标准差不同，这里用全局批次标准差 σ_batch 归一化，以统一混合批次中优势的缩放尺度。

**变量说明**：

| 符号 | 含义 | 值/范围 |
|------|------|---------|
| R_i | 第 i 个 rollouts 的奖励 | [0,1] |
| $\mu_{\text{group}}$ | 组内平均奖励 | 实数 |
| $\sigma_{\text{batch}}$ | 全局批次标准差 | 正实数 |
| $\beta$ | KL 惩罚系数 | 0.01 |
| n | 并行 rollouts 数 | 8 |

**直觉**：组内均值保留 rollout 之间的相对比较，批次级标准差调整归一化尺度；作者用此方法缓解异构任务训练冲突，不能理解为无条件消除所有任务间的尺度差异。

**分段线性奖励衰减函数**（核心奖励设计）：

```
φ(d; τ_p, τ_z) = clip((τ_z - d) / (τ_z - τ_p), 0, 1)
```

当距离 d < τ_p 时给满分，d ≥ τ_z 时给零分，中间线性衰减，为连续误差提供部分奖励。

原文 §4.2.2 有五类奖励：确定答案用 exact match，框定位直接用 IoU，点定位与轨迹误差使用距离衰减，开放文本使用语义奖励模型。φ 不是全部任务共用的唯一奖励；点数和轨迹长度不匹配时还另有惩罚。

## 3. 带数字走一遍：玩具例子 (Worked Example)

以下是人为设定的简化点定位示例，只用于演算距离、奖励与优势；不是论文实验或真实推理耗时。

**场景设定**：
- 图像分辨率 $224 \times 224$，坐标归一化到 $[0, 1000]$
- Ground truth 把手坐标：(450, 320)
- 模型输出 3 个候选点：(460, 330), (445, 315), (470, 340)

**Step 1: 计算最近邻距离**

```
d_nn = mean([dist((460,330),(450,320)), dist((445,315),(450,320)), dist((470,340),(450,320))])
     = mean([14.14, 7.07, 28.28]) ≈ 16.50  // [0,1000] 坐标单位
// 若换成224×224图像上的像素距离：16.50 × (224/1000) ≈ 3.70像素
// 下文奖励阈值与距离均使用[0,1000]坐标单位，不混用像素。
```

**Step 2: 应用分段线性衰减**

```
R = φ(16.5; 40, 150) = clip((150 - 16.5) / (150 - 40), 0, 1)
  = clip(133.5 / 110, 0, 1) = clip(1.21, 0, 1) = 1.0
```

→ 距离奖励分量为 1，因为距离低于 τ_p=40。此处只演示距离项；按论文的完整规则，点数不匹配还另有 δ_c=0.3 惩罚，不能将本例的 1.0 直接当成最终训练奖励。

**Step 3: RL 优势计算**

假设同一 prompt 的 8 个 rollouts 奖励为 [1.0, 0.85, 0.6, 1.0, 0.3, 0.92, 0.75, 0.45]，并另设整个混合批次的标准差为 0.245：

```
μ_group = mean([1.0, 0.85, 0.6, 1.0, 0.3, 0.92, 0.75, 0.45]) = 0.73375
σ_batch = 0.245  // 示例假设，不能仅从上面单个group推得

A_i = (1.0 - 0.73375) / (0.245 + ε) ≈ 1.09
```

→ 正优势，策略被强化。

**Step 4: 自适应推理长度**

论文 §4.2.1 将这种现象称为 adaptive thinking：奖励只评价最终答案，简单定位任务可产生接近零的额外推理开销，复杂规划则使用更多推理。本笔记未核实“200→30 tokens”的逐项测量，故不保留该数字。

| 裁剪比率 | 0.2/0.28 | 实际裁剪率极低（具身推理响应较短） |
| 训练轮数 | SFT 1 epoch + RFT 2 epochs | 全数据系统 15B tokens |

| 部署方式 | 单模型异步调用 | PGC 框架中 Planner/Grounder/Corrector 共用同一推理服务 |

**关键工程洞察**：
- **坐标作为纯文本输出**（归一化到 [0,1000]）而非特殊 token，预测更稳定且词表开销可忽略
- **自适应推理长度**：RL 阶段模型自发学会简单任务少推理、复杂任务多推理——这是奖励驱动的计算资源自适应分配
- **语义泛化假设**：轨迹生成不依赖高保真仿真，低精度仿真数据也能提供有效的运动语义监督（拓扑结构和方向语义）

### 6.1 隐含假设 (Hidden Assumptions)

1. **"具身推理可部分替代动作预训练"** — 本文仿真与具身推理评估提供了初步证据；不同数据预算、机器人及真实环境的收益仍需独立验证。
2. **"单一模型可以同时服务 Planner/Grounder/Corrector 三个角色"** — 假设 8B 模型的容量足以覆盖三种不同抽象层次的能力，无需模型间通信开销
3. **"低精度仿真的轨迹数据足够"** — "语义泛化"假设，VTG 关注拓扑结构和方向语义而非渲染保真度，这在桌面操作场景成立，但对精细操作可能不够
4. **"距离奖励阈值能够跨任务复用"** — 点距离和轨迹 RMSE 使用不同阈值；框定位直接用 IoU，开放文本另用语义奖励模型。迁移到新任务时仍需核对奖励定义和阈值。
5. **"PGC 框架的极简 FIFO 内存足够"** — 作者承认更复杂的记忆策略可能增强设计，但未做对比实验

## 8. 精讀建議 (Reading Guide)

**值得精讀原文的人**：
- 做多模态具身 Agent 的研究者，特别是关注"推理→动作"接口的
- 要评估从 VLM 迁移到 VLA 可行性的工程师——"推理先行、动作轻量"的范式值得参考
- 对多任务 RL 训练感兴趣的研究者——Multi-Task Balanced RL Recipe 是可直接复用的技术

**建議章節路徑**：
1. 先读 §2（Unified Embodied Capabilities & Architecture）——理解三维度能力体系的设计哲学
2. 再看 §4（Training Strategy）——SFT→RFT 两阶段训练和 Multi-Task Balanced RL 是技术核心
3. 然后读 §5（PGC Framework）——闭环执行的创新设计
4. 可跳过 §3（Data Construction）的细节和附录——除非你要复现数据管道

**不值得精讀的理由**：
- 如果你不做具身推理/基础模型方向，只关心纯动作策略，读摘要和 §7 的实验结果即可
- 如果你已熟悉 Embodied-R1 和 GRPO，本文的方法论增量主要在能力统一和 PGC 框架，训练细节变化不大
