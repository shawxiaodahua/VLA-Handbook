## 1. 核心架構/方法總覽 (Overview / Architecture)

### 1.1 系統對比概覽 (System Component Comparison)

UniMPA 在 π0.5 的「VLM 骨幹 + Action Expert」雙系統上再加一條 **World Expert** 流，形成三流架構。

| 模組 | 輸入 | 輸出 | 時序/頻率 | 訓練 vs 推理 |
|------|------|------|-----------|--------------|
| VLM 骨幹 (PaliGemma-2B) | 多視角 RGB + 語言指令 | 視覺-語言前綴 C_t | 每控制步一次 | 訓練/推理皆用 |
| World Expert（18 層 Transformer，1024 維，16 個可學習 world token） | 零初始化的轉移 query + 上下文 | 轉移 token Z_tr | 每控制步一次 | 訓練/推理皆用（解碼頭僅訓練用） |
| Latent 預測頭 | Z_tr | 未來 V-JEPA 2 潛特徵（16 token × 1408 維） | 訓練時全程開啟 | **僅訓練** |
| Pixel 預測頭（64 token → 4 層 → 32×32 patch → 256×256 圖） | Z_tr 上採樣 + 檢索到的視覺記憶值 | 未來影像 | 訓練時**選擇性**開啟（Trigger Gate） | **僅訓練** |
| Visual-Action Memory Bank | 未來監督的轉移 query | 歷史上執行過的視覺-動作演化 | 檢索時呼叫 | Stage-1 預訓練，Stage-2 凍結 |
| Action-Visual Memory Bank | 近端動作歷史 query | 視覺接地的動作原型 | 每控制步一次 | Stage-1 預訓練，Stage-2 **推理仍啟用** |
| Action Expert (Gemma 311M) | 噪聲動作 + C_t + Z_tr + 動作先驗 | 速度場，10 步 Euler 去噪 | 每動作塊一次 | 訓練/推理皆用 |

> 一個關鍵工程決策：**推理時只移除 latent/pixel 解碼頭，World Expert 與其轉移 token 全程保留**，因此「未來監督」塑造出的表徵在部署時仍然參與動作生成——這正是它比「預測只是輔助任務」的方法更省、更準的原因。

### 1.2 關鍵機制 (Key Mechanism)

- **Persistent-Selective Future Prediction（持續-選擇式未來預測）**：latent 監督**全程**開啟，把任務進度寫進轉移 token；pixel 監督**只在轉移關鍵時刻**開啟（接觸、夾爪開合、姿態調整、釋放）。理由是：稠密像素預測大量算力浪費在靜態背景與紋理上，而關鍵時刻的細粒度變化才是動作真正需要的信號。
- **Visual-Action Memory Bank（視覺→動作記憶庫）**：用「未來監督的轉移表徵（解碼後的端點）」而非「當下外觀」去檢索歷史——按**預期狀態變化**找經驗，且檢索到的值是**歷史上真正執行過**的視覺-動作配對，為預測提供「可執行證據」。
- **Action-Visual Memory Bank + Prototype-Biased Flow（動作→視覺記憶庫 + 原型偏置流）**：用近端動作歷史檢索出「視覺接地的動作原型」，**不是直接執行它**，而是把它當作 flow-matching 的**源分布偏移**，讓動作專家在「歷史支持的可行動流形」附近起跑，再依當下觀測精修。
- **Coarse-to-Fine Temporal Indexing（粗到細時序索引）**：先鎖定最相關的一條示範軌跡（episode），再在該軌跡內部做軟檢索；避免把視覺相似但時序不相容的跨示範狀態平均進來。

⚡ **Eureka Moment**：預測、記憶、動作生成不該是三件獨立的事——它們應該共用同一個「action-grounded transition」；**預測消除意圖歧義並生產檢索 query，記憶把該轉移落地到可執行的視覺-動作證據，動作生成在檢索到的先驗上精修**。一句話：從「預測會發生什麼 / 回想發生過什麼」轉向「學會意圖中的世界變化如何被可複用的可執行經驗承接」。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
ε̃ = ε + λ_p · P_a,t     然後  x_ρ = ρ·ε̃ + (1-ρ)·A_t,  u_ρ = ε̃ - A_t
```

即：**先讓「檢索到的可執行動作原型」把高斯噪聲源平移一段，再做標準 flow-matching 去噪**。其他一切（轉移預測、記憶檢索）都是為了把 P_a,t 造得可靠。

**目標**：在不破壞生成式動作頭表達力的前提下，讓採樣從「歷史支持的可行動流形」附近出發，減少盲目去噪步數與幻覺動作。

**關鍵公式（全文以代碼塊書寫，避免 LaTeX 渲染問題）**：

```
# (1) 動作先驗：檢索值與近端動作歷史融合，平移源分布
P_a,t = h_prior( [ φ_prev(H_t), ū_a,t ] )
p(ε̃ | P_a,t) = Normal( λ_p · P_a,t , I )          # 只移均值，保留協方差與隨機性

# (2) flow-matching 目標速度與損失
x_ρ = ρ·ε̃ + (1-ρ)·A_t
u_ρ = ε̃ - A_t
L_act = E[ (1/(K·D)) · ‖ v_θ(x_ρ, ρ | C_t, Z_tr, P_a,t) - u_ρ ‖² ]

# (3) 序列級總目標
L_UniMPA = L_act + λ_lat · L_lat + λ_pix · L_pix

# (4) 記憶預訓練目標（Stage 1）
L_bank = L_rec + λ_ret · L_ret + λ_pair · L_pair
L_rec  = Σ_ν (1/|Ω_ν|)·‖Îν_{t+Δ} - Iν_{t+Δ}‖₁ + λ_a·(1/(K·D))·‖Â_t - A_t‖₁
L_ret  = Σ_ν (1/|Ω_ν|)·‖Dν(ūν) - Iν_{t+Δ}‖₁ + λ_ra·(1/(K·D))·‖Da(ū_a) - A_t‖₁

# (5) Trigger Gate（選擇性開啟像素監督）
r_lat = ‖F̂_main_{t+Δ} - F_main_t‖₂ / (‖F_main_t‖₂ + ε)
m_t   = 1[ r_lat > η_lat  OR  b_p = 1  OR  b_r = 1  OR  b_g = 1 ]     # 線性/旋轉/夾爪任一觸發
L_pix = m_t · Σ_ν (1/|Ω_ν|)·‖Îν_{t+Δ} - Iν_{t+Δ}‖₁

# (6) 粗到細檢索
e* = argmax_e max_s sim(q_t, k_{e,s})                    # 粗：選示範
ū_t = Σ_s softmax( sim(q_t, k_{e*,s}) / τ ) · u_{e*,s}  # 細：軌跡內軟檢索
```

**變量說明**：

| 符號 | 含義 |
|------|------|
| X_t = 畫面 V_t, 語言 ℓ, 本體 q_t, 動作歷史 H_t | 當前上下文 |
| T_t^Δ | 「意圖轉移」算子（條件狀態演變），非像素差 |
| Z_tr | World Expert 的轉移 token（訓練/推理皆用） |
| F̂, Î | 預測的未來 V-JEPA 潛特徵 / 未來影像 |
| P_a,t | 動作流形先驗（記憶原型 + 近端動作） |
| λ_p | 動作先驗強度（偏置幅度） |
| τ | 檢索溫度，實驗取 0.1 |
| m_t | Trigger Gate 二值開關（僅訓練） |

**直覺**：整條 pipeline 只做一件事——**把「未來的可執行版本」準備好，用它同時校準表徵與初始化動作**。World Expert 學的是「意圖如何演變」；兩個記憶庫學的是「這種演變歷史上長什麼樣、當時動作怎麼做」；Action Expert 只負責把這份粗糙但可執行的先驗，貼合當下場景。

> 符號與本文/相關文檔保持一致：Z_tr（transition tokens）、P_a,t（action prior）為作者原文記法；flow-matching 記法沿用 π0/π0.5 系列傳統（噪聲 ε、時間 ρ、目標速度 u）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

設一個 2D 桌面「把杯子放到盤子上」任務，動作 D=2（平面位移），動作塊 K=4。

**假設**：當前杯子在 (0.20, 0.10)，盤子在 (0.60, 0.50)，單位米。近端動作歷史 H_t 顯示機械臂正朝右上方移動，故動作 query q_a,t 命中了記憶庫中一段「從左下方抓取並放置」的示範軌跡。

1. **檢索得到動作原型**：假定 Action-Visual Bank 返回 ū_a,t，其對應的 K=4 步位移增量（米）約為：

```
Δt=0: (+0.04, +0.04)
Δt=1: (+0.05, +0.05)
Δt=2: (+0.04, +0.06)
Δt=3: ( 0.00, +0.02)   # 接近目標時的細微收斂
```

2. **源分布偏置**：取 λ_p = 0.5，則均值被推向 (0.02, 0.02) 附近（半步大小）。原本標準高斯源 N(0, I) 在每個維度 std=1，意味著初始樣本可能落在 ±1 米的荒謬誤差上；偏置後均值落到典型步長量級——**自由噪聲的「搜索半徑」被歷史經驗壓縮到厘米級**。

3. **閘控開啟判斷**：假設 Δt=3 那一步夾爪狀態從 1→0（釋放），且有旋轉變化，兩者任一觸發 → b_g=1 → m_t=1 → 該時刻**開啟像素監督**，強制 World Expert 把「釋放瞬間」的細粒度視覺變化寫進 Z_tr。其餘平順移動步 m_t=0，省下像素解碼成本。

4. **去噪**：Action Expert 以 C_t + Z_tr + P_a,t 為條件，10 步 Euler 從偏置後的 x_1 收斂到 Â_t。因為起點已在正確流形附近，實測（論文 §IV-B1）維持 10 步即可，無需更多步數換精度。

**閉環檢查**：若檢索到的是「錯誤的歷史動作原型」（例如檢索到的是向右下的放置），λ_p 越大偏置越強 → 越容易被錯誤經驗拖走。論文的消融（Table XIV）正是驗證這點：**直接複製最近鄰動作（NN Action Copy）在真機 TSR/CSR 掉 22.9/18.9 個百分點**——所以先驗必須強度可控且允許精修。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 視覺相似但處於不同操作階段的場景下分辨意圖（如疊衣服的起始/繼續/抓取調整/釋放）——由持續 latent 轉移追蹤支撐。
- 分佈偏移下的零樣本泛化（相機、光照、背景、佈局、噪聲）——檢索按「預期狀態變化」而非外觀匹配。
- 長程組合與**失敗恢復**（Stack/Folding Recovery 套件 TSR 72.0%，比 π0.5 高 20.0 pp）。
- 雙臂關節空間控制（附錄 A1 提供 joint-space Trigger Gate 變體）。

**不能／存疑**：
- **僅桌面與雙臂操作域**：未在移動操作、人形全身控制上驗證。
- **平台綁定**：兩台真機各平台獨立訓練，未展示跨具身零樣本遷移。
- **記憶庫需重建**：Stage-1 預訓練依賴該域的示範軌跡；新任務域大概率需重訓記憶庫。
- **長程仍最弱**：LIBERO-Plus 的 Long 套件僅 76.5%（其餘 84.3–89.7），長程一致性仍是瓶頸。
- **未外部復現**：TPAMI 投稿、項目頁提供，無公開代碼復現記錄（截至撰寫時）。

### 6.1 隱含假設 (Hidden Assumptions)

- **示範軌跡已覆蓋目標分佈**：記憶庫檢索的前提是「歷史裡有相似轉移」；若目標場景超出示範覆蓋，記憶先驗可能成為有害偏置（消融中 NN 複製的大幅掉分就是極端情況）。
- **V-JEPA 2 特徵足以表徵「任務相關的未來」**：latent 監督直接對齊凍結 V-JEPA 2，若其特徵對接觸/幾何細節不敏感，細粒度信號只能靠 pixel 分支補——這正是作者加 pixel 分支的隱含動機。
- **Trigger Gate 的閾值可跨任務通用**：η 系列閾值在論文中按域調整（λ 也按域不同），暗示「關鍵時刻」的定義並非全域普適。
- **三流共享注意力足以建立轉移介面**：未驗證是否必須三流；可能兩流 + 專用交叉注意力也能達到類似效果（未做此消融）。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**生成式 VLA 動作頭**（diffusion/flow-matching）的研究者——§III-D 的 Prototype-Biased Flow 是可直接移植的「源分布偏置」技巧；
  2. 做**記憶/經驗檢索增強機器人策略**的工程師——§III-B 的雙向記憶構造與兩階段預訓練目標是完整範式；
  3. 需要在**分佈偏移/真機部署**下保性能的團隊——§IV-C、§IV-D 的零樣本與真機協議值得照搬設計評測。
- **建議章節路徑**：先讀 §I 的三種 mismatch 拆解（問題定義最精華）→ 再看 §III-C（持續-選擇式預測 + Trigger Gate）與 §III-D（動作先驗）→ 最後看 §III-B 的記憶預訓練公式 → 附錄 A2（三流共享注意力）按需。
- **不值得精讀的理由**：若你不做機器人學習、或已熟悉 π0.5 雙系統 + 記憶檢索范式、或只關心骨幹加速，讀摘要與 Table I/II 即可。此外若你的場景示範數據稀缺、無法建記憶庫，這篇的核心機制（依賴示範覆蓋）可能幫不上忙。
