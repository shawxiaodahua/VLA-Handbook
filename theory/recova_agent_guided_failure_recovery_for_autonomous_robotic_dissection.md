## 1. 核心架構/方法總覽 (Overview / Architecture)

Recova 的核心設計哲學是**解耦**：任務策略負責「完成任務」，恢復策略負責「把場景恢復到可續跑的狀態」。兩者由一個 agent 串接，貫穿「模擬開發 → 真實部署 → 學習回流」三個階段（論文 Fig. 2）。

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 頻率/時序 | 訓練 vs 推理 |
|------|------|------|-----------|--------------|
| 任務策略 π_θ | 觀測 o_t（頭頂+手腕相機）、語言指令 g | 動作 a_t | 30 Hz 連續 | 推理時凍結；DAgger 輪次間用 S_k ∪ E_k 微調 |
| 恢復策略 ρ_φ | 觀測 o_t、恢復指令 z | 動作 a_t | 觸發後 30 Hz，上限 50s | 推理時凍結；輪次間用 R_k ∪ A_k 微調 |
| Code-as-Policy 技能庫 K | 場景查詢 + 運動原語 | 程式化恢復動作 | 觸發時執行 | 無訓練；由 agent 在孿生中開發/測 |
| Coding agent | 真實錄影、標定、軌跡 | MuJoCo 數位孿生 + 恢復程式 | 離線 | 語言模型寫碼/執行/改碼 |

### 1.2 關鍵機制 (Key Mechanism)

- **為何解耦？** 若把恢復混進任務策略，所有恢復樣本會稀釋任務資料、且恢復技能無法跨任務複用。解耦後 K（恢復指令集合）以自然語言 z 為鍵，同一失敗在何處復現即可複用。
- **為何用數位孿生探索失敗？** 真機上找失敗需要頻繁人為 reset、且有損壞物件的風險（論文引 Torne 等）。agent 從相機觀測+標定+軌跡重建 MuJoCo 場景，擬合物件位姿與接觸參數。
- **三類恢復技能**：Restorative（把場景復原到可用，如扶正倒下的物件）、Enabling（為下一步鋪路，如把物件移到可及範圍）、Adaptive（換個方式而非重試，如換抓取姿態）。
- **失敗即資料**：當沒有技能可用時，人類示範解決當下失敗，同時成為新技能的第一個訓練樣本，並反向驅動孿生中開發對應程式。

⚡ **Eureka Moment**：**把「怎麼從失敗裡爬起來」變成一個以語言指令為索引、可獨立累積的技能庫——失敗不再是訓練資料的丟棄項，而是新技能的生產資料。**

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：恢復 = 把失敗狀態映回「任務策略可續跑」的可作區。

```
任務: π_θ(a_t | o_t, g) 執行至 C_g 成立
恢復: ρ_φ(a_t | o_t, z)  或  Program_k ∈ K
目標: s_fail ──ρ_φ/Program──► s'  s.t.  π_θ 可從 s' 續跑
```

**變數說明**

| 符號 | 含義 |
|------|------|
| g | 任務語言指令（如「把筆裝進筆盒」） |
| o_t | t 時刻相機觀測 + 機器人狀態 |
| C_g | 任務完成條件（由 requirement query 從 g 與初始影像生成） |
| z | 恢復語言指令（如「把卡住的環壓下去」），是恢復技能的索引 |
| π_θ | 任務策略（condition on g） |
| ρ_φ | 恢復策略（condition on z，而非 g） |
| K | 已知恢復指令集合；K_ρ ⊆ K 為已訓練、可被 ρ_φ 自主執行的子集 |

**DAgger 資料分流（論文 Eq. 1）**——這是全文的「學習閉環」核心：

```
D_task^{k+1} = D_task^k ∪ S_k ∪ E_k
D_rec^{k+1}  = D_rec^k  ∪ R_k ∪ A_k

S_k: 無人類接手的任務成功 rollouts
E_k: 人類任務示範 (Expand)
R_k: 人類恢復示範（各以 z 標註）
A_k: 通過場景恢復檢查的自主恢復
失敗片段: 保存供分析，但不進訓練
```

**直覺**：DAgger 的原始形式是把「學習者造訪過的狀態」上都補上專家標籤（Ross 等, 2011）。Recova 的變體是**只在一部分交接點要人**——只有當自主執行無以為繼時才介入，且依「是場景被破壞還是單純停滯」把示範路由到正確的策略。因此人工標註量從「每個造訪狀態」降到「每次失敗交接」。

> 符號與本文一致：π_θ（任務）／ρ_φ（恢復）／z（恢復指令）／C_g（完成條件）。原文用 \pi_\theta, \rho_\phi。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

以真實任務「疊環（stacking rings）——按大小順序把環套上柱」為例（論文 §3.1、§4.2）：

1. **正常執行**：π_θ 開始套環，累計動作步數達 T_max = 5400 步（30 Hz → 180 s）前，每 N_c = 600 步（20 s）由 M_done 檢查 C_g。
2. **失敗發生**：機器人釋放第三個環時角度偏差，環**卡在柱頂**而非滑入 → 場景進入 s_fail，任務停滯。
3. **偵測介入**：每 N_i = 300 步（10 s）M_int 比較近期影格與初始場景，判定「需介入、場景被破壞、復用已知指令 z =『把卡住的環壓下去』」。
4. **恢復**：因 z ∈ K_ρ，ρ_φ 在 T_rec = 1500 步（50 s）預算內執行 → 把環壓入定位。
5. **驗證續跑**：M_res 以初始影像為參照判定場景可續跑（不要求回到完全相同的位姿）→ 回 home pose，π_θ 開新一次嘗試。
6. **若無技能可用**：操作員示範，該軌跡以 z 標註進 R_k；此後 z 進入 K 與孿生程式開發流程。

**數字閉環（真實機器人，論文 §4.2）**：

- 任務成功率：base π0.5 23.8% → DAgger 微調 77.5%（+53.7）→ 開恢復技能 87.5%（再 +10）。
- 疊環 / 筆盒兩任務恢復增益各 +15.0 分（單一障礙擋住後續步驟），兩個麻將任務各 +5.0 分。
- 「抽麻將牌」任務的四輪收集：任務策略完成比例 12.5% → 85.7%；人類接手 8 次中 7 次（87.5%）→ 第 4 輪 7 次中 0 次（0%）。
- 一次 14 分鐘、4 站並行 session：任務策略完成 31 個 episode 中的 22 個，人類控制僅佔各站時間總和的 11%。

## 4. 工程視角 (Engineering View)

**時序與預算**（論文 Alg. 1 預設值，30 Hz 控制）：

| 參數 | 值 | 步數 | 時間 | 工程含義 |
|------|----|------|------|----------|
| N_c | 完成檢查間隔 | 600 | 20 s | 太密→VLM 呼叫爆炸；太疏→卡死偵測遲緩 |

| T_max | 單次任務步數上限 | 5400 | 180 s | 超時即讓恢復程式接手 |
| T_rec | 恢復時間預算 | 1500 | 50 s | 恢復跑太久不如直接叫人 |
| c_max | 連續介入閾值 | 2 | — | 連續 2 次介入後下一次改為完整人類示範，避免反覆失敗循環 |

**部署含義**：

- **監控器是外掛 VLM，不是策略的一部分**：M 由 4 個 VLM 查詢實現（done / intervention / restoration / requirement），每次檢查都是獨立呼叫；論文未報告其延遲與成本 → 這是落地時最不確定的開銷項。
- **恢復是「模組邊界」而非「連續控制」**：任務策略與恢復策略是兩個獨立權重（皆從 π0.5 微調），切換點由 VLM 判定，天然適合把恢復當成可插拔的 skill。
- **人力被攤薄**：因為只在交接點需要人，1 名操作員可同時監督多台不同場景的工作站 → 資料收集的邊際人力成本隨站數次線性下降。這是「並行 DAgger」能撐起 4 站的原因。
- **硬體**：雙臂 I2RT YAM（平行夾爪）、4 台 Intel RealSense（頭頂、前方、每腕一台）、30 Hz 迴路。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 從「場景被破壞」的失敗中恢復（扶正、壓入、重新抓取），並驗證恢復是否足以續跑。
- 用自然語言指令複用恢復技能到復現同類失敗的任何任務。
- 在 4 站並行下把人類介入率從 87.5% 壓到 0%（單任務、4 輪），把人工標註集中在失敗交接點。

**不能做 / 風險**：
- **未驗證跨形態**：真機只在 I2RT YAM 雙臂上；模擬用 MolmoAct2/π0.5，不能外推移動/人形/單臂。
- **孿生重建不可自動化**：每個任務都要 agent 重建 MuJoCo 場景並擬合接觸參數，新場景成本未量化。
- **技能不自動註冊/共享**：論文明確把「自動註冊新學技能並跨任務共享」列為未來工作（Conclusion），當前新技能仍需走完「人示範 → 微調 → 進 K_ρ」流程。
- **監控器的誤判風險**：介入 / 恢復驗證全由 VLM 判定，視覺相似度可能漏檢「看似復原但實際不可續跑」的狀態。
- **恢復時間預算硬切**：T_rec = 50 s 到點即放棄，對需要長程重排的失敗無能為力。

### 6.1 隱含假設 (Hidden Assumptions)

- **假設失敗是「可視且局部」的**：判定完全基於影像比對，若失敗在感測盲區或外觀無變化（如力控失敗）則偵測不到。
- **假設 C_g 可由 VLM 從 g 與初始影像可靠生成**：若完成條件模糊或需物理量（力矩/溫度），C_g 不成立。
- **假設「場景恢復」與「任務完成」可視覺區分**：驗證只要求「可續跑」而非精確位姿，這是寬鬆但也可能過寬的假設。
- **假設數位孿生的接觸參數足以遷移**：真機仍有孿生無法預期的接觸動力學（論文本就承認），因此 DAgger 回流是必要補丁。
- **假設操作員隨時在場監督多站**：並行收集的經濟性依賴此前提，全自主場景下不成立。

| ENPIRE (2026) | agent 管 reset/rollout | agent 編排 | agent + 模仿 | 真機自改進 |
| **Recova (本文)** | **解耦 task/rec 雙策略 + 技能庫** | **學習策略 or 程式化技能，視覺驗證** | **數位孿生開發 + 並行 DAgger 分流** | **多任務、多站真機部署** |

**面試 Tip**：被問到 Recova 與 ASPIRE/RATs 的區別時，一句話答——**它們是 code-as-policy 的技能發現框架，而 Recova 的關鍵在於把「恢復」提升為與任務平級、可跨任務複用的獨立策略，並用四次 VLM 查詢把失敗交接轉成資料標籤**；它不是更強的 VLA，而是一套把既有 VLA 包進「失敗—恢復—學習」閉環的編排系統。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做 VLA 真機部署、被「一次小失誤就卡死」困擾的研究者/工程師；
  2. 要設計 real-to-sim-to-real 資料閉環、評估人機協作收集成本的人；
  3. 研究 agent 如何把自然語言失敗診斷轉為可複用技能的人。
- **建議章節路徑**：先讀 §3.3（真實部署四步：Monitor/Detect/Decide/Verify）→ 再看 §3.4 + Eq. 1（資料分流）→ 最後 §4.2（真機數字與介入率曲線）。§2 相關工作可快速掃，作為 baseline 地圖。
- **不值得精讀的理由**：如果你不做機器人學習、或已熟悉 RecoveryChaining/DAgger 家族，讀摘要 + §4 表格即可——它的新意在**編排與閉環**，不在單一模型或損失函數的創新。
