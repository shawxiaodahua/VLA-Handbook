## 1. 核心架構/方法總覽 (Overview / Architecture)

这不是一篇「提出模型」的论文，而是一篇**受控实验论文**。它的「架构」是三层证据链：定位病灶 → 证伪疗法 → 最小对修复。要读懂它，先看它的系统部件。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | Teacher (Octo-Base-1.5) | Student (8 层蒸馏) | 差异/说明 |
|------|------------------------|-------------------|-----------|
| Transformer 层数 | 12 层 | 8 层（expert surgery 保留 `{0,1,3,4,6,8,10,11}`：两个边界层 + 均匀内部采样） | 蒸馏对象 |

| 训练数据 | Open X-Embodiment (OXE) 混合 | 同 OXE，300k steps，batch 128 | 同分布训练 |
| 训练目标 | diffusion action head 原生 loss | 凸组合：`α·hidden-state 蒸馏 + (1-α)·action head 原生 loss`，α=0.5 | 蒸馏用 cosine 距离，覆盖 observation/task/readout token 组 |

### 1.2 关键机制 (Key Mechanism)

- **压缩是「轻度」的，恰恰让它更有信息量**：只掉 14% 参数、只快 1.08×，离线指标毫发无损，却导致类目级别的闭环失败。作者论点：正因为幅度小，无法用「容量不足」搪塞。
- **失败是结构化的，不是弥散的**：早期阶段「逐渐降级」，最后阶段「类目性崩塌」——这正是「部分状态区间的条件映射坏掉」的指纹，而不是「整体能力滑坡」。
- **否定法（needness arm）**：四种由浅入深的疗法依次失败，每一条排除一类简单解释，逼着作者往上游（训练监督）走。
- **最小对（minimal pair）修复**：唯一变量换成 `ρR`（batch 中部署 rollout 的占比），其余全部锁死，用执行记录逐项核对。

⚡ **Eureka Moment**：闭环失败的**近因**不是任何单一动作通道的 bug，而是「学到的、状态条件的动作映射存在缺陷」——它最明显的投影是晚期偏重的负 z 残差，但残差是**症状不是病灶**；把症状强行夹住，策略依然无法 transport。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
闭环失败 ≠ 离线指标差；失败 = 状态条件映射缺陷 × 协变量漂移的复利放大
```

本文没有引入新的损失函数，它的「数学」体现在**蒸馏目标**与**诊断/干预的量纲约定**上。

### 2.1 蒸馏目标（训练）

```
L_student = α · L_distill + (1 - α) · L_action,      α = 0.5
L_distill = 1 - cos( h_student , h_teacher )   # 对 observation / task / readout token 组分别取余弦距离
L_action  = diffusion action head 的原生去噪损失
```

变量说明：

| 符号 | 含义 | 取值/量纲 |
|------|------|-----------|
| α | 蒸馏项权重 | 0.5（凸组合，无任务/z 专用项） |
| L_distill | 隐藏态余弦蒸馏损失 | 300k 步末 ≈ 0.010 |
| L_action | 动作去噪损失 | 均值 0.98（每 100 步记录区间 0.81–1.23） |
| grad norm | 梯度范数 | 均值 4.3（3.6–5.3） |

> 训练遥测全程稳定，说明「训练没崩」——这本身就是本文的关键背景：student 的崩塌不是训练不收敛造成的。

### 2.2 诊断量：配对 z 残差（核心测量）

```
dz(panel) = mean_over_episodes( z_student(t) - z_teacher(t) )
```

变量说明：

| 符号 | 含义 | 注 |
|------|------|-----|
| z | 每步世界坐标系平移命令（action 反归一化后） | 单位：米；+z = 向上 |
| panel | 固定的 4 个困难初始化 ID {2,11,14,23} | 从 6 episode 列表中，选 teacher 也失败的 4 个 |
| 时间三分 | 120 步 rollout 按步数等分三段 | 非 grasp 对齐阶段（V1 只 grasp 2/4） |

关键读数（V1 失败学生）：

```
全 rollout:  dz = -0.0067
末三分:      dz = -0.0103        ← 「晚期偏重」的负残差签名
连续训练两支:  全 -0.0067 / -0.0048 / -0.0047，末 -0.0103 / -0.0073 / -0.0081
修复后:      全 +0.0009，末 -0.00065  ← 被消除（数量级下降）
```

**直觉**：学生相对 teacher 在**晚期向上位移不够**，任务在 transport 阶段无法把物体抬到目标。但 §5 的干预会证明：这只是「最可见的投影」，不是病灶本身。

### 2.3 证据分级（论文的纪律性）

| 证据等级 | 内容 | 承载的主张 |
|----------|------|-----------|
| **计数型** (counted) | 36/24 次试跑的成功与阶段计数 | 承载**所有因果主张** |

## 3. 帶數字走一遍：玩具例子 (Worked Example)

用一个极简「抬升」直觉走一遍 closed-loop 复利。

假设一个 3 步的 transport 子序列，teacher 每步世界系 z 命令（单位米，+z 向上）：

```
teacher z:  [+0.010, +0.008, +0.006]
student z:  [+0.004, -0.001, -0.004]   # 晚期偏重负残差
```

逐步差：

```
t1: 0.004-0.010 = -0.006
t2: -0.001-0.008 = -0.009
t3: -0.004-0.006 = -0.010
全段 mean dz ≈ -0.0083   (晚期更大)
```

**复利效应（闭环的关键）**：这一步的小差会改变物体/夹爪的物理状态，下一步学生看到的是**它自己造成的**、teacher 从未见过的状态（off-distribution），于是误差再放大。三步后物体高度差可能累积到几厘米——足以让「放置到目标」判定失败。

**为什么加法补偿救不了**：如果病灶只是常数偏置，加 `+0.006` 就应恢复。但论文扫 `{0.002, 0.004, 0.006, 0.008, 0.012, 0.020}`，成功数读作：

```
offset:  0     0.002  0.004  0.006  0.008  0.012  0.020
success: 1     0      1      0      0      0      0     (out of 36)
```

全部落在学生「地板区间 0–2/36」内。而**同一个工具**施加在健康策略上会单调变差（offset ≥ 0.008 时让所有策略都抓不起来）——所以「工具迟钝」不是借口，是「加法偏置假设被排除」。

## 4. 工程視角 (Engineering View)

| 工程维度 | 论文中的数字/事实 | 工程含义 |
|----------|------------------|----------|
| 压缩收益 | 参数 202.5M→174.1M，延迟 135.4→124.9 ms (1.08×) | 收益极小，风险极大——**不值得为这点延迟赌闭环成功率** |
| 离线验收成本 | 600 条 held-out 轨迹，全部给 teacher 级分 | 离线再贵也不能替代闭环 |
| 闭环探针成本 | **24 次闭环 rollout 就完全分开两个策略**；1 次配对轨迹比对就定位签名 | 验收流水线应加几十次闭环探测，成本可忽略 |
| 控制频率 | 120 步 rollout，gripper 二值化阈值 0.75 | 每步动作量纲一致（米），便于残差比对 |
| 复现性抖动 | teacher 重跑 15/24 vs 14/24；±1 归因于 120 步 GPU 浮点非确定性 | 报「parity」而非「超越」，因为差异落在重复性噪声内 |
| 修复数据规模 | 324 条成功 teacher rollout → RLDS 38,880 帧；被复看 ≈13 次 (到 step 8k) | 小数据、非额外预算（替换而非增加），排除「多训了」的解释 |
| 内存/部署 | 8 层仍能恢复 parity | 压缩不是容量上限问题，是**监督分布**问题 |

工程结论：**部署前对压缩策略做闭环探测（几十次）应成为新的验收规范**；离线 gate（含厂商自带指标）只能当必要条件，不能当充分条件。

## 5. 數據與評測 (Data & Eval)

**离线侧**
- 验证：训练混合的三个 in-distribution 数据集 Bridge / Fractal / Kuka，各 200 条 held-out。
- 指标：gripper-prediction accuracy 与 EE 平移方向误差，比值定向为「1.0 = parity」。
- 追加保留扫描：3 个分布外数据集（fridge-opening / tabletop rotation / pouring，各 200）。六个探针中，student 在 4 个方向误差上领先；最好的 fridge-opening 上 student 13.3°/0.914 严格精度 vs teacher 14.2°/0.918——**离线电池无法区分 student 与一次成功蒸馏**。

**闭环侧**
- 环境：SimplerEnv / ManiSkill2 (SAPIEN)，`PutEggplantInBasketScene-v0`，WidowX 机械臂。
- 规模：72 配置 = seeds {0,1,2} × episode IDs 0–23；单 seed 切片（24 配置）带密集仪表。
- 阶段谓词（环境自带评估器）：object moved → grasped → sustained hold (≥5 连续步) → transport to target。
- 数据划分（修复阶段）：**selection set** = IDs {0–2, 9–14, 21–23}；**held-out set** = IDs {3–8, 15–20}（12 ID × 3 seeds = 36 配置）。checkpoint 只用 selection set 选，选完后**锁定**，held-out 每个 checkpoint 只评一次。

**修复数据**
- 324 条部署环境成功 teacher rollout（记录 seed {100–179}，与评测 seed {0,1,2} 不相交；held-out IDs 永不录制）。
- 打包成 RLDS，38,880 帧；图像全栈指纹确认 324/324 唯一、零往返误差；动作归一化统计与学生**逐位一致**（`max|Δ|=0`）。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做什么**
- 在单一仿真抓放任务上，把「离线满分、闭环归零」的失败**定位到阶段**（transport）与**动作签名**（晚期偏重负 z 残差）。
- 用最小对证明：**替换**一半训练流为部署分布 teacher rollout（`ρR=0.5`）可恢复到 teacher parity（held-out 18/36 vs 17/36），且消除签名、恢复 teacher 式扰动响应曲线。
- 证明修复不是靠忘记：held-out grasp 34/36（未修复学生仅 17/36）。

**不能做什么 / 失败模式**
- **不证普适性**：明确「我们主张存在性，不主张所有压缩 VLA 都这样」。单机器人、单任务、仿真。
- **无法定位内部表征**：压缩→崩塌的「表征路径」是论文够不到的那一层，属系统级推断。
- **修复包是多属性共变**：rollout 数据同时带来部署状态覆盖、success-only 过滤、teacher 一致标签等，**无法拆出哪一项是活性成分**（success-only 过滤是作者自曝的未测局限）。
- **容量洗清**：teacher 在同离线语料上训不出此缺陷；同一 8 层网络一旦被重新监督即可恢复 → 压缩是「使能条件」，不是「容量判决」。

### 6.1 隱含假設 (Hidden Assumptions)

- 假定 SimplerEnv 的 gripper 二值化阈值 0.75 对该模型家族是正确的（用旧 Octo base 做 sanity run 验证，但对 1.5 家族是否最优未深究）。
- 假定「配对 4-episode 面板」的残差签名可外推到全 72 配置（作者自己限定该主张只在面板级）。
- 假定 rollout 数据「成功过滤」不会引入偏差（论文承认这是未测的混淆项）。
- 假定 teacher 的 17/36 与 student 的 18/36 差异是噪声而非真实提升（回落到 ±1 重复性）。

  3. 研究离线-闭环落差、covariate shift 复利效应的学习者。
