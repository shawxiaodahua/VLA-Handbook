💡 **X-Ray 开场**
论文先问：自回归机器人视频世界模型越长越乱，是因为历史留得不够多吗？作者的观察是「不是」——全量保留历史时，模型对最近一帧的注意力反而随 rollout 衰减（图 1a）。于是它把上下文按功能分三类：永久场景锚点、最近视觉–动作状态、陈旧生成历史，只留前两类。对 VLA 研究者的意义是：**长程稳定性可以是一个推理期上下文调度问题，而不必然是重训问题**。

## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 组件 | 输入 | 输出 | 时序/频率 | 训练 or 推理 |
|------|------|------|-----------|--------------|
| 视觉 tokenizer E_v | 观测 o_t | z_t（上下文帧 1280 token；动力学帧 80 token） | 每帧一次 | 冻结 |
| 动作 tokenizer E_a | 动作 a_t | u_t（13 token） | 每帧一次 | 冻结 |
| 世界模型 p_θ | 活跃上下文 C_t | ẑ_{t+1} | 每 token 自回归，每帧 80 个视觉 token | 冻结 |
| 视觉解码器 D | ẑ_{t+1}, C_0 | ô_{t+1} | 每帧一次 | 冻结 |
| 上下文调度器 S（ReCAP） | B_{1:t} | A ⊕ R_t | 每帧追加一块、逐出最老一块 | **无参数、纯推理** |

关键量：一个视觉–动作块 B_i = [z_i; u_i] 共 93 token（80 视觉 + 13 动作）；锚点 A = 1280 场景 token + 93 初始块 = 1373 token；W = 6 时活跃输入上限 1931 token。

### 1.2 关键机制

- **按角色切分上下文**：锚点（真实观测，无自回归误差，提供机器人形态/物体身份/工位布局）、最近连续窗口（当前机器人状态与动作演化）、陈旧历史（被逐出）。
- **块级而非 token 级调度**：一个物理时间步对应一个结构化 token 块，碎片化会破坏空间连贯与动作对齐，因此逐出以「整块」为单位。
- **保序与连续**：R_t 取尾部连续 W 块，保留块内结构与因果顺序，不做重编码、不把生成 token 解码回图像再编码。
- **有界性**：t ≥ W 后活跃 prompt 与 KV 都不再随 rollout 增长（式 7、式 8）。

⚡ **Eureka Moment**：把「保留更多历史」换成「保留正确角色的历史」，并且把调度单位从 token 提升到完整视觉–动作块。

### 1.3 信息流/架构图

```
真实初始观测 o_{1:C}
      │
      ├─► 锚点 A = C_0 ⊕ z_0 ⊕ u_0  ────────────────┐（永久保留）
      │                                              │
step t: 最近块 R_t = B_{max(1,t-W+1) … t}  ──────────┤
      │                                              ▼
      │                                   P_t = A ⊕ R_t  (≤1931 token)
      │                                              │
      │                                   p_θ 逐 token 采样 80 个视觉 token
      │                                              │
      │                                   B_{t+1} = [ẑ_{t+1}; u_{t+1}]
      │                                              │
      └──────────────  R_{t+1} = Tail_W(R_t ⊕ B_{t+1})  ← 逐出最老整块
                                                     │
                                            D(ẑ; C_0) → ô
```

## 2. 数学核心

📌 **Napkin Formula**：

```
ReCAP: C_t = A ⊕ B_{max(1, t-W+1) : t}      （锚点 + 最近 W 个完整块）
```

目标（式 2）：在参数冻结与上下文预算约束下最小化长程预测误差。

```
S* = argmin_S  E[ Σ_{t=C}^{C+T-1} ℓ(ô_{t+1}, o_{t+1}) ]
     s.t.  |C_t| ≤ M ,  θ fixed
```

单步生成（式 4）：

```
ẑ_{t+1,j} ~ p_θ( · | A, R_t, ẑ_{t+1,<j} ),   j = 1 … n_v
```

上下文长度与 KV 占用（式 7、式 8）：

```
N_t^full    = n_A + t·n_B
N_t^ReCAP   = n_A + min(t, W)·n_B  ≤  n_A + W·n_B

M_KV^ReCAP(t) = 2·L·d·b·N_t^ReCAP  ≤  2·L·d·b·(n_A + W·n_B)
```

| 符号 | 含义 | 本文取值 |
|------|------|----------|
| n_A | 锚点 token 数 | 1373 |
| n_B | 单块 token 数 | 93 |
| W | 最近窗口块数 | 6 |
| L / d / b | 层数 / 隐藏维 / 每元素字节 | 12 / 768（KV 头 12、头维 64）/ 2（BF16） |
| n_v | 每帧视觉 token | 80（不计入输入预算） |

直觉：Full Context 的成本随 rollout 线性增长，而 ReCAP 在 t ≥ W 后是一条水平线；但**长度有界不等于信息无损**——被逐出的块其注意力贡献无法恢复。

> 注意：式 6 只是形式化的 KV 更新记号。作者明确说明「token 选择不等价于缓存激活不变」：BridgeV2 参考后端在逐出后**重建 KV 并重定位置基准**（附录 B.6），缓存管理与块选择算法是两件事。

## 3. 带数字走一遍：玩具例子

**（A）小型假设例子（假设数值，非论文实测）**
设 n_A = 200，n_B = 10，W = 2，L = 2，d = 8，b = 2 字节，则每 token KV = 2·2·8·2 = 64 B。

| 步 t | Full N_t | ReCAP N_t | Full KV | ReCAP KV |
|------|----------|-----------|---------|----------|
| 1 | 210 | 210 | 13,440 B | 13,440 B |
| 2 | 220 | 220 | 14,080 B | 14,080 B |
| 4 | 240 | 220 | 15,360 B | 14,080 B |
| 6 | 260 | 220 | 16,640 B | 14,080 B |

验算：t ≤ W 时两者完全一致——这与论文「前七个预测在逐出前产生相同视觉 token」的说明一致（附录 B.6）。t > W 后 ReCAP 每步增量为 0，Full 每步 +10 token。

**（B）论文配置下的算术校验（用论文公式验证论文表格）**
- 上限：1280 + 93 × (1 + 6) = 1280 + 651 = **1931** ✓（附录 B.3 式 9）
- H=64 时 Full：锚点已含初始块，故为 1373 + 63 × 93 = 1373 + 5859 = **7232** ✓（表 3）
- KV：7232 × 36,864 B ≈ 254.2 MiB；1931 × 36,864 B ≈ 67.89 MiB ✓（与表 3 的 254.25 / 67.89 MiB 吻合）
- 比值 1931 / 7232 ≈ 0.267，即 −73.3% ✓

这一步说明表 3 的 −73.3% 不是独立测量，而是 token 数与每 token KV 占用的直接推论；逻辑 KV 不含分配器开销、激活与工作区。

工程含义：

- **延迟收益远小于内存收益**。p50 只降 6.51%；该数据来自 vLLM BF16 基准，不能归因于 BridgeV2 参考后端的逐出后 KV 重建；ReCAP 的主要收益在**并发吞吐**（1.07× @1 → 2.94× @32 → 4.28× @256），即显存腾出来给 batch。
- **逐出不是免费的**：BridgeV2 后端在逐出后重建 KV 并 rebase 位置索引，这部分开销论文未单独报告；换后端时它是首要变量。
- **部署约束**：效率数字在独占 H20、vLLM 0.13.0、BF16、eager/-O0、max_model_len=8192、每帧预留 80 输出 token、关闭 automatic prefix caching、2 次预热 + 5 次测量的条件下取得，且只覆盖世界模型生成延迟。
- **实时性判断（我的条件性分析）**：约 293 ms/帧仍不足以支撑高频闭环控制；ReCAP 改善的是长程画质与吞吐，不是单帧实时性。
- **Full Context 截断阈值**：rollout 第 72 步后 prompt 才被截到 7,900 token；H=64 时 Full Context 的 prompt 为 7,232 token，尚未触发截断，因此该对比仍是完整全历史。

| 免训练迁移到多骨干 | iVideoGPT、RobotAlign-R1 上同向 | RLVR-World 需按数据集先做 tokenizer + 世界模型适配，并非零成本；另两骨干的适配范围原文未展开 |

### 6.1 隐含假设

1. **最近 W 块足以刻画当前动力学**。对缓慢变化的桌面操作成立；对长时遮挡后重现、需要回访早期物体状态的任务，W=6（6 个完整视觉–动作块）可能不足。论文未做独立的 W 扫描或自适应策略；附录 E 的场景前缀实验在固定预算下间接改变了最近窗口块数。
2. **初始锚点长期有效**。锚点来自真实观测，误差为零，但若场景光照/视角大幅变化，固定锚点可能成为误导。附录 E 显示锚点从 4 token 扩到 1280 token 只换来 0.005 的 Late LPIPS 改善，提示「锚点语义分辨率」的边际收益很低——但这是 LIBERO-90 静态相机下的结论。
3. **块内 token 不可分割**。论文论证了碎片化会破坏空间连贯，但没有做「块内选择性保留」的对照，因此无法判断块粒度本身是否过粗。
4. **注意力下降 = 信息冲突**。作者自己承认注意力下降也可能来自位置编码外推失效、缓存更新方式或单纯的注意力归一化变化（移 token 会改变归一化）。
5. **推理预算与适配长度匹配**。1,931 token 恰好等于世界模型适配时的训练序列长度（附录 B），这可能给 ReCAP 带来长度匹配上的隐性优势，论文将此列为未解混杂。

## 7. 与相关工作对比

| 方法 | 调度粒度 | 是否保留锚点 | 是否需训练/改架构 | 适用对象 |
|------|----------|--------------|-------------------|----------|
| Full Context | 全保留 | — | 否 | 基线 |
| H2O / Scissorhands / SnapKV | token 级重要性 | 否 | 否 | 语言模型 KV |
| StreamingLLM 类 | 初始 + 最近 token | 是（token 级） | 否 | 语言模型流式解码 |
| Anchor + Uniform（本文消融） | 块级均匀采样 | 是 | 否 | 机器人视频 |
| Recent Only（本文消融） | 仅最近块 | 否 | 否 | 机器人视频 |
| **ReCAP** | **完整视觉–动作块** | **是** | **否** | **冻结的机器人视频世界模型** |

差别要点：语言模型的驱逐单位是 token，机器人 rollout 的单位必须是「一帧视觉 + 一步动作」的结构化块；且锚点在这里承载的是机器人形态与工位布局这类持久语义，不只是 attention sink。

🎤 **面试 Tip**：被问到「这和 StreamingLLM 的 attention sink 有什么区别」时，答：机制直觉同源（保留早期 + 最近），但单位从 token 换成完整视觉–动作块，且额外论证了块内结构不可碎片化；同时要主动说明本文的因果归因未与长度/位置效应解耦。
