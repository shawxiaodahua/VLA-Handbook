💡 **X-Ray 開場**

想像你讓一個機器人「先在腦子裡預演五步，再挑一條最接近終點的路」。這篇論文問的是：如果真正的終點在 30 步之外，而它只預演了 5 步，這個「憑想像挑動作」的機制還靠譜嗎？答案是——**不靠譜，而且即使把預測器放大 81 倍、用完美的模擬器來預測，也一樣不靠譜**。真正能救它的是兩件事：把終點拉進預演範圍（延長 rollout），或者把遙遠終點拆成一串「近端子目標」。對 VLA 研究者，這意味著：世界模型作為 critic/驗證器是有用的（能把 π0 從 65% 提到 77%），但作為長程規劃器，它的瓶頸是距離，不是模型大小。

## 1. 核心架構/方法總覽 (Overview / Architecture)

這不是一篇「提出新模型」的論文，而是一篇**受控診斷研究**：作者把世界模型的每一根螺絲擰到固定，只轉動一根來測量「規劃範圍」如何變化。

### 1.1 系統對比概覽 (System Component Comparison)

| 模塊 | 角色 | 輸入 | 輸出 | 訓練/推理差異 |
|------|------|------|------|----------------|
| 凍結視覺編碼器 | 提供跨環境可遷移的表徵 | 256×256 影像（角落相機） | latent 特徵 | **凍結**，不在 Meta-World 上自適應 |
| 動作條件預測器 | 在 latent 空間推演未來 | 視覺 token + 動作塊 | 下一步 latent 殘差更新 | 可訓練；同一架構對所有編碼器 |
| 規劃器（CEM） | 搜尋動作序列 | 候選動作序列 | 評分後執行的最好動作 | 推理期；3 次迭代 + warm start |
| 距離評分 | 判「離目標多近」 | 想像出的 latent vs 目標 latent | cosine 距離分數 | 推理期目標函數 |
| 真實模擬器 | 「完美預測」對照組 | 動作 | 精確下一狀態 | 用於分離「預測誤差」與「目標位置」兩個因素 |

預測器規模：**3,754,240 參數**，transformer width 256、4 個 block、4 個 attention head、MLP 擴張比 4、4 步狀態歷史、對時間方向做因果注意力、預測對最後 latent 的**殘差更新**。所有編碼器共用同一預測器架構，只單獨調訓練。

### 1.2 關鍵機制 (Key Mechanism)

- **為什麼凍結編碼器**：要測試「本來就設計來跨環境遷移的表徵」到底能不能支撐規劃，所以不能讓編碼器針對任務過擬合。
- **為什麼用同一預測器架構**：把「編碼器」變成唯一自變量，讓不同表徵的差異可比。
- **為什麼對照「真實模擬器」**：這是全文最漂亮的一刀——把「預測是否準」和「目標落在哪」徹底解耦。若連完美預測都失敗，那問題就不在預測器。

⚡ **Eureka Moment**：**世界模型的規劃瓶頸不是「預測得準不準」，而是「目標離想像軌跡的終點有多遠」——把終點拉進預演範圍，比把預測器做大 81 倍更有效。**

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
可規劃範圍 P* = 最大的目標前瞻 L，使「專家動作百分位」≤ 10
```

先給目標：定義「世界模型往前多遠還能把專家動作排在隨機動作之上」。再給公式。

**動作序列評分（Eq. 1）**：對候選動作序列 a，取其在 K 步 rollout 內與目標 latent 的**最接近距離**：

```
J_L(a) = min_{1 ≤ k ≤ K} [ 1 − cos( ẑ_{t+k}(a), z_demo_{t+L} ) ]
```

**專家百分位（Eq. 2）**：100 條隨機序列中，有多少條的 J 比專家更低（更低 = 離目標更近）：

```
q_L = (100 / M) · Σ_{i=1}^{M} 1{ J_L(a_i) < J_L(a_expert) },   M = 100
```

**可規劃範圍 P***: 任務平均 q_L ≤ 10 的最大測試 L（否則為 0 = 診斷失敗）。

變量說明：

| 符號 | 含義 |
|------|------|
| K | rollout horizon：規劃時想像多少個控制步 |
| L | target lookahead：目標在多少控制步之後 |
| 1 控制步 | = 2 個環境動作 |
| q_L | expert percentile，越低越好；chance = 50 |
| P* | plannable range，本文核心度量 |

> 符號與原文一致：ẑ = 預測 latent，z_demo = 專家觀測編碼後目標 latent，cos = cosine 相似度。
> 直覺：K 是「我能預演多長」，L 是「終點有多遠」。當 L 遠大於 K，所有候選的 ẑ 都停在半路，離終點都差不多遠 → 分數無法區分好壞 → 百分位退化到 50（隨機）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設一個 1D latent 玩具：目標在 20 步之外，rollout K = 5。用 cosine 距離打分的世界模型。

**情境 A：L = 20，K = 5（目標遠超 rollout）**
- 專家軌跡前 5 步：逐步靠近但不是終點，例如 latent 位置 0.0 → 0.15 → 0.30 → 0.44 → 0.58（距終點 1.0 仍遠）。
- 100 條隨機序列：多數亂走，但**沒有一條能到終點**，5 步後 latent 大都在 0.2–0.6 區間。
- 結果：專家序列的 min 距離和一堆隨機序列的距離**重疊** → q_20 ≈ 50（chance）。**判定失敗**。

**情境 B：L = 5，K = 5（目標剛好在 rollout 末尾）**
- 專家第 5 步 latent 幾乎落在目標上（cos ≈ 0.99，J ≈ 0.01）。
- 隨機序列第 5 步仍散在遠處（J ≈ 0.3–0.8）。
- 結果：幾乎所有隨機序列的 J 都大於專家 → q_5 ≈ 2–5。**通過門檻 10**。

**情境 C：L = 20，K = 20（想像直到抵達目標）**
- 專家第 20 步落在終點，隨機序列即便晃到附近也比專家更遠 → q_20 重新回到低值。**範圍被延長**。

這個玩具例子就是全文的核心：**決定成敗的不是預測器好壞，而是 L 和 K 的相對關係**。作者用真實模擬器（完美預測）作對照時也看到同樣的模式（見 §5.5）。

真實尺度上的數字：16 個 Meta-World 任務的專家示範需 **16–53 步**完成（典型約 **33 步**），而 5 步 rollout 的可規劃範圍只有約 **10 步**——**只覆蓋典型任務的約 30%**。

## 4. 工程視角 (Engineering View)

| 工程維度 | 觀察 | 含義 |
|----------|------|------|
| 計算 vs 範圍 | 30 步 rollout ≈ 5 步 rollout 的 **6×** 計算 | 延長 rollout 直接換算成算力成本 |
| CEM 成本 | 標準設定每次控制步要評分**數百**條候選，3 次迭代 | 純世界模型規劃 = 大搜索，多數候選與任務無關 |
| MPC 頻率 | 每控制步重規劃，單 episode 最多 replan **100 次** | 反饋有延遲與抖動代價；短 rollout 下反饋收益小 |
| 容量 | 預測器放大 **81×** 不改變可規劃範圍 | 別指望「更大模型 = 更遠規劃」 |
| 評分函數 | cosine→Euclidean 也不延長範圍 | 瓶頸在目標位置，不在距離度量選型 |
| 邊界 | 1 控制步 = 2 環境動作；episode 上限 200 環境動作 = 100 控制步 | 部署時的控制頻率與 rollout 長度需一起權衡 |

**核心工程結論**：與其花 6× 算力延長 rollout，不如**給近端子目標**——在相同 5 步預算下，子目標把成功率從 30% 提到 76%，遠超 30 步 rollout 的 47%。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

| 能做 | 具體證據 | 不能做 | 原因 |
|------|----------|--------|------|
| 目標在 rollout 內時可靠排序動作 | L=5, K=5 時 q ≤ 10 | 目標遠超 rollout 時失效 | 候選 ẑ 都停在半路，分數無法區分 |
| 作為 VLA 的驗證器/critic | π0 65% → 77%（16 任務） | 修復「候選全都很差」的策略 | 新物體/動作任務兩者都近 0 |
| 近端子目標下完成長任務 | 5 步子目標 76% | 無示範時自生成子目標 | 子目標來自專家 rollout |
| 在 latent 空間規劃（不需重建像素） | 凍結編碼器 + 輕量預測器 | 取代真實 dynamics | 連完美模擬器在 L>>K 時也掉到 41% |

### 6.1 隱含假設 (Hidden Assumptions)

- **假設「距離越近 = 動作越好」**：作者明確指出此假設會失敗——像「先移動夾爪到位再抓取」這類**先遠離再接近**的動作，會先增大距離。
- **假設成功由「匹配演示下一步」代理**：可規劃範圍用「排序專家動作」定義，而非真實閉環成功；作者用閉環實驗部分驗證，但兩者並非同一目標。
- **假設凍結編碼器的表徵足夠通用**：只測了 5 種編碼器，且都是 ViT-L 級別。
- **假設子目標可得**：閉環 76% 依賴同 episode 專家 rollout 的近端子目標，脫離示範的可行性未驗證。
- **假設線性外推**：某些任務在最大測試 L=20 仍通過（右截斷），真實範圍可能更長。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**世界模型驅動規劃 / MPC** 的研究者——§5.5 的「距離評分假設」值得逐字讀；
  2. 評估**把世界模型接到 VLA 當 critic** 是否划算的工程師——§7 有完整的 candidate sweep；
  3. 想設計**層級規劃 / 子目標生成**的人——§6.3 給出「為什麼近端子目標最有效」的受控證據。
- **建議章節路徑**：先讀 §4（可規劃範圍的定義與測量）→ 再看 §5.5（為什麼距離評分會崩）→ 再讀 §6.3（子目標為何最有效）→ §7（VLA–WM 應用）。§2 相關工作與附錄 A 可略讀。
- **不值得精讀的理由**：如果你不做機器人學習、或已熟悉 TD-MPC2/DINO-WM 這類凍結編碼器規劃，**讀摘要 + §4 + §6.3 即可**——方法本身不新，價值在診斷結論。
