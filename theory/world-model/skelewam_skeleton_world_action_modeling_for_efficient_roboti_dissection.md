## 1. 核心架構/方法總覽 (Overview / Architecture)

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 時序/頻率 | 訓練 vs 推理差異 |
|------|------|------|-----------|------------------|
| 骨架抽取器 Φ_ψ（凍結感知網路 + 正向運動學） | RGB-D 觀測 o_t、機器人本體狀態 q_t、語言 ℓ | 稀疏骨架 S_t ∈ R^{N×3} | 每次重規劃時線上構造 | 訓練/推理皆用；網路**凍結**不更新 |
| World Expert（骨架 token 處理） | 當前骨架 token + 噪聲化未來骨架 token | 未來骨架向量場 v̂^s | 單次前向 | **僅訓練**（推理時整支丟棄） |
| Action Expert | 噪聲化動作 chunk token | 動作向量場 v̂^a | 單次前向 | 訓練 + 推理皆用 |

| MAC 共識選擇 | K 條隨機初始化的動作樣本 | 1 條代表動作 chunk | 每次推理 | **僅推理**（無需獎勵模型） |

關鍵設計：World Expert 與 Action Expert 採 **two-expert Mixture-of-Transformers**（沿用 Fast-WAM 結構），共享當前骨架上下文；未來骨架分支在推理時可整段移除。

### 1.2 關鍵機制 (Key Mechanism)

- **為什麼用骨架而非視頻/latent**：視覺 latent 的資訊內容被「視覺編碼器及其預訓練目標」決定，壓縮觀測**本身不會**隔離出真正驅動操作的那些幾何變量（空間排布、相對運動）。骨架把這些變量直接參數化成顯式狀態。
- **為什麼「物體中心 + 交互點」兩者都要**：中心提供穩定的空間錨點，交互點描述「可能被碰觸」的區域。消融顯示兩者合併（85.9%）遠優於僅中心（82.3%）或僅交互點（77.7%）。
- **為什麼未來骨架只在訓練用**：把未來幾何當**輔助監督**去塑造共享表徵，推理時不需要世界預測 → 既拿到幾何歸納偏置，又不付推理成本。移除該損失直接掉 5.8 個百分點（85.9% → 80.1%）。
- **分支間不互相注意**：消融顯示跨分支注意力差異極小（85.9% vs 85.6% vs 84.8%），主要收益來自「共享 World Expert 的共同訓練」，因此選擇關閉跨分支注意力，好處是推理時能乾淨地砍掉未來分支。

⚡ **Eureka Moment**：**操縱中最關鍵的資訊不是「畫面長什麼樣」，而是「機器人與物體在 3D 空間中的相對幾何」——把它抽成幾十個點的稀疏骨架，就能用極小的模型同時做動作生成與有價值的地基監督。**

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
動作流匹配 + 骨架流匹配聯合訓練：L = E[MSE(v̂_a, ε_a − A_t)] + λ_s · E[MSE(v̂_s, ε_s − S+_t)]
```

**目標**：在語言 ℓ 條件下，同時學會生成動作 chunk（推理用）與預測未來骨架（僅訓練用的幾何監督），兩者共用同一個 World Expert 的當前骨架上下文。

**問題設定**：
```
動作 chunk:   A_t = [a_t, ..., a_{t+Ha-1}] ∈ R^{Ha×da}
當前骨架:     S_t = Φ_ψ(o_t, q_t, ℓ) ∈ R^{N×3}
未來骨架序列: S+_t = [S_{t+δ1}, ..., S_{t+δHs}] ∈ R^{Hs×N×3}，0 < δ1 < ... < δHs
聯合分佈:     p^a_θ(A_t | S_t, ℓ)  ，  p^s_θ(S+_t | S_t, ℓ)
```

**骨架組成**（單一物體 m）：
```
P_{t,m} = [ c_{t,m} ; u_{t,m,1} ; ... ; u_{t,m,Lm} ] ∈ R^{(1+Lm)×3}
S_t     = [ J_t ; P_{t,1} ; ... ; P_{t,M} ]
N       = Nr + Σ_{m=1..M} (1 + Lm)
```

**流匹配插值與目標向量場**：
```
Ã_{t,τa}   = (1 − τa)·A_t  + τa·ε_a         （τa: 0=資料, 1=噪聲）
S̃+_{t,τs}  = (1 − τs)·S+_t + τs·ε_s
v_a = ε_a − A_t ，  v_s = ε_s − S+_t
L_action   = E[ MSE(v̂^a_θ, v_a) ]
L_skeleton = E[ MSE(v̂^s_θ, v_s) ]
L          = L_action + λ_s · L_skeleton
```

**注意力遮罩**（行=query 群組，列=key/value 群組；1=允許，0=遮蔽）：
```
          cur  act  fut
 cur   [   1    0    0  ]   當前骨架 token 只在自己群組內注意
 act   [   1    1    0  ]   動作 token 注意當前骨架 + 自己
 fut   [   1    0    1  ]   未來骨架 token 注意當前骨架 + 自己
                            （動作與未來骨架之間互不注意）
```

**推理 ODE 積分**（從純噪聲 τ=1 回到資料 τ=0）：
```
dÃ_{t,τ}/dτ = v̂^a_θ( Ã_{t,τ}, τ ; S_t, ℓ ) ，  τ: 1 → 0
A_t = Ã_{t,0}
```

**Medoid Action Consensus (MAC)**：對 K 條獨立噪聲初始化的候選動作，取其前 h 步、前 dm 個連續運動維度，在歸一化動作空間算兩兩距離：
```
d_ij = (1 / (h·dm)) · ‖ (A^(i))_{1:h, 1:dm} − (A^(j))_{1:h, 1:dm} ‖_F^2
c_i  = (1 / (K−1)) · Σ_{j≠i} d_ij
i_sel = argmin_i c_i        →  選出「離其他樣本平均最近」的那一條
A^MAC = A^(i_sel)           （保留整段 chunk，含未參與距離計算的維度）
```

> 符號與本文/相關文檔保持一致：Ha=動作視界、da=動作維度、Hs=未來骨架步數、N=骨架節點數、Nr=機器人節點數、M=物體數、Lm=物體 m 的交互點數、λ_s=骨架損失權重、τ=流匹配噪聲時間、h=MAC 共識窗口、dm=參與距離計算的運動維度。

**直覺**：動作生成與未來骨架預測是兩個流匹配任務，共用同一條「當前骨架」上下文；關鍵洞見在於**只用當前骨架做條件**——未來預測的價值在於「逼」共享表徵學到操縱動力學，而非在推理時真的去想像未來。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

設一個 2D 平面抓取任務。動作 chunk 的每個時間步取 2 個連續運動維度（dm=2：x、y），MAC 只看前 h=2 步。推理時從高斯噪聲抽了 K=3 條候選（數值為歸一化後的動作空間）：

```
A1 = [ (0.10, 0.05), (0.20, 0.10) ]     ← 群集 A
A2 = [ (0.12, 0.06), (0.22, 0.11) ]     ← 群集 A（與 A1 接近）
A3 = [ (0.50,-0.30), (0.60,-0.40) ]     ← 離群樣本
```

逐步計算成對均方距離（分母 h·dm = 2×2 = 4）：

```
d_12 = [ (0.02^2+0.01^2) + (0.02^2+0.01^2) ] / 4 = (2×0.0005)/4 = 0.00025
d_13 = [ (0.40^2+0.35^2) + (0.40^2+0.50^2) ] / 4 = (0.2825+0.41)/4 = 0.17313
d_23 = [ (0.38^2+0.36^2) + (0.38^2+0.51^2) ] / 4 = (0.274+0.4045)/4 = 0.16963
```

再算每條候選到其他兩條的平均差異：

```
c_1 = (d_12 + d_13)/2 = (0.00025 + 0.17313)/2 = 0.08669
c_2 = (d_12 + d_23)/2 = (0.00025 + 0.16963)/2 = 0.08494   ← 最小
c_3 = (d_13 + d_23)/2 = (0.17313 + 0.16963)/2 = 0.17138
```

argmin → 選 **A2**。直覺：A1、A2 是同一個「決策模式」的兩個樣本，A3 是離群；MAC 選出的是**群集內的 medoid（A2）**，而**不是**三條的平均——平均值會把離群的 A3 拉進來，可能產生一條誰都不像、且運動上不自洽的軌跡。這正是作者強調「avoid averaging potentially incompatible trajectories」的具體含義。

代價：候選 K=3 需要 **3 次獨立流積分**（每次 10 步），即約 3× 採樣計算量。消融顯示 K=3（85.9%）優於 K=1（84.2%）、K=5（85.2%）、K=10（84.1%）——**不是候選越多越好**。

## 4. 工程視角 (Engineering View)

| 模型規模 | 57.1M 參數（sim-state 變體 51.4M）；對比動輒數 B 的 VLA，可單卡 RTX 4090 訓練/推理 |

| 重規劃頻率 | He=16 意味著「回饋延遲」與「動作連貫性」的折中；太短抖動、太長遲鈍 |

**工程含義**：這類「稀疏狀態 + 小型流匹配」路線的最大吸引力是**部署成本**。骨架節點數 N 遠小於視頻 token 數，序列長度短 → attention 成本低；同時未來分支可在推理時整段移除，使實際推理圖比訓練圖更小。真正的工程風險在感知端：物體中心與交互點必須由一個泛化良好的 RGB-D 感知模組穩定輸出，否則誤差直接進入幾何狀態。

## 5. 數據與評測 (Data & Eval)

**模擬**：LIBERO-Plus 全量基準，**10,030 個變體、七類擾動**（相機、語言、背景、噪聲、佈局、機器人初始狀態等），**零樣本**評估、不在評測變體上微調。

**主要結果（zero-shot 成功率，%）**：
- 觀測式主設定：**85.9%**（57.1M），比最強觀測式基線 Cosmos-Policy（82.2%）高 3.7 點
- 相機擾動：**93.4%**，超 Cosmos-Policy 17.6 點
- 語言/背景/噪聲擾動：89.1% / 96.0% / 93.9%（均為觀測式最佳）
- sim-state 診斷變體（用模擬器坐標替代視覺估計）：87.7%（51.4M），僅比主設定高 1.8 點 → 凍結感知網路的地標估計相當有效，但仍有提升空間
- **短板**：佈局擾動僅 **66.6%**，遠低於 π0.5 的 84.1%

**真實世界**：ARX R5 單臂 + 外部/腕部 RealSense，桌面場景（抽屜、積木、碗），5 個任務各 20 次試驗：
- SkeleWAM 平均 **89%**，分別超 Cosmos-Policy / Fast-WAM / π0.5 達 2 / 6 / 13 點
- 5 個任務中 4 個達到最佳或並列最佳

**關鍵消融（RGB-D 設定，LIBERO-Plus）**：
- 物體骨架組成：中心+交互點 85.9% ＞ 僅中心 82.3% ＞ 僅交互點 77.7%
- 未來骨架監督：保留 85.9% vs 移除 80.1%（**−5.8 點**）
- 執行 horizon：He=16 最佳（85.9%）＞ He=32（81.8%）＞ He=5（80.7%）
- MAC 候選數：K=3 最佳（85.9%）＞ K=5（85.2%）＞ K=1（84.2%）＞ K=10（84.1%）
- 共識窗口：h∈{3,5,10,16} → 85.3/85.4/85.9/85.7%，極穩定

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 桌面單臂語言條件操作，含抽屜開合、積木放入、疊碗等；對**相機視角、背景、噪聲**擾動魯棒（機器人-物體幾何在共享坐標系中，不依賴外觀）
- 以極小參數取得強零樣本成功率；訓練/推理皆可單卡完成

**不能/吃力**：
- **大範圍佈局變化**：僅 66.6%（即使 sim-state 也僅 69.0%）→ 瓶頸不只是視覺定位，而是**策略本身對全新空間排布的泛化不足**
- 真實世界僅驗證**單臂、桌面、剛體**；未測雙臂、移動、人形、柔性物體
- 依賴**預先定義的物體交互點結構**（每個物體 Lm 個點）；對未見過的物體/關節物體泛化未驗證

### 6.1 隱含假設 (Hidden Assumptions)

1. **地標可被凍結感知網路可靠估計**——在遮擋、雜亂、未見物體、透明/反光材質下可能失效，而論文未展示這些條件的失敗剖析。
2. **節點身份/順序/連接在時間上固定**（"Node identities, ordering, and connectivity remain consistent over time"）——要求任務的物體集合 M 與每物體的交互點數 Lm 事先確定；動態出現/消失的物體未涵蓋。
3. **交互點「與中心相連」是一種既定抽象**——何處算交互點並非自動學得，而是場景設計的一部分。
4. **機器人節點由正向運動學取得**——假設運動學已知且剛體；對柔性/冗餘/觸覺反饋驅動的系統未必成立。
5. **訓練分佈覆蓋骨架分佈**——零樣本能力受限於訓練時見過的物體/場景幾何多樣性（這也解釋了佈局泛化弱）。

| π0 / π0.5 | 無顯式未來 | 動作流匹配 | 否 | 純動作監督 |
| WorldVLA / UniVLA | 視覺世界演進 | 動作 + 視覺自回歸 | 是 | 隱式幾何 |
| Cosmos-Policy | 微調視頻模型 | 視頻生成 + 控制 | 是 | 隱式、重 |
| VLA-JEPA | 未來 latent 目標表徵 | 動作 + latent 預測 | 視設定 | 隱式幾何 |
| Fast-WAM | 未來視頻（僅訓練） | 動作 + 視頻 co-train | 否（推理丟棄） | 隱式、像素 |
| **SkeleWAM（本文）** | **稀疏 3D 骨架** | 動作流匹配 + 骨架流匹配 | **否（推理丟棄）** | **顯式幾何、去外觀、緊湊** |

**一句話定位**：SkeleWAM = Fast-WAM 的「推理時丟掉世界預測」思路 + **顯式稀疏幾何狀態**，用最少的表徵換取最強的幾何歸納偏置。

> 🎯 **面試 Tip**：被問到「world model 對 VLA 到底有沒有用」時，可以這樣答——**用法有兩種：a) 推理時真的去想像未來（重，如 Cosmos-Policy）；b) 只在訓練時用未來預測做輔助監督、推理時丟掉（輕，如 Fast-WAM / SkeleWAM）。SkeleWAM 的貢獻是進一步追問『未來應該用什麼表徵』——答案是顯式的稀疏 3D 幾何，而非視頻或視覺 latent。它的消融（移除未來骨架監督掉 5.8 點）正是『世界模型的收益可以來自幾何監督信號本身』的直接證據。**

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 正在設計 **world model + VLA 耦合架構**的研究者——這篇給出「狀態表徵選擇」這一維度的乾淨對照實驗；
  2. 關注 **高效/輕量世界模型**的工程師——57M 參數、可單卡、推理圖可剪枝，是難得的落地樣本；
  3. 研究**結構化/object-centric 狀態表徵**的人——骨架組成消融（中心 vs 交互點）值得細看。
- **建議章節路徑**：先讀 **§3.2 Skeleton World Representation**（看懂狀態長什麼樣）→ 再看 **§3.4 Training Objective**（流匹配雙損失）→ 再讀 **§3.5 + §4.4 MAC 與消融**（工程與設計取捨）→ 可跳 §2 Related Work（除非要寫文獻綜述）。
- **不值得精讀的理由**：如果你不做機器人學習、或已熟悉 Fast-WAM / 流匹配 VLA（π0 系列），那讀摘要 + 快速判斷表即可掌握；本文的方法論增量是「狀態表徵」而非「訓練框架」。
