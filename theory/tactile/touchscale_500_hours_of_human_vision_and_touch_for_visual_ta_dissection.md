TouchScale 本身是数据集 + 采集管线，不是一个新模型。它的"方法"体现在三处：采集管线的统一性、跨传感器评测的解剖映射协议、以及把 N0-VTLA 的 Stage-1 future-tactile 预训练搬到人类数据上。

### 1.2 关键机制 (Key Mechanism)

- **单一管线是方法而非工程细节。** 论文反复强调所有 500 小时共享同一代硬件与同步流程——这是它能"只改数据量、不改别的"的前提。相比之下，文献里常有把多个数据集合并使用的做法，传感器与标注差异会混淆规模效应。
- **稠密全覆盖。** 880 taxels/hand 覆盖五指 + 手掌；对比表中 EgoTouch 是 16×16 掌部布局、FEEL 只有 6 个指尖+掌点、EgoTactile 是 162 taxels 单手。这是"手-wide contact"与"局部接触"的差别。
- **不 retarget、不用动作标签。** mid-training 阶段只优化 tactile projection + tactile predictor + 一个 8×8 重建头，VLA backbone 完全冻结并以 eval 模式运行。这与 TactAlign / TTP 那种需要对共享触觉表征做对齐的做法不同。
- **双目标。** 对比学习（symmetric InfoNCE）拉近预测潜变量与真实未来触觉潜变量；8×8 重建做稠密监督。两者相加，权重 λ_rec = 0.5。

⚡ **Eureka Moment**：规模效应在视觉-触觉领域并非不可测——只要把"传感器 + 采集协议"固定成常量，把"数据量"作为唯一变量，就能观察到零样本触觉预测与真实机器人成功率随规模的整体上升趋势。这是本文相对于"再发一个数据集"的真正增量。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_mid = L_NCE + 0.5 · L_rec ，目标是让预测的潜触觉 token 与 H=50 帧后的真实触觉变化在对比空间中靠近
```

**目标**：给定当前触觉观测与视觉-语言上下文，预测未来 H=50 帧的触觉变化表征，作为动作专家的条件信号；同时用 8×8 的稠密重建提供辅助监督。

**公式**（来自附录 9 与 10.2）：

```
ẑ_i = MeanPool(Ẑ_i) / ‖MeanPool(Ẑ_i)‖₂
z*_i = MeanPool(Z*_i) / ‖MeanPool(Z*_i)‖₂

s_ij = ẑ_iᵀ z*_j

L_pool = -(1/N) Σ_i log( exp(s_ii / τ) / Σ_j exp(s_ij / τ) )，τ = 0.07

L_mid = L_NCE + λ_rec · L_rec，λ_rec = 0.5
```

> 符号说明：Ẑ_i 为 Stage-1 predictor 输出的 latent tactile tokens；Z*_i 为对同一 horizon 的真实触觉变化用 tactile encoder 编码得到的目标；目标分支 stop-gradient。论文正文称"symmetric InfoNCE"，但附录式 (21) 只写出了单向形式——**双向的实现细节论文未展开**，复现时需注意。

**区域级评测量**（附录 6，跨传感器评测的核心协议）：

```
c_{t,r}(p) = 1[ (Σ_m M_{r,m} · 1[p_{t,m} > τ]) / (Σ_m M_{r,m}) > ρ ]
             τ = 0.1，ρ = 0.2

μ_{t,r}(p) = Σ_m M_{r,m} p_{t,m} / Σ_m M_{r,m}

g_{t,r}(p) = Σ_m M_{r,m} p_{t,m} x_m / (Σ_m M_{r,m} p_{t,m} + ε)

s_{t,r}(p) = Σ_m M_{r,m} p_{t,m}² / (Σ_m M_{r,m} p_{t,m} + ε)
```

| 变量 | 含义 |
|------|------|
| M_{r,m} | 数据集 d 的 12×N_d 二值分配矩阵，把第 m 个原生 taxel 映到解剖区域 r |
| τ = 0.1 | taxel 级接触阈值，作用于"按每条序列最大值归一化"后的压力 |
| ρ = 0.2 | 区域内至少 20% 的 taxel 活跃才算接触 |
| Ω | 12 个解剖区域：5 指尖 + 5 指中/根部 + 手掌 + 拇指根 |
| x_m | taxel m 在手部中心坐标系中的归一化 2D 坐标 |
| ε | 数值稳定项 |

**直觉**：τ 用"序列内最大值归一化"意味着这是一个**相对压力**阈值，不是绝对物理量；ρ 用"活跃 taxel 比例"而非绝对数量，正是为了抵消 TouchScale（880）、EgoTouch（217）、EgoTactile（137）三者 sensing density 的巨大差异。也就是说，这套指标衡量的是"哪块区域被压到了、压的相对强弱大概是什么样"，而不是"多少牛顿"。

**四个指标各管什么**：

| 指标 | 衡量 | 方向 |
|------|------|------|
| cIoU | 区域是否接触，时间维上的 IoU | ↑ |
| vIoU | 区域平均压力的重叠 | ↑ |
| CoP Loc. | 压力中心的空间定位误差 | ↓ |
| Press. Mag. | 区域压力强度的绝对误差 | ↓ |

## 3. 带数字走一遍：玩具例子 (Worked Example)

> ⚠️ **以下数值为假设的演示数据，不是论文实测**，仅用于把附录 6 的四个指标走通、验证公式之间的一致性。

**设定**：单序列、单解剖区域、4 个 taxel，归一化压力上限为 1。

- 真值：p = [0.60, 0.05, 0.00, 0.30]
- 预测：p̂ = [0.50, 0.15, 0.00, 0.05]
- 2D 坐标：x_0 = (0.1, 0.1)，x_1 = (0.9, 0.1)，x_2 = (0.1, 0.9)，x_3 = (0.9, 0.9)
- τ = 0.1，ρ = 0.2

**第 1 步：接触判定**

真值活跃 taxel：0.60 > 0.1、0.30 > 0.1 → 2/4 = 0.50 > 0.2 → c = 1
预测活跃 taxel：0.50 > 0.1、0.15 > 0.1 → 2/4 = 0.50 > 0.2 → ĉ = 1

→ 这一帧 contact 完全一致。**如果只报 cIoU，这一帧看起来完美。**

**第 2 步：vIoU 单帧项**

μ(p) = (0.60 + 0.05 + 0.00 + 0.30) / 4 = 0.2375
μ(p̂) = (0.50 + 0.15 + 0.00 + 0.05) / 4 = 0.1750
min/max = 0.1750 / 0.2375 ≈ **0.737**

**第 3 步：CoP 距离**

g(p) 分子 = 0.60·(0.1,0.1) + 0.05·(0.9,0.1) + 0.30·(0.9,0.9)
　　　　= (0.06+0.045+0.27, 0.06+0.005+0.27) = (0.375, 0.335)
g(p) ≈ (0.375/0.95, 0.335/0.95) ≈ (0.3947, 0.3526)

g(p̂) 分子 = 0.50·(0.1,0.1) + 0.15·(0.9,0.1) + 0.05·(0.9,0.9)
　　　　= (0.05+0.135+0.045, 0.05+0.015+0.045) = (0.230, 0.110)
g(p̂) ≈ (0.230/0.70, 0.110/0.70) ≈ (0.3286, 0.1571)

CoP 误差 ≈ √(0.0661² + 0.1955²) ≈ √(0.00437 + 0.03822) ≈ **0.206**

**第 4 步：压力强度误差**

s(p) = (0.60² + 0.05² + 0 + 0.30²) / 0.95 = (0.36 + 0.0025 + 0.09) / 0.95 ≈ 0.4763
s(p̂) = (0.50² + 0.15² + 0 + 0.05²) / 0.70 = (0.25 + 0.0225 + 0.0025) / 0.70 ≈ 0.3929
|s(p̂) − s(p)| ≈ **0.083**

**结论**：contact 状态 100% 一致的一帧，vIoU 只有 0.737、CoP 偏了 0.206、强度差 0.083。这正好解释了论文为什么必须同时报四个指标：**"压没压到"和"压在哪儿、压多重"是两件独立的事**。

**补充 cIoU 的时间维度**：若 10 帧内真值有 6 帧接触、预测有 5 帧接触、其中 4 帧重叠，则 cIoU = 4 / (6 + 5 − 4) = 4/7 ≈ **0.571**。

## 4. 工程视角 (Engineering View)

**数据带宽与同步**

- 触觉：880 taxels/hand × 2 hands × 50 Hz = **88,000 taxel 读数/秒**（无线）；切到 100 Hz 有线则翻倍。这是一个不容忽视的采集带宽。
- 视觉：3 路 RGB（均 1280×720）+ 1 路 depth（640×480），全部 30 Hz。
- 同步策略是"原始时间戳保留、训练时最近邻对齐到 30 Hz"。**工程含义**：触觉的 50/100 Hz 高频成分在 mid-training 阶段没有被用满。若下游任务需要高频接触（例如 slip detection），这个降采样是一个潜在的信息损失——这是编辑视角的条件性分析，论文未做此消融。

**训练预算**

- mid-training 只更新 **123.8M / 3.83B ≈ 3.2%** 的参数；backbone 在 eval 模式下无梯度前向，显存与算力开销相对温和。
- AdamW，global batch 64，grad clip 1.0，warmup **500 steps** 到 1e-4，到 **20K steps** 衰减到 1e-5。也就是说 mid-training 的量级是"两万步"，不是几十万步。
- 触觉 predictor 用 tactile_kv 架构、5 个 latent tokens，与已发布 checkpoint 配置一致。这意味着 **mid-training 的可插拔性很强**：所有超参基本沿用原 checkpoint。

**推理 / 部署**

- H = 50 帧 @30 Hz ≈ **1.67 秒**的未来 horizon。对擦拭这类持续接触任务可能合适；对快速抓取 / 旋转可能偏长。论文没有报告不同 H 的消融。
- 部署时策略只需要 predictor 输出的条件 token，不需要未来触觉真值——也就是说机器人端只要有当前触觉和相机即可运行，不需要额外的传感器。

**采集部署**

- 手套电池 >10 h，无线 50 Hz，理论上支持长时间户外采集；但论文实际在 9 个受控场景（实验室、厨房、工作台、办公室、卧室、医疗、打包等）采集，不是 in-the-wild。
- 质量控制用 Gemini 3.7 Flash 以 **2 fps** 看腕部视频做视觉盲测，噪声候选复核用 **6 fps** 加 1.5 s 上下文。这是把人力的第一道筛子自动化，但仍有 REVIEW 分支需要人工复核——是一条两阶段流水线，不是端到端自动标注。

**一个被低估的工程约束**：论文明确说 "TouchScale does not include action labels"。这意味着它不能直接做 imitation learning，只能作为 mid-training / 表征预训练的监督源。任何想直接用它训策略的工程方案都需要额外补动作数据。

**规模缩放（Fig. 4）**：TouchScale 从 10% 到 100%，cIoU 0.311 → 0.383，vIoU 0.252 → 0.276，CoP 0.332 → 0.317，Mag 0.108 → 0.105。

> ⚠️ **编辑注**：摘要把 0.134 → 0.383 写成一句话，容易被误读成"同一次实验的对比"。实际上 0.134 来自 EgoTouch 16.2 h，0.181 来自 TouchScale 16 h 子集，0.383 来自 TouchScale 全量。**这是三个不同条件下的三个数，不是一条对照线。**

| Mid-training 数据 | Train Top-10 ↑ | Val Top-10 ↑ | Pooled Top-10 ↑ | Pool NCE ↓ |

| 20% | 2.87% | 2.93% | 2.34% | 8.890 |
| 40% | 3.11% | 2.80% | 2.63% | 8.889 |
| 60% | 3.18% | 3.13% | 2.58% | 8.884 |

## 6. 能力与失败模式 (Capabilities & Failure Modes)

### 6.1 能做什么

- **跨传感器零样本接触预测**：在完全未见的 EgoTactile 手套布局上，16 h TouchScale 训练的模型 cIoU 0.181，高于同预算 EgoTouch 的 0.134（论文实测，表 2）。
- **视觉表征迁移**：Hiera-B 用触觉目标预训练后，在 MECCANO / SSv2 / Ego-Exo4D 三处均取得所比数据集中的最高平均准确率（论文实测，表 3）。
- **作为 action-free mid-training 改善真实策略**：四任务平均 22.5% → 57.5%（论文实测，表 4，每任务 20 trials）。
- **规模趋势**：在传感器与采集协议固定的条件下，触觉预测与机器人成功率均呈整体上升（论文实测，Fig. 4 / Fig. 6）。

### 6.2 不能做什么 / 哪里会坏

| 失败模式 | 具体表现 | 原因 |
|---------|---------|------|
| 只覆盖一种机器人形态 | 仅 xArm6 + BrainCo Revo 2 + 四任务 | 论文明确列为局限 |
| 不能直接做 imitation learning | 无动作标签 | §5 结论段明写 |
| 高频接触信息丢失 | 训练降采到 30 Hz，抛弃 50/100 Hz 触觉原生频率 | 附录 10.2 的对齐方式 |
| 只有法向压力 | shear、温度、滑移无直接测量 | 附录 7：手套记录 normal pressure |
| 机制未厘清 | future-tactile 误差与 action 误差相关性 r=0.119（p=0.020）；基线 r=0.003（p=0.953） | §4.3 末段，作者自述 "the role of future-tactile prediction in robot control remains an open question" |
| 规模收益出现饱和迹象 | Top-10 从 20% 到 100% 只涨 0.44 个百分点 | 表 5 |
| 数据未确认可用 | 论文版本仍是 "We will publicly release" | 摘要 / §1 |

### 6.3 隐含假设 (Hidden Assumptions)

1. **"统一管线"足以隔离规模效应。** 论文在规模实验中确实只变数据量，但 500 小时里同时包含更多的物体多样性、更多参与者、更多场景。规模与多样性没有解耦控制（例如"同样物体数、不同总时长"的对照），所以"更多数据"与"更多变化"的贡献无法分离。
2. **人类视觉-触觉与机器人视觉-触觉的分布差异可以被 future-tactile mid-training 弥合**，且无需动作对齐。这一假设得到了成功率数字的经验支持，但机制没有解释——r=0.119 的相关性太弱，不足以说明因果链。
3. **12 个解剖区域是跨传感器比较的合适粒度。** 这个粒度牺牲了 taxel 级细节；论文没有做"更粗/更细映射"的敏感性分析。
4. **EgoTactile 是代表性未见传感器。** 只有单一零样本目标，不能排除对该数据集特定布局的偶然适配。
5. **VLM 视觉盲测可以替代人工质量判定。** 论文未报告 Gemini 3.7 Flash 的判定与人工 review 的一致率 / 混淆矩阵。

## 8. 精读建议 (Reading Guide)

**值得精读原文的人**

1. **做接触丰富操作、想用人类触觉数据做预训练 / mid-training 的研究者**：直接看 §2.2（人类触觉用于机器人学习的路线梳理）、§4.3（表 4）、附录 9（future-tactile 指标定义）、附录 10.2（训练配置与可训练参数范围）。
2. **做触觉表征、跨传感器迁移的工程师**：§4.1 + 附录 6 是本文最可复用的部分——12 区域解剖映射、四个区域级指标的定义与直觉，可以直接搬到其他触觉数据集对比里。
3. **需要判断"人类数据规模是否值得投入"的项目负责人**：§4.3 的 Fig. 6 + §5 局限，两条曲线（成功率持续涨、future-tactile 早期饱和）给出的信息比摘要更诚实。

**建议章节路径**

摘要 + Fig. 1 → §4.1 表 2（跨传感器零样本）→ §4.3 表 4（机器人成功率）→ 附录 6（若要做复现或跨数据集对比）→ 附录 10.2（若要跑 mid-training）→ 可跳 §2 Related Work 的完整引用列表（表 1 已覆盖关键差异）。

**不值得精读的理由**

如果你不做机器人学习、不做触觉感知，或者只关心语言 / 视觉侧的 VLA scaling law，读摘要 + Fig. 1 + 表 4 三处即可；中间的数据采集协议、质量控制和跨传感器映射对你的边际价值有限。
