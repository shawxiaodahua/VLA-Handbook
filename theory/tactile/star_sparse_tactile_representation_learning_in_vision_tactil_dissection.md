## 1. 核心架構/方法總覽 (Overview / Architecture)

STAR = **ST**AR 配方（三件套）× **π0.5** backbone × **自採 200h 數據**。論文的核心不是新模型，而是一套「讓觸覺真的被用起來」的訓練流程。

### 1.2 關鍵機制 (Key Mechanism)

- **VTP（視觸聯合預訓練）**：單獨拿觸覺做 MAE 會讓模型「躺平」——直接預測全零 patch 最省事（因為觸覺大片是 0）。把對應的腕部 RGB 圖像和觸覺圖像**拼在一起做遮蔽預測**後，「全零猜測」就跟視覺上下文矛盾了，逼著編碼器學出有信息量的觸覺表徵，順帶完成跨模態對齊。
- **SGTTR（稀疏-全局觸覺 token）**：用一個**接觸門控**（contact gate，基於校準後的觸覺讀數 + 傳感器特定閾值）只保留被激活的空間 patch token，砍掉大片冗餘；同時**永遠保留**一個「全局觸覺 token」作為整手接觸場的摘要。全局 token 採**非對稱注意力**——它不看視覺/語言/動作 token，但其他模態可以看它。
- **SFTP（稀疏未來觸覺預測）**：在固定「只預測 5 幀」的預算下，把預測目標**沿動作視野均勻鋪開**於 T_S={10,20,30,40,50}（H=50），而不是擠在最近幾幀（DFTP={1,2,3,4,5}）。30 Hz 下前者覆蓋 1.67 s，後者只有 0.17 s。作者假設：**相鄰近期的觸覺最好猜，因而信息量最低**，拉開時間跨度才能逼模型學「接觸如何演變」。

⚡ **Eureka Moment**：**觸覺的稀疏不是一種，是三種（空間/時間/信息），必須用「token 選擇 + 輔助預測」在表徵層同時化解——而不是靠堆數據。**

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
訓練 = 去噪學動作(flow matching)  +  λ·預測未來觸覺力
```

**目標**：在觸覺極度稀疏的前提下，學出一個既會用觸覺、又不會被觸覺冗餘拖累的策略。

**（A）動作生成——條件流匹配**（論文 Eq.1-3）：

```
L_FM(θ) = E_{a,ε,τ} [ || v_θ(a^τ, o, τ) − (a − ε) ||² ]

插值路徑:  a^τ = (1 − τ)·ε + τ·a ,   ε ~ N(0, I) ,  τ ∈ [0,1]
推理積分:  a^{τ+δ} = a^τ + δ · v_θ(a^τ, o, τ)   # 10 步 Euler
```

**（B）視觸聯合預訓練損失**（論文 Eq.4-5，patch 級歸一化）：

```
L_joint = Σ_{m ∈ {img, tac}}  1/|P_m^mask| · Σ_{j ∈ P_m^mask} || x̂_m^(j) − x̄_m^(j) ||²

其中  x̄_m^(j) = ( x_m^(j) − μ_m^(j) ) / σ_m^(j)   # 逐 patch 標準化
遮罩比例 = 75%
```

**（C）稀疏未來觸覺預測損失**（論文 Eq.6）：

```
L_future = 1/|T| · Σ_{t ∈ T}  1/|P_tac^t| · Σ_{j ∈ P_tac^t} || x̂_tac^(j) − x_tac^(j) ||²

T = {10, 20, 30, 40, 50}（5 幀，H=50，30 Hz 下覆蓋 1.67 s）
預測目標 = 觸覺圖像第 3 通道（法向力）
```

**變量說明**：

| 符號 | 含義 |
|------|------|
| a | 動作塊（H=50 步），相對當前機器人狀態 |
| o_t | 觀測 = {I_t（多視圖）, T_t（多觸覺信號）, s_t（本體）, l_t（語言）} |
| τ | flow matching 時間步，從 shifted-beta 分佈採樣 |
| ε | 高斯先驗噪聲 |
| δ | Euler 積分步長（10 步覆蓋 τ∈[0,1]） |
| P_m^mask / P_tac^t | 被遮罩 patch 集合 / 未來時步 t 的觸覺 patch 集合 |

**直覺**：動作學習是「把噪聲搬運成動作」（可去噪即生成）；觸覺學習是「被視覺『看著』地補全觸覺」（防躺平）+「提前猜未來接觸力」（把稀疏的時間信號變成密集的監督）。三者疊加 = 稀疏問題的三路夾擊。

> 符號與論文/π0.5 文檔保持一致：內積用 ·，範數用 ||·||，下標 τ 表 flow 時間。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

**3.1 流匹配 10 步去噪（1 維玩具）**
設 σ 目標動作 a = 1.3，採樣 ε = −0.4。線性路徑速度恆為 v = a − ε = 1.7。

```
τ=0 : a = −0.40
每步 δ=0.1，a ← a + 0.1·1.7 = a + 0.17
τ=0.1: −0.23 | τ=0.5: 0.45 | τ=0.9: 1.13
τ=1.0: 1.30  ✅ 復原目標
```

真模型裡 v_θ 由觀測條件決定，所以 10 步只是「逼近」，不是精確解——這正是延遲與質量的 trade-off 來源。

**3.2 接觸門控能砍掉多少 token**
一手 196 個空間 patch token，加上 1 個全局 token。

```
假設全局最高激活 taxel 比例 = 24%（論文 §IV-B 實測上限）
若激活沿空間聚集，粗略估計被激活的 patch ≲ 24% → 約 ≤47 / 196
兩手空間 token：≈ 94（激活） + 2（全局）  vs  原始 392
→ 觸覺 token 縮減 ≈ 75%，且全局摘要在任何情況下都保留
```

> 注意：24% 是**taxel 級**上限，patch 級激活數未在正文給出精確數字，此處為量級估算，非論文原值。

**3.3 為何 SFTP 比 DFTP 好**
固定 5 幀預算，30 Hz：

```
DFTP：幀 {1,2,3,4,5}  → 覆蓋 5/30 ≈ 0.17 s（幾乎是「複製當前力」）
SFTP：幀 {10,20,30,40,50} → 覆蓋 50/30 ≈ 1.67 s（跨越抓取→旋轉→釋放的轉折）
```

預測越近越好猜 → 監督信號越「便宜」→ 學到的東西越少。拉開跨度，模型被迫編碼「接觸如何演變」的動態。

## 4. 工程視角 (Engineering View)

- **推理延遲**：策略每步要跑 **10 次 Euler** 前向（action expert 300M），但 prefix 的 KV 已緩存，只有動作 suffix 反覆計算。觸覺 token 經門控縮減後，後續注意力成本同步下降——這是「稀疏化」在推理側的直接紅利。
- **控制頻率**：數據採集 30 Hz；動作塊 H=50 → 一次推理給未來 ~1.67 s 的動作。SFTP 恰好在這個視野上分佈監督，與控制週期對齊。
- **記憶體/token 預算**：完整序列 1562 token = 768（3 視圖×256）+ 394（觸覺 197×2）+ ≤350（語言/本體）+ 50（動作）。觸覺門控是唯一可以「動態變長」的部分，也是最值得省的。
- **量化誤差與傳感器限制**：觸覺只測**法向力**，且只分佈在**掌心 + 手指內側接觸面**，**指尖邊緣未覆蓋**——這是一個硬體級天花板（見 §6）。壓阻式傳感器的噪聲/漂移/斷 taxel 魯棒性被作者列為未來工作。
- **部署約束**：配方本身「即插即用」（不改 backbone），但**前提是你得先複現一顆 268-taxel 的靈巧手**——跨硬體遷移可行性未被驗證。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 多指協同的精細操作（翻轉、抽取、指尖捏取），在**觸覺密集**任務（如耳機翻轉）上明顯受益。
- 用 100 條任務特供軌跡即完成新任務適配——**低數據 post-training 友好**。

**不能做 / 會退化**：
- **指尖邊緣抓取**：傳感器未覆蓋指緣，小指/無名指邊緣抓取易偏，多物體抓取任務 TCR 遠高於 SR（子任務能過，整體卻失敗）。
- **觸覺反成負擔的任務**：作者觀察到策略「過度依賴觸覺、擠壓了視覺利用」，在疊書抽取這類**靠視覺定位**的任務上，觸覺增益有限甚至為負。
- **跨傳感器泛化**：方法綁定 268-taxel 壓阻手與法向力通道，未驗證向 GelSight 等其它觸覺傳感器遷移。

### 6.1 隱含假設 (Hidden Assumptions)

- **假設接觸門控閾值可靠**：門控依賴「校準後的觸覺讀數 + 傳感器特定閾值」，但論文未給閾值標定/噪聲下的敏感性分析。
- **假設法向力足以表徵接觸**：只預測/使用第 3 通道法向力，隱含「切向力與滑移不重要」——對需要防滑的任務可能不成立。
- **假設 4 個任務能代表靈巧操作**：作者自認任務集有限，61% 不能外推到更廣的靈巧操作分佈。
- **假設視覺與觸覺天然可對齊**：VTP 用「腕部圖像 ↔ 觸覺」配對，隱含兩者在時空上足夠同步且對應——手部遮擋或相機視角變化時該假設未必成立。
- **未做語言對齊**：配方只對齊了視觸，作者明言語言對齊仍缺失，卻仍以語言指令驅動策略。
