## 1. 核心架构/方法总览 (Overview / Architecture)

Bench2Dex 不是一个新策略，而是一条完整的**基准流水线**：任务构建 → 人类遥操作采集 → 离线多模态回放 → 可执行评测。它把 8 种模态、12 种手、26 个任务收进同一个 Isaac Lab 框架。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练 vs 推理差异 |
|------|------|------|-----------|------------------|
| 在线遥操作 | Manus 手套 25 节点骨架 + ARKit 腕部位姿 | 绝对关节位置指令 + 逐步观测 | 仿真步内实时 | 仅采集，不参与训练 |
| 离线回放 | 已录关节轨迹 + 对象初始状态 | RGB-D / 分割 / 3D 框 / 占据栅格 / 触觉图 | 按 episode 平行化重放 | 渲染与仿真解耦，可重跑/部分应用 |
| 统一触觉接口 | 手部接触网格 + 任务对象网格 | 8-bit 触觉图 + 度量射线深度 + 有效性掩码 | 每次回放逐帧 | 推理时可直接喂视觉编码器 |
| 评测套件 | 回放后的 HDF5 记录 | SR / LSCR / 安全与效率诊断 | 每 episode 一次 | 训练与评测解耦 |

> 关键工程取舍：遥操作只录"轻量运动流"，昂贵的多视角 RGB-D 与触觉渲染放到**离线回放**阶段做，并且可以并行、可重跑、可只对子集应用。

### 1.2 关键机制 (Key Mechanism)

- **统一触觉接口的核心**：不去复现任何一款真实传感器（GelSight / DIGIT 等），而是把**接触几何**本身变成图像。为每只手重建接触表面网格，预先存成"表面点 + 内向法向"资产，让 12 种手走同一条射线投射管线。
- **触觉注册表 (tactile registry)**：把每个具身映射到站点名、表面资产、分辨率、法向约定、站点-身体附着规则，从而**在数据采集代码里消除手别分支**。
- **DexPilot 重定向**：把 25 节点手骨架统一转成 21 个 MediaPipe 关键点，再解出 12 种手的关节角，实现"一套遥操作协议打通所有手"。
- **两类扰动的分离**：把 7 种扰动拆成不变轴（背景/桌面纹理/光照/干扰物/相机位姿——不改任务语义）和等变轴（物体位姿/桌面高度——必须改变动作）。分开汇报，避免把"抗噪能力"和"真·几何泛化"混成一个数。

⚡ **Eureka Moment**：**不重建真实触觉传感器，而是用"表面网格 + 内向法向射线求穿透深度"把各异的手几何压成统一的图像化触觉表示——统一的是表示，不是硬件。** 这样在硬件尚未收敛时就能先做跨具身算法研究。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
触觉 = 把接触几何投影到每只手固定的表面网格上，沿内向法向射线的穿透深度再量化成图
```

**目标**：把"某只手某手指压在某物体上的接触状态"变成一个和手形无关、可被视觉编码器吃的图像张量。

**核心公式（射线投射 + 量化）**：

```
d_s(u)  = < p_obj(u) − p_s(u),  n_s(u) >        # 站点 s 网格单元 u 处沿内向法向的穿透深度
T_{s,t} = Q( d_s(u) )   ,  Q: 分段深度量化       # 编码为 8-bit
T_{s,t} ∈ {0, 1, ..., 255}^{H×W}                # 站点 s 在时刻 t 的触觉图像
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| s | 触觉站点（tactile site），对应某只手的一个接触区域 |
| u | 该站点局部表面网格单元（固定表面点 + 内向单位法向） |
| p_s(u), n_s(u) | 表面点位置与其内向法向（预计算资产） |
| p_obj(u) | 从该点沿法向射线与物体网格的首个交点 |
| d_s(u) | 穿透深度（首击点越过名义接触面的距离） |
| T_{s,t} | 时刻 t 的触觉图；另存度量射线深度与二值接触有效性掩码 |

**评测公式**：

```
稳定成功率:      SR  = (1/N) · Σ_{e=1..N} S_e          # S_e=1 仅当终止谓词稳定成立
带锁存阶段完成率: LSCR_e = (1/K_e) · Σ_{k=1..K_e} L_{e,k}
```

**泛化场景构造**：

```
S_e = Build(T, g_e)        # T 为任务规范，g_e 为解析后的扰动参数（背景/纹理/光照/干扰物/位姿/桌高/相机）
```

**直觉**：SR 只认"稳定成功"，会把"差一点完成"和"完全没动"都记 0；LSCR 则用**锁存机制**记录依赖成立的阶段进度，即使后面的动作把前面的谓词反转（比如开门后又关门），先前的进度也不会被抹掉。

> 符号与本文保持一致：`T` 表示触觉图张量，`T`（斜体语境）表示任务规范，两者按上下文区分。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设某只手指端一个 4×4 的触觉站点，压在一个圆柱面上（半径 0.04 m），手指略偏左。名义接触面为平面，物面向内凸起。

对每个网格单元 u 沿内向法向投射射线，得到穿透深度（单位：mm，取正值表示物体压入）：

```
d = [ 0.0  0.1  0.3  0.0
      0.2  1.2  2.0  0.4
      0.1  0.9  1.6  0.3
      0.0  0.2  0.4  0.0 ]     # 中间偏右最深处
```

用分段量化 Q（假设 0–2.5 mm 映射到 0–255）后：

```
T = [  0   10   31    0
       20  122  204   41
       10   92  163   31
        0   20   41    0 ]
```

这一步就是"接触几何 → 图像"的全部：**换一只手，只要把它的接触网格重建成同样的表面点-法向资产，同一个 Q 就能产出同样语义的触觉图**。训练时策略看到的不是"某型号传感器的读数"，而是"接触有多深、分布在哪里"。

再看评测闭环：某 episode 里机器人先抓住工具（stage 1 谓词成立，L_{e,1}=1 锁存），再放到托架（stage 2 成立），末端稳定按住 0.5s → S_e=1。若 stage 2 失败但 stage 1 锁存成功，则 SR=0 但 LSCR_e = 1/2 = 0.5 —— 这正是论文强调的"二值成功率把接近成功和毫无进展混为一谈"的修正。

## 4. 工程视角 (Engineering View)

| 权衡点 | 设计选择 | 工程含义 |
|--------|----------|----------|
| 采集开销 | 在线只录轻量运动流，渲染放离线 | 遥操作会话短、实时性有保障；渲染可并行/重跑/子集化 |
| 相机数量 | 6 视角（胸/顶/立体左右/左右腕） | 多视角提高可观测性，但回放显存/IO 成本线性上升 |
| 触觉分辨率 | 8-bit 图 + 分段量化 + 空间平滑 | 压缩带宽、便于喂视觉编码器；代价是丢细粒度力信息 |
| 评测规模 | 26 设置 × 4 策略 × 4 通道 × 50 rollout = 20,800 episodes | 单机难以一次跑完，必须分片/并行；结果统计开销大 |
| 时间预算 | 每任务 horizon = 1.5× 专家轨迹长度 | 长程任务允许一定冗余，但超时即判负 |
| 终止判据 | reach-and-stop + 0.5s 驻留 | 防止"瞬时掠过"被误判成功，代价是成功判定延迟 0.5s |

**部署约束提示**：触觉图当前只做图像化几何编码，**没有力/力矩维度**，也不含真实传感器的迟滞、噪声、温漂特性。若要把结论迁到真机，需重新标定传感器模型；作者本人也在 Limitation 中明确这一点。

## 5. 数据与评测 (Data & Eval)

**数据组成**：
- 约 **1.3K** 条人类遥操作演示轨迹
- **26** 个双臂长程任务（工具使用 / 关节物体交互 / 多阶段操作）
- **12** 种双臂灵巧手具身（如 IIWA7+Sharpa、JAKA ZU7+DexHand021、Panda+Allegro、xArm7+LEAP、UR5+Shadow、UR5+Schunk、RM65+Revo2 等）
- 每条轨迹回放成统一 HDF5 记录，含 8 模态：RGB、深度、关节状态、对象状态、统一视触觉表示、2D/3D 边界框、占据栅格

**评测设置**：
- 策略：ACT、Diffusion Policy（图像条件 1D U-Net 变体）、π0.5、GR00T N1.5；前两者从零训练（多视角 RGB + 关节状态），后两者从预训练 checkpoint 全量微调
- 通道：None（匹配锚点）/ Equi.（只重采样等变因子）/ Inv.（只重采样不变因子）/ Full（两者独立重采样，无锚点）
- 每设置 50 次 rollout，主指标为 reach-and-stop 稳定成功率，并按 26 设置等权做 task-macro

**主结果（Table 2，task-macro %）**：

| 策略 | None | Equi. | Inv. | Full | SR(四通道均值) | LSCR |
|------|------|-------|------|------|----------------|------|
| ACT | 29.5 | 15.4 | 14.0 | 13.0 | 18.0 | 33.5 |
| DP | 12.9 | 6.3 | 5.2 | 3.8 | 7.1 | 23.0 |
| π0.5 | 27.3 | 13.2 | 21.0 | 19.7 | 20.3 | 36.1 |
| GR00T N1.5 | 48.5 | 18.8 | 26.0 | 19.8 | 28.3 | 47.3 |

**关键观察**：
- 匹配场景（None）：GR00T 最强（1300 次 rollout 中 631 次成功，48.5%），且在 26 个设置中 23 个领先
- 组合扰动（Full）：GR00T(19.8%) 与 π0.5(19.7%) 几乎并列，但 π0.5 拿下**最多**的逐任务领先数（12 vs 8）——聚合胜者和任务级胜者不是一回事
- Full/None 成功率比：π0.5 最高（72.1%），GR00T 40.9%，ACT 44.1%，DP 29.8%
- 两轴敏感度因策略而异：ACT/DP 在 Equi. 上高于 Inv.；π0.5/GR00T 恰好相反
- LSCR 普遍高于 SR 15–19 个百分点，说明大量"接近成功"的长程进度被二值 SR 吞掉了

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：
- 在同一任务与同一触觉表示下，横向比较不同灵巧手 / 不同策略
- 用不变轴 vs 等变轴分离"Nuisance 敏感"与"真·几何泛化"两类失败
- 用 LSCR 诊断长程任务的部分进度，而不只是一个通过/失败比特

**不能做什么 / 失败模式**：
- **仿真触觉不替代真实触觉**：作者明确表态，接口不试图复现任何具体物理传感器；真机结论需重新验证
- **难度分层极端**：Full 条件下有 3 个设置（Jigsaw Puzzle Assembly、Fridge Fruit Shelf Sorting、Soup Serving）**所有策略全 0**；同时有 12 个设置所有策略都非零，任务难度分布不均
- **样本量限制**：每格 50 次 rollout 是**评测**样本，不是独立重训重复，因此不反映训练间方差
- **非因子交叉**：任务与具身没有做全因子交叉，无法干净地隔离"具身效应"
- **稳定成功率单一**：SR 无法区分部分进度、安全性或执行时间（须配合 LSCR 和安全诊断看）

### 6.1 隐含假设 (Hidden Assumptions)

- **几何一致性可以替代传感器物理**：假设"穿透深度"这一几何量足以承载触觉任务所需的信息，忽略真实传感器的摩擦力、剪切、迟滞等——未验证哪些任务依赖这些被丢弃的物理量。
- **手部接触网格重建准确**：整套触觉接口建立在"预计算表面点+法向资产"之上，若某只手的接触网格重建有偏，会系统性污染该具身的触觉数据，论文未逐手给出重建误差。
- **遥操作演示即"正确动作"**：把人类遥操作当作监督信号，默认其质量足够；但跨 12 种手的手-臂耦合差异可能导致某些手演示质量偏低。
- **扰动采样范围固定**：泛化结论只对论文 Appendix G 给出的采样范围与组成成立，不等价于"对任意分布漂移都抗"。
- **等变/不变二分完备**：把 7 种扰动划成两轴，隐含"扰动要么改答案要么不改答案"的二元结构，未覆盖介于两者之间、需部分调整的中间情形。
