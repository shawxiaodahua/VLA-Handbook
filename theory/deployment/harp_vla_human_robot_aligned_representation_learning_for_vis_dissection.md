## 1. 核心架构/方法总览 (Overview / Architecture)

HARP 是一个**三段式（three-stage）框架**：

1. **Stage 1**：联合训练「机器人自适应视觉编码器 HARP-VE」+「潜动作模型 HARP-LAM」，用配对视频做跨具身预测、非配对视频做自预测。
2. **Stage 2**：用 Stage 1 的编码器 + 潜动作标签，把 VLM 预训练成 VLA（预测离散潜动作 token）。
3. **Stage 3**：用真机动作数据微调，加一个轻量 action head 把潜动作 embedding 落成可执行命令。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理差异 | 是否冻结 |
|------|------|------|--------------|----------|
| 人类视觉编码器 F | 人类视频帧 x | patch-level 视觉 token | 锚定到预训练空间 | 冻结 |
| 机器人自适应编码器 T_θ | 机器人视频帧 x | patch-level 视觉 token | 轻量适配模块 | 可训练 |
| 潜动作编码器 E_θ | 相邻帧 token 对 + 语言 l | 连续潜动作 a | 逆动力学 | 可训练 |
| VQ codebook Q_θ | 连续 a | 离散 q（每 transition 4 个 token） | 量化 | 可训练 |
| 解码器 D_θ | 条件特征 + q + l | 未来帧 patch token | 前向动力学 | 可训练 |
| VLA 策略 π_θ | 图像 + 语言 + 本体状态 | 潜动作 token（Stage2）/10 步动作 chunk（Stage3） | Stage2 预测潜动作、Stage3 出真动作 | Stage3 用 LoRA 微调 |

关键设计：**人类分支冻结，只适配机器人分支**——这样人类语义空间不被破坏，只把机器人拉到它附近。

### 1.2 关键机制 (Key Mechanism)

- **配对作桥、非配对作规模化动力学监督**：配对视频少且有跨具身监督，非配对视频多但只能自预测。二者互补。
- **self-prediction + cross-prediction 双目标**：self-prediction 在同一视频内预测未来（保动力学），cross-prediction 让从 A 具身抽出的潜动作去解释 B 具身的未来（强制潜动作跨具身一致）。
- **manipulation-centric 辅助线索**：2D 物体关键点轨迹 K + 手腕/末端轨迹 E 通过 Huber 损失正则潜动作，使其捕捉"物体运动 + 粗略运动意图"而非外观。
- **Source-Relative + Pair-Discriminative 对齐损失**：不是把配对特征硬拉到一个绝对距离，而是要求"适配后比冻结版更靠近配对目标"（source-relative），同时用对比正则保持配对可区分（避免所有特征塌缩到一点）。

⚡ **Eureka Moment**：潜动作模型的问题不只是"动作差"，而是"潜动作本身建在了错位的视觉特征上"——所以要**同时对齐视觉与潜动作，并用跨具身交叉预测把两者耦合起来**，而不是只做其中一个。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_stage1 = L_lam + λ_aux·L_aux + λ_align·L_align
```

**目标**：Stage 1 同时学三件事——(1) 潜动作能预测未来视觉动力学，(2) 潜动作被操作线索正则，(3) 机器人表征向人类语义对齐且保持可区分。

**潜动作预测损失**（自预测 + 交叉预测）：

```
L_lam = E_{t<T_X, X~D} || Ŷ_X^t − Y_X^t ||_2^2  +  L_vq

L_vq = || sg[a_X^t] − q_X^t ||_2^2 + β·|| a_X^t − sg[q_X^t] ||_2^2
```

**对齐损失**（source-relative + pair-discriminative）：

```
L_SR = E_{(H,R)~D_p} [ m_s + d(f^R, f^H) − d(f^R0, f^H) ]_+

L_PD = E_{(H,R)~D_p} Σ_{α∈{R→H, H→R}} λ_α [ m_t + d(f^R, f^H) − d̄^α ]_+

L_align = L_SR + L_PD
```

**VLA 预训练损失**（预测离散潜动作 token）：

```
L_pretrain = − E_{(x^t, l_X)~D} [ Σ_{i=1}^{N_q} log π_θ( q̂_i = q_{X,i}^t | x^t, l_X ) ]
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| X ∈ {H, R, V} | 视频来源：人类 / 机器人 / 非配对 |
| z_X^t | 第 t 帧的 patch-level 视觉 token（Φ_θ 输出） |
| a_X^t, q_X^t | 连续潜动作 / 量化后的离散潜动作 |
| f^H, f^R0, f^R | 人类池化特征 / 冻结机器人特征 / 适配后机器人特征 |
| d(u,v)=1−cos(u,v) | 余弦距离 |
| d̄^{R→H}, d̄^{H→R} | 批次内负样本（不配对）的平均距离 |
| m_s, m_t | 固定 triplet margin |
| N_q=4 | 每个 transition 的离散潜动作 token 数 |
| sg[·] | stop-gradient |

**直觉**：`L_SR` 的巧妙在于它是**相对**的——它只说"适配后的机器人特征要离配对人类更近，比原来近至少 m_s"，不强制一个绝对距离目标，从而避免所有配对特征塌缩。`L_PD` 再补一刀：配对特征不仅要近，还要比"任何不配对对象"近至少 m_t，保住可区分性。两者合起来 = "靠近但不坍塌"。

> 符号与本文/相关文档保持一致：`d` 为余弦距离；`f^R0` 表示未适配的冻结机器人特征（HARP 特有的对照项）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一批配对样本 (H, R)，池化后是二维单位向量（简化），余弦距离 d = 1 − cos。

- 设 f^H = (1, 0)，冻结机器人 f^R0 = (0, 1) → cos = 0 → d(f^R0, f^H) = 1.0
- 适配前 robot 与 human 距离 = 1.0（几乎正交，错位严重）
- 取 m_s = 0.2

**L_SR 想要什么**：要求 d(f^R, f^H) ≤ d(f^R0, f^H) − m_s = 1.0 − 0.2 = 0.8，即适配后 cos(f^R, f^H) ≥ 0.2。

若适配后 f^R = (0.9, 0.44)（归一化后约 cos=0.9）→ d(f^R, f^H)=0.1，则 `[0.2 + 0.1 − 1.0]_+ = [−0.7]_+ = 0`，损失归零 ✅。

**L_PD 想要什么**：设批次内负样本 d̄^{R→H} = 0.6（不配对对象平均距离），m_t = 0.15：
要求 d(f^R, f^H) ≤ d̄ − m_t = 0.45。当前 0.1 ≤ 0.45 ✅ 也归零。

**反例**：若模型把所有机器人特征都塌缩到同一个点（cos 恒为 1），则 d(f^R, f^H)=0 很小，看起来 L_SR 很好；但此时 d̄^{R→H} 也趋近 0，则 `[m_t + 0 − 0]_+ = m_t > 0`，L_PD 立刻惩罚。这就是 pair-discriminative 项的意义——**阻止对齐退化成无信息坍塌**。

## 4. 工程视角 (Engineering View)

| 维度 | 设计/约束 | 工程含义 |
|------|----------|----------|
| 潜动作 token 数 | 每 transition N_q = 4 | 动作空间被压成离散码，decoder/策略 token 序列短 |
| Stage 2 冻结视觉编码器 | 论文实测：冻结更好（CALVIN 4.250→4.481） | 一旦跨具身对齐被建立，再训反而破坏对齐与 web 级视觉特征 |
| Stage 3 action head | 潜动作 embedding → 归一化真动作，L1 损失 | 真机控制只需轻量头 + LoRA，训练成本低 |
| 输出动作 chunk | 10 步（真机 XArm7 + Robotera XHand） | 减少推理频率抖动，与 OpenVLA-OFT 风格一致 |
| 数据管线 | DTW（以机器人视频为时间基准重采样人类视频） | 采集侧只需大致对齐动作模式，不必精确同步 |
| 关键点提取 | Qwen3-VL 生成物体描述 → GroundingDINO 定位 → TAPIR 跟踪 + WiLoR 手部重建 | 重标注管线，但显式处理遮挡（TAPIR 的 visibility 分数可衰减不可靠预测）|
| 配对数据依赖 | 5% 配对仍可保持强性能（CALVIN 4.214） | 可先在少量配对上建桥，再靠非配对数据扩容 |

**部署约束**：真机实验用 XArm7 + Robotera XHand，第三视角 + 手腕相机 + 本体状态输入。视觉编码器一旦冻结，机器人侧适配模块是有界的小改动——意味着**迁移到新平台时主要成本在采配对数据和重训 action head，而非重训大视觉骨干**。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做什么**：

- 在有限配对人-机示范下，显著缩小人-机视觉与潜动作表征差距（Table 1/2）。
- 用对齐后的编码器提升下游策略（RLBench、CALVIN、真机一致增益）。
- 对配对数据量有较强鲁棒性：仅 5% 配对仍保持强下游表现（Table 6）。

**不能做什么 / 失败场景**：

- **必须任务级配对人-机示范**：虽然 5% 也可，但配对采集本身昂贵（论文 §6 Limitations 明确承认）。
- **轨迹对齐假设视角近似匹配**：在跟踪误差大、或大视角/FOV 变化下，DTW 与关键点对齐会退化。
- **架构泛化未验证**：仅在 Prismatic / OpenVLA-OFT 风格骨干上验证，更广的架构通用性未测。
- **长程 / 双臂 / 人形未测**：Future work 才提到要扩展到更丰富视频、具身、长程与双臂操作——即当前结论**不应外推到移动/双臂/人形**。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设物体关键点/手腕轨迹可稳定提取**：整个辅助监督建立在 Qwen3-VL + GroundingDINO + TAPIR + WiLoR 管线的鲁棒性上，但管线本身的失败率未在论文中量化。
- **假设"人类手腕 ≈ 机器人末端"是有效坐标代理**：这一粗粒度假设在灵巧手/非抓取类操作上是否成立存疑。
- **假设冻结人类分支 + 只适配机器人分支不会引入单向偏差**：对齐是"把机器人拉向人类"，若人类视频本身噪声大，偏差会传导到机器人表征。
- **假设配对视频"仅时间不同步"**：DTW 处理的是速度差，但若采集时动作模式本身不一致（不同轨迹），时间对齐无法修复语义错位。

- **不值得精讀的理由**：如果你不做机器人学习、或你的流水线已用大规模真机数据且不在意图人类视频，读摘要即可——HARP 的价值高度集中在"人类视频→VLA"这一条链路上。
