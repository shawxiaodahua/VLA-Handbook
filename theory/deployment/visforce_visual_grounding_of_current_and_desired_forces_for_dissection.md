### 1.2 關鍵機制 (Key Mechanism)

- **力走視覺通路，而非專用通道**：`f_t^i` 是純量、沒有空間對應，且指尖常被物體遮擋。論文用 MuJoCo 重建真實手型，把力畫成從指尖沿法向的箭頭，疊到真實手腕圖上——力就變成「圖裡的一部分」。好處是複用 VLM 既有的視覺表徵，不必新增力編碼器。
- **期望力也「畫」進目標圖**：傳統視覺目標只編碼手/物配置，不編碼「多大力」。VisForce 取每個子任務中實測力最接近期望力的 demo 幀，分割前景，再在對應指尖渲染期望力箭頭，讓「怎麼抓」與「抓多緊」統一在一個視覺目標裡。
- **目標條件 cross-attention 而非拼接**：直接用 concatenation 時，當前 token 與目標 token 的對應關係要由後續 VLM 層隱式學習；改用 cross-attention 讓手腕 token 直接 attend 到「前景目標 token」（用 patch 級前景遮罩 `M_fg` 剔除背景），顯式把當前觀察條件化到目標上。
- **箭頭長度不代表接觸力**：`v_t^i = α f_t^i d_t^i` 是視覺提示，不是估計的接觸力向量；`α = 1e-4`。作者明說這點，避免誤讀。

⚡ **Eureka Moment**：把物理量（力）「渲染回視覺空間並對齊到作用點」——不需要新模態編碼器，只要讓力變成圖像裡、落在正確指尖位置的箭頭，VLA 的視覺通路自然就能用它做條件。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
力 f → 視覺向量 v = α · f · d（畫在指尖）;  A ~ π(· | I_w^F, I_e, I_g^F, s, ℓ)
```

**目標**：給定力接地的當前手腕圖、外視角圖、力接地的目標圖、本體狀態與子任務指令，輸出一段 H 步動作：

```
A_t ~ π( · | I^F_{w,t}, I_e,t, I^F_{g,k}, s_t, ℓ_k )
```

**動作空間**：每步 `a_t = [Δa_arm, Δa_hand]`，前 6 維是機械臂關節 delta，後 6 維是靈巧手關節 delta，共 12 維。

**力渲染向量**：

```
v_t^i = α · f_t^i · d_t^i        （d_t^i 為第 i 指尖法向；α = 1×10^-4）
```

**Cross-attention 融合**：

```
x'_t = x_t + CA( LN(x_t), LN(c_k); M_fg )
x_t^G = x'_t + FFN( LN(x'_t) )
```

| 符號 | 含義 |
|------|------|
| `f_t^i` | 第 i 根手指在 t 步的致動器力量值（5 指，`F_t ∈ R^5`） |
| `d_t^i` | 第 i 指尖的法向單位向量 |
| `α` | 力→箭頭長度的縮放係數，`1e-4` |
| `v_t^i` | 渲染用的視覺力提示向量（非接觸力估計） |
| `c_k` | 子任務 k 的目標圖 token（經前景遮罩後作 K/V） |
| `x_t` / `x_t^G` | 手腕圖 token / 目標條件化後的輸出表徵 |
| `M_fg` | patch 級前景遮罩（14×14 patch 內含非背景像素即為前景） |

**直覺**：`v` 這一步是把「純量力 × 方向」投影成可被視覺編碼器消費的空間線索；`x_t^G` 這一步是讓「我現在的手腕狀態」去查「我要達成的目標狀態」，而遮罩保證只查前景（手 + 物），不查背景噪聲。整個流程不改 π0.5 的 flow-matching 目標函數，只改條件輸入。

> 符號與本文/相關文檔保持一致：Per-finger 力記 `f^i`，期望力記 `F^g`，動作 chunk 記 `A_t`（H 步）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設某步抓握，食指與拇指各量到 `f = 20 N`（此處假設為合理數值），指尖法向 `d` 指向物體：

1. **渲染長度**：`|v| = α · f = 1e-4 × 20 = 2×10^-3`（即 0.002 個單位長度），在 MuJoCo 裡沿 `d` 畫一支小箭頭，落在食指/拇指指尖像素位置。
2. **期望力**：假設子任務「抓牙膏、期望 15 N」，則目標圖在對應指尖畫 `|v_g| = 1e-4 × 15 = 1.5×10^-3` 的箭頭。
3. **條件比較**：當前箭頭（20 N，偏長）vs 目標箭頭（15 N，偏短）→ 策略被引導「稍微收力」，避免膏體被擠出。
4. **遮罩**：目標圖中牙膏與手佔據的 patch 保留；桌面/背景 patch 因無非背景像素被遮掉，cross-attention 的 K/V 只含前景。
5. **輸出**：`A_t` 為 H 步 delta 動作，前 6 維驅動 UR10，後 6 維驅動 RH56F1，閉環修正到穩定夾持。

這裡強調「可計算閉環」：力不是抽象標籤，而是有明確縮放、明確像素落點、明確目標差值的可視化量。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 力檔位調變（剛性物：低/中/高期望力，聚合致動器力隨之單調上升且有分離）。
- 力敏感物抓取（蛋 70%、牙膏 80%），在「過小滑落/過大損壞」的窄窗口內成功。
- 遮擋下的抓握狀態判別（T2 倒瓶強抓握指尖被遮）。
- 同一工具跨階段反覆調力（T3），及同一物體「低力滑動 → 高力穩定」的轉換（T4）。

**不能/易失敗**：
- **子任務切換非自主**：推理時使用者只指定當前子任務 k，指令與目標圖自動檢索——策略不會自己決定「何時進入下一階段」。
- **終端成功率偏低**：T4 僅 40%、T3 55%，長序列累積誤差明顯（T3 從 20/20 掉到 11/20）。
- **平台泛化未驗證**：僅單臂 + 單手 + 桌面操作，未測移動/雙臂/人形。
- **力非真實接觸力**：用的是致動器力，箭頭是渲染提示；遇摩擦/柔順差異，`α` 與閾值需重標。
- **依賴外部工具鏈**：GroundedDINO + SAM2 分割、MuJoCo 重建，任一環不穩會污染目標圖與當前圖。

### 6.1 隱含假設 (Hidden Assumptions)

- 假設**手腕相機可穩定標定到仿真手型**，且手部遮罩/前景分割足夠準——論文未量化標定誤差對策略的影響。
- 假設**期望力可離線給定**（Table I/II 的固定數值），亦即「任務適用力」是人工先驗，而非在線估計。
- 假設**致動器力與指尖接觸力足夠相關**，因此渲染提示能代表接觸狀態——這個關聯未經嚴格驗證。
- 假設**每個子任務存在一張代表性目標幀**（力最接近期望力的 demo 幀），複雜/多模態子任務下此假設可能失效。
