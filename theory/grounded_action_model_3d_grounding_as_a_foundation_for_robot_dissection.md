💡 **X-Ray 開場**

操作策略必须知道"哪个物体重要、它在哪里"，但今天主流的机器人基座——VLA 用的是语言预训练、WAM 用的是视频生成——它们的训练目标**都不直接要求**这种度量级(metric)的 3D 定位，于是"物体在哪、多大、朝向如何"只能从有限的示教里隐式猜出来。GAM 的答案是：干脆换一个预训练目标——用一个**可提示的 3D 检测基础模型**，把语言 / 点 / 框统一解析成"物体中心"的视觉特征 + 度量几何，再让冻结的这个骨干去支撑动作头。结果是：物体一被移动、或被重新指定，观察随之更新，策略不再依赖"记住的轨迹"。

## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 训练/推理 | 备注 |
|------|------|------|-----------|------|
| 3D grounding 骨干 G（WildDet3D） | RGB 图 + 任务提示（语言/2D 点/2D 框） | 每物体 2D box、度量 3D box、稠密度量深度图、视觉特征 F_t | 预训练后**冻结** | 语言提示经 Flan-T5 + span-tagging 头抽物体短语 |
| 语言解析 | 指令句 | 物体短语 → 多个 grounding query | 冻结编码器 | "pick the sponge and place it in the bowl" → sponge, bowl |
| 图像 token 流 | 平均池化到 16×16 网格的特征 | 只保留物体/机械臂覆盖的格子，其余置零 | 只训线性适配器 | 屏蔽无关场景变异 |
| 检测 token 流 | 每物体点云 + 3D box | M=8 个/物体，编码形状/中心/尺寸/朝向 | 只训点云编码器与适配器 | 显式度量几何 |
| 状态历史 token | 当前 + 上一帧关节位置 | 1 个 token | 只训投影 | 提供机械臂位形与最近运动 |
| 动作头（MM-DiT） | 上述 token + 噪声动作块 + 语言嵌入 | 绝对关节位置目标块 + 夹爪命令 | 用 flow matching 训练 | 12 个 block，四流注意力 |

### 1.2 关键机制 (Key Mechanism)

- **换预训练目标**：作者的核心主张是"基座学什么，决定了策略先天会什么"。语言目标只奖励"识别物体并描述关系"，不要求精确的 3D 位置与范围；视频目标奖励外观/纹理/背景变化，而这些大多与交互无关。二者都不保证表征里带有可用于控制的几何。
- **统一任务接口**：语言、2D 点、2D 框都被映射到同一个"物体中心"表示。语言只是"指定目标"的一种方式，视觉提示则能**直接指定**要操作哪个物体——当多个物体描述相同，或高层规划器已选定目标时尤其有用。
- **物体中心观察 + 抑制其余场景**：只保留任务物体与机械臂覆盖的图像格子，其余特征置零；重复、无关的 distractors、背景、外观变化因此**进不了观察**。消融显示这一步贡献最大。
- **分层可组合**：GAM 可自主运行，也可作为被高层规划器（Molmo2）通过点接口驱动的低层控制器，用观察历史支持"目标已不在当前画面"的记忆依赖任务。

⚡ **Eureka Moment**：robot foundation model 的基座，不一定是语言或视频——**可以是 3D grounding 本身**。一旦把"哪些物体、在 3D 空间的哪里与多大"作为预训练目标显式喂给策略，策略就学会"对已 grounding 的物体动作"，而不再是"回放针对某个固定布局记住的轨迹"。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
用冻结的可提示 3D 检测器把 语言/点/框 → 物体级 几何token，
再用 flow matching 从噪声积分出 动作块。
```

**目标**：训练动作头 v_θ，使其在给定"grounded 观察 + 语言嵌入"下，把高斯噪声积分成一段绝对关节目标。

**物体描述子**（论文 Eq. 1）：

```
z_i = [ ũ_i , c_i , γ(c_i) , φ(P_i) , e_i , r_i ]
```

| 变量 | 含义 |
|------|------|
| ũ_i | 归一化 2D 检测框 |
| c_i | 物体中心（机器人基坐标系） |
| γ(c_i) | 中心的傅里叶特征（8 个频率） |
| φ(P_i) | 512 个采样点的形状特征（逐点 MLP + 全局 max/mean + 8 个卦限 max 池化 → 512 维） |
| e_i, r_i | 3D box 尺寸；旋转的 6D 表示 |

**语言条件注入**（论文 Eq. 2，不增加 token）：

```
h_{τ,s} = TimeEmbed(τ) + W_ℓ · e_s + b_ℓ
```

其中 e_s 为句子嵌入（768 维），W_ℓ ∈ R^{576×768}，b_ℓ ∈ R^{576}。W_ℓ、b_ℓ **初始化为 0**，保证初始时不影响原模型。

**流匹配损失**（论文 Eq. 3）：给定示教块 A_t、噪声 ε~N(0,I)、τ∈[0,1]，构造 A_t^τ = τ·A_t + (1-τ)·ε，让模型预测速度场：

```
L = E_{A_t,ε,τ} [ || v_θ(A_t^τ | τ, C, e_s) − (A_t − ε) ||₂² ]
```

**直觉**：不去直接回归唯一答案，而是学一个从纯噪声指向真实动作块的"速度场"，推理时从 τ=0 积分到 1（K 步 Euler）即得动作块。grounding 骨干只负责"物体在哪、多大、什么形状"，动作头只负责"怎么操作它"——职责被干净切开。

> 符号与本文保持一致：G=16（图像网格边长），M=8（每物体检测 token 数），N=物体数，L = G² + M·N + 1，d=token 宽度。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设一个"把海绵放进碗里"的任务，N=2（sponge、bowl），取 G=16、M=8：

1. **图像 token**：16×16=256 个池化格子。只有被 sponge/bowl 检测框覆盖≥30%、或被机械臂轮廓覆盖>10% 的格子保留，其余置零 → 假设留下约 40 个格子 → 40 个图像 token。
2. **检测 token**：每个物体 8 个 token → 2×8=16 个。
3. **状态历史 token**：1 个。
4. **拼接长度**：L = 256 + 8×2 + 1 = 273（注意 token 预算固定，未检测到的槽位用 learned null token 填满，长度仍稳定）。
5. **动作预测**：动作头接收 273 个条件 token + H 个噪声动作 token，经 12 层四流 MM-DiT。用 K 步 Euler 从噪声积分出 H 步关节目标。
6. **闭环**：执行若干步后重新查询。若 sponge 被移到训练未见过的新位置，grounding 检测框随之移动 → 检测 token 的 c_i 更新 → 策略对"新位置的海绵"动作，而不是回放旧轨迹。

这就是 LIBERO-PRO 中 Pos / Task 场景 GAM 大幅领先的机制来源：**输入随 grounding 变化，而不是随"训练时配对的固定布局"变化**。

## 4. 工程视角 (Engineering View)

- **只训动作头**：骨干 G 全程冻结，训练面 = 图像适配器 + 检测适配器（含点云编码器 φ）+ 条件融合层 + 语言投影 + 动作 Transformer。这显著降低训练成本，但把**感知质量的下限锁死在骨干上**。
- **感知延迟预算**：每次策略查询都要跑一次 grounding（检测 + 深度 + 特征），再跑 K 步 Euler 积分。控制频率受"检测器前向 + K 步去噪"共同制约；K 越大越平滑越慢，需按控制周期折中。
- **领域适配是必要工程步骤**：骨干在真实图像上预训练，而 RoboTwin 2.0 是渲染域——作者先用仿真导出的 2D/3D box 与深度**单独微调骨干**（无需人工标注），再冻结。跨域部署时这一步通常不可省。
- **token 预算固定**：未检测槽位用 null token 填充，序列长度恒定，便于批处理与推理稳定。
- **跟踪稳定性**：CoTracker3 在初始检测框内跟踪点，把点提示持续提供给 G，避免逐帧重新 grounding 带来的身份漂移。
- **失败无回退**：grounding 一旦出错，动作没有恢复机制（作者明确列为局限），对安全关键场景需要额外的失败检测。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 训练布局之外的新目标位置（Pos）与新指定目标（Task）上保持成功——因为观察由 grounding 定义而非由固定 visuomotor 映射定义。
- 视觉偏移（背景/光照/物体实例/颜色/干扰物）下真机显著更稳（YAM 17/20 vs 4/20）。
- 作为低层控制器与高层规划器组合，完成长程与记忆依赖任务（目标已不在当前画面时，用观察历史选目标）。

**不能做 / 弱点**：
- **依赖 grounding 质量**：检测/深度/点云错误会直接传导到动作且无恢复。
- **物体中心过滤丢上下文**：未选中的障碍物等可能被过滤掉，安全场景需注意。
- **尺寸泛化弱**：Obj 扰动下落后（物体尺寸变化会改变合适的抓取位置，策略可能难以调整）。
- **泛化范围有限**：仅验证桌面操作、双臂 YAM、单臂 Franka，**未验证移动/人形/更广具身**，不要外推。
- **3D box 只是一种 grounding**：作者指出更细的稠密 3D 实例分割可能是更丰富的监督。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设**有一个足够好的可提示 3D 检测器可用，并且**可低成本领域适配**（仿真可直接导出 box/深度当监督）——真实部署里"从零标注 3D box"并不便宜。
- **假设**任务相关物体可由语言短语/点/框可靠指定；当物体不可命名、遮挡严重或杂乱堆叠时未验证。
- **假设**被过滤掉的场景内容确实无关——但障碍物避让等恰恰需要"未选中"的信息。
- **假设**冻结骨干的 grounding 在分布偏移下仍然稳定——这部分靠实验支撑，但未给出偏移强度与失效阈值。
- **假设**K 步 Euler + 一次 grounding 的延迟落在控制可接受范围内——论文未给出端到端频率数字（待补）。

## 7. 与相关工作对比 (Comparison)

| 方法 | 基座/关注点 | 观察构造 | 训练方式 | 随机化/扰动表现 |
