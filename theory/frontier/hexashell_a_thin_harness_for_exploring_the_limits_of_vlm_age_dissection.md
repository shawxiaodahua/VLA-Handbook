## 1. 核心架构/方法总览 (Overview / Architecture)

> 权重归属要点：**本文不动模型权重**。GPT-6-Astra 属于外部预训练模型，本文只把它放进编码 agent CLI 里用；“记忆”不是模型的参数记忆，而是**工具代码 + `playbook.md`/`skill.md` 文本**这种 scaffold 层记忆。VPP2 是 world action model、PhysicalRSI 是语言模型 agent 驱动的 VLA，两者都是**学习策略基线**，与 HexaShell 的记忆机制完全不同。

### 1.2 关键机制

1. **薄封装原则：只翻译，不决策。** harness 只把 `robo` 命令变成关节运动，不替 agent 选目标、不注入策略。“策略活在工具里”。
2. **真值隔离靠架构，不靠承诺。** 行为 agent 的容器里没有仿真器、没有任务代码、没有评分代码；成功只由官方 checker 判定，作者不改 checker。
3. **工具即记忆，且必须可运行、可测试。** 工具是目录（`tool.py` + `interface.md`），只能调 `EpisodeAPI`（关节角、TCP 位姿、RGB、基元运动），不得导入仿真器、读物体位姿、硬编码布局数字；交付前有交付检查（文件名、可加载、`interface.md` 不得出现任务名和物体名，违者回退）。
4. **修复回路是“读 bug 报告改代码”，验收靠再跑一次。** 失败后优化 agent 读命令日志、每命令的相机帧、当前工具代码，写诊断到 `skill.md`，改一个工具并加单元测试，然后**重开同一布局再跑一次**，而不是靠自我评估。
5. **精度靠几何不靠深度网络。** 单目深度需要外部定标且在本场景误差几厘米；三相机是已标定的，于是用**平面约束**和**三角化**把“像素 → 三维点”变成有明确误差来源的闭式计算。
6. **主动感知要付预算。** 腕部相机换视角是真实运动，会消耗 `step_lim`（200–1900 步；push T 为 600 步，约合 24 s 机器人时间）。

⚡ **Eureka Moment**：在与深度网络相同的封装、同一回路、同一模型下，**“三角化 + 已知平面”这种教科书几何**反而比学出来的单目深度更可靠（38.3 vs 29.6，配对胜 57 负 23），并且把 agent 从“猜位置”变成“量位置”。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
P = 三角化(相机1, 相机2)  或  P = 射线 ∩ 平面(z = h)
误差来源 = 标定误差 ⊕ 像素定位误差；不含深度网络的“先验尺度误差”
```

先给目标：**把“图像上一个像素”变成“世界坐标中一个点”**。再给公式，再给变量，最后给直觉。

### 2.1 针孔投影与反投影

```
x ~ K · [R | t] · X
d = Rᵀ · K⁻¹ · [u, v, 1]ᵀ        （像素反投影成世界系方向）
r(λ) = C + λ · d                  （相机中心 C 出发的射线）
```

```
符号说明：
  K   ：3×3 相机内参（论文中由 `state.json` 给出）
  R,t ：世界到相机的外参（投影式 x ~ K·[R|t]·X；反投影用 Rᵀ）
  u,v ：像素坐标
  C   ：相机中心在世界系的坐标
  d   ：单位方向（归一化后）
  λ   ：沿射线的距离
```

### 2.2 平面约束：射线 × 已知高度平面

```
若平面为水平面 z = h，则
  λ = (h - C_z) / d_z
  P = C + λ · d
```

直觉：一个像素给一条射线，射线本身不是点；**再补一个“高度已知”的约束**，就唯一确定了这个点。论文中三类约束：桌面（`table_plane`，每回合只测一次、零步数成本）、块顶/碗沿/盒槽的水平面、以及**第二视角三角化**。

### 2.3 三角化：两视图射线求交

```
min_P  Σ_i || (I - d_i d_iᵀ)(P - C_i) ||²
```

即点到两条射线的距离平方和最小化；闭式解是两条异面直线公垂线段的**中点**。论文中第二视角可由 agent 在两幅图上各点一次像素给出，也可由工具内部的模板匹配/轮廓/圆拟合给出。

### 2.4 桌面高度：平面扫描（plane sweep）

```
h* = argmin_h  Σ_pairs  || I_A( x ) - I_B( warp(x; h) ) ||
```

把相机 A 的图像按候选高度 h 投影到相机 B 的视角，取光度最一致的高度。论文报告三组相机对在本场景内一致到 **1 mm 以内**（0.7646–0.7656 m）。

### 2.5 预算约束

```
执行步数 = 实际运动步数（含为第二视角移动腕部相机的运动） ≤ step_lim
step_lim ∈ [200, 1900]；push T = 600（≈ 24 s 机器人时间，25 Hz）；图像观测、测量计算与模型思考不计步
```

> 说明：论文**没有定义观察窗口帧数 K 或帧间隔 Δt**。观测是“每命令/请求刷新”的单帧三相机 RGB（640×480），不是固定 K 帧堆叠。因此本笔记不给出任何 K 或 Δt 的数值；凡涉及“时间跨度”的讨论应落到 `step_lim` 与 25 Hz 动作步上。

### 2.6 直觉总结

深度网络失败的地方在于**尺度需要外部定标**且误差集中在腕部（中位误差头部 41 mm、腕部约 100 mm，即便用桌面定了尺度）；几何方法在已知平面或可三角化、标定可用的条件下，可避免本文所测深度网络的尺度问题；仍受像素定位、标定与几何条件限制，不等于没有系统误差或精度下限。代价是：**要付出主动运动的步数**（见 §4.5）。

## 3. 带数字走一遍：玩具例子 (Worked Example)

> ⚠️ 以下为**假设数值**的教学例子，用于把公式走通；非论文实测，勿作为指标引用。所有数字均已验算。

**设定（假设）**：世界坐标下相机中心 `C = (0, 0, 0.90) m`，桌面为 `z = 0.765 m`，高度差 `H = 0.135 m`。相机光轴垂直朝向桌面，焦距假设为 `f = 600 px`。下面分别演示中央像素的局部尺度与另一条离轴射线的平面求交；不能把未归一化射线的参数当成距离。

**第一步：正对平面时，一个像素对应多大横向位移？**

```
H = 0.90 - 0.765 = 0.135 m
中央像素附近，1 px 对应 H / f = 0.135 / 600 m = 0.225 mm
```

该结果只适用于这里假设的正对平面、已知高度与精确标定。论文报告的实际头部相机像素尺度为约 2–3 mm；两者不是同一相机设置，不能直接相减当作方法提升，也不能由这个玩具例子保证实际精度。

**第二步：另一条射线与桌面求交**

假设离轴像素对应未归一化方向 `d = (0.1, 0.2, -0.5)`：

```
λ = (0.765 - 0.90) / (-0.5) = 0.27
P = C + λ d = (0.027, 0.054, 0.765) m
||P - C|| = λ ||d|| ≈ 0.1479 m
```

验算：`P_z = 0.765 m`，交点确在桌面；`λ = 0.27` 是该方向参数化下的射线系数，不是相机到交点的欧氏距离。

**第三步：三角化的深度误差如何随基线缩放？**

假设两个相机基线 `b = 0.20 m`，目标深度（沿相机主轴）`Z = 0.70 m`，焦距 `f = 600 px`，像素匹配误差 `σ_disp = 1 px`：

```
视差         = f · b / Z = 600 · 0.20 / 0.70 ≈ 171 px
深度误差 σ_Z ≈ Z² / (f · b) · σ_disp
             ≈ 0.49 / (600 · 0.20) · 1 ≈ 4.1 mm
```

若把匹配误差降到 `σ_disp = 0.5 px`（例如用模板匹配或圆拟合），则 `σ_Z ≈ 2 mm`。**工程含义**：在 0.7 m 距离、0.2 m 基线下，仅考虑所假设的匹配误差，一阶近似给出几毫米的误差量级；尚未计入标定、遮挡等误差，因此不是稳定精度保证；如果基线更短（头部两腕不一定张开很大），误差会按 `1/b` 放大。这解释了为什么论文要**主动移动腕部相机去获得第二视角**，而不是只用固定的头部视角。

**第四步：和深度网络对照**

论文在 300 帧、8 个任务上实测（**这是论文实测，不是假设**）：Depth Anything V2 在头部中位误差 41 mm、腕部约 100 mm（用桌面定标后）；Depth Pro 与两版 MoGe 把头部降到 20–31 mm，但腕部仍在 21–72 mm。该场景的几何路线优于被测深度网络，不代表任意场景的毫米级精度保证。**代价是获取第二视角的运动步数**：三角化版本至少 **3.6%**，深度网络版本至少 **0.7%**；这些统计是下界，不能看成精确总开销。

## 4. 工程视角 (Engineering View)

### 4.1 延迟与吞吐

| 指标 | 数值（论文实测） | 工程含义 |
|------|------------------|-----------|
| 单次重测回合的墙钟时间 | 中位 **739 s** | 几乎全是模型延迟；RoboDojo **不把模型思考计入动作预算** |
| 同一回合的机器人仿真时间 | **26 s** | 机器人的真实执行时间远小于模型推理时间 |
| 动作速率 | **25 Hz** | 每个动作步约 40 ms |
| 每回合命令上限 | **60 条** | 与 `step_lim` 是两个独立约束 |

| 失败后一轮修复的时长 | 中位 **6.3 min**，90% 在 11 min 内 | 一轮只改一个工具；中位新增 118 行、删除 6 行 |
| 每轮 token | 输入中位 0.75 M（多半命中缓存），输出 5.7 k；全程 487 M 输入 / 3.8 M 输出 | 单卡 RTX 4090 跑一次任务开发 |

**工程含义**：如果部署到真实机器人，瓶颈不是控制频率（25 Hz 对操作任务够用），而是**模型侧的回合延迟**和**修复回路的样本效率**（一轮 6 分钟、需要 10 个开发布局才能冻结工具）。把“思考成本”和“执行成本”分开计价，是本架构能跑通的前提。

### 4.2 动作接口的工程细节

- **运动**：笛卡尔直线按 2 cm 间隔插值，每个航点用 cuRobo 求逆解，再按机器人官方限位做梯形速度规划；**没有独立运动规划器，也没有除机器人本体和桌子之外的碰撞模型**。
- **腕部相机位姿**：由 TCP 位姿推出，因此“移动腕部相机去观察”必须走基元运动，会消耗动作步。
- **两套执行器**：直接执行器（同进程，可 reset/replay/记录真值到容器永远看不到的字段）与 bridge 执行器（包装成官方客户端可调用的策略，无 reset、无真值）。**每个交付的工具都必须能在 bridge 下运行**。
- **安全隔离**：容器无直连网络、无 API key、无宿主目录；出站流量经代理只放行模型端点与 harness 路由。

- **本文不训练任何模型**。行为 agent 与优化 agent 都是 Codex CLI 里未改动的 GPT-6-Astra，medium reasoning effort；每个任务一次运行，单卡 RTX 4090。
- 对照基线 VPP2（world action model）与 PhysicalRSI（语言模型 agent 驱动的 VLA）为排行榜提交，属于外部**已训练**的策略，本文不重训，只引用其排行榜数字。

### 6.2 失败模式（420 个开发布局回合，RGB 工具，seed 0，论文实测）

- 失败 **268** 个：5 个因工具错误提前终止；其余 263 个中，**57% 耗尽预算**、**30% 声称完成但 checker 不同意**、**13% 主动放弃且剩余预算 ≥25%**，2 个因违反规则被 checker 停止。
- **按类分解**：可变形/关节/刚性任务里 60–77% 的失败是耗尽预算（agent 能看到结果不对，但做不出正确运动）；记忆任务里约一半是“声称成功但 checker 不同意”（视觉细节与成功判定的弱点）；运动物体任务里常见“等的东西已经过去就放弃”。
- **诊断意义**：**“声称成功但被拒”指向感知/规格缺口；“耗尽预算”指向执行缺口。**

### 6.3 隐含假设 (Hidden Assumptions)

> X-Ray 批判视角：以下前提是作者默认成立、但论文没有正面验证的。

1. **平面结构充分**：桌面、块顶、碗沿、盒槽都被假定为水平面或已知高度的平面。非平面（布、不规则物体）是已知例外，fold clothes 在杂乱变体上从 4/5 掉到 2/5 就发生在“颜色连通性”这一假设被打破时。
2. **相机标定长期稳定**：三组相机对的桌面高度一致到 1 mm；真实场景中相机热漂、振动、换镜头都会破坏这个前提。
3. **运动学与碰撞模型足够**：只有机器人和桌子的碰撞模型；工具里出现的“沿射线未测深度体素当障碍”正是这个简化假设的反面（insert tubes 案例中因此误判而提前停止）。
4. **开发/重测来自同一布局族**：开发用种子 0 的前 10 个布局，重测用接下来的 10 个新布局（Generalization 任务为标准/杂乱布局 0–4 作开发、5–9 作重测），同一随机规则、同一物体集。这**不是跨任务族泛化**，只能说明“对同分布新布局的泛化”。
5. **工具可复用性**：每个任务一套工具，跨任务不复用；共享池只有 `pick` 和 `table_plane`。
6. **基准 checker 是可信裁判**：成功/失败全由官方 checker 判定，作者不改；但在 **25 个任务**上，优化 agent 读过作者根据公开任务定义写的短笔记（行为 agent 看不到）。这些笔记不只说明 checker 要求，部分任务还含物体尺寸或目标位置，因此是比“仅用机器人观测”更强的**信息注入口**，也是 §5.3 中“信息 vs 能力”讨论的来源。

## 8. 精读建议 (Reading Guide)

- **值得精读原文的人**：
  1) 做多模态具身 agent / 工具使用的研究者：重点 §3.2–3.4 与 §4.5，看“测量、持久化、修复、预算”四个环如何咬合；
  2) 要评估“VLM 编码 agent 能否顶替专门策略”的工程团队：重点 §5.1 能力图与附录 D 的审计（7 个任务被查出硬编码几何体，替换后 0/10）；
  3) 研究主动感知与动作预算 trade-off 的人：重点 §4.5 与表 2。

- **建议章节路径**：先读 §3.1–3.4（机制骨架）→ 再看 §4.4–4.5（三角化 vs 深度、第二视角代价）→ 再看 §5.1 与 §5.2（能力边界与失败诊断）→ 附录 D（审计与信息注入的诚实披露）→ 可跳 §6 的大部分案例细节（除非你要复现某条修复）。

- **不值得精读的理由**：如果你不做机器人学习、或已经熟悉“LLM 写机器人代码”这条线，读摘要 + §5.1 的表 3 即可；再深的内容对端到端 VLA 训练没有直接迁移。
