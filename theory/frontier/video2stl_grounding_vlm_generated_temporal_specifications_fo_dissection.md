### 1.2 關鍵機制 (Key Mechanism)

- **結構/數值解耦（本文的中心設計）**：視頻決定 *符號* 結構（哪些實體重要、哪些事件發生、順序如何）；機器人軌跡決定 *數值* 量（多近算 Near、位移多少算 Displaced、一個時間關係允許多長）。這樣人/動物視頻可以定義任務，而不要求演示者與機器人形態一致。
- **兩段式 VLM 而非一次到位**：直接讓 VLM 從像素寫獎勵，會把感知、任務解讀、機器人幾何、獎勵工程混在一次調用裡。先出「語義事件軌跡」，再出「STL 公式」，每一步都可檢查。
- **本体論不足要顯式報告**：若視頻出現本体論（ontology）裡沒有的重要概念，VLM 必須報告「missing concept」，而不是自己發明新謂詞——把「規範語言的缺陷」變成可觀測的失敗模式。
- **符號與接地的數據分離**：成功軌跡被切成不相交的 D_ground / D_filter（本文 70/30）。接地只用 D_ground，驗證只用 D_filter——避免用同一批數據既擬合又自證。
- **保號平滑語義**：標準 STL 鲁棒性用嵌套 min/max，直接平滑會改變鲁棒性的正負號（硬 STL 下為假，平滑後變正）。本文用**保號 Boltzmann 歸約**，讓「滿足邊界」嚴格不變。
- **兩時間尺度信用分配**：短公式走滾動窗口給稠密反饋；長公式不壓進同一個窗口，而用**因果前綴監控器**在跨過新階段時給一次性獎勵，保證進度不可刷分（Σ r^progress ≤ 1）。

⚡ **Eureka Moment**：真正的新意不在「用邏輯寫獎勵」（這早有前人），而在**把 STL 當作視頻與機器人之間的一層「中間表示」**——視頻只負責抽出時間骨架，數值全部由機器人數據接地，於是同一條公式同時是**需求**（可讀）、**監控器**（可評估）、**獎勵**（可學習）。一個表示，三種用途。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
奖励 = λ_L · mean_i tanh( ρ_sp(φi, W_t) / s_i )   +   λ_P · (b_t − b_{t−1}) / K
```

先給目標，再給公式，再給變量說明，最後給直覺。

**目標**：把一條 STL 公式的「定量鲁棒性」轉成 RL 可用的獎勵——短跨度給稠密局部反饋，長跨度給稀疏但不可刷的進度信號。

**(a) STL 定量鲁棒性（背景）**

```
原子谓词:      ρ(f(x) ≥ 0, x, t) = f(x(t))
合取:          ρ(φ∧ψ)(t) = min( ρφ(t), ρψ(t) )
析取:          ρ(φ∨ψ)(t) = max( ρφ(t), ρψ(t) )
总是 G_I:      ρ(G_I φ)(t) = inf_{t'∈t+I} ρφ(t')
最终 F_I:      ρ(F_I φ)(t) = sup_{t'∈t+I} ρφ(t')
```
鲁棒性 > 0 表示滿足，大小表示「滿足裕度」。

**(b) 保號平滑語義（sign-preserving）**

```
BMin_β(z; A) = ( Σ_{i∈A} e^{−β z_i} · z_i ) / ( Σ_{j∈A} e^{−β z_j} )     # BMax 用正指數
smin_sp(z): min_i z_i < 0 时对负坐标做 BMin；min_i z_i > 0 时对全部坐标做；否则返回 0
smax_sp(z): 对称定义
性质:  smin_sp(z) ≥ 0  ⇔  min_i z_i ≥ 0
       smax_sp(z) ≥ 0  ⇔  max_i z_i ≥ 0     # 满足边界严格不变
```

**(c) 局部滾動窗口獎勵**

```
Φ_local = { φi ∈ Φ_keep : span(φi) ≤ H_local }
W_t     = [ max(0, t − H_local), t ]                  # 尾随窗口
s_i     = Q_α( |ρ_sp(φi, W_t)| )   估计于 τ ∈ D_ground  # 每条公式一个尺度
ρ̄_i(W_t) = tanh( ρ_sp(φi, W_t) / s_i )   ∈ [−1, 1]
r_t^local = (1/|Φ_local|) · Σ_{φi∈Φ_local} ρ̄_i(W_t)
```

**(d) 長期因果進度獎勵**

```
backbone:  φ_backbone  →  有序阶段 p1 → p2 → … → pK
b_t = 到时刻 t 为止「满足顺序且满足时间约束」的最远有效前缀长度, b_t ∈ {0,..,K}
r_t^progress = (b_t − b_{t−1}) / K        # 仅在跨入新有效阶段时非零
⇒ Σ_t r_t^progress ≤ 1                    # 已完成阶段不可重复领奖，天然防刷分
```

**變量說明**

| 符號 | 含義 |
|------|------|
| ρ | STL 定量鲁棒性（正值=滿足，幅值=裕度） |
| β | Boltzmann 平滑的逆溫度參數 |
| H_local | 局部窗口長度（時間跨度） |
| span(φ) | 評估一條公式所需的最長時間跨度 |
| s_i | 第 i 條公式的鲁棒性歸一化尺度（經驗分位數） |
| b_t | 已達成的「最遠有效階段前綴」 |
| K | backbone 的階段總數 |
| λ_L, λ_P | 局部項與進度項的權重（原論文給定，本文未列具體值） |

**直覺**：tanh(ρ/s) 把「每條公式的裕度」壓進 [−1,1]，避免幅度天生很大的公式獨占獎勵；而進度項把「長程順序」變成離散的里程碑，跨一個階段拿一份，回頭不會再拿。

> 符號與本文/相關文檔保持一致：ρ 用於鲁棒性、φ 用於 STL 公式、Φ 用於公式庫；本文刻意避開 LaTeX 數學語法，所有公式以代碼塊或純文本書寫。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

以 PushCube 的謂詞 `Near(a,b)`（末端執行器 a 與物體 b 的距離）為例，走一遍「符號 → 接地 → 獎勵」的閉環。以下數值為**便於說明的假設值**。

**Step 1 — VLM 只給符號（不給數值）**
公式庫裡的一條（原論文式 (1)）：
```
φ1 = F[0, H_task] ( Near ∧ F[0, h_engage] Engaged )
```
此時 `Near` 沒有閾值，`H_task`、`h_engage` 也沒有數值。

**Step 2 — 用 D_ground 擬合閾值（分位數）**
假設成功軌跡在「抓取前」的距離樣本 95 分位數為 δ = 0.045 m。這是一個**上界型**謂詞（距離越小越好）：
```
p(x) : f_p(x) ≤ δp          # f_p = 距离
ρ_p(x) = δp − f_p(x) = 0.045 − d
```
- 某 rollout 抓取前 d = 0.030 → ρ = 0.015 > 0，**滿足**。
- 若 d = 0.060 → ρ = −0.015 < 0，**違反**（離物體太遠，還沒「靠近」）。

**Step 3 — 局部窗口鲁棒性 + 歸一化**
假設窗口 `W_t` 內這條公式的原始鲁棒性 ρ_sp = 0.012，而尺度（|ρ| 的某分位數）s_i = 0.020：
```
ρ̄ = tanh(0.012 / 0.020) = tanh(0.60) ≈ 0.537
```

**Step 4 — 多條公式取平均**
假設 `Φ_local` 有 4 條短公式，歸一化後分別為 [0.54, 0.10, −0.20, 0.30]：
```
r_t^local = (0.54 + 0.10 − 0.20 + 0.30) / 4 = 0.185
```

**Step 5 — 進度項（長程）**
backbone 階段為 `Near → Engaged → TowardGoal → AtGoal → Static`（K=5）。某一步首次穩定跨入第 3 階段（TowardGoal）：
```
b_t = 3, b_{t−1} = 2  ⇒  r_t^progress = (3 − 2)/5 = 0.2
```
若這一步沒跨階段，則 r_t^progress = 0。

**Step 6 — 合成**
設 λ_L = 1.0, λ_P = 1.0（示意）：
```
r_t = 1.0×0.185 + 1.0×0.2 = 0.385
```
關鍵性質：即使策略反覆「假裝完成」同一階段，b_t 記的是**最遠有效前綴**，重複進入不會再給分 → Σ r^progress ≤ 1。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**
- 從**只有觀測的視頻**（含人/動物視頻）抽出任務時間結構，並轉成可讀、可驗證的規範。
- 在**四足運動**上跨 0.3–2.1 m/s 全程保持 100% 成功率，且在高速段能效可與生成式基線競爭。
- 在**操作**三/四個任務上，學習信號可與原生稠密獎勵競爭、並強於直接生成獎勵代碼。
- 提供**可檢查的失敗模式**：本体論缺概念會顯式報告，而非靜默改寫規範語言。

**不能做 / 風險**
- **依賴成功軌跡做接地**：沒有 D_ground 就無法擬合閾值；純視頻不足以直接給出數值。
- **LiftPegUpright 揭示的較真問題**：benchmark 只要求「peg 在桌面上直立（即使仍被夾著）」，而從示範抽出的規範還要求「釋放且保持靜止」。結果 Video2STL 學到了轉正（59% success-once），但常在高而窄的 peg 穩定前就釋放 → **success-at-end 只有 5%**。作者歸因於接地的 Upright 容差 **15.9°** 比 peg 的傾倒角 **11.8°** 還寬鬆——**門檻比物理臨界值鬆，導致「以為直立了其實會倒」**。
- **locomotion 只用局部項**：作者明說四足本質週期性、不像操作那樣可分階段，故**不啟用**長程進度項——即本文的兩時間尺度機制在該域並未被驗證。
- **只做了仿真**：四足與操作都在仿真（MJX / ManiSkill3），無真機結果；跨具身主要體現在「視頻來源可以不是同一本體」，而非真機遷移。
- **VLM 抽取品質是瓶頸**：規範品質上限取決於事件軌跡與公式庫的語義正確性；錯誤的符號結構無法靠接地修復。

### 6.1 隱含假設 (Hidden Assumptions)

- **假定每個「成功」軌跡都真的滿足從視頻抽出的時間結構**——否則接地會把錯誤結構也擬合進去，且過濾（Q_0.10 ≥ 0）只是「寬鬆的留出驗證」，未必能剔除所有誤結構。
- **假定分位數選取（如 95 分位、α=0.10）在小樣本成功集上穩定**——樣本少時分位數對噪聲敏感，門檻可能偏鬆或偏緊。
- **假定「語義事件」可用固定本体論枚舉**——跨到本体論外的新任務時，missing concepts 會累積，規範表達力受限。
- **假定單一 backbone 足以代表任務主進度**——長程結構複雜（多分支、條件並行）的任務可能被壓扁。
- **假定平滑不改變滿足邊界**是重要的（本文用保號歸約保證），但**未討論平滑對優化景觀的實際影響**（β 取值對收斂的敏感度）。
- **假定 `success-once` 與 benchmark 原生 success 條件的差異可接受**——LiftPegUpright 恰恰說明：規範更嚴格時，用 benchmark 指標評分會低估/錯判。

## 7. 與相關工作對比 (Comparison)

| 方法 | 從源信號遷移什麼 | 中間表示 | 訓練方式 | 適用場景 |
|------|------------------|----------|----------|----------|
| VIP (Ma et al. 2023) | 視覺嵌入空間中的稠密獎勵 | 學到的表示向量 | 距離→獎勵 | 需要大規模人類視頻；可解釋性弱 |
| RoboCLIP (Sontakke et al. 2023) | 軌跡與視頻/語言的相似度 | 標量相似度 | episodic reward | 任務規格易用語言描述時 |
| GVL (Ma et al. 2025) | VLM 估計的逐幀進度 | 標量進度 | 進度→獎勵 | 300+ 真實任務；仍為標量 |
| Text2Reward (Xie et al. 2024) | 語言意圖→可執行獎勵代碼 | 程序代碼 | 直接執行 | 需要環境 API；結構隱含在代碼裡 |
| Eureka (Ma et al. 2024) | LLM 生成並迭代改進獎勵代碼 | 程序代碼 | 以策略表現回饋迭代 | 反饋迴路成本高 |
| Lang2LTL (Liu et al. 2023) | 語言命令→LTL | 形式化邏輯 | 用於規劃/執行 | **假設時間結構已由語言給定** |
| **Video2STL (本文)** | 視頻→參數化 STL→接地獎勵/監控器 | **可讀的 STL 公式庫** | 兩時間尺度 PPO 獎勵 | 從觀測視頻學操作/運動；**結構來自視頻、數值來自機器人數據** |

**面試 Tip**：被問到「Video2STL 和 Text2Reward 有什麼本質差別」時，一句話答：**Text2Reward 把結構與數值一起燒進不可讀的代碼；Video2STL 把結構交給了視頻（可檢查的 STL），把數值交給機器人軌跡去擬合，於是同一條規範既是需求、又是監控器、又是獎勵。**

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**獎勵設計自動化 / 視頻示範 → 策略**的研究者，尤其是關心「中間表示該長什麼樣」的人。
  2. 要**評估遷移到新機器人平台可行性**的工程師——重點看 §4.3 接地與 §4.6 兩時間尺度，判斷自己的成功軌跡夠不夠、控制頻率合不合。
  3. 對**形式化方法 + 學習**交叉感興趣的人（STL/PSTL + PPO）。
- **建議章節路徑**：先讀 §4.1–§4.6（方法主線）→ 再看 §5.2 操作結果與 LiftPegUpright 的失敗分析 → §2 相關工作若你已熟，可**跳讀**（本文對比段落的價值主要在最後一段的「遷移什麼」總結）。
- **不值得精讀的理由**：若你不做機器人學習、或只關心端到端 VLA 大模型（像素→動作），讀摘要 + 本節即可；本文的貢獻位於「獎勵/規範接口層」，而非新網絡結構或新預訓練範式。
