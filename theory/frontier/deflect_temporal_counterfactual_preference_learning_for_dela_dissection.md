💡 **X-Ray 开场**

异步 VLA 的常识是：机器人一边执行当前 chunk，一边算下一个 chunk，用运动盖住推理延迟。代价是下一个 chunk 是"用旧帧算的"，等它真正执行时，杯子已经被传送带带走了。DEFLECT 的观察很朴素：在线时拿不到未来帧，但**离线轨迹里未来帧是现成的**。于是它把"未来帧会生成的动作"标成偏好，让策略在**完全相同的过期输入**下学会偏向那个动作。对 VLA 研究者的意义：本文把延迟问题表述成一个"离线可构造的偏好排序问题"，而不是只能靠改网络或改采样器。

## 1. 核心架构 / 方法总览

### 1.1 系统对比概览

DEFLECT 不是新模型，而是一个**离线 post-training 阶段**。它的三个"模型身份"必须分开看，因为论文对每个 backbone 的初始化、冻结范围、chunk 长度都不一样。

|---|---|---|---|---|---|
| SFT 初始化 | VLASH（delay-aware） | VLASH（delay-aware） | Standard SFT | Standard SFT | VLASH（自采数据训练） |
| 部署输入形态 | 沿用 base policy 的 C_b(I_t) | 沿用 VLASH 上下文 | (o_t, s_t, l_t) Naive Async | (o_t, s_t, l_t) Naive Async | 沿用 VLASH 上下文 |

### 1.2 关键机制

**(a) 问题定义。** 设推理延迟为 d 个控制步，t 时刻发起的预测在 t+d 才可用。策略拿到的是 o_t、s_t、l_t，但执行时世界已经是 t+d。标准 SFT 学的是"给定输入模仿单一专家目标"，delay-aware SFT（以 VLASH 为代表）把 proprioceptive state 前滚成 (o_t, ŝ_{t+d})，但**视觉仍然是过期的**。运行时修补（RTC、BID、A²C²）改 chunk 衔接，却不改"动作语义对齐的是预测时刻"这件事。

**(b) DEFLECT 的做法。** 冻结一份 SFT 策略副本 π_ref,b 作为参考模型。对轨迹上每个 t，采样一个时间对比跨度 δ ∼ Unif{1,…,d_max}，d_max=4，用**相同的采样随机性 ξ**（相同高斯噪声、相同 ODE 日程）分别生成：

- A⁺_t：从未来输入 (s_{t+δ}, o_{t+δ}) 生成
- A⁻_t：从过期输入 (s_t, o_t) 生成

把 A⁺ 标为偏好。**这个标签只由观测时间戳决定，不由执行结果决定**——论文在 §3.1 明确写了这一点，并声明它"不意味着 A⁺ 在每个 pair 上执行更好"。δ=0 被排除，因为此时 A⁺=A⁻，pair 退化（附录 B、算法 1 第 3 行）。

**(c) 关键的一步：共享 deployment input。** A⁺ 和 A⁻ 是在**不同的生成上下文**下产生的，但 DEFLECT 在计算偏好损失时，把两者都放到**同一个** c^dep_{t,b} 下打分。这一步把"两个时间戳的对比"转换成了"部署策略真正面对的那个决策"。附录 F 的消融直接量化了它：如果改成"各在自己的生成上下文下打分"，Kinetix 平均从 89.2% 掉到 88.4%，d=4 从 86.1% 掉到 84.8%，且差距随延迟单调扩大（−0.3/−0.5/−0.7/−0.9/−1.3 对应 d=0…4）。

**(d) 为什么必须保留 SFT anchor。** 附录 F 的第二个消融很刺眼：去掉 SFT 项、只留偏好项，Kinetix 平均成功率崩到 15.1%，d=4 只有 10.6%。作者的解读是"偏好目标单独不足以支撑该设置"。我的条件性分析：FM-DPO 只提供**相对**信号，它可以把 A⁺ 的相对得分抬上去，但不约束动作落在专家流形上；在 Kinetix 这种 contact-rich、动态性极强的任务里，相对信号很容易把策略推离可行区域。

⚡ **Eureka Moment**：未来观测在线拿不到，但在**离线轨迹里是免费的**；所以延迟对齐不必是推理期修补，可以是一次"用未来帧当正例"的离线偏好排序。

## 2. 数学核心

📌 **Napkin Formula**：

```
L = λ_SFT·‖v_θ(A^exp_τ, τ, c) − (A^exp − ε)‖²
  + λ_DPO·(−log σ( β·[(Δ⁻_θ − Δ⁺_θ)] ))
其中 Δ^±_θ = L_FM(θ; A^±, c) − L_FM(π_ref; A^±, c)
```

**目标**：在**不改变部署输入 c^dep** 的前提下，让策略对"未来帧生成的 chunk"赋予比"过期帧生成的 chunk"更高的隐式似然，同时不偏离专家动作流形。

**部署输入定义（式 1）**：

```
c^dep_{t,b} = C_b(I_t)
I_t = {o_t, s_t, l_t, 控制器侧信号}
Naive Async:  c^dep = (o_t, s_t, l_t)
VLASH:        c^dep = (o_t, ŝ_{t+d}, l_t)   ← ŝ 由已提交动作前滚得到
```

**偏好对构造（式 2）**：

```
A⁺_t = π_ref,b( (s_{t+δ}, o_{t+δ}), l_t ; ξ )
A⁻_t = π_ref,b( (s_t,     o_t),     l_t ; ξ )
标签：A⁺ ≻ A⁻（仅由观测时间戳决定）
```

**SFT 采样（式 3）**：`(c^dep_{t,b}, A^exp_{t,b}) ~ S_b(D, t)`，DEFLECT 直接复用 base policy 原来的采样器，不另造输入。

**Flow-matching 损失（式 4）**：

```
A_τ = τ·A + (1−τ)·ε,   ε ~ N(0, I),  τ ~ Unif[0,1]
L_FM(θ; A, c, τ, ε) = ‖ v_θ(A_τ, τ, c) − (A − ε) ‖²₂
```

**参考校准的偏好损失（式 5）**：

```
Δ^±_θ = L_FM(θ;       A^±, c^dep, τ, ε)
       − L_FM(π_ref,b; A^±, c^dep, τ, ε)

L_FM-DPO(θ) = − log σ( β·[ Δ⁻_θ − Δ⁺_θ ] )
```

**总目标（式 6）**：

```
L_DEFLECT(θ) = λ_SFT·L_FM(θ; A^exp, c^dep, τ, ε) + λ_DPO·L_FM-DPO(θ)
```

| 符号 | 含义 | 取值 / 约束 |
|---|---|---|
| d | 部署期推理延迟（控制步） | 仿真实测 {0,…,4}；真机不额外注入 |
| δ | 训练期时间对比跨度（步） | Unif{1,…,d_max}，d_max=4；与 S_b 的 context delay 独立采样 |
| τ, ε | flow 时间与高斯噪声 | 每个偏好对采样一次，**跨 A⁺/A⁻、跨 θ/ref、跨 SFT anchor 共享** |
| β | 偏好温度 | 全局 β=1.0 |
| λ_SFT | SFT 锚权重 | 1.0（所有设置） |
| λ_DPO | 偏好权重 | Kinetix 扫描 {0,0.01,0.02,0.05,0.1,0.2,0.5} 取 0.02（稳健带 [0.01,0.05]）；LIBERO 0.1；真机 0.02 |
| H | action chunk 长度 | 8 / 50 / 16 因模型而异，不可混用 |
| K | 执行 horizon | Kinetix 用 max(1,d)；LIBERO 用 5 或 8 |

**直觉**：L_FM 越小 = 该 chunk 在当前条件下的隐式似然越高。偏好项希望 Δ⁺ < Δ⁻，即"A⁺ 相对于参考模型的改善量"要大于"A⁻ 相对于参考模型的改善量"。减去参考项的作用是校准——否则模型可以通过整体压低 loss 来"作弊"，而不是真的把 A⁺ 排到 A⁻ 前面。

**一个必须说清的边界（附录 D）**：作者明确声明，−L_FM 只是条件 log-likelihood 的**替代量（surrogate）**，不是精确值；单样本 (τ, ε) 蒙特卡洛估计保留了方差；只有当"期望 FM 目标与精确 NLL 只差一个与模型无关的常数"这个更强假设成立时，M_FM 才等于 DPO 的 log-ratio margin。论文说"我们的优化不需要这个更强等式"。这是全文最诚实的一段，也是复现时最容易忽略的一段。

## 3. 带数字走一遍：玩具例子

> ⚠️ **以下为假设性数值，用于验算公式方向，不是论文实验数据。** 为可手算，把 action chunk 压成 1 维、1 步，取 β=1.0、τ=0.5、ε=0.5。

**设定**：

```
A⁺ = 1.0   （未来帧生成的 chunk）
A⁻ = 0.0   （过期帧生成的 chunk）
τ = 0.5, ε = 0.5
A_τ = 0.5·A + 0.5·0.5 = 0.5A + 0.25
目标速度 A − ε
```

**插值点与回归目标**：

```
A⁺_τ = 0.5·1.0 + 0.25 = 0.75   目标 = 1.0 − 0.5 = 0.5
A⁻_τ = 0.5·0.0 + 0.25 = 0.25   目标 = 0.0 − 0.5 = −0.5
```

**假设当前策略与参考策略的预测速度**：

```
v_θ(A⁺_τ) = 0.40      v_θ(A⁻_τ) = −0.20
v_ref(A⁺_τ) = 0.45    v_ref(A⁻_τ) = −0.25
```

**逐项算 L_FM**：

```
L_FM(θ; A⁺) = (0.40 − 0.50)² = 0.0100
L_FM(θ; A⁻) = (−0.20 + 0.50)² = 0.0900
L_FM(ref; A⁺) = (0.45 − 0.50)² = 0.0025
L_FM(ref; A⁻) = (−0.25 + 0.50)² = 0.0625
```

**算 Δ 与 logit**：

```
Δ⁺_θ = 0.0100 − 0.0025 = 0.0075
Δ⁻_θ = 0.0900 − 0.0625 = 0.0275
Δ⁻_θ − Δ⁺_θ = 0.0200
logit z = β·0.0200 = 0.0200
σ(0.02) ≈ 0.5050
L_FM-DPO = −log(0.5050) ≈ 0.6833
```

**方向验算**：z>0 说明当前策略已经**略微**偏向 A⁺，loss 略低于 log 2 ≈ 0.693。梯度 ∂L/∂z = −(1−σ(z)) ≈ −0.495，即优化会把 z 继续推大，也就是**进一步压低 L_FM(θ; A⁺) 或抬高 L_FM(θ; A⁻)**。这与"偏好 A⁺"的意图一致，符号没写反。

**反向标签验算（附录 G 的极端情形）**：若把标签反过来（偏好 A⁻），z = −0.02，σ ≈ 0.4950，loss ≈ 0.7033。两者差 0.02——在这个玩具量级上差别很小，正好说明**单对样本的信号很弱**，DEFLECT 依赖的是成千上万对上的统计累积，而不是单对判决。这也解释了为什么 λ_DPO 要小（Kinetix 只取 0.02）。

**第二个验算：延迟换算（这个是论文真数据）**。真机 30 Hz，控制周期 Δt = 1/30 s ≈ 33.33 ms。论文 Table 2：

```
RTX 5090: 57.1 ms  → 57.1/33.33 = 1.71 → 向上取整 2 步
RTX 4090: 78.8 ms  → 78.8/33.33 = 2.36 → 3 步
RTX 5070: 152.0 ms → 152.0/33.33 = 4.56 → 5 步
```

与论文"2 / 3 / 5 control steps"完全对上。注意 **5070 的 5 步已经超出训练时 δ≤4 的范围**，这是一个值得注意的外推点（见 §6.1）。

**第三个验算：训练期 δ 的物理跨度**。δ 是**步数差**，所以 t 与 t+δ 的时间差是 δ×Δt，不是 (δ−1)×Δt——因为 δ 本身就是"差了几步"。在 30 Hz 下 δ=4 对应 133 ms。若改用"帧数 K"表述，则 K 帧覆盖 (K−1) 个间隔、跨度 (K−1)×Δt；本文用的是步数差 δ，故写作 δ×Δt。两者不可混用。

## 4. 工程视角

**(a) 推理侧零成本，训练侧有账。** 附录 I 与 Table 10 写得很清楚：

| 项目 | Continued SFT | DEFLECT |
|---|---|---|
| Kinetix 每 gradient step | 1 fwd + bwd | 1 fwd + bwd **+ 11 次 reference forward**（2 次 chunk 生成 × 5 denoising steps，+ 1 次 margin 用的 reference velocity） |
| LIBERO 每 gradient step（Table 10 仅对 GR00T N1.7 说明） | 1 fwd + bwd | **2 fwd + bwd + 1 次 reference forward**（4 对偏好 = 8 个候选输入拼成一次前向；另一次给 SFT anchor） |
| LIBERO 一次性开销 | — | ≈ 3.8×10⁵ 次单候选 forward（GR00T：48,000 对 × 2 × 4 步 = 384,000） |
| 推理 | 1× | **1×** |

工程含义：Kinetix 上偏好对是**训练中即时生成**，所以每步都要付 11 次冻结参考前向；LIBERO 上是**预生成缓存**，一次性付 3.8×10⁵ 次前向，之后每步只多 1 次带梯度前向和 1 次无梯度前向。如果团队已经有离线轨迹和固定 base checkpoint，LIBERO 这条路的边际成本可以接受；Kinetix 那种 on-the-fly 生成会显著拉长 wall-clock。

**(b) 缓存与显存。** GR00T N1.7 每 suite 缓存 12,000 对，4 个 suite 共 48,000 对；2,000 步 × batch 4 = 8,000 次使用（含重复采样）。论文特别注明"这些是训练使用次数，不是缓存中不同 pair 的数量"。做容量规划时这两个数不能混。

**(c) 真机的实际延迟预算。** 真机用 H=50、10 步 denoising、30 Hz，即一个 chunk 覆盖 50×33.33 ms ≈ 1.667 s。异步控制器在"当前队列剩一半"时请求新预测，即约 25 步 ≈ 833 ms 处发起，推理 57.1 ms（≈2 步）完成。**论文没有说明新 chunk 到达后是立即切换还是等旧队列耗尽**，因此"实际生效的 d 是否等于 2"不能从正文直接推出，这是我在复现时会首先确认的实现细节（TODO：待补，论文未给）。若真的等到队列耗尽才切换，则有效 d 会远大于 2，而 5070 上的 5 步延迟就更值得担心。

**(d) 抖动与切换。** DEFLECT **不修改** runtime 的 chunk 衔接逻辑。这意味着 RTC 那类“保留已提交动作、对新 chunk 剩余部分 inpainting”的修补，以及 BID 那类“测试时按 forward-contrast 与 backward-coherence 重采样 action chunk”的修补，与 DEFLECT 是**正交**的，理论上可叠加；但论文没有做这个组合实验，我不替它宣称。

**(e) 部署约束清单**：

- 必须能拿到 base policy 的 `c^dep` 构造函数 C_b（否则无法共享 deployment input）
- 必须有离线轨迹，且轨迹内相邻 δ≤4 步的观测齐全
- action head 必须是 flow-matching / diffusion 类（DPO 用的是 FM loss 作 surrogate）
- 若 base policy 已经很鲁棒（如 VLASH π0.5 在 LIBERO 上 95.54%），收益会被天花板压缩

### 5.1 预训练与初始化（三层要分开）

| 层 | 内容 | 是否由本文产生 |
|---|---|---|
| VLA backbone 预训练 | π0.5、SmolVLA、GR00T N1.7、Kinetix 上的 action-chunking flow policy（4 层 MLP-Mixer） | 否，均为现成模型；Kinetix 用 VLASH 放出的 checkpoint |

## 6. 能力与失败模式

**能做**：

- 在**不增加推理算力**的前提下，把长延迟下的成功率拉回来（Kinetix d=4 +4.2 pp；GR00T d=4 +22.70 pp）
- 对**两种 SFT 初始化都有效**：delay-aware（π0.5 +0.74）和 standard（SmolVLA +10.49、GR00T +11.56）
- 对**训练时没见过的更长对比跨度**有一定外推（δ≤2 训练的 Model A 在 d=4 仍 +3.2 pp）
- 在动态真实任务上有效（运动传送带取放、打地鼠式反应）

**不能做 / 做不好**：

- **短延迟不占优**：GR00T d=1 上 Future SFT 95.20 > DEFLECT 93.60。偏好学习需要"两个时间戳产生实质差异"才有信号
- **替代 SFT**：去掉 anchor 直接崩到 15.1%（avg）/ 10.6%（d=4）
- **修 runtime 衔接**：DEFLECT 不动 chunk 边界，RTC/BID 那类问题它不管
- **恢复精确似然**：作者自己说 FM 目标只是 surrogate，不主张等价于 DPO log-ratio
- **跨硬件外推**：5070 上 5 步延迟已超出 δ≤4 的训练范围；Model C 试了 δ≤7 但同时改了 async interval=8，论文明确说"这个差异不能单独归因于对比跨度范围"

### 6.1 隐含假设（X-Ray 批判视角）

1. **偏好标签只由观测时间戳定义，未按执行结果验证。** 论文 §3.1 明确：A⁺ 仅因来自未来观测而被标为偏好，标签不基于执行两个 chunk 的结果，且不表示 A⁺ 在每个 pair 上执行更好；论文并未把“未来帧生成的 chunk 平均更优”作为定义，更未验证这一经验命题。所以 DEFLECT 优化的是**时间戳对齐的代理目标**。这个代理在什么条件下与真实任务回报同向，论文没有独立验证（没有做“用执行结果打标签”的对照）。我认为这是最值得后续工作补的一格。
2. **参考模型 = base policy 的冻结副本**，所以 A⁺ 是"同一个模型看到未来帧会输出什么"，不是专家最优。如果 base policy 看到未来帧也做错，偏好信号会把错误固化。论文没有报告"A⁺ 与专家动作的偏差分布"。
3. **δ ≤ 4 步的密度假设**。构造 (s_t, o_t) 与 (s_{t+δ}, o_{t+δ}) 要求轨迹在 t 到 t+δ 之间连续可查。30 Hz 下 δ=4 只有 133 ms；如果真实部署延迟达到 5 步（RTX 5070 的情况），训练与部署的对比跨度就错位了。
4. **真机不注入额外延迟**。所有真机结论都建立在"原生 2 步延迟"上，没有做延迟 sweep。仿真里的 d∈{0..4} 扫描不能直接搬到真机。
5. **统计功效**。真机每任务每方法 30 trials，Conveyor-I 上 DEFLECT 96.7% vs VLASH 86.7% 是 29/30 vs 26/30，差 3 个样本；这个量级的差异对单次失败很敏感。
6. **协议不可混比**。Kinetix 的 K=max(1,d) 与 REMAC 的"K 全平均"是两套协议，论文自己分开报。任何把 87.8% 与 89.2% 放同一张表对比的做法都是错的。
7. **消融的一处舍入不一致（技术编辑备注）**：附录 F 正文说"在自己的生成输入下打分"相比完整版"costs −0.7 on average"，但 Table 5 的 88.4 vs 89.2 相减是 0.8；d=4 的 84.8 vs 86.1 是 1.3，与正文 −1.3 一致。差异应源于"舍入前计算"（Table 6 有同样说明）。复现时应以未舍入值为准。

## 7. 与相关工作对比

| 方法 | 干预位置 | 是否改 runtime | 是否用未来信息 | 训练信号 | 备注 |
|---|---|---|---|---|---|
| Naive Async | 无 | 切换即可 | 否 | 标准 SFT | 基线，延迟越长越差 |
| RTC (Black et al., 2026) | 运行时 inpainting | 是，需额外计算 | 否（只用已提交前缀） | 无 | d≥5 时残差前缀只剩 1–3 步，太短 |
| BID (Liu et al., 2025) | 测试时重采样 | 是，需额外计算 | 否 | 无 | 前向对比 + 后向一致性 |
| A²C² (Sendai et al., 2025) | 运行时观测校正 | 是 | 否 | 无 | 论文列为 runtime repair |
| VLASH (Tang et al., 2025) | 训练时上下文 | 否 | 部分（前滚 proprio） | delay-aware SFT | 视觉仍过期；本文的主要 base |
| TT-RTC (Black et al., 2025) | 训练时动作前缀条件 | 否 | 否 | 条件化 SFT | 只在协议匹配的单独实验比较 |
| REMAC (Wang et al., 2026) | 训练时掩码修正 | 否 | 否 | 掩码 chunk 修正 | 报告方式为 K 全平均，需换协议 |
| Future SFT（本文基线） | 训练时增加未来目标 | 否 | **是**（把 A⁺ 作为额外监督目标，同时保留原始 expert-target SFT 项） | 监督回归 | d=1 最强（95.20），d=4 掉到 65.75 |
| Continued SFT（本文基线） | 训练时继续 SFT | 否 | 否 | 标准 SFT | λ_DPO=0 的对照 |
| **DEFLECT** | **离线 post-training** | **否** | **是（仅构造偏好，不进部署输入）** | **FM-DPO + SFT anchor** | 推理 1×，接口不变 |

**Future SFT vs DEFLECT 是本文最有信息量的一组对照**：两者都用了未来信息，区别是"把 A⁺ 作为额外监督目标（同时保留原始 expert-target SFT 项）"还是"只学相对排序"。结果是 d=1 上 Future SFT 更高（95.20 vs 93.60），但从 d=2 起被反超，d=4 差 7.35 pp（73.10 vs 65.75），平均差 2.85 pp。作者的解读是"偏好学习在直接学习未来生成目标之外进一步提升延迟鲁棒性"。我的补充：把 A⁺ 作为额外监督目标会把这个"未来帧下的单点采样"当成硬目标，等于把参考模型的采样噪声也一起学进去；相对排序对这种噪声更不敏感——这与附录 D 说的"共享 (τ,ε) 降低 pair 差异方差"是同一件事的两面。

🎤 **面试 Tip**：如果被问"DEFLECT 和 VLASH 有什么本质区别"，一句话答：**VLASH 改的是训练时的输入/目标构造（把状态前滚到执行时刻），DEFLECT 不改输入，改的是损失——在同一个部署输入下，用未来帧生成的 chunk 当正例做相对排序。所以 VLASH 是 base policy，DEFLECT 是叠在它上面的 post-training，两者可以串联，论文里 Kinetix、π0.5、真机三处正是这么做的。**

## 8. 精读建议

**值得精读原文的人**：

1. **正在做异步 action chunking 部署的工程师**：你们大概率已经在用 RTC 或 VLASH 之一。这篇给了第三条路——不改 runtime、不改输入，只加一个离线 DPO 阶段。重点看 §3.2、附录 B（超参与缓存）、附录 I（训练成本）。
2. **做 preference learning / RL 与机器人交叉的研究者**：附录 D 对"FM loss 作为 likelihood surrogate"的边界讨论，比正文更有价值，它明确列出了"什么条件下才等价于 DPO log-ratio"。
3. **要评估跨 backbone 迁移可行性的团队**：Table 1(b) 的三个 backbone + 三种初始化组合，是目前少见的"同一方法在强弱不同的 base 上都试一遍"的证据。

**建议章节路径**：

```
§3.1–3.2（机制 + 公式，必须先看）
  → 附录 D（surrogate 的边界，决定你敢不敢用）
  → 附录 B（超参 / 缓存 / δ 采样，决定你能不能复现）
  → 附录 F（两个消融，决定你的场景适不适用）
  → 附录 G（标签方向，决定这是不是"随便加个正则"）
  → §4.1.2 Table 1(b)（增益与 base 强度的关系）
  → 附录 H（真机分目标，看失败模式落在哪）
可跳：附录 A（相关工作综述）、附录 C（算法伪码，正文已够）
```

**不值得精读的理由**：

- 你只关心推理加速（DeeR-VLA / SnapFlow / FASTER 那条线）——这篇明确说自己是正交的，读摘要 + §4.2.2 的延迟表即可
- 你的 action head 不是 flow-matching / diffusion（比如是离散 token 自回归）——FM-DPO 的推导不直接适用，需要重做 surrogate
- 你需要多机器人 / 多embodiment 的泛化证据——本文只有单平台双臂 + 三个仿真 backbone，没有跨本体实验
