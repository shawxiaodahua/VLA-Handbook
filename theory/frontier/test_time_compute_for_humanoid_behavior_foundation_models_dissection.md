## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理 |
|------|------|------|-----------|-----------|
| 预训练 BFM π（冻结） | 观测历史 o_{0:t-1}、运动命令 c_t | 低层动作 a_t | 50 Hz（Δt=0.02 s，4 个物理步/动作） | 训练时完成，本文全程冻结 |
| 环境动力学 f | 状态 s_{t-1}、动作 a_t | 新状态、观测 | 物理步 0.005 s | 仿真（MuJoCo Warp / Isaac Sim） |
| TTCO 优化器 | 参考运动 τ^ref、当前状态 z_{t-1} | 命令段 c_{t:t+H-1} | 每个 planning call 花 I·N·H 次仿真转移 | 推理期在线/离线均可 |
| 高层策略（§4.4） | 图像 + 语言 + 本体感觉 | 运动命令 | 预测 24 步、执行 20 步（仿真）；40 步（真机） | Diffusion Policy / GR00T N1.7 微调 |

### 1.2 关键机制

- **把「命令」和「目标」解耦**：标准推理令 c^nom = τ^ref，执行出 τ^nom = T_π(c^nom) 有系统偏差；TTCO 求 c* 使 T_π(c*) 更贴近 τ^ref，代价是命令本身偏离参考（论文 Fig. 1 明确说「调整被夸大以便展示」）。
- **滚动时域**：长序列直接优化不可解（决策变量随 T 增长），改为优化 H 步命令段、执行前 E 步、重规划，形成闭环。
- **控制节点参数化**：决策向量 x 是稀疏 knot，节点数 n_knot(H) = max(2, floor(5H/40 + 0.5))，clip 到 [-1,1] 后乘物理尺度 D 并线性插值到 H 步。这样把高维命令压到低维搜索空间。
- **采样优化器横评**：CEM、Predictive Sampling、MPPI-CMA、CMA-ES、CBO；最终选 CEM（在多数预算上竞争性最好，论文 Fig. 5a）。
- **计算预算定义为仿真转移次数**：这是本文最可迁移的度量选择——不是 wall-clock，不是 GPU 小时，而是「跑过多少次 BFM 闭环」。

⚡ **Eureka Moment**：要补偿 BFM 的执行偏差，优化的对象应该是**输入命令**而不是**模型权重**；命令偏移量与偏差同阶，因此可以在很小的搜索空间里用闭环仿真把它找出来。

## 2. 数学核心

📌 **Napkin Formula**：
```
c* = argmin_c  J(c, τ^ref) = L_track(T_π(c), τ^ref) + L_reg(c)
```
一句话：**在冻结的闭环动力学 T_π 下，找一条命令让执行轨迹最像参考，同时别让命令抖得太厉害。**

**目标**：给定冻结 BFM π 和参考 τ^ref，求补偿后的输入命令。

**全序列问题（Eq. 1）**：
```
c* = argmin_{c ∈ M_{1:T}}  J(c, τ^ref)
J  = L_track(c, τ^ref) + L_reg(c, τ^ref)
L_track = Σ_{t=1}^{T} ℓ_t^track( T_π(c)_t , τ_t^ref )
```

**滚动时域局部问题（Eq. 2–4）**：
```
c*_{t:t+H-1} = argmin  J_local(c_{t:t+H-1}, z_{t-1}, τ^ref_{t:t+H-1})
J_local = Σ_{h=0}^{H-1} (ℓ^track_{t+h} + ℓ^reg_{t+h}) + ℓ^term_{t+H-1}
s.t.  z_k = F_π(z_{k-1}, c_k),  k = t, ..., t+H-1
```

**单步代价构成（论文 Eq. 14–19）**：
```
ℓ^track = w_q·e_q + w_q̇·e_q̇ + w_x·e_x + w_R·e_R
ℓ^reg   = w̄_q·e_q^deform + w̄_x·e_x^deform + w̄_R·e_R^deform + (w_s/n_q)·||q̇_t||²
权重： (w_q, w_q̇, w_x, w_R) = (1, 0, 1, 0.5)
       (w̄_q, w̄_x, w̄_R)     = (0.1, 0.1, 0.05)，w_s = 0.01
       (w_q^term, w_x^term) = (5, 5)
```

**计算预算（§3.3）**：
```
C(ξ, T) = ceil(T/E) · I · N · H          （总仿真转移次数）
K(ξ)    = I · N · H / E                   （预算比，与运动长度无关）
```

**代理成本模型（Eq. 6–9）**：
```
Ĵ_TTC(A, ξ) = J_∞ + ε_horizon(H,E) + ε_sample(A,I,N | H,E)

ε_horizon(H,E) = C_H · exp(-α_H (2H - E)) + C_E (E - 1)
ε_solver(A,I,N) = C_I I^{-α_I} + C_N N^{-α_N}
ε_sample        = ε_solver^{η/H} · γ^H
```

**连续松弛下的最优分配（Eq. 29）**：
```
I* = (α_I C_I / (α_N C_N))^{1/(α_I+α_N)} · O^{α_N/(α_I+α_N)}
N* = O / I*        （O = I·N 为求解器预算）
```

> 符号与论文保持一致：ξ = (I, N, H, E)；A 为采样优化器；z_t = (s_t, o_{0:t}) 为闭环状态；T_π(c) 为命令 c 诱导的执行轨迹。

**变量速查**：

| 符号 | 含义 | 论文取值示例 |
|------|------|-------------|
| I | 优化迭代数 | Q1：4；Table 11：8–15 |
| N | 每次迭代候选数 | Q1：80；Table 11：31–78 |
| H | planning horizon（步） | Q1：40 |
| E | 执行步数（重规划间隔） | Q1：20 |
| K | 预算比 INH/E | Q1：640 |
| n_q | G1 关节数 | 29 |
| Δt | 控制周期 | 0.02 s |

**直觉**：ε_horizon 随 2H−E 指数衰减（终端代价近似 H 以外代价，引用 Kunisch & Pfeiffer 2020 的上界），加上 E 的线性修正（执行越久越不抗扰）；ε_solver 是反幂律，符合采样优化的收益递减；η/H 让长 horizon 下采样更难（决策维数随 H 增长，Lipschitz 极小极大率 n^{-1/d} 的动机）。

**拟合值（Table 10，CEM）**：J_∞=0.034123，C_H=1.8011，α_H=0.094838，C_E=0.00047245，C_I=0.49438，C_N=0.83919，α_I=0.40234，α_N=0.34379，η=160.00，γ=0.98201。

> ⚠️ 我的观察（条件性分析）：η 拟合值 160.00 恰好等于 Table 10 给定的搜索上界 [0.1, 160]，提示该参数可能撞界、不可辨识或存在外推风险。论文未讨论这一点。

## 3. 带数字走一遍：玩具例子

> **以下为假设性玩具例子，数字为我构造并验算，仅用于理解机制，不代表论文实测。** 论文的最小真实单元是 G1 29 关节 + 14 个评估 bodies 的闭环，无法在此复现。

**假设**：执行器是一阶低通，x_t = 0.8·c_t + 0.2·x_{t-1}，x_0 = 0，α=0.8 表示 20% 增益不足。参考要求 x_1^ref = 1.0，x_2^ref = 2.0。无正则。

名义命令 c^nom = (1.0, 2.0)：
```
x_1 = 0.8·1.0 = 0.8                      e_1 = 0.20，e_1² = 0.0400
x_2 = 0.8·2.0 + 0.2·0.8 = 1.76           e_2 = 0.24，e_2² = 0.0576
L_track(nominal) = 0.0976
```

补偿命令（解析解）：
```
c_1 = 1.0 / 0.8 = 1.25          → x_1 = 1.0       误差 0
c_2 = (2.0 - 0.2·1.0) / 0.8 = 2.25 → x_2 = 2.0    误差 0
L_track(optimized) = 0
```

**加正则后出现 trade-off**。设 J = L_track + λ·Σ(c_t − c_t^ref)²，c^ref = (1.0, 2.0)：
```
名义：      0.0976 + 0            = 0.0976
优化（λ=0.1）：0 + 0.1·(0.25²+0.25²) = 0.0125   ← 仍选优化
优化（λ=1.0）：0 + 1.0·0.125         = 0.1250   ← 反而不如名义
```
这解释了论文 Eq. 17 正则项的必要性，以及「优化有上限、并非越偏越好」。

**验证论文模型自洽性**（我的复算，非论文实测）：取 K=256 配置 (I,N,H,E)=(8,32,40,40)（Table 11）与 Table 10 参数代入 Eq. 6–9：
```
ε_solver = 0.494·8^{-0.402} + 0.839·32^{-0.344} ≈ 0.214 + 0.255 = 0.469
ε_sample = 0.469^{160/40} · 0.982^{40} ≈ 0.0484 · 0.484 ≈ 0.0234
ε_horizon = 1.801·exp(-0.0948·40) + 0.000472·39 ≈ 0.0405 + 0.0184 = 0.0589
Ĵ ≈ 0.0341 + 0.0589 + 0.0234 ≈ 0.1164
```
Table 11 报 Ĵ = 0.11652，一致到小数点后三位。这只**验证公式自洽**，不验证对真实成本的预测准确性（后者由 MARE 11.38% / 12.77% 与 regret 刻画）。

## 6. 能力与失败模式

**能做**

- 冻结 BFM 提升仿真跟踪精度（79–84% 体位误差降幅，代价是关节加速度上升）。
- 在跨 BFM 场景下把已有演示「翻译」成目标 BFM 的动作标签（真机 SONIC→HEFT 从 1.7% 恢复到 48.8%）。
- 给出可分配的计算预算策略，在拟合域内平均 regret 4.02%，跨 BFM 新运动平均 4.60%。

**不能做 / 未验证**

- **实时闭环真机命令优化**：作者明确列为 limitation，真机只有开环两段轨迹的定性展示（Fig. 4）。
- **平滑性**：三个 BFM 关节加速度全部上升，执行更「抖」。
- **精确接触任务**：残余误差仍限制需要精确接触和全身协同的任务（limitation 原话）。
- **绝对最优性**：regret 相对于有限随机集；换随机集或加预算网格，排序可能变（例如 K=8192 拟合运动上 Ours 5.10% 劣于 RF 1.35%、GP 0.00%）。
- **State 标签的极端失败**：仿真 SONIC→SONIC 下 State 0.0%，说明当标签表示与 BFM 输入分布严重不匹配时会完全失效——这是本文一个反直觉但重要的事实。

### 6.1 隐含假设

1. **闭环确定性 + 固定初始状态**（论文明确）：π 和 f 确定性，s_0 固定。真机有扰动时，需要靠 E 步重规划吸收，但论文未量化其鲁棒性上界。
2. **仿真动力学与真机足够接近**：真机标签优化用 4 个随机动力学场景（Table 20）缓解，但 Figure 4 的真机展示是开环执行，并非闭环命令优化。
3. **参考运动本身可跟踪**：若 τ^ref 物理不可行，命令补偿也无法救——论文在 §3.1 承认这是 command–execution gap 的来源之一，但没有给出「参考不可行」的判别器。
4. **优化后的命令不逃出 BFM 训练分布太远**：正则项只是软约束；clip 到 [-1,1] 后乘物理尺度是硬边界，但边界本身是否等于「安全区」未说明。
5. **成本模型形式可外推**：在 183 个点上拟合的 10 参数模型（且 η 撞界）用于 K=256–8192，外推到更高预算需要证据。
6. **随机配置集可代表最优邻域**：regret 分母 J_best 由 200/50 个随机配置决定。

|------|--------|----------------|---------------------|---------|
| SONIC / HEFT / TWIST2（训练时规模化） | 加数据/模型/算力让 BFM 更准 | 是 | 训练 | 通用运动跟踪 |
| Sumo（Zhang 2026） | 在预训练全身策略命令空间采样，做物体交互规划 | 否 | 命令 | 特定 loco-manipulation |
| BFM-Zero（Li 2026b） | 优化 latent prompt 序列 | 否 | 潜变量 | 仅自家模型 |
| Predictive Sampling / MPPI-CMA | 采样式实时控制 | 否 | 低层动作 | 通用机器人控制 |
| LLM test-time scaling（Snell 2025 等） | 推理预算分配 | 否 | token | 语言推理 |
| RoboMonkey（Kwok 2025） | 采样+验证 VLA 动作 | 否 | 动作 | 操作 VLA |
| **本文 TTCO** | **任意预训练人形 BFM 的命令优化 + 预算分配** | **否** | **命令** | **人形 loco-manipulation 与演示复用** |

**相对差距**：本文与 BFM-Zero 都做「潜/命令空间优化」，但本文强调**跨 BFM 通用性**与**计算最优分配**；与 Sumo 的差别是需要固定参考运动做轨迹级误差优化，而非交互规划。论文 Related Work 未给出与 Sumo / BFM-Zero 的定量对比，这是任何「比 baseline 好」的说法的边界。

**面试 Tip**：被问到「这篇和 train-time scaling 有何不同」时，一句话作答——「它把算力从训练搬到推理，且花在**输入命令**上而不是模型参数上；最大的工程价值是可复用演示做跨 BFM 的动作标签，而非同 BFM 的精度提升。」

## 8. 精读建议

- **值得精读原文的人**：
  1. 做 humanoid loco-manipulation、已有冻结 BFM、需要更高体位精度的研究者；
  2. 研究 test-time compute scaling 并想移植到具身系统的算法同学；
  3. 需要把历史遥操作演示迁移到新控制器的数据/平台工程师。
- **建议章节路径**：先读 §3.1（问题设定）→ §3.2（滚动时域 + CEM 循环）→ §4.1 与 §4.4 的表格（看真实收益与前提）→ 最后读 §3.3 与 Appendix C.4（成本模型与拟合细节，评估外推风险）。
- **不值得精读的理由**：只关心 LLM 推理 scaling、不做机器人、或已熟悉 sampling-based MPC 的读者，读摘要 + Figure 1 + Table 1/3 即可。
