## 1. 核心架構/方法總覽 (Overview / Architecture)

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 時序/頻率 | 訓練 vs 推理 |
|------|------|------|-----------|--------------|
| DROID 分組採樣 | ~35k 成功 episodes | 520 個場景組（每組取 1 episode） | 一次性 | 無（數據處理）|
| 校準閘門 (Calibration Gate) | 四路立體影片 + 軌跡 + 外參 p | 通過/不通過 + 場景級比率 ρ | 每場景一次 | 無（確定性統計）|
| 重建骨幹 (ZipSplat) | 三/四個外部視角影像 (+ 可選外參) | 3D Gaussian 場景 G_hat | 每場景一次 | 預訓練，凍結；單次前向 |
| 渲染 | Gaussian + 目標相機 ξ | 影像 I_hat、深度、alpha/coverage | 按需 | 推理 |
| 可靠性標註 | 渲染深度 vs 立體深度 vs 運動學幾何 | 逐場景可靠性度量 + coverage | 發佈時一次性 | 無 |

關鍵讀法：這條管線**沒有任何網路被訓練或微調**。ZipSplat 用的是官方預訓練權重，作者做的全部是「選場景、驗外參、注入姿態、量可靠性」——方法貢獻在校準與評測協議，而非模型。

### 1.2 關鍵機制 (Key Mechanism)

- **為什麼需要公制錨定**：影像空間監督只約束「渲染圖好看」，不提供全局公制參考。任何全局相似變換（縮放+旋轉+平移）同時作用於場景與相機，渲染結果不變 → 重建對尺度是不可辨識的。
- **為什麼不能直接信外參**：DROID 的相機姿態本就含噪；即使精修過的外參（PointWorld 提供的左眼位姿）也不能直接當作公制真值。所以要先獨立驗證，再重建。
- **為什麼分開兩件事**：作者把「校準是否適合（calibration suitability）」與「重建是否可靠（reconstruction reliability）」拆開量。前者在重建**之前**用確定性閘門篩場景；後者在重建**之後**用覆蓋率感知的深度一致性協議評估。
- **姿態條件化做什麼**：把（精修的）相機外參作為網路輸入，把重建從「自由 Sim(3)」收窄到「與給定相機一致」，從而錨定尺度。但作者強調：收益取決於注入外參的可靠性，且**不保證**幾何正確。

⚡ **Eureka Moment**：3DGS 重建對「全局相似變換」是不變的，所以「渲染好看」永遠無法告訴你場景尺度對不對；唯一能把它釘回物理世界的錨，是機器人**運動學幾何與相機深度的一致性**——而這個一致性本身必須逐場景測量、當作數據的一部分發佈。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
ρ = median( stereo_depth / projected_arm_depth )   —— 校準閘門的核心統計量
```

先給目標：把「重建場景是否對得上機器人真實工作空間」變成一個可計算、可設閾值的逐點比率。再給公式，最後給直覺。

**Step 1 — 免姿態前向重建（只受影像監督）**

```
G_hat_e = F_θ(X_e)                       # 由場景 e 的輸入重建 Gaussian
I_hat_et = R(G_hat_e, ξ_et)              # 在目標相機 ξ_et 渲染
θ* = argmin_θ  E_{e,t}[ d_img(I_hat_et, I_et) ]   # 只對齊圖像
```

**Step 2 — 尺度不可辨識性（為什麼圖像不夠）**

```
S(x) = s·R·x + t,   S ∈ Sim(3),  s > 0,  R ∈ SO(3)
R(G_hat_e, C_e) = R(S·G_hat_e, S·C_e)    # 場景與相機同乘 S，渲染不變
```

**Step 3 — 公制錨：運動學投影應對齊相機深度**

```
P_ei^B = FK(q_e; c_i)                      # 關節 q_e + CAD 點 c_i → 機器人基座座標
x*_eiv = R*_ev · P_ei^B + t*_ev            # 理想基座→相機外參 (R*, t*)
u*_eiv = π(K_ev · x*_eiv),  z*_eiv = [x*_eiv]_z
D_true_ev(u*_eiv) = z*_eiv                 # 理想條件：相機深度 == 投影軸深
```

**Step 4 — 用可得的立體深度替代真值，逐點成比率**

```
x^p_eiv = R^p_ev · P_ei^B + t^p_ev          # 候選外參源 p
u^p_eiv = π(K_ev · x^p_eiv),  z^p_eiv = [x^p_eiv]_z
r^p_eiv = D_st_ev(u^p_eiv) / z^p_eiv        # 立體深度 / 投影軸深
ρ^p_e = median_{(i,v) ∈ A^p_e} r^p_eiv      # 場景級穩健統計量
E_valid^p = { e | |A^p_e| ≥ n_min,  τ_min ≤ ρ^p_e ≤ τ_max }   # 閘門
```

**Step 5 — 通過閘門後才做姿態條件化重建**

```
G_hat_e^B = F_θ( X_e, C_e^p ),   e ∈ E_valid^p
C_e^p = { K_ev, [R^p_ev | t^p_ev] }_{v ∈ V_e}
```

**符號說明**（與論文 §3 一致）

| 符號 | 含義 |
|------|------|
| X_e | 場景 e 的原生（免姿態）輸入 |
| G_hat_e | 重建出的 3D Gaussian 場景 |
| ξ_et | 目標相機配置 |
| Sim(3) | 相似變換群（縮放+旋轉+平移）|
| q_e, c_i | 關節狀態、CAD 表面點 |
| K_ev, [R\|t] | 相機內參、外參 |
| D_st | 經典立體（SGBM）深度圖 |
| ρ_e | 場景級深度比率中位數（校準統計量）|

> 直覺：理想情況下「立體看到的手臂深度」和「運動學推算的手臂深度」應當相等，比率 ≈ 1。系統性偏離（如比率 1.3）就代表重建把手臂放得「太遠」，尺度漂了。用中位數而非均值，是為了抗離群點（遮擋、無效立體像素）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假設某場景，作者在**原始外參**下量得機器人深度比率 ρ ≈ 1.31（論文 §4.2.4 報告了 1.34 / 1.31 / 1.26 三個骨幹）。含義是：立體量到的深度，比「按運動學投影到該像素」的軸深**大 31%**——渲染出的手臂被推遠了。

走一遍閉環（數值為說明性推演，非論文原始逐點數據）：

```
輸入：某機器人表面點投影到像素 u，運動學給出軸深 z = 0.50 m
      立體深度圖在 u 給出 D_st = 0.655 m
比率：r = 0.655 / 0.50 = 1.31          # 尺度偏大 31%
對全場景所有有效投影取中位數 → ρ = 1.31

閘門 (n_min=30, τ∈[0.85, 1.15])：
  1.31 > 1.15  →  不通過（原始外參源下此場景被剔除）

改用精修外參後（假設外參修正把投影拉回）：
  D_st = 0.51 m,  z = 0.50 m  →  r = 1.02
  ρ = 1.02 ∈ [0.85, 1.15]  →  通過，進入發佈集

若有效投影數 |A| = 42 ≥ 30  →  支持度足夠，計數有效
```

這個「比率—中位數—閘門」鏈條就是整套方法的可計算核心：不用訓練任何網路，只要 FK + 立體 + 一個穩健統計量，就能把「場景尺度是否可信」變成布爾判決，並把 ρ 值本身作為可靠性元數據一起存檔。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**
- 提供**尺度錨定到機器人公制座標系**的可渲染 3DGS 場景（精修外參 + 姿態條件化下 PSNR 中位增益 +0.73~+2.73 dB，固定外參源）。
- 提供**逐場景可靠性元數據**：校準比率 ρ、coverage、渲染深度一致性——這是同類數據集缺失的一等公民。
- 把「物理一致性」從「照片寫實」中剝離，給出可复算的評測協議。

**不能做 / 失敗模式**
- **姿態條件化 ≠ 幾何保證**：作者自己指出，單靠姿態條件化「不能一致地改善幾何度量」。原始外參下 ZipSplat robot-error 中位數反升至 30.58 cm（成對變化不顯著）。
- **不宣稱幾何真值**：作者明確「不主張全場景幾何 ground truth」，也不宣稱下游操作增益。立體深度被當作「輸入視角一致性」而非真值。
- **非可加性**：姿態條件化與精修外參合併時，增益對 YoNoSplat/ZipSplat **非可加**——不能簡單假設兩者獨立疊加。
- **覆蓋有限**：幾何只在「機器人表面或立體有支撐」處可測；遮擋與低紋理區域量不到。
- **丟手腕相機**：排除了近距離、可動視角，限制了對抓取場景的適用性。
- **靜態單幀**：無時間一致性，無法支撐動態策略學習。

### 6.1 隱含假設 (Hidden Assumptions)

1. **經典立體深度可作為「輸入視角一致性」代理**：作者把 SGBM 深度當作比對基準，但自己也承認它不是真值——若立體本身在某些場景偏差，閘門判決會受影響。
2. **PointWorld 精修外參「更可信」**：閘門用「通過數更多」來隱含支持精修外參，但作者提醒這度量的是**閘門一致性**，不是獨立絕對位姿精度。
3. **FK + CAD 能精確刻畫機器人表面點**：比率統計的準確性依賴正運動學與 CAD 模型與真機一致（未見誤差分析）。
4. **DROID 場景的代表性**：單實驗室/多 serial 的靜態幀被當作機器人操作數據的縮影，未驗證向其他平台/機器人的遷移。
5. **凍結骨幹可泛化**：假設 ZipSplat 預訓練先驗足以處理機器人域的四視角輸入，且不因域差產生系統性尺度漂移。

|------|----------|----------|-----------|--------|----------|
| DP3 / FP3 | 稀疏點雲 | 無 | 無 | 否 | 點雲策略預訓練 |
| DROID-3D | 深度 + 點雲 | 沿用外參 | 無 | 否 | 幾何先驗 |
| 4D-VLA / Lift3D-VLA | 時空幾何 | 域內校準 | 無 | 否 | 時序 VLA |
| PointWorld / Robo3R | 精修位姿/幀對齊 | 精修外參 | 部分 | 否 | 座標系對齊 |
| RoboSnap | mesh-Gaussian | 單圖 | **無** | 是 | 單圖 real-to-sim |
| GenSplat | 免姿態視角增強 | 無 | 僅定性 | 是 | 策略視角泛化 |
| **3DROID（本文）** | **姿態條件化 3DGS** | **閘門驗證** | **逐場景實測** | **是** | **公制錨定幾何先驗/校準參考** |

🎯 **面試 Tip**：被問到「3DROID 相比 RoboSnap / GenSplat 的核心區別」時，一句話答——**別人在造可渲染場景，3DROID 額外把「每場景校準是否可信、重建幾何是否可靠」量出來並作為數據發佈**；而且它明確不主張幾何真值與策略增益，是一份「測量支持」而非「結論」。

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 正在構建**大規模 3D 機器人數據**的研究者——§3 校準閘門與 §4 評測協議可直接借用；
  2. 要把 3DGS/幾何先驗注入 **VLA 策略**的工程師——重點理解「照片寫實 ≠ 物理一致」這個坑；
  3. 需要評估「重建能否遷移到新機器人平台」的工程師——看 §4.2.4 的比率與閾值敏感性。
- **建議章節路徑**：先讀 §1 貢獻 + §4.1 數據漏斗（理解數據怎麼篩出來）→ 再看 §3.3 校準閘門公式 → 然後 §4.2 評測與 Table 2/4 → 可跳 §2 相關工作細節（若已熟悉 feed-forward 3DGS 譜系）。
- **不值得精讀的理由**：如果你不做機器人學習、不做 3D 重建、或已熟悉 Sim(3) 不變性與 feed-forward 3DGS，讀摘要 + Table 2/4 即可——它沒有新策略、沒有新網路架構，方法貢獻集中在數據協議。
