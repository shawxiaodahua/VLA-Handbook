## 1. 核心架构/方法总览 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

DIDO 是**两阶段**训练、推理时**一步**的世界行动模型。核心组件与其输入输出如下：

| 模块 | 输入 | 输出 | 训练/推理角色 | 频率/时序 |
|------|------|------|--------------|-----------|
| 视频骨干 (Wan2.2-TI2V-5B) | 当前观测 o + 语言 ℓ + 噪声 | 未来 latent z | 预训练初始化，四步蒸馏变体起点 | 推理：1 次前向 |
| 四步教师 (robot-domain teacher) | 同视频骨干 | 收敛后的未来 latent | **仅训练用**：DMD 的分布对齐目标 | 训练：4 步 |
| 一步生成器 θ | o, ℓ | 一步未来 latent | DMD 蒸馏目标 | 推理：1 步 |
| 交互 token 组 T_inter | 视频 token | obj/int/grip/align 表示 | 与视频表示共同演化 | 训练全程 |
| 轨迹预测头 | [T_grip;T_int] / [T_obj;T_int] | 未来 H_a 个 bbox | 有监督（smoothL1 + GIoU） | 预测动作时域 H_a |
| DINOv3 编码器 | 目标物体裁剪 | 物体视觉 token | **冻结**，对齐参照 | 训练监督 |
| 动作专家 v_θ | 视频表示（含压缩后未来 token） | 动作块 a (长度 H_a) | flow matching 生成 | 推理：生成一个 chunk |
| 动力学 token 精炼 | 未来视频 token | 323→191 token | 压缩空间冗余 | 每帧条件化前 |

### 1.2 关键机制 (Key Mechanism)

- **为什么"截断"不行**：作者实证（论文 Fig.1）发现去噪存在**时空不对称**——单步后静态背景已清晰，而夹爪与被操作物体仍然模糊；latent 空间同理，交互区域的帧间变化早期很弱、随去噪逐步增强并空间局部化。这与扩散模型 coarse-to-fine 的既有观察一致。
- **为什么用 DMD 而非"直接用第一步输出"**：DMD 训练一步生成器去**匹配四步教师的收敛分布**，而不是复现教师第一步的粗预测。所以一步就能逼近"磨完"的结果，而非"磨了一半"。
- **为什么要交互中心 token**：蒸馏目标本身并不显式鼓励建模"夹爪-物体"的耦合动力学。因此加入四组 token，并用 bbox 轨迹 + DINOv3 特征做监督，把预测"钉"在操作相关实体上。
- **为什么要 token 精炼**：未来视频表示 token 多、空间冗余大，操作相关变化集中在少数局部区域。按预测动力学打分，保留高动态区细粒度 token、压缩其余区域，既省算力又保交互细节。

⚡ **Eureka Moment**：**"一步生成该保留的不是画面，而是分布"——把多步教师的收敛分布（而非其早期粗预测）作为蒸馏目标，再用交互 token 显式补回蒸馏目标本身没管的夹爪-物体动力学。**

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
L_stage1 ≈ D_KL( p_θ,t ‖ p_T,t ) + Σ bbox 回归 + ‖T_align - DINOv3‖₁
          (对齐"磨完后"的分布)   (钉住交互实体)     (兜住物体视觉)
```

**目标**：让一步生成器的输出分布逼近四步教师的收敛分布，同时把预测显式绑定到夹爪与目标物体上。

**变量**：p_T,t / p_θ,t 分别为四步教师与一步生成器在扩散步 t 的扰动分布；T_align^l 为第 l 层对齐 token 表示；F_DINO 为冻结 DINOv3 的物体 token；H_a 为动作块长度；V_t 为视频骨干的 value 特征。

```
(1) 分布匹配蒸馏 (DMD)
    L_DMD = E_t [ D_KL( p_θ,t ‖ p_T,t ) ]        # 梯度用 real/fake score net 估计

(2) 交互 token 拼接
    T_inter = [ T_obj ; T_int ; T_grip ; T_align ]

(3) 单实体 bbox 损失 (b̂, b 为 H_a 长序列)
    L_box(b̂, b) = (1/H_a) Σ_h [ smoothL1(b̂_h, b_h) + λ_giou · L_giou(b̂_h, b_h) ]

(4) 交互轨迹目标
    L_inter = λ_obj · L_box(b̂_obj, b_obj) + λ_grip · L_box(b̂_grip, b_grip)
    # T_int 被两分支共享 → 逼它编码两者的相对时空演化

(5) 多层视觉对齐 (S = 参与对齐的层集合)
    L_align = (1/|S|) Σ_{l∈S} ‖ P_l( T_align^l ) - F_DINO ‖₁

(6) 动力学打分与区域聚合 (4×5 网格共 20 区, 每区 4 个 2×2 cell)
    s_{t_k}(r)   = ‖ V_{t_k}(r) - V_{t_0}(r) ‖₂
    S_{t_k}(R_m) = Σ_{r∈R_m} s_{t_k}(r),  |R_m| = 4
    # 按 S 排序, 前 3 区保留细粒度 token, 其余 17 区做 2×2 平均池化

(7) 动作流匹配 (a 为 GT 动作块, ε~N(0,I), τ~U[0,1])
    a_τ = (1-τ)·ε + τ·a ,  u = a - ε
    L_act = E[ ‖ v_θ(a_τ, τ) - u ‖₂² ]

(8) 两阶段总损失
    L_stage1 = L_DMD + L_inter + λ_align · L_align
    L_stage2 = λ_video · L_video + λ_act · L_act + L_inter + λ_align · L_align
    # DMD 仅用于 Stage I; 视频生成器全程保持一步
```

> 符号与本文/相关文档保持一致：术语沿用论文式 (1)–(10) 的表示；λ_* 为各损失权重（论文正文未给具体数值，见其 Appendix C.2）。

**怎么读这张表**：

2. 但截断在**扰动环境（LIBERO-Plus）只有 71.4**，暴露交互动力学缺失的代价。
3. 交互 token 那一跳在 LIBERO-Plus 上 +3.6——增益主要花在"难场景"，说明补回的正是"背景好糊弄、交互难糊弄"的那部分。
4. token 精炼几乎不涨点（+0.1）却省 ~30 ms、砍掉 132 个 token——典型"工程收益型"组件。

另一条独立验证（论文 Fig.5）：固定四步模型 + 动作专家，只改动作条件用第几步表示：

```
LIBERO      : 第1步 97.7 → 第4步 98.4
LIBERO-Plus : 第1步 71.4 → 第4步 72.6
```

即"越晚的去噪步，对动作预测越有用"——这就是 DMD 存在的理由：**用一步把"第 4 步的信息"找回来**。

## 4. 工程视角 (Engineering View)

- **吞吐/延迟**：H100、batch=1 下，DIDO 端到端预测一个动作块 **384 ms**，四步教师 **562 ms**（-32%）；对比不做未来想象的 Fast-WAM 356 ms，DIDO 只多 **28 ms**，但 LIBERO +1.4 点、LIBERO-Plus +25.1 点。工程含义：**"预测未来"不必是延迟黑洞**，一步蒸馏后它的代价接近"不预测"。
- **闭环频率**：单次前向 ~0.38 s ⇒ 直接逐帧闭环只有 ~2.6 Hz。真实闭环依赖**动作分块（action chunk, 长度 H_a）**：一次前向输出 H_a 步动作，把有效控制频率抬到 H_a × 2.6 Hz。所以 H_a 的取值直接决定部署可用性。
- **token 预算**：条件化上下文从 **323 → 191 token**（约 -41%），换来 ~30 ms。对显存/带宽受限的边缘部署是关键杠杆。
- **精度 vs 速度的 trade**：DIDO 用 **28 ms** 换 LIBERO-Plus 上 **25.1 点**的鲁棒性提升——在扰动敏感的产线/真机场景，这笔交换极其划算。
- **依赖与部署约束**：骨干是 5B 级视频模型 + 冻结 DINOv3，训练分两阶段且需先造"机器人域四步教师"。这是**训练侧的重资产**，推理侧则是轻量一步前向。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：
- 一步前向同时给出"未来 latent 表示 + 动作块"，闭环延迟接近不做未来预测的策略；
- 在**分布扰动**（相机、机器人初始位姿、语言改写、光照、布局）下显著更鲁棒——LIBERO-Plus 76.6，其中机器人初始化 74.3（比 Faster-WAM 高 6.4）；
- 真机在"位置变化 + 视觉杂乱"双扰动下退化更小（14.8 点 vs π0.5 的 21.2 / Fast-WAM 的 20.8）。

**不能做 / 风险**：
- **单平台泛化未证**：真机只在 Galbot G1 上验证，未跨本体、移动/人形；不要外推到论文没测的形态。
- **强依赖大视频骨干**：5B 级骨干 + 冻结 DINOv3，训练需先造机器人域教师，复现成本高。
- **相机扰动是弱项**：LIBERO-Plus 的 Camera 列只有 45.3（同组 ST-WAM 55.4、Faster-WAM 57.0 更高），说明视角大幅变化仍是短板。
- **单步的分布匹配风险**：DMD 匹配的是教师收敛分布，若教师本身有偏，误差会被一步放大（论文未做教师质量敏感性分析）。
- **bbox 监督依赖自动标注**：轨迹/对齐目标"自动从演示中整理"（Appendix A），标注管线质量直接影响交互 token 的有效性。

### 6.1 隐含假设 (Hidden Assumptions)

1. **"背景早收敛、交互晚收敛"的规律跨数据/本体稳定**——仅在某类操作演示与单一视频骨干上验证；换骨干（非 Wan 系）或换域是否仍成立，未证。
2. **bbox 能充分代表"交互"**——把夹爪-物体交互压缩成两个框的轨迹，隐含假设"相对框运动=交互动力学"，对形变物体、遮挡、接触力等无框可表达的情形可能失效。
3. **DINOv3 特征 = 适合的物体视觉监督**——假设通用视觉编码器的物体表示对操作相关判别信息足够，未与非 VLA 领域的其他监督做对照。
4. **四步教师已足够好**——DIDO 的上限被教师分布锁死；论文未讨论教师步数/质量对蒸馏上限的影响。

**面试 Tip**：被问到"WAM 怎么降延迟、会不会牺牲性能"时，一句话答——**"关键不是截断去噪步数，而是选择蒸馏目标：对齐教师收敛后的分布（DMD）+ 显式监督交互实体，才能让一步输出保住夹爪-物体动力学；DIDO 用 28 ms 的代价换来 LIBERO-Plus +25 点的鲁棒性。"**

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**闭环高频控制**的世界模型 / WAM 研究者，关心未来预测与延迟的权衡；
  2. 要把视频预测模型**部署到真实机器人**、评估一步蒸馏可行性的工程师；
  3. 研究**交互中心表征**（object/interaction token、视觉对齐监督）的方法学者。
