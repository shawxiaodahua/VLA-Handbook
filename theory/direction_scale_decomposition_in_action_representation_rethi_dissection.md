# 动作表示的「方向–尺度解耦」（Direction-Scale Decomposition, DSD）：重新审视离散 token VLA 该 tokenize 什么

>
> **论文**: Direction-Scale Decomposition in Action Representation: Rethinking What to Tokenize for Vision-Language-Action Models

> **核心定位**: 把「位姿增量 ΔEEF」这一被默认的前置表示拆成 **方向（direction）+ 尺度（scale）**，让离散动作 token 不再被执行速度和数据集归一化绑架——在混合数据集训练下比 OpenVLA 式 BIN 高 10.3 个百分点。

💡 **X-Ray 开场**
离散 token VLA 通常把机器人的动作写成「末端位姿增量 ΔEEF」再做归一化和分箱。但同一条几何路径，**跑快一点、或换一个数据集统计量归一化，就会变成完全不同的 token 序列**——模型只好从零去猜「这其实是同一个动作」。DSD 的想法很朴素：先把动作拆成「朝哪个方向动（方向）」和「动多远（尺度）」，方向用固定边界，尺度单独放一个通道。这样方向 token 就该跨速度、跨数据集共享，模型不必再学一个「速度不变性」。对 VLA 研究者意味着：**动作表示本身是被低估的一层，它和分词器一样值得设计。**

## 1. 核心架構/方法總覽 (Overview / Architecture)

### 1.1 系统对比概览 (System Component Comparison)

| 分量 | 原始 ΔEEF 表示 (raw) | DSD 表示 | 归一化方式 | 备注 |
|------|----------------------|----------|-----------|------|
| 平移 | Δx, Δy, Δz（3 个标量） | 方向 n_pos ∈ S²（3 分量）+ 模长 s_pos（1） | 方向：固定边界 [−1,1]；模长：数据集/目标统计量 | 方向已天然落在 [−1,1] |
| 旋转 | Δr, Δp, Δyaw（3 个标量） | 转轴 n_ori ∈ S²（3 分量）+ 转角 s_ori（1） | 同上 | 需稳定的矩阵→轴角转换 |
| 夹爪 | g（离散指令） | g（原样保留） | 原编码 | 不参与分解 |
| 每臂标量数 | 7 | 9（6 运动自由度 + 夹爪，方向冗余表示） | — | 自由度不变 |
| 是否含学习组件 | 否 | 否 | — | 可与任意 tokenizer 组合 |

### 1.2 关键机制 (Key Mechanism)

论文先论证「原始位姿增量表示」的**三个问题**，再给出 DSD 的对应修复：

- **问题 1（速度敏感）**：ΔEEF 直接绑定演示速度。空间相似但速度不同的路径 → 被分到相隔很远的 token。token 是类别量，不显式编码「差一个比例因子」，模型只能从 token 身份间接猜。
- **问题 2（归一化不一致）**：按数据集 1%/99% 分位数归一化，会把**同一物理动作**在不同数据集映射到不同 bin（论文用 Bridge vs VIOLA 举例）。
- **问题 3（迁移中的方向扭曲）**：训练用源数据集统计量、部署用目标统计量反归一化，仿射偏移 + 各轴不均匀缩放可能**改变运动方向甚至翻符号**——即使 token 预测本身是对的。
- **DSD 的修复**：方向 token 用固定、与数据集无关的边界（单位球面天然有界，无需 dataset-specific norm），因此速度变化只改尺度通道、不改方向 token；跨数据集方向 token 目标一致；解码时方向不再被反归一化的仿射项扭曲。

⚡ **Eureka Moment**：**把「朝哪动」和「动多大」在 tokenize 之前就分开——方向分量放进一个跨数据集共享的固定数值约定里，于是速度与归一化的干扰只落在标量尺度通道上，几何结构被显式暴露而非留给模型去猜。**

### 1.3 信息流/架构图 (Flow / Diagram)

```
raw ΔEEF action a_t = (Δx,Δy,Δz | Δr,Δp,Δyaw | g)
        │
        ├─ 平移 p = (Δx,Δy,Δz)
        │     s_pos = ||p||₂ ,  n_pos = p / s_pos  (p=0 时取默认 e₃)
        │
        └─ 旋转 R = Rz(Δyaw)·Ry(Δp)·Rx(Δr)
              ω = Log(R)  (轴角向量),  s_ori = ||ω||₂ , n_ori = ω / s_ori
        │
        ▼
  DSD action  ã_t = ( s_pos , s_ori , g | n_pos | n_ori )
        │
        ├─ 尺度通道 (s_pos, s_ori): 归一化到 [−1,1]  ← 数据集/目标统计量
        └─ 方向通道 (n_pos, n_ori): 天然 ∈[−1,1]，固定边界，不归一化
        │
        ▼
  Tokenizer (BIN 均匀分箱 / BEAST B-spline 控制点 …)
        │
        ▼
  离散 token 序列  → LLM/VLM 自回归或并行解码
        │
        ▼
  解码: 尺度反归一化 → p=s_pos·n_pos , R=exp(s_ori·[n_ori]×) → 还原 ΔEEF
```

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
动作 = 单位方向（固定有界） ⊕ 尺度（可归一化的标量）
```

论文的核心是把 raw action 做一次解析分解（Eq.1–Eq.6）：

```
# 位移：模长 + 单位方向
s_pos = ||p_t||₂                          p_t = (Δx, Δy, Δz)ᵀ
n_pos = p_t / s_pos   if s_pos > 0 ;  n_pos = e₃   if s_pos = 0

# 旋转：转角 + 单位转轴（轴角表示）
R_t   = Rz(Δyaw)·Ry(Δp)·Rx(Δr) = exp([ω_t]×) ,  ||ω_t||₂ ≤ π
s_ori = ||ω_t||₂
n_ori = ω_t / s_ori   if s_ori > 0 ;  n_ori = e₃   if s_ori = 0

# DSD 动作向量
ã_t = ( s_pos , s_ori , g_t , n_posᵀ , n_oriᵀ )ᵀ ∈ A_DSD ⊂ ℝ² × 𝔹 × 𝕊² × 𝕊²

# 逆变换（还原物理动作）
p_t = s_pos · n_pos
R_t = exp( s_ori · [n_ori]× )   → 转回 roll-pitch-yaw，保留 g_t
```

变量说明：

| 符号 | 含义 | 取值/范围 |
|------|------|-----------|
| p_t | 平移增量 | ℝ³ |
| s_pos | 平移模长（尺度通道） | ≥ 0，归一化到 [−1,1] |
| n_pos | 平移单位方向 | 𝕊²（‖n‖₂=1） |
| ω_t | 旋转轴角向量 | ℝ³, ‖ω_t‖₂ ≤ π |
| s_ori | 旋转角（尺度通道） | [0, π]，归一化到 [−1,1] |
| n_ori | 旋转单位轴 | 𝕊² |
| [v]× | 反对称矩阵，[v]× x = v × x | — |
| g_t | 夹爪指令 | 离散集 𝔹 |
| τ | 小尺度屏蔽阈值 | 微调 0.05–0.3%、预训练 0.5%（占全尺度范围比例） |

直觉：**单位球面上的点（方向）天然有界，不需要任何数据集统计量就能跨数据集比较**；而速度变化只改变标量 s，不改变 n。于是「同一几何路径的不同速度版本」共享方向 token，只有尺度 token 不同——把不变性**写进表示**，而不是指望模型从数据里学出来。

**小尺度方向损失屏蔽（稳定性）**：当 s_pos 或 s_ori → 0，方向对噪声极敏感，微小扰动会产生完全不同的方向目标。论文在 s < τ 时**下加权**方向 token 损失，保留最小权重 w_min = 0.1：

```
L_dir_weighted = max( w_min , min(1, s / τ) ) · L_direction
```

理由：小位移下方向误差对重建位移影响有限，且通常落在下游控制器的死区内。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

**场景 A：同一条对角路径，跑快一倍（对应问题 1）**

设平移增量（单位米），慢速：p = (0.03, 0.04, 0.0)。快速：p = (0.06, 0.08, 0.0)。

```
慢速:  s_pos = √(0.03²+0.04²) = 0.05 ,  n_pos = (0.6 , 0.8 , 0.0)
快速:  s_pos = √(0.06²+0.08²) = 0.10 ,  n_pos = (0.6 , 0.8 , 0.0)
```

- **DSD**：方向 token **完全相同**（0.6, 0.8, 0.0 分箱后一致），只有尺度通道从 0.05 → 0.10 变化。模型只需在一条「共享方向」上学，尺度是独立标量。
- **raw ΔEEF + 分箱**：慢速三个分量 ≈ (0.03, 0.04, 0.0)，快速 ≈ (0.06, 0.08, 0.0)。归一化后三坐标同时落进不同 bin → 产生**三处不同的 token**，几何相似性被 token 身份掩盖。

**场景 B：正 z 位移在不同数据集反归一化后翻符号（对应问题 3）**

```
某数据集 A 的 z 通道 1%/99% 分位 = [−0.02, 0.06] , 中点 = 0.02
原始 Δz = +0.01  →  归一化 (0.01 − 0.02)/(0.06 − 0.02) = −0.25  (负值!)
                                  ↓ 反归一化用数据集 B 统计量
数据集 B（Berkeley-UR5）中点 = 0 , 范围 ±0.05  →  物理位移 = −0.25 × 0.05 = −0.0125 m
```

一次**本应朝 +z 的动作，反归一化后变成朝 −z**。在 DSD 里，方向被 n_pos 直接编码（与归一化无关），尺度通道 s_pos 只影响「走多远」，不会把方向搞反——除非整体尺度反号（论文用固定边界 + 正尺度避免）。

**场景 C：DTW 指标怎么给分（对应评测）**

```
score = 100 · clip( (0.05 − d_DTW) / (0.05 − d_demo) , 0 , 1 ) ,  d_demo = 0.005768
```

若某方法 d_DTW = 0.02：score = 100·(0.05−0.02)/(0.05−0.005768) ≈ 100·0.03/0.044232 ≈ **67.8 分**。d_DTW ≤ 0.005768（演示级误差）得满分，≥0.05 得零分。

## 4. 工程視角 (Engineering View)

| 关注点 | 含义 / trade-off |
|--------|------------------|
| 推理开销 | DSD 是**纯解析预处理**，无额外学习模块；token 数不变（每臂仍 7T 数量级，方向分量冗余但仍是标量分箱），不增加自回归步数 |
| 解码步数 | 与基线 tokenizer 平齐：论文用 20 步 action chunk + **并行解码**（双向自注意力，每位一个分布），不是自回归逐 token 慢解 |
| 延迟/控制率 | 改动只在归一化/反归一化层，不改变控制频率；反而因减少「速度/归一化不匹配导致的重试与安全中止」而提升有效成功率 |
| 数值稳定性 | 近 0 与近 π 的矩阵↔轴角转换需专门处理；π 处 n 与 −n 等价，需固定符号约定 |
| 归一化边界 | 方向用**固定、跨数据集共享**边界；尺度用共享参数（co-training，支持 zero-shot 迁移）或目标特定参数（fine-tuning） |
| 内存 | 无额外参数；仅动作维度从 7 增到 9 每臂（表示冗余），对 0.23B 骨干可忽略 |
| 与分词器解耦 | DSD 定义的是**连续表示**，可接 BIN（均匀分箱）、BEAST（B-spline 控制点）、乃至压缩类 tokenizer，属正交组件 |
| 部署约束 | 因方向 token 跨数据集一致，**混合数据集训练后迁移到新本体**时反归一化不再扭曲方向——对需要多数据集预训练的实际管线价值最大 |

工程含义一句话：**它是「插在归一化之前的一层几何预处理」，改造成本低、风险可控，收益主要体现在多数据集训练与跨本体迁移。**

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 同一路径不同执行速度 → 方向 token 稳定（光点追踪 DTW 显著更低）。
- 跨数据集混合训练 → 减少 token 目标冲突，混合反而增益。
- 跨本体迁移（源/目标归一化统计不同）→ 避免反归一化扭曲运动方向。
- 与不同分词器组合（BIN、BEAST 都受益）。

**不能做 / 失败模式**：
- **任务间收益不均**：SimplerEnv 中混合训练提升了 carrot / eggplant，但**降低了 spoon / stack**——作者承认需进一步分析任务特征与失败根因。
- **规模未验证**：混合评测只覆盖 5 个 OXE 数据集，未测全量 OXE，更长尾混合的效果未知。
- **阈值 τ 依赖调参**：微调阶段（0.05–0.3%）与预训练阶段（0.5%）阈值不同，跨训练阶段可能需重调。
- **本体覆盖窄**：真机仅 Franka；仿真仅 Franka + WidowX；**未验证双臂**（双臂是明确 future work）。
- **分词器覆盖窄**：只测了 BIN 与 BEAST，未测 FAST 类/学习式 codebook。
- **单目自视角尺度不确定**：单目 ego 演示的度量尺度不确定；作者推测 DSD 在「均匀缩放」下保持方向一致可能有利于此，但**尚未实验验证**（属待证猜想）。

### 6.1 隐含假设 (Hidden Assumptions)

- **「几何路径不变性」是任务相关结构**：DSD 假定不同速度的同一路径应共享方向 token。对某些任务（如接触丰富、力度/节奏本身就是任务信号的任务），速度变化可能是**任务相关**而非噪声——把速度剥离到尺度通道可能丢失信息。作者在讨论中承认「并非所有任务都有几何路径不变性结构」，此时靠「尺度通道保留原始幅度」兜底。
- **方向与尺度可独立归一化**：假定尺度通道可以单独归一化/反归一化而不影响方向语义。这依赖方向分量确实落在固定边界内（单位球面）且正尺度不反号。
- **轴角转换数值正确**：near-0 / near-π 的转换与 π 处符号约定被假定稳定，论文称用了数值稳定实现，但未给误差界。
- **夹爪维度无需分解**：把夹爪当作独立离散指令保留，未讨论其与运动的耦合。
- **分位数归一化假设**：沿用 OpenVLA 式 1%/99% 分位数归一化，未质疑该统计量本身的鲁棒性。

| SpatialVLA | 空间表示 | 球坐标：方向 + 距离 | 否 | 仍对幅度/统计敏感 | 空间泛化 |
| MoMo | 时空运动模式 | 空间/时间双码本 | 是 | 保留速度到时间码 | 运动模式条件化 |
| **DSD（本文）** | **前置表示重设计** | **方向(S²,固定界) ⊕ 尺度(标量通道)** | **否** | **方向：不敏感** | **多数据集/跨本体/离散 token VLA** |

**面试 Tip**：被问到时一句话答——「DSD 不是新 tokenizer，而是 tokenizer **之前**的动作表示：它把 ΔEEF 解析地拆成方向与尺度，让方向 token 与固定边界绑定，从而在速度和数据集归一化变化下保持稳定，可以和任意现成分词方案（BIN/BEAST）正交叠加。」再补一句最硬的数据：**混合数据集下比 BIN 高 10.3pp（p=0.003）。**

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 做**离散 token VLA**、正在设计或更换动作空间/分词方案的研究者与工程师；
  2. 需要做**多数据集混合预训练 + 跨本体迁移**、被归一化不一致困扰的团队；
  3. 研究**动作表示 / 机器人学习归纳偏置**方向、关心「把不变性写进表示」这一思路的人。
- **建議章節路徑**：先讀 §IV（三个问题的形式化，理解动机）→ 再看 §V–V-C（DSD 的定义、转换、稳定性屏蔽）→ 接著 §VI-C（SimplerEnv 混合数据集，收益最有说服力）→ 可跳 §VI-A 的 DTW 细节（仅验证速度不变性，工程读者可略）。§II 相关工作可作背景快览。
- **不值得精讀的理由**：如果你不使用离散 token 动作头（如纯 flow-matching/diffusion 的 π0 类）、或只在单一数据集上训练且本体固定，本文的收益边界较小——读摘要 + §IV 即可，不必进入 §V 的转换细节。
