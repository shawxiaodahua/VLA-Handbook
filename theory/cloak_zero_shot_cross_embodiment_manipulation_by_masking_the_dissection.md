## 1. 核心架構/方法總覽 (Overview / Architecture)

Cloak 不是新模型，而是一套**训练配方**（recipe）。它把「视觉差」和「运动学差」拆开分别处理：视觉差用掩码，运动学差用 IK 重定向。

### 1.1 系统对比概览 (System Component Comparison)

| 模块 | 输入 | 输出 | 频率/时序 | 训练 vs 推理差异 |
|------|------|------|-----------|------------------|
| 掩码生成 (Embodiment mask) | 本体 q（关节）、URDF 链接网格 G、腕相机外参 T_ec、内参 K | 二值掩码 M ∈ {0,1}^{H×W} | 离线预计算（源本体） | 训练时在线增广 M→M̃；推理时只用构造、不增广 |
| 图像回填 (Roll-and-fill) | 腕图 I、掩码 M | 回填后的图 Ĩ | 每个训练 step | 仅训练使用 |
| 视觉编码器 (ViT) | Ĩ（+外视图） | patch tokens | 每帧 | 全层复用同一掩码 M̃^A |
| 注意力偏置 | mask 下采样到 patch 网格 | 注意力偏置矩阵 A | 每层 self-attn | 无梯度、常量序列长度 |
| 动作头 (action head) | 图像 token + 语言 ℓ + 状态 q | 动作块 â | 每个控制 step | 输出仍在源本体关节空间 |
| Tip-pose 重定向 | 源关节 q̂_src / 目标关节 q_trg | 目标动作 q̂_trg / 源状态 q_src | 推理时 | FK→IK，逐动作计算 |

### 1.2 关键机制 (Key Mechanism)

- **为什么遮手腕而不是换外视图**：消融显示「去掉腕相机」会让源本体性能从 89.3 崩到 36.5（Table 2）。外视图几乎不承载任务信号，腕视图才是有用的，所以作者只遮腕视图里的**末端执行器**，保留其余像素。
- **为什么不用分割/生成模型**：Mirage、RoboEngine 等用学习式分割或图像重绘，会误判、把物体当成机器人一部分、薄结构上失效，或产生 hallucination。Cloak 直接由**已知几何**光栅化出掩码，零 hallucination。
- **为什么锚定在 patch 网格而非像素**：模型消费的是 patch token；把掩码按「多数投票」降采样到 patch 网格，再在注意力里屏蔽对应 patch，等价于「在恒定序列长度下丢掉这些 patch」。
- **为什么增广掩码**：固定轮廓会让模型过拟合源夹爪的剪影；用胶囊增补 + 圆盘挖除扰动轮廓，使模型见到一族「合理的手形」，从而泛化到**事先未知**的目标本体。

⚡ **Eureka Moment**：跨本体的决定性因素不是动作接口、而是腕视图里那只「自己的手」的外观——把它遮掉，就等于把策略从「依赖自身外观」改写成「依赖场景理解」，其余迁移问题交给 IK 兜底。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
M = rasterize( ∪_ℓ K · T_wc(q)^{-1} · T_wℓ(q) · V_ℓ ) ∈ {0,1}^{H×W}
Attn(Q,K,V) = softmax( Q·Kᵀ / √d + A ) · V ,   A_ij = -inf if M̃_j = 1 else 0
```

先给目标，再给公式，再给变量说明。

**目标一：几何掩码。** 用机器人的运动学与腕相机参数，把「末端执行器会落在图像哪块像素」精确画出来，不靠学习。

**公式**（掩码构造，论文 Eq.1）：

```
M = rasterize( ∪_{ℓ∈G} K · T_wc(q)^{-1} · T_wℓ(q) · V_ℓ )
```

**公式**（掩码增广，论文 Eq.2，仅训练）：

```
M̃ = ( M ∪ ⋃_{i=1}^{N+} C_i⁺ ) \ ⋃_{j=1}^{N-} D_j⁻
```

**公式**（掩码注意力，论文 Eq.4）：

```
Attn(Q,K,V) = softmax( Q·Kᵀ / √d + A ) · V
A_ij = -inf  if M̃^A_j = 1   (masked patch)
       0     otherwise
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| I ∈ R^{H×W×3} | 腕相机图像（π0.5 中 H=W=224） |
| q | 本体关节状态（DROID 源本体为 8 DoF：7 臂 + 1 夹爪） |
| G, V_ℓ | 机器人描述文件给出的链接网格集合与顶点 |
| T_wc(q), T_wℓ(q) | 相机 / 链接的世界位姿（由 FK 组合得到） |
| T_ec ∈ SE(3) | 腕相机在末端执行器坐标系下的外参（逐 episode 标定） |
| K | 相机内参 |
| M̃^A ∈ {0,1}^{256} | 降采样到 patch 网格后的掩码（P=14 → 16×16=256） |
| A_ij | 注意力偏置；被遮 patch 对所有 query 贡献 -inf |

**直觉**：`softmax(QKᵀ/√d + A)` 里给被遮 patch 加 -inf，等价于「这些位置的注意力权重归零」——token 的序列槽位还在（长度不变，不打断位置编码），但它既不能被别人读到、也不影响别人。

> 符号与本文/相关文档保持一致：`\` 表示集合差，`∪` 表示并集；-inf 在实现中通常用一个足够大的负数。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

假设一张 224×224 的腕图，编码器 patch 大小 P=14：

- patch 网格：H_p = W_p = 224/14 = 16，总 patch 数 N = 16×16 = **256**。
- 假设末端执行器（平行夹爪）在图中占据约 100×100 像素的一块区域，共约 10000 像素。
- **多数投票降采样**：某 patch 有 196 个像素（14×14），若其中 > 98 个像素落在掩码内，该 patch 标记为 masked。
- 若夹爪覆盖约 40 个完整 patch，则 M̃^A 中约 40/256 ≈ 15.6% 的槽位被屏蔽。

注意力层面走一遍（单头，d=64）：

```
设 A 中 40 个 patch 位置为 -inf。
对某个未遮 patch（query），其与 256 个 key 的相似度打分 QKᵀ/√d。
加偏置后，被遮 40 个 key 的分数 → -inf。
softmax 后，这 40 个 key 的权重 → 0；未遮的 216 个 key 权重归一化。
结果：query 只能从「场景/物体/其他可见像素」聚合信息，拿不到自身外观。
```

部署时（目标本体）反过来：

```
模型输出源夹爪关节 â_src (8 DoF)
  → FK 得到两个指尖位姿 T̂_l, T̂_r ∈ SE(3)
  → 目标本体 IK(q̂_trg) 使两个对应指尖达到同一 6-DoF 位姿
  → 用模型输出的夹爪开度 ĝ 覆盖 IK 的夹爪解（五指手则在开/合构型间线性插值）
这就是一个「可计算的闭环」：源空间的指令 ↔ 目标空间的执行。
```

## 4. 工程視角 (Engineering View)

| 维度 | 数字 / 结论 | 工程含义 |
|------|-------------|----------|
| 训练成本 | 100k step ≈ 1 epoch，8×H100 跑 48 小时 | 单机多卡可完成；配方可插进现有微调流程（openpi 风格） |
| 掩码生成 | 每 episode 标定后离线预计算 + 在线增广 | 增广在 CPU 上做图像操作，不占 GPU |
| 注意力开销 | 序列长度不变，只加偏置矩阵 | 显存/延迟与基线几乎一致，无额外模块 |
| 相机外参 | DROID 自带外参噪声大，需逐 episode「Silhouette Calibration」 | 外参标定是隐形成本；外参不准 → 掩码错位 → 泄露 |
| IK 稳定性 | 加阻尼/姿态/朝向正则，防 null-space 跳变 | 调参换取稳定性；代价是抑制某些 tilt 行为 |
| 遮挡粒度 | patch 级（14×14 像素） | 靠近末端执行器的物体可能被误遮；更细 patch 可缓解 |

**工程含义**：Cloak 的诱人之处在于「零新增推理成本」——它改变的是训练数据的观测处理，而不是模型结构。部署侧的复杂度主要落在 **IK 重定向 + 相机标定** 两个传统机器人工程环节。控制频率上，掩码是每帧一次的光栅化+投影，IK 是每个动作块逐动作求解；两者都属于确定性计算，抖动风险低于学习式分割。

## 5. 數據與評測 (Data & Eval)

- **源数据**：DROID，约 75K 条 in-the-wild 遥操作轨迹（约 350 小时），Franka Panda 臂 + Robotiq 2F-85 平行夹爪，为**唯一源本体**。
- **数据过滤**（论文 Appendix A.2）：剔除标为失败的 ~22%（95K 中）；剔除外参离群最大的 1%（占剩余 75K 的 ~1.7%）；再留 5% 作验证集 → 最终约 **70K** 条训练轨迹。
- **任务**：4 个 DROID 常见任务——Pick and Place、Remove、Move、Fold/Unfold，均要求精确的指尖放置与稳固抓取（正是 tip-pose retargeting 覆盖的区间）。
- **协议**：每任务 12 个随机实例（物体/摆放/prompt），共 **48 次试验**；实例只生成一次，对所有基线复用；每试最大 60 秒或提前终止以防损坏末端。
- **主指标**：task progression rate（完成子任务进度），另报 success rate。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做**：
- 从单一平行夹爪源数据，零样本迁移到**未见过的**另一夹爪（UMI，颜色/形状/开度都不同）、另一机械臂（YAM）、以及五指手（Sharpa，被当作 two-tip 夹爪使用）。
- 保留源本体性能（不掉点）。
- 作为「body-agnostic」初始化，用于后续微调或持续学习（作者称之为让数据「活过硬件」）。

**不能做**：
- 只覆盖「用两个指尖即可表达」的操作技能；**不覆盖**需要丰富接触策略或 in-hand 重排的灵巧技能。五指手在此被当夹爪用，作者明确不宣称灵巧操作。
- 行为继承自源模型与 DROID 的夹爪式桌面数据，受数据分布限制。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设腕相机外参可被准确标定**：DROID 自带外参不够用，需逐 episode 的 Silhouette Calibration（用「暗且在时间上刚性」的启发式伪真值 + Nelder-Mead 优化）。若外参漂移，掩码会错位，源头外观就会泄露。
- **假设两指尖的对应关系可从几何上确定**：夹爪间对应直接；五指手把「左右平行夹爪尖」映射到「拇指 + 中指尖」。这一映射的合理性未做大规模验证，属于工程选择。
- **假设 IK 正则可跨本体复用**：为抑制 null-space 不稳定而加入的正则会压制 tilt，可能牺牲某些更适合倾斜的任务——这是「稳定性 vs 表达力」的隐性取舍。
- **假设外视图对视觉差贡献小**：故不遮外视图；这在 DROID 的单外视图设置下成立，其它相机布置未必。
- **假设任务不依赖 patch 级细粒度遮挡**：掩码在 14×14 patch 粒度上工作，靠近末端执行器的物体会被误遮。
