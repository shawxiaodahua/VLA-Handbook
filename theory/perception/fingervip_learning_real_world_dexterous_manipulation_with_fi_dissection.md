### 1.2 关键机制 (Key Mechanism)

- **为什么用指尖而不是腕部**：外置相机远且常被手/物体遮挡；腕部相机虽近，但单视角、且抓取时被手和物体挡住，还会因体积大压缩手部运动间隙。指尖镜头随手指一起贴近接触点，天然获得**近接触 + 多视角**。
- **为什么要相机位姿编码**：指尖相机刚性安装在会运动的手指上，图像内容与当前手型强耦合（同一物体在不同手指姿态下拍出来完全不同）。把相机在手基座系下的位姿显式编码进去，等于告诉策略「这张图是从哪个角度看出去的」，改善**视角—本体对齐**。
- **为什么要逐指关节电流**：电流随负载/接触状态变化，在 RGB 因遮挡看不到接触时提供**接触线索**。逐指独立编码（而非整手打包）以保留手指间的独立性。

⚡ **Eureka Moment**：把「看得清」这件事从**远端的全局相机**迁移到**近端的、随接触点移动的指尖相机**——多视角不再是策略的负担，而是对抗遮挡的结构性解药。

## 2. 数学核心 (Math Core)

📌 **Napkin Formula**（一行抓住本质）：

```
策略 = 以「指尖多视角视觉 + 相机位姿 + 关节电流」为条件，对 26 维关节动作做扩散去噪
```

**目标**：给定观测 O_t 与一段噪声动作，学习一个去噪器逐步还原出未来关节指令轨迹 A_t。

**公式**（标准条件扩散 / Diffusion Policy 训练目标）：

```
L = E_{k, x0, ε} [ ‖ ε − ε_θ(x_t^k, k, O_t) ‖² ]
```

其中 `x_t^k = sqrt(ᾱ_k)·x0 + sqrt(1−ᾱ_k)·ε` 是第 k 步加噪后的动作 token。

**相机位姿编码**（前向运动学 + 旋转表示）：

```
T_c,t^B = [ R_c,t^B  p_c,t^B ; 0ᵀ  1 ] = F(Q_t^h)
r_c,t^B = vec(R_c,t^B[:, :2]) ∈ R^6        # 取旋转矩阵前两列，避免不连续
pose   = (p_c,t^B, r_c,t^B) ∈ R^9          # 3-D 位置 + 6-D 旋转
```

**变量说明**：

| 符号 | 含义 |
|------|------|
| `x_t^k` | 第 t 步、第 k 去噪步的动作 token |
| `ε_θ` | Transformer 去噪器（参数 θ） |
| `O_t` | 观测 token 序列（视觉+位姿+电流+本体） |
| `Q_t^h ⊂ Q_t` | 手部关节角（用于前向运动学） |
| `F` | 手 URDF 前向运动学（Pinocchio） |
| `T_c,t^B` | 手基座系 B → 指尖相机系 c 的变换 |
| `r_c,t^B` | 用前两列表示的 6-D 旋转（Zhou et al. 2019） |

> 符号与本文/相关文档保持一致：`R` 旋转，`p` 位置，`k` 去噪步，`K` 总去噪步数，`m/n` 为动作块执行/预测长度。

**直觉**：扩散负责「生成多模态、平滑的未来动作」；而相机位姿与关节电流负责「把视觉观测放到正确的手部坐标与接触语境里」。缺了位姿，策略不知道图像来自哪根手指的哪个角度；缺了电流，策略在遮挡下失去接触感的替代信号。

## 3. 带数字走一遍：玩具例子 (Worked Example)

假设单指（食指）指尖相机、单个物体，走一遍观测构造与一次推理：

1. **前向运动学**：由当前手关节角算出食指相机在手基座系下的位姿，设 `p = (0.08, 0.02, -0.15)` m，`r ∈ R^6` 由旋转矩阵前两列展平得到 → 拼接成 9-D，分别线性投影到 128-D，再串成 256-D 位姿嵌入。
2. **视觉**：食指 224×224 RGB 经冻结 CLIP 得视觉特征（假设 197 个 patch token），与上面的 256-D 位姿嵌入、该指 4-D 电流投影出的 128-D 特征拼接 → 形成该指的观测 token。
3. **组装**：5 指各一个 token + 第三视角 1 个 + 本体 26-D 投影 1 个 → 约 7 个观测 token。
4. **推理**：从纯噪声动作 token 起步，跑 K 步去噪，得到 `n=16` 步、每步 26 维的关节轨迹；只把前 `m=8` 步发给机械臂与手，再重新观测、重新推理（闭环）。

**可计算的闭环**：若端到端 10.2 FPS（论文 Table 2），则一个控制周期约 `1/10.2 ≈ 98 ms`；执行 8 步意味着约 `8 × 98 = 784 ms` 的运动在执行中被下一轮推理接续——**延迟直接决定动作块大小与响应性的权衡**。

## 4. 工程视角 (Engineering View)

论文给出了直接可比的系统开销（Table 2，对比基线 TVC + WC）：

| 指标 | Ours (FTC+TVC) | 基线 (TVC+WC) | 解读 |
|------|----------------|----------------|------|
| 单帧数据采集时间 | 35.2 ms | 34.4 ms | 多 3 路图像流，采集几乎不增负担 |
| 策略 FLOPs | 215.01 GFLOPs | 79.00 GFLOPs | 计算量约 2.7×，主要来自 6 路视觉编码 |
| 端到端系统速度 | 10.2 FPS | 13.2 FPS | 约降 23% 帧率，仍满足实时灵巧操作 |
| 平均成功率 | 80.8% | 51.6% | 用约 2/3 帧率换 ~1.57× 成功率 |

**工程含义**：

- **FLOPs 大头在视觉编码**（6 路 ViT），不是策略主体；想提速优先从「多视角 encoder 共享/蒸馏」入手。
- **10 FPS 的控制频率**对慢速精确操作够用，但对快速接触响应是瓶颈——作者在 Future Work 中提出用异步执行（action chunking 的异步推理）缓解推理延迟。
- **采集带 6 路图像会显著增加 I/O 与带宽**；论文称采集时间几乎不变，说明瓶颈在计算而非传输。
- **硬件体积**：传感器封装 8.5×8.5×4.95 mm，倾角约 30°，控制器 PCB 30×15×1.6 mm 置于手背（指甲位），维持手部外形、不压缩运动间隙——这是「不显著增大手部包络」的关键工程点。

## 6. 能力与失败模式 (Capabilities & Failure Modes)

**能做**：在重度遮挡、狭窄空间内做近接触定位与抓取；对训练中未见过的颜色/形状/材质/光照有一定泛化；长程任务（先开门再取物）可用。

**不能做 / 会失败**（论文 Fig. 6 + §6 明示）：

| 失败场景 | 现象 | 原因 |
|----------|------|------|
| 无照明的按钮（S1） | 指尖视角伸入后近乎全黑，反复对不准 | 缺少集成照明，暗环境下 RGB 退化 |
| 细而光滑的瓶子（S4） | 抓取中从手中滑脱 | 手部表面摩擦不足（同尺寸粗糙白瓶则正常） |
| in-hand 重定向等复杂灵巧 | 未评测 | 实验范围仅限受限/遮挡场景的多指操作 |

**其他失败来源（附录 A.2 分类结果）**：S1 中白色按钮盒（1/3）、未见形状按钮（3/6）较弱；S4 中未见手柄形状（3/5）较弱——说明对新几何的精细接触仍有缺口。

### 6.1 隐含假设 (Hidden Assumptions)

- **假设指尖相机视角始终有效**：但论文自己的失败案例（无照明按钮）直接反驳——光照是该设计的隐含前提。
- **假设关节电流可替代接触感**：电流与负载相关，但对手部表面摩擦不足（滑脱）无法补偿，触觉的缺失在滑脱场景暴露。
- **假设 6 路视觉的泛化靠冻结 CLIP 足够**：Table 3 显示冻结 CLIP 在动作预测 MAE 上最优/接近最优，但这是在其自身示教分布内的结论，跨物体/跨机器人迁移未验证。
- **假设手部形态与示教分布匹配**：所有任务用同一手、同一臂、桌面场景；对移动/双臂/人形的迁移未涉及。

**关键差异**：与光学触觉传感器「只在接触后给接触面信息」相比，指尖 RGB 相机在**接近（pre-contact）阶段**就能提供定位与场景上下文；与既有指尖视觉方案相比，本文的关键是**多视角 + 相机位姿/电流编码**，把「视角随手指动」这个麻烦变成了可用条件信号。

**面试 Tip**：被问到「这篇和 Diffusion Policy 有什么区别」时，一句话答——「策略骨架沿用 Diffusion Policy，但**观测表征换了**：把外置/腕部单视角换成 5 指尖多视角 RGB，并显式编码指尖相机位姿与逐指关节电流，用来对抗狭窄空间遮挡；增益主要来自感知层而非策略层。」（若被追问增量性，承认它本质是感知模块改进，但给出了真机 4 任务 + 消融 + 延迟的完整证据链。）
