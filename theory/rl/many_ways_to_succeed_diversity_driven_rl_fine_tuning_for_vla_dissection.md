这篇论文问的是：用强化学习微调 VLA 之后，策略究竟「变得更会做」，还是「变得更只会一种做法」？作者用相似度分析给出了一个有点反直觉的答案——整体行为在收缩（看起来更单调），但在成功的那些轨迹之间，策略反而覆盖了更多不同的解法。于是他们把「成功轨迹之间的差异」直接变成奖励项，让模型去追求更多可行的成功路径，而不是被 KL 约束拉回演示分布。对 VLA 研究者而言，这意味着奖励设计可以不只是「做成了没有」，还可以是「用了几种不同的方式做成」。

## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 模块 | 输入 | 输出 | 时序/频率 | 训练/推理差异 |
|------|------|------|-----------|----------------|
| VLA 策略 π_θ | 视觉 + 本体观测 s_t、语言指令 l | 动作 a_t 或动作块 | 每次决策输出一个动作块（action chunk） | 训练走 Flow-SDE 采样；推理同接口 |
| 轨迹特征提取 | 策略内部已算好的 VLM-prefix 表示 | 每个决策一个均值池化嵌入 z | 每条轨迹 L_i + 1 个特征（含终止观测） | 只训练时用，推理不需要 |
| GAK 相似度 | 同一组内两条轨迹的特征序列 | 归一化相似度 K̃_ij ∈ [0,1] | 每条轨迹与组内其他 N-1 条各算一次 | 只训练时用 |
| 多样性奖励 | 组内相似度 + 成功标志 y_i | 轨迹级内在奖励 r_div | 每条轨迹一个标量，作用在终止动作块 | 只训练时用 |
| PPO 更新 | 环境奖励 + α·r_div | 策略梯度 | 每次采集 512 条轨迹后更新 | 与 Vanilla RFT 管线一致 |

### 1.2 关键机制

- **打组采样**：每次采集 64 个组、每组 8 条随机 rollout，同组共享同一任务与环境条件。相似度只在组内比较，避免把「不同任务」误当成「不同解法」。
- **时间对齐比较**：直接用逐步比较会被执行速度差异污染（同一条路径走快走慢会被判成不同）。GAK 沿所有单调对齐路径累加局部核，对局部时序偏移宽容，但保留全局顺序。
- **成功条件化**：先算组内相对多样性 d_i，但只在成功集合 S_g 内做 min-max 归一化；失败轨迹的 d̂ 直接置 0。作者明确说这是为了避免「奖励失败的多样性」。
- **势函数塑形**：奖励取相邻状态势差 r = γΦ(s') − Φ(s)，使得轨迹级折扣回报塌缩为 γ^{L}·y·d̂。这一步同时让中间前缀不需要单独算多样性。

⚡ **Eureka Moment**：VLA 的 RL 微调不是「把行为空间压小」，而是在压小整体分布的同时把**成功模式**摊开；因此正确的奖励信号不是「探索更多」，而是「在成功的那部分里探索更多」。

## 2. 数学核心

📌 **Napkin Formula**（一行抓住本质）：

```
r_DRIVE = r_env + α · γ^L · 1[成功] · 组内相对多样性
```

先给目标：在标准 PPO 目标上加一项**只对成功轨迹生效**的多样性奖励，同时不改变最优策略集合。

```text
L_PPO(θ) = E_t[ min( ρ_t(θ)·Â_t , clip(ρ_t(θ), 1-ε, 1+ε)·Â_t ) ]
ρ_t(θ) = π_θ(a_t | s_t, l) / π_{θ_old}(a_t | s_t, l)
```

先给轨迹表示：每条轨迹记 L_i 个已执行动作块，加上终止观测，得到长度 M_i = L_i + 1 的特征序列。

```text
Z_i = (z_{i,0}, z_{i,1}, ..., z_{i,L_i-1}, z_{i,term})
```

先给局部核：用平移余弦把相似度压到 [0,1]，下界 ε = 1e-12。

```text
κ(z, z') = clip( ( cos(z, z') + 1 ) / 2 , ε, 1 )
```

先给 GAK 递推（正文式 (3) 与附录 B 索引略有差异，附录版本带边界条件，以下采用附录 B）：

```text
G_ij(a, b) = κ(z_{i,a-1}, z_{j,b-1}) · [ G_ij(a-1,b) + G_ij(a,b-1) + G_ij(a-1,b-1) ]
边界：G_ij(0,0) = 1；其余含 0 的项为 0
```

三个前驱分别表示「i 前进」「j 前进」「两者同时前进」，因此求和覆盖全部单调对齐路径，而不是取单条最优对齐。

先给归一化轨迹核：

```text
K_GAK(Z_i, Z_j) = G_ij(M_i, M_j)
K̃_ij = K_GAK(Z_i, Z_j) / sqrt( K_GAK(Z_i, Z_i) · K_GAK(Z_j, Z_j) )
```

先给组内多样性与归一化：

```text
sim_i = (1/(N-1)) · Σ_{j≠i} K̃_ij
d_i   = 1 − sim_i
d̂_i   = clip( (d_i − d_min) / max(d_max − d_min, δ), 0, 1 )
        其中 d_min = min_{j∈S_g} d_j，d_max = max_{j∈S_g} d_j
d̂_i = 0，若 i ∉ S_g（失败轨迹）
```

先给势函数与轨迹级奖励：

```text
Φ_g(s_{i,c}) = y_i · d̂(s_{i,c})
r_div_{i,c}  = γ · Φ_g(s_{i,c+1}) − Φ_g(s_{i,c})
r_div_{τ_i}  = Σ_{c=0}^{L_i-1} γ^c · r_div_{i,c}
             = γ^{L_i} · Φ_g(s_{i,L_i}) − Φ_g(s_{i,0})
             = γ^{L_i} · y_i · d̂_i          （初态势为 0）
r_DRIVE_{τ_i} = r_env_{τ_i} + α · r_div_{τ_i}
```

**变量说明**

| 符号 | 含义 | 取值/来源 |
|------|------|-----------|
| N | 一个组内的轨迹数 | 8（每次采集 64 组） |
| L_i | 第 i 条轨迹执行的动作块数 | 由 episode horizon 与执行步长决定 |
| γ | 折扣因子 | 0.99（全部实验） |
| ε | PPO 裁剪系数 | 0.20 |
| δ | 防止 min-max 放大的小常数 | 论文未给具体值 |
| α | 多样性奖励强度 | 0.02 / 0.05 / 0.10（按基准与骨干不同） |
| y_i | 成功指示 | 二值 |

**直觉**：d̂_i 是「在同一组成功轨迹里，这条比其他成功轨迹更像异类」的相对排名，被 min-max 压到 [0,1]。乘上 γ^{L_i} 之后，越早结束的轨迹，奖励衰减越小；乘上 y_i 之后，失败轨迹再怎么独特也拿不到奖励。因为奖励是势差形式，最优策略集合不变。

> 定理 1（最优策略不变性）：在 M 上加上 r_div = γΦ(s') − Φ(s) 后，变换后 MDP 的最优策略与 M 的最优策略互为对方的最优策略。证明走 Bellman 最优方程做变量替换 Q̃ = Q* − αΦ，因为 Φ 只依赖状态不依赖动作，argmax 不受影响（附录 A，沿用势函数塑形的经典论证）。

## 3. 带数字走一遍：玩具例子（假设数值）

> 以下数值是我为演示机制而设的**假设例子**，不是论文实验结果；所有计算均已手工验算。

设一次采集中某一组有 N = 4 条轨迹，同一任务与同一环境条件。为简化，假设每条轨迹只有 2 个动作块（再加终止观测，M_i = 3，但下面只用前两位做演示），且特征已被归一化，局部核取值为：

```text
κ(a,a) = κ(b,b) = κ(c,c) = κ(d,d) = 1
所有不同符号对（含 a–b、a–c、a–d、b–c、b–d、c–d）的局部核均为 0.6
```

四条轨迹的序列设为：

```text
τ1: (a, b)  成功    τ2: (a, b)  成功
τ3: (a, c)  成功    τ4: (a, d)  失败
```

按附录递推手算 GAK：

```text
K_11 = K_22 = K_33 = K_44 = 2.2          （自身对齐，1 + 2×0.6）
K_12 = 2.2   → K̃_12 = 2.2 / 2.2  = 1.0000
K_13 = 1.32  → K̃_13 = 1.32 / 2.2 = 0.6000
K_14 = K_23 = K_24 = K_34 = 1.32 → 均为 0.6000
```

组内平均相似度与多样性：

```text
sim_1 = (1.0000 + 0.6000 + 0.6000) / 3 = 0.7333 → d_1 = 0.2667
sim_2 = 0.7333                                  → d_2 = 0.2667
sim_3 = (0.6000 + 0.6000 + 0.6000) / 3 = 0.6000 → d_3 = 0.4000
sim_4 = 0.6000                                  → d_4 = 0.4000   ← 失败但很"独特"
```

成功集合 S_g = {1, 2, 3}，故 d_min = 0.2667、d_max = 0.4000：

```text
d̂_1 = (0.2667 − 0.2667) / (0.4000 − 0.2667) = 0
d̂_2 = 0
d̂_3 = (0.4000 − 0.2667) / (0.4000 − 0.2667) = 1
d̂_4 = 0      ← 因为 y_4 = 0
```

取 γ = 0.99、L_i = 2（即 γ^2 = 0.9801）、α = 0.1：

```text
r_div_τ1 = 0.9801 × 0 × 0 = 0
r_div_τ3 = 0.9801 × 1 × 1 = 0.9801
r_DRIVE_τ3 = r_env_τ3 + 0.1 × 0.9801 = r_env_τ3 + 0.09801
```

**对照验算（去掉成功条件化会怎样）**：若在全部 4 条轨迹上做 min-max，则 d_min = 0.2667、d_max = 0.4000 不变，τ4 的 d̂ 变成

```text
d̂_4 = (0.4000 − 0.2667) / (0.4000 − 0.2667) = 1.0
```

也就是说，一条**失败**轨迹会拿到与最独特成功轨迹相同的满额奖励。这正是作者强调「不得奖励 diverse failures」的具体后果——在这个例子里差异会立刻显形。

**再验算一个数**：两条完全相同的成功轨迹（只有 τ1、τ2）时，d_max − d_min = 0，分子也为 0，clip 后两者都是 0。这说明奖励在「成功解没有差异」时自动归零，不会凭空制造梯度。

## 4. 工程视角

| 关注点 | 具体数字/约束 | 工程含义 |
|------|--------------|----------|
| 每次采集规模 | 64 组 × 8 条 = 512 条轨迹 | 组是并行的最小单位；少于 8 条会让 sim_i 估计方差变大 |
| 组内比较复杂度 | 每组 O(N²) 对，每对一次 O(M_i·M_j) 动态规划 | N=8 只有 28 对；M_i 随 episode horizon 增长，长任务上是主要开销 |
| 数值稳定性 | 动态规划在 log 空间求值 | 乘积递推在长序列上极易溢出/下溢，必须换到对数域 |
| 特征来源 | 复用策略已算好的 VLM-prefix 表示，均值池化 | 不需要额外前向，但需要把 prefix 表示留到 rollout 结束 |
| 奖励注入位置 | 只作用在终止动作块 | 训练时不用为每个中间前缀算多样性，省掉一次逐前缀前向 |
| 训练轮次 | LIBERO-Plus 100–400 轮；ManiSkill3 200–300 轮；RoboTwin 50–100 轮 | 轮次按基准与骨干分别选，同列内所有方法共用 |
| 每次采集的时间步 | episode horizon：LIBERO 240/320/480；ManiSkill3 80；RoboTwin 200 | 「轮次」「采集次数」「时间步」是三个不同量纲，不能混用 |
| PPO 更新轮次 | 3–5 | 与 Vanilla RFT 对齐，避免混淆变量 |
| 学习率 | actor 5e-6 或 7.91e-6；critic 1.0e-4 / 1.1e-4 / 1.55e-4 | 与标准 RFT 同量级 |
| α 取值 | 0.02 / 0.05 / 0.10，训练中不衰减 | 作者明确说没有 α 衰减调度；这意味着强度靠手调而非自适应 |

**部署侧的现实约束**：DRIVE 只在训练时用。推理时策略结构完全不变，不增加延迟、不增加显存。代价全部压在一次训练采集里——每条轨迹要保留 L_i + 1 个 prefix 嵌入，以及组内 28 次动态规划。作者在结论里把这一点列为局限：成对 GAK 比较带来额外计算，且依赖 VLM 表示能否捕捉到有意义的行为差异。

- π0.5：12 列里 11 列提升，唯一下降是 Goal-OOD（57.9 → 56.8）。
- π0.5 上与最强替代基线比：OOD 宏平均 DRIVE 73.1 vs Clip-Higher 72.6，差距 0.5 点；IND 宏平均 DRIVE 88.2 vs KL 正则 87.1，差距 1.1 点。在 ManiSkill3-OOD 这一列上 Clip-Higher（52.9）实际上优于 DRIVE（51.9）。

### 5.3 真机结果（表 2，20 trials / 条件）

| 任务 | 方法 | Clean | Distractor | Background | Lighting | OOD Avg. |
|------|------|-------|-----------|-----------|----------|----------|
| Click Bell | Vanilla RFT | 80 | 60 | 70 | 65 | 65.0 |
| Click Bell | DRIVE | 85 | 75 | 75 | 65 | 71.7 |
| Press Stapler | Vanilla RFT | 75 | 70 | 65 | 55 | 63.3 |
| Press Stapler | DRIVE | 80 | 75 | 80 | 70 | 75.0 |

8 个任务-条件组合里 7 个提升、1 个持平（Click Bell 的 Lighting：65 → 65）。两任务平均 Clean 77.5 → 82.5，OOD 64.1 → 73.3。复算：((65.0 + 63.3)/2 = 64.15)、((71.7 + 75.0)/2 = 73.35)，与论文的 64.1 / 73.3 一致。

### 5.4 机制验证（ManiSkill3，π0.5）

- 训练动力学：IND 在训练中快速上升；OOD 曲线**非单调**，在不同检查点之间波动，两个 α（0.1 / 0.2）趋势相近。作者据此强调「只看 IND 无法刻画泛化」。
- 相似度：全体 rollout 的 GAK 相似度，Vanilla 与 DRIVE 差别不大；只在**成功轨迹**里，DRIVE 在训练后期保持更低相似度（即更高多样性）。作者据此说效应集中在任务有效解空间内。
- 成功条件化消融：把同样的多样性塑形去掉成功条件后，早期两者 IND 相当，后期完整 DRIVE 更高——作者据此判断「成功条件化的作用随训练推进才显现」。
- 采样预算分析：32 个任务-初始状态配置，最多 256 条 rollout；Coverage@K 以 SFT 在 K=256 的成功样本为参照，对 SFT 查询做 leave-one-out 匹配避免自匹配。

## 6. 能力与失败模式

**能做**：

- 在**同一任务、同一环境条件**下区分「不同的成功做法」——GAK 的单调对齐让它对执行速度差异不敏感，对路径形状差异敏感。
- 在奖励尺度上做相对化——d̂ 是组内 min-max 排名，天然抵消了不同任务成功奖励量级差异。
- 保持最优策略不变——势函数形式使这一点有形式化保证（定理 1）。

**不能做 / 论文未验证**：

- **不区分「有意义的差异」和「表征噪声」**：相似度完全由 VLM-prefix 嵌入决定。如果某些差异只是外观、光照、视角带来的表征漂移，而不是动作策略差异，GAK 会把它当作多样性奖励。作者在局限里明确承认这一点。
- **失败轨迹的多样性被完全丢弃**：这是设计选择，不是缺陷，但也意味着在某些任务里「从失败中学到新路线」的路径被堵死。消融实验只显示 IND 上后期有差距，没有报告 OOD 上的消融结果。
- **需要组内成功样本**：min-max 归一化只在 S_g 上做。如果某组全都失败，该组所有 d̂ = 0，奖励项完全失效。论文没有讨论早期训练成功率低时的行为。
- **长任务开销**：动态规划是 O(M_i·M_j)，M_i 随 horizon 线性增长。LIBERO-Long 的 episode horizon 是 480 时间步，是全表里最长的，但论文没有报告这一项的实际墙钟开销。
- **任务覆盖窄**：仿真 3 个基准 + 真机 2 个任务（Click Bell、Press Stapler），全部是桌面/双臂操作。不能据此推断移动操作、人形或长时序装配任务。

### 6.1 隐含假设

1. **「成功轨迹之间的行为差异 ≈ 对 OOD 有用的策略差异」**。这是全文最核心但未被直接验证的假设。论文提供的是相关性证据（成功轨迹相似度下降 + OOD 提升同时出现），没有做因果隔离（比如固定多样性、只变 OOD）。
2. **VLM-prefix 均值池化足以表征行为**。均值池化会丢失 token 顺序信息，论文没有对比其他池化方式或不同层特征。
3. **组内 8 条轨迹足以稳定估计 sim_i**。N=8 时 sim_i 是 7 个相似度的平均，方差没有报告。
4. **宏平均的等权构造能代表「泛化」**。如 §5.2 复算所示，LIBERO-Plus 的 4 个套件在最终数字里被压成 1/3 权重，而 RoboTwin 只有 2 个任务也占 1/3。
5. **同一 SFT 初始化下比较是公平的**。所有方法共享 SFT 检查点、训练轮数、rollout 分布和 PPO 配置，这点作者写得很明确；但训练轮数是「按任务难度和收敛行为选的」，这意味着不同方法的训练量是匹配的，而不是各自最优。

## 7. 与相关工作对比

| 方法类别 | 代表做法 | 奖励信号 | 是否区分成功解 | 与 DRIVE 的差异 |
|---------|---------|---------|---------------|----------------|
| Vanilla RFT | 标准 PPO + Flow-SDE | 仅环境奖励 | 否 | DRIVE 的对照基线 |
| 提高采样噪声 | Flow-SDE σ = 0.7 | 仅环境奖励 | 否 | 靠随机性换探索，不区分成功/失败 |
| KL 正则 | 向 SFT 参考策略加 KL 惩罚（β = 0.5） | 环境奖励 + KL | 否 | 把策略往演示分布拉，方向与「扩散成功解」相反 |
| Clip-Higher | PPO 上界 0.20 → 0.28 | 仅环境奖励 | 否 | 放宽更新幅度，属于优化层干预 |
| 无监督技能发现 / 策略多样化 | 最大化轨迹分布差异 | 内在奖励 | 否 | 会奖励表面差异和失败行为 |
| DRIVE（本文） | 组内 GAK + 成功条件化 + 势函数塑形 | 环境奖励 + α·r_div | 是 | 只在成功集合内做相对排名 |

**面试 Tip**：如果被问到「DRIVE 和普通好奇心探索有什么区别」，一句话答——好奇心奖励的是「没见过的状态」，DRIVE 奖励的是「在已经成功的轨迹里，比别人更不一样的那一条」；前者会给失败发奖金，后者不会。

## 8. 精读建议

- **值得精读原文的人**：
  1. 正在做 VLA 强化微调、且已经跑通 PPO/GRPO 管线，想加第二项奖励的研究者——重点看 §4.2、§4.3 和附录 B 的递推细节。
  2. 需要判断「这个方法能不能搬到我的机器人上」的工程师——重点看 §5.3、附录 D 的 α 取值和附录 E 的 sim-to-real 对齐流程。
  3. 关心「RL 微调到底改变了什么」这一分析性问题的人——重点看 §3 的 Pass@K / Coverage@K 设计。
- **建议章节路径**：先读 §3 建立「全局收缩 + 成功区扩散」的直觉 → 再看 §4.2/§4.3 搞清楚奖励怎么算 → 然后看 §5.1 和表 1 判断增益量级 → 附录 B 和 D 留到要复现时再读。
