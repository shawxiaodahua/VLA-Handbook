## 1. 核心架構/方法總覽 (Overview / Architecture)

RAPID 不改動偏好模型與策略學習器（沿用 RL-VLM-F 的 Bradley-Terry 獎勵集成 + SAC），而是**重新組織它們與資料收集之間的互動**。四個組件形成一個協同的反饋閉環。

### 1.1 系統對比概覽 (System Component Comparison)

| 模組 | 輸入 | 輸出 | 頻率/時序 | 訓練 vs 推理 |
|------|------|------|-----------|--------------|
| 並行環境 (50×) | 動作命令 (8-dim) | 轉移 + 128×128 RGB | 每步同步；每 4,000 步觸發一次標註輪 | 僅訓練 |
| 自適應更新排程 | ΔN (新轉移數) | n 次 SAC 更新 | 每採集迭代 | 訓練 |
| 單請求 VLM 標註 | 圖像對 + 任務描述 + 輸出 schema | 三元標籤 {0, 1, −1} | 每輪 40 對比較 | 訓練（離線基準另評） |
| 獎勵模型集成 (3×) | RGB 圖像 | 標量獎勵 | 每輪標註後擬合 | 訓練 |
| 穩定性監控 | 錨點集 A (512 圖) 的預測 | 凍結/繼續信號 | 每次獎勵更新後 | 訓練 |
| 代表性採樣 | 5,000 近期候選圖 | 50 張多樣化圖池 | 每輪標註前刷新 | 訓練 |
| SAC 策略 | 仿真狀態 | 動作 | 每步 | 訓練 + 評估 |

> 注意**觀測非對稱**：策略讀的是仿真狀態（關節位置/速度 + 物體狀態 + 上一動作），而 VLM 與獎勵模型只看固定視角的 128×128 RGB 圖像。

### 1.2 關鍵機制 (Key Mechanism)

- **並行 rollout 會打亂「資料/更新」平衡**：E_active 個環境每次迭代產生 E_active 條轉移；若維持固定更新次數，等於偷偷改變了策略更新與收集資料的比例。RAPID 因此按**新轉移數**分配更新額度，並在初始資料收集後設上限抑制 off-policy 網絡的 primacy bias。
- **兩段式請求是隱形成本**：基線每對圖像要兩次 API（先自由分析、再映射成標籤），請求數與延遲翻倍。單請求把圖像對、任務描述、輸出 schema 打包進一次請求，直接砍半。
- **固定查詢預算不適應收斂**：題目太難時停太早、太簡單時停太晚。用「連續兩輪獎勵模型對同一批狀態的打分是否幾乎不變」來判斷收斂，收斂即凍結獎勵、停止調用。
- **FIFO 採樣會拿到雷同圖像**：同步環境容易訪問鄰近狀態，比較價值低卻照樣消耗 API。改用最遠點採樣維持視覺多樣性；且刻意用**固定低解析度特徵**（不隨獎勵模型更新而變），避免把「查詢選擇」和「被監控收斂的模型」耦合在一起。

⚡ **Eureka Moment**：在並行仿真下，最貴的資源不是 GPU 算力，而是 VLM 標註調用；因此要讓「停止調用」與「挑哪對圖像去問」都變成由資料分佈驅動的自適應決策 —— 一旦獎勵信號穩定就別再問，並且只問最不像的一對。

## 2. 數學核心 (Math Core)

📌 **Napkin Formula**（一行抓住本質）：

```
獎勵穩定 ⇔ corr(r_t, r_{t-1}) ≥ 0.99  → 立刻停止問 VLM
```

**目標**：在沒有手工獎勵函數的操作任務上，用 VLM 提供的成對偏好，學出一個足夠好又足夠省的獎勵信號，同時把訓練壁鐘時間壓到最小。

**(A) 偏好機率（Bradley-Terry 模型，論文 Eq.1）**

```
P[σ_i ≻ σ_j] = exp( Σ_{t=1..H} r_θ(I_t^i) )
               ─────────────────────────────────
               Σ_{k∈{i,j}} exp( Σ_{t=1..H} r_θ(I_t^k) )
```

| 符號 | 含義 |
|------|------|
| σ_i | 第 i 段軌跡片段 = {(s_t, a_t, I_t)}_{t=1..H} |
| I_t | 渲染出的 RGB 圖像（本文 H=1，單圖片段） |
| r_θ | 獎勵模型（輸入圖像） |
| 標籤 | 三元 {0= i 較好, 1= j 較好, −1= 不確定}，−1 在訓練前丟棄 |

以二元交叉熵最小化擬合 r_θ，並訓練 n_e = 3 個網絡取集成均值作為 RL 獎勵。

**(B) 自適應更新預算（論文 Eq.2–4）**

```
b̃_t = min( b_{t-1} + α·ΔN_t , U_max + 1 )     # 可用預算
n_t  = ⌊ min( b̃_t , U_max ) ⌋                 # 本次執行更新數
b_t  = b̃_t − n_t                              # 結轉信用
```

| 符號 | 含義 | 本文取值 |
|------|------|----------|
| α | 每條轉移的目標 SAC 更新數 | 0.5 |
| ΔN_t | 自上輪以來新增轉移數 | — |
| U_max | 單次優化突發上限 | 50 |
| b | 結轉信用（fractional update budget） | — |

**直覺**：把更新當作「按轉移量計費的預算」而非「每迭代固定次數」，並用上限切掉初始階段的巨大突發，避免 primacy bias。

**(C) 相關性穩定性監控（論文 Eq.5–6）**

```
ρ_t = corr( r⃗_{t-1} , r⃗_t )                 # Pearson 相關
δ_t = (1/N) Σ_{i=1..N} | r_t^(i) − r_{t-1}^(i) |   # 平均絕對變化
凍結條件: ρ_t ≥ 0.99  AND  δ_t ≤ 0.025  連續 patience = 2 次
```

| 符號 | 含義 | 本文取值 |
|------|------|----------|
| A | 錨點圖像集（自 replay buffer 取樣） | N = 512 |
| ρ_thresh | Pearson 相關閾值 | 0.99 |
| δ_thresh | 平均絕對變化閾值 | 0.025 |
| P | patience（連續達標次數） | 2 |

**(D) 代表性採樣（最遠點採樣）**

```
輸入: 最近 M 張候選圖 → L2 歸一化 16×16 灰度特徵
從中間候選開始，貪心迭代加入「到已選集合最小 L2 距離最大」的圖
直到保留 K 張 → 從此池中成對取樣送 VLM
```

本文取值 M = 5,000、K = 50、特徵 16×16 灰度。

> 符號與原文保持一致：b̃ / b 為預算與結轉信用；α 為更新/轉移比；U_max 為突發上限。論文未給出對 FPS 最遠點採樣的收斂證明，屬工程啟發式。TODO: 可補 greedy farthest-point 的近似比背景（Gonzalez 1985 / Sener & Savarese 2018）。

## 3. 帶數字走一遍：玩具例子 (Worked Example)

**例 1 — 更新預算排程如何平滑化（50 環境、α=0.5、U_max=50）**

假設 10K 步隨機種子階段結束時，第一個「有預算」的迭代看到 ΔN = 10,000（種子階段累積的轉移）：

```
迭代1: b̃ = min(0 + 0.5×10000, 51) = min(5000, 51) = 51
       n = ⌊min(51, 50)⌋ = 50   (撞到上限)   b = 51 − 50 = 1
迭代2: ΔN = 50 → b̃ = min(1 + 0.5×50, 51) = min(26, 51) = 26
       n = 26                              b = 0
迭代3: ΔN = 50 → b̃ = 25 → n = 25            b = 0  (此後穩態)
```

結論：上限只在種子階段後的第一次迭代被觸發，留下一單位信用，下一輪補成 26 次更新，之後穩定在每迭代 25 次（= α×50）。這正是論文 §IV-A 描述的日誌現象。

**例 2 — 穩定性停止的計數器如何運作（假設錨點 N=512）**

```
輪次 t   ρ_t     δ_t     兩條件同時滿足?   c_stable   動作
 t=1    0.985   0.040     否 (ρ<0.99)       0          繼續
 t=2    0.995   0.040     否 (δ>0.025)      0          繼續、計數歸零
 t=3    0.993   0.020     是                 1          繼續
 t=4    0.996   0.018     是                 2          FREEZE (≥ patience=2)
```

凍結後停止 VLM 查詢與獎勵更新，策略用凍結獎勵繼續訓練。論文實測 C5 全部 15 個 run 都在 22K–274K 步之間停止（均值 95.6K 步）。

**例 3 — API 調用是怎麼省下來的**

```
每輪標註: 40 對圖像比較
C1 (基線): 兩段式 → 每對 2 次請求 → 80 次/輪
           不停止 → 全程 ~248 輪 → 約 19,840 次/run
C3 (並行+單請求): 每對 1 次 → 40 次/輪
           不停止 → ~248 輪 → 約 9,920 次/run
C5 (RAPID): 單請求 + 平均 ~96K 步停止 → ~22–24 輪 → 896 次/run
```

即：**請求格式減半（÷2）× 提前停止（輪數大幅縮短）= 95.5% 的調用下降**。

- 加速來自**協調**而非單點算法——並行 rollout 只貢獻 2.9×，真正把循環成本壓下來的是「少問、問對、早停」。

## 6. 能力與失敗模式 (Capabilities & Failure Modes)

**能做的**
- 在 5 個仿真操作任務上，RAPID 平均成功率達 98.7%（C1 為 86.3%），每任務 95–100%。
- 相較 C1：8.0× 端到端加速、95.5% API 調用下降；50 個 C5 run 約需 44,800 次調用，而 C1 約需 992,000 次。
- 穩定性停止在 15/15 個 C5 run 觸發，幾乎把查詢預算從「跑滿」變成「按收斂停」。

**不能做 / 會失敗的場景**
- **真機遷移未驗證**：全程仿真，作者明說「需要 domain randomization、真實圖像校準、物理評估才能聲稱可遷移」。實機純 RL 也吃不到並行物理的加速。
- **感知-動作不對稱**：獎勵模型看單一固定相機圖像，策略卻讀仿真狀態；光照、紋理、視角、動力學、接觸差異都可能讓學到的獎勵在真機上失效。
- **長視界任務未測**：僅 5 個短視界任務；作者建議未來用 LLM 任務規劃器分解子目標再逐段學子獎勵。
- **第二個 VLM 僅離線評測**：GPT-4.1 mini 沒進入訓練回路，泛化性只在 1,000 對基準上驗證。
- **prompt 格式的效果依模型而異**：離線基準中 GPT-4.1 mini 單請求更準（74.0% vs 72.0%），但 Gemma 偏好兩段式（70.9% vs 65.1%）——單請求雖便宜 32.4%、快 44.2%，卻可能損傷標籤準確率。因此「成功率提升」不能單獨歸因於 VLM 標籤準確率。
- **凍結後的短暫退化**：11/15 個 run 在停止標註後性能先降後恢復，若任務對暫時退化敏感需留意。

### 6.1 隱含假設 (Hidden Assumptions)

- 假設**獎勵收斂 ⇔ 策略最優已足夠**：用「連續兩輪打分不變」判定停止，但這只證明獎勵模型穩定，不證明它穩定在「正確」的獎勵上——一個穩定但錯的獎勵同樣會觸發凍結。
- 假設**固定 16×16 灰度特徵足以表徵視覺多樣性**：對這 5 個低紋理、幾何性任務成立，但作者也承認未測預訓練固定嵌入，語義更細的任務可能不成立。
- 假設**VLM 的成對偏好是可靠監督**：整個框架的上限由 VLM 標籤質量決定；論文只離線測了 2 個模型的準確率（70–74% 區間），未量化錯誤標籤如何傳導到策略。
- 假設**並行 50 環境的圖像分佈仍具代表性**：同步環境可能過度集中於鄰近狀態（正是要最遠點採樣去救的地方），但沒有分析殘餘偏差。
- 假設**單一固定相機足以支撐獎勵**：未測多相機或主動視角；對需要遮擋推理的任務可能信息不足。

## 7. 與相關工作對比 (Comparison)

| 方法 | 關注點 | 架構/機制 | 訓練方式 | 適用場景 |
|------|--------|-----------|----------|----------|
| PEBBLE (2021) | 反饋效率 | 經驗重標註 + 無監督預訓練 | 人類偏好，離策略 | 需要少量人類反饋 |
| SURF (2022) | 標註效率 | 半監督獎勵 + 資料增廣 | 人類偏好 | 標籤稀缺 |
| RL-VLM-F (2024) | 去人類化 | VLM 取代人類，兩段式請求、單環境 | 在線偏好 RL | VLM 偏好獎勵學習的基準 |
| RL-SaLLM-F (2025) | 標籤質量 | 軌跡增廣 + 標籤驗證 | LLM 反饋 | 需要更乾淨的標籤 |
| PRIMT (2025) | 多模態反饋 | 多模態反饋 + 軌跡合成 | 基礎模型反饋 | 合成高質量偏好資料 |
| **RAPID (本文, 2026)** | **吞吐與成本** | **並行 rollout + 自適應更新 + 單請求 + 穩定性停止 + 最遠點採樣** | **IsaacLab 在線 VLM 偏好 RL** | **已有 GPU 並行仿真、想壓低 LLM 調用的工程棧** |

**關鍵差異**：前述工作多在改進「獎勵/標籤本身有多好」，RAPID 明確把目標換成「把同一個學習過程跑得更快、更省」——它保留 RL-VLM-F 的獎勵與策略學習器，只重排了資料流與反饋時序。

🎯 **面試 Tip**：被問到「RAPID 的貢獻是不是只是把幾個已有技巧拼在一起？」時，這樣答——「四個組件單獨看都是適配既有方法，但它們的價值在於**聯合設計**：並行 rollout 讓採集速率變快，卻同時製造了『資料/更新失衡』與『VLM 查詢瓶頸』兩個新問題；自適應更新、單請求標註、穩定性停止與多樣化採樣正是針對這兩個衍生問題的協同解，消融顯示單靠並行只賺 2.9×，全套協調才拿到 8.0×。」

## 8. 精讀建議 (Reading Guide)

- **值得精讀原文的人**：
  1. 正在做 VLM/人類偏好獎勵學習，想降低 LLM-as-annotator 的調用成本與延遲；
  2. 建 IsaacLab / IsaacGym 並行仿真訓練棧，想解決「並行後更新比例失衡」的工程師；
  3. 想把 online reward learning 打包成可計費、可監控的服務化 pipeline 的團隊。
- **建議章節路徑**：先讀 **§IV**（四個組件與公式，快速抓設計動機）→ 再看 **§VI + Table I/II/III**（消融數字與 2×2 對比）→ 可跳 **§II 相關工作**（若已熟悉 PEBBLE/RL-VLM-F 可直接略過）。
- **不值得精讀的理由**：如果你不做仿真訓練、或已經熟悉並行 RL 與偏好學習的基本套路，這篇的每一項技巧你都見過；讀摘要 + §VI 的消融表即可掌握全部增量。真正的新意在「協調」而非「組件」。
