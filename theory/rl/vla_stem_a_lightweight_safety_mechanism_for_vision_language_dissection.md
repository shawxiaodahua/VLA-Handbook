💡 **X-Ray 开场**

这篇论文问的是：VLA 已经能理解语言和场景，为什么一遇到桌面上多出来的障碍物就频繁碰撞？作者的观察是，现有 VLA 主要针对无约束静态操作训练，缺少对即时物理风险的“反射式”响应。他们的做法不是重新训练 VLA，而是在 VLA 外面挂一个小的 RL policy（Stem），把 VLA 输出的未来动作块当成“我想往哪走”的参考，让 Stem 在每个控制步根据当前关节状态和局部障碍物做微调，必要时等待。对 VLA 研究者来说，这意味着安全不一定非要写进大模型权重里，也可以是一个推理时的轻量耦合模块；但代价是你需要一个可靠的低维障碍物感知接口。

## 1. 核心架构/方法总览

### 1.1 系统对比概览

| 模块 | 输入 | 输出 | 频率/时序 | 训练/推理差异 |
|------|------|------|-----------|----------------|
| Base VLA（论文实验用 π_0.5，冻结） | 视觉观测 + 语言指令（o_t^VLA） | h=8 步 action chunk A_c^VLA | 每个 execution interval 查询一次（每 8 个控制步） | 论文中 base VLA 先在 100 demos 上微调 30,000 optimization steps，之后冻结；Stem 训练期间不更新 |
| Stem policy（可部署学生） | 16 维本体感受 x_t + 33 维局部障碍物 o_t^obs + 8×8 VLA reference 特征 τ_c^rel | 7 维归一化末端 delta-pose 动作 a_t^exec | 每个控制步运行（t_c ≤ t < t_c+h） | 用 PPO + 教师-学生蒸馏训练；部署时只用学生，不需要特权信息 |
| 教师 policy（仅训练） | 学生输入 + 特权任务信息（如目标物体位置；教师状态输入 23 维） | 动作分布 | 训练时每个控制步 | 先 PPO 训练，再冻结用于蒸馏学生 |
| 障碍物感知（外部） | 真实世界：AprilTag + RealSense D455；仿真：ground-truth 障碍物中心与尺寸 | 最多 3 个障碍物，每个 11 维特征 | 每个控制步更新 | 不是本文训练的模块；论文假设低维障碍物信息可用 |

注意：这里的“频率”是基于 h=8 和“Stem 每个控制步运行”的架构描述，论文没有给出实际控制频率（Hz），因此本文不写具体 Hz。base VLA 的 π_0 与 π_0.5 在论文中作为 frozen policy 使用；论文未在正文展开其内部架构，本文也不把两者的不同属性合并归因。

### 1.2 关键机制

- **Action chunk 变 motion reference**：VLA 输出的 h=8 步动作不被直接执行，而是通过运动学映射成未来末端执行器位姿序列，再相对于区间起始位姿表示。Stem 拿到的是“空间意图”，而不是必须逐步复现的时间索引动作。
- **Trajectory-level guidance**：不是逐步对齐动作，而是把当前末端位姿投影到参考轨迹的局部段上，计算位置 + 旋转偏差，映射成稠密奖励。前向走廊约束防止匹配到已经走过的段，允许等待和局部绕行。
- **Teacher-student distillation**：教师能看到目标物体位置等特权信息，学得更快的恢复行为；学生只看可部署观测，通过 KL 蒸馏继承教师的动作分布，λ=0.1。
- **Curriculum**：先无障碍跟轨迹，再加静态障碍，再加动态障碍。奖励权重按阶段变化（Table V）。
- **模块化但不独立**：与 VLSA 那种纯几何安全层不同，Stem 的输出是完整可执行动作，且条件在 VLA 参考上，所以安全修正和任务意图是耦合的；但代价是 Stem 必须自己学会“什么时候该等、什么时候该绕”。

⚡ **Eureka Moment**：把 VLA 的 action chunk 从“要执行的动作”重新解释为“要保留的空间意图参考”，安全策略就不再是逐步纠正一个脆弱的时间索引动作序列，而是在轨迹层面做柔性匹配和局部重规划。

### 1.3 信息流/架构图

```
┌─────────────────────────────────────────────────────────────┐
│ 每个 execution interval c（h=8 个控制步）                      │
│                                                             │
│  o_t^VLA ──► 冻结 VLA π_VLA ──► A_c^VLA (8 步 action chunk) │
│                                      │                      │
│                                      ▼                      │
│                         运动学映射 + 相对化                    │
│                         τ_c^rel = {ΔT_{c,k}}_{k=1..8}       │
│                                      │                      │
│  x_t (本体感受) ───────────────┐      │                      │
│  o_t^obs (局部障碍物) ─────────┼──────┼──► Stem π_stem       │
│                                      │        │              │
│                                      │        ▼              │
│                                      │   a_t^exec (7 维)     │
│                                      │        │              │
│                                      │        ▼              │
│                                      │   机器人执行           │
│                                      │        │              │
│                                      └────────┘ 更新观测      │
│                                                             │
│  8 步后：用新观测重新查询 VLA，生成下一个 chunk                 │
└─────────────────────────────────────────────────────────────┘
```

时序说明：τ_c^rel 是未来 8 步的参考，不是历史帧。Stem 没有跨 interval 的显式记忆；每个 interval 开始时进度索引 m 重置为 1，reference 重新生成。跨 interval 的信息通过 VLA 重新查询时的观测更新传递，而不是通过 Stem 内部的记忆窗口。h=8 是该论文实现中的单一设置，不应写成所有 VLA 或所有实验共有的记忆窗口。

## 2. 数学核心

📌 **Napkin Formula**：

```
a_t^exec = π_stem(x_t, o_t^obs, τ_c^rel),  τ_c^rel = {(T_tc^w)^{-1} T_{tc+k}^w}_{k=1..h}
```

一句话：每个控制步，Stem 根据当前状态、局部障碍物和 VLA 的未来运动参考输出动作；VLA 每 h 步更新一次参考。

**目标**：在不更新 base VLA 的前提下，学一个 Stem policy，使得在约束场景中最大化任务成功并避免碰撞，同时尽量贴近 VLA 参考轨迹的空间意图。

**核心公式**：

```
(1) A_c^VLA = π_VLA(o_{t_c}^VLA)                     # VLA 生成 h 步 action chunk
(2) ΔT_{c,k} = (T_{t_c}^w)^{-1} T_{t_c+k}^w          # 转成相对末端位姿
    τ_c^rel = {ΔT_{c,k}}_{k=1..h}
(3) o_t^obs = {(c_{j,t}^w, d_{j,t})}_{j=1..M}         # 局部障碍物中心 + 尺寸
(4) a_t^exec = π_stem(x_t, o_t^obs, τ_c^rel)          # Stem 每步输出动作
(5) I_t^+ = {m_{t-1}, ..., min(m_{t-1}+K, h-1)}      # 前向候选段
(6) i_t^* = argmin_{i∈I_t^+} d_i,  d_t^* = d_{i_t^*} # 匹配段
    m_t = max(m_{t-1}, i_t^*)                        # 非递减进度
(7) r_t^follow = exp(-k_pose d_t^*)                  # 轨迹跟随奖励
(8) L(π_stu) = L_RL(π_stu) + λ D_KL(π_stu || π_tea)  # 蒸馏损失
(9) r_t = w_task r_t^task + w_coll r_t^coll + w_guidance r_t^guidance
```

**变量说明**：

| 符号 | 含义 | 论文中的取值/说明 |
|------|------|-------------------|
| h | 每个 execution interval 的控制步数 / VLA action chunk 长度 | 8（App A1） |
| t_c | 当前 execution interval 的第一个控制步 | 每个 interval 查询一次 VLA |
| T_t^w | 世界坐标系下的末端执行器位姿，∈ SE(3) | 由 VLA 动作映射得到 |
| τ_c^rel | 相对于 t_c 位姿的未来 h 步参考轨迹 | 8 个相对位姿 |
| x_t | 本体感受，∈ R^n | 16 维：9 关节位置 + 7 维末端位姿 |
| o_t^obs | 局部障碍物集合 | 最多 3 个，每个 11 维特征，共 33 维 |
| M | 局部障碍物数量 | ≤ 3 |
| d_i | 第 i 段的位姿偏差 | d_i = d_i^pos + α d_i^rot, α=4/7 |
| K | look-ahead range | h-2=6（h=8） |
| m_t | 非递减段索引 | 每个 interval 开始重置为 1 |
| k_pose | 轨迹跟随奖励敏感度 | 实现中等价于 exp(-7 d_t^*) |
| λ | 蒸馏系数 | 0.1 |

**时序与跨度说明**：τ_c^rel 含 h=8 个相对位姿，覆盖 t_c+1 到 t_c+8；若相邻控制步间隔为 Δt，终点距 t_c 为 8Δt，段数为 h-1=7。这里的 8 是未来预测区间长度，不是历史帧数，也不是 Stem 的记忆窗口。段偏差在 i=1..7 上计算；前向走廊在 h-1=7 个段上选择候选。

**直觉**：
- 公式 (2) 把 VLA 的“动作”变成“相对运动意图”，这样 Stem 不必逐步复现动作，只需保持空间走向。
- 公式 (5)-(6) 是关键：匹配只在当前段和后续 K 段中进行，且索引不递减。这允许机器人等待（停在当前段附近）或绕行，但不会“倒退”去匹配已经走过的段。
- 公式 (7) 把偏差变成 0 到 1 的稠密奖励；偏差越小奖励越接近 1。
- 公式 (8) 让学生在没有特权信息时模仿教师的动作分布，而不是直接复制教师的观测。

**Implementation 中的细节**（App C）：

```
λ_i = clip(((p_t - A_i)^T (B_i - A_i)) / (||B_i - A_i||^2 + ε), 0, 1)
p̂_i = A_i + λ_i (B_i - A_i)
d_i^pos = ||p_t - p̂_i||
d_i^rot = 2 arccos(clip(|<q_t, q̂_i>|, 0, 1))
d_i = d_i^pos + (4/7) d_i^rot
d̃_i = 0.7 d_i = 0.7 d_i^pos + 0.4 d_i^rot
r_t^follow = exp(-10 d̃_t^*) = exp(-7 d_t^*)
r_t^step = max(0, m_t - m_{t-1}) / (h - 1)
```

注意：论文同时给了 α=4/7 的段偏差形式和实现中的 0.7/0.4 加权偏差形式，本文照录，不擅自统一。

## 3. 带数字走一遍：玩具例子

> 以下数值为假设，仅用于验算公式，不是论文实验数据。

假设当前 execution interval 中 h=8，参考轨迹有 8 个 waypoint，7 个段。当前进度索引 m_{t-1}=3，K=6，所以候选段 I_t^+ = {3,4,5,6,7}（因为 min(3+6, 7)=7）。

假设各段偏差：
- d_3 = 0.05
- d_4 = 0.02
- d_5 = 0.01
- d_6 = 0.03
- d_7 = 0.04

则：

```
i_t^* = argmin = 5
d_t^* = 0.01
m_t = max(3, 5) = 5
r_t^follow = exp(-7 × 0.01) = exp(-0.07) ≈ 0.9324
r_t^step = max(0, 5-3)/(8-1) = 2/7 ≈ 0.2857
```

验算：exp(-0.07) ≈ 0.93239；2/7 ≈ 0.28571。对。

再走一个位置投影：

```
A_i = (0,0,0), B_i = (1,0,0), p_t = (0.3, 0.4, 0)
λ_i = clip(0.3×1 / (1^2 + ε), 0, 1) ≈ 0.3
p̂_i = (0.3, 0, 0)
d_i^pos = ||(0.3,0.4,0) - (0.3,0,0)|| = 0.4
```

如果旋转偏差 d_i^rot = 0.2 rad，则：

```
d_i = 0.4 + (4/7)×0.2 ≈ 0.4 + 0.1143 = 0.5143
d̃_i = 0.7×0.5143 ≈ 0.3600
r_t^follow = exp(-10×0.3600) = exp(-3.6) ≈ 0.0273
```

验算：4/7 ≈ 0.5714，0.5714×0.2 = 0.1143，d_i = 0.5143；0.7×0.5143 = 0.3600；exp(-3.6) ≈ 0.02732。对。

这个例子说明：位置偏差 0.4 已经会让跟随奖励很低（约 0.027），所以 Stem 需要把末端拉回参考段附近才能拿到高奖励；前向走廊又保证它不会为了拿高奖励而倒退匹配已经走过的段。

## 4. 工程视角

**控制频率与模块边界**：
- VLA 每 h=8 个控制步查询一次；Stem 每个控制步运行。这意味着 Stem 的推理频率是 VLA 的 8 倍。论文没有给出实际 Hz，但从架构看，Stem 是小型 MLP（约 4.56M 参数），输入约 16+64+33=113 维，输出 7 维，单次前向计算量远小于 VLA。
- 工程含义：如果你的 VLA 推理延迟是 T_VLA，Stem 需要在每个控制步的预算内完成前向。论文未报告 T_VLA 或 Stem 延迟，所以不能直接判断实时性；但模块化设计允许 Stem 独立优化。这是条件性分析，不是论文实测。

**输入依赖**：
- 低维障碍物表示是部署的关键接口。仿真用 ground-truth 中心 + 尺寸；真实世界用 AprilTag + RealSense D455 估计位姿，再转成 11 维特征（中心、尺寸、朝向、存在指示）。这意味着系统需要外部障碍物感知和标定。
- 没有用原始视觉输入，Stem 的域差距比端到端视觉策略小，这是作者主张的 sim-to-real 直接部署原因之一；论文用真实世界实验支持这一主张，但没有做感知噪声的消融。

**训练成本**：
- 每个 seed 约 38.0M（following）+ 23.7M（static）+ 20.6M（dynamic）≈ 82.3M simulated environment transitions，包括 teacher 和 student。这是仿真环境转移数，不是真实机器人数据，也不是梯度步数。
- base VLA 微调：每个任务 100 demos，30,000 optimization steps。这个 checkpoint 在 safety mechanisms 之间共享。
- 课程三个阶段分别训练，奖励权重不同；不能把三个阶段的总转移数误写成单阶段预算。PPO 配置也按阶段不同：following 用 256 并行环境、8 update epochs、minibatch 3,200；static/dynamic 用 192、12 epochs、minibatch 19,200；rollout horizon 均为 100 steps，γ=0.8。

**内存与参数量**：
- Stem 约 4.56M 可训练参数。Actor 和 critic 共享 576 维编码，各自 3 层 (1024,1024,512)。这个规模可以放在机器人本体或边缘 GPU 上。
- VLA reference 用 8×8 特征序列，不是原始图像；障碍物最多 3 个槽位。内存占用小。

**部署约束**：
- 真实世界每个任务 50 个 teleoperated demos 微调 VLA；Stem 只在仿真训练，直接部署，没有真实世界微调。这减少了真实数据需求，但也意味着 Stem 对真实障碍物感知噪声的鲁棒性未被系统测试。
- 动态场景中，VLSA 基线不估计障碍物速度或预测轨迹，只做瞬时几何修正；VLA-Stem 的 Stem policy 输入是当前障碍物信息 + 未来 VLA reference，没有显式障碍物速度输入。论文没有说 Stem 是否从障碍物序列中推断运动；从输入看，每个控制步的 o_t^obs 是当前估计，没有历史堆叠。所以“等待”行为可能是从课程训练中学到的反应，而不是显式预测。这一点是条件性分析，需要外部复现确认。

**抖动/平滑性**：
- 论文没有报告动作抖动或 jerk 指标。Trajectory-level guidance 的设计意图是减少逐步修正带来的不连续，但定量证据是任务成功率和碰撞率，不是平滑性指标。这是一个待补的工程评估维度。

## 5. 数据与评测

**仿真设置**：
- 平台：ManiSkill。
- 任务：PickCube、StackCube、Object Stowing（后者是作者提出的任务，要求把家居物体放入目标容器，有空间约束）。
- 场景：normal（无障碍）、static（静态障碍）、dynamic（动态障碍）。
- 静态障碍两种放置策略：靠近目标物体/放置区域；沿名义物体到放置路径采样并加随机横向偏移。检查工作空间有效性和重叠。
- 动态障碍：沿任务运动采样穿越区域，随机起点、方向、恒定速度；穿越时间在机器人预期经过该区域的时间窗内采样。
- 每个 trained policy，每个 task-scenario 评估 3,200 episodes。
- Base VLA：每个任务 100 demos，30,000 optimization steps；checkpoint 共享。

**真实世界设置**：
- 机器人：UR7e，两个 RealSense D435i 用于 VLA 观测。
- 障碍物位姿：AprilTag + RealSense D455。
- 每个任务 50 个 teleoperated demos 微调真实世界 VLA。
- 论文称每个 task and scenario 15 trials；结果部分报告了 normal、static、dynamic 三类设置。
- 任务：object stowing、stacking。
- 静态与动态障碍下的结果范围（两个任务合计）：碰撞率从 73–100% 降到 20–40%，任务成功率从 0–20% 升到 47–60%（作者报告的范围，未给逐设置表格）。

**基线**：
- π_0、π_0.5：原始 base VLA，无安全机制。论文未在正文展开两者内部架构，本文只把它们作为 frozen policy 讨论。
- VLA-finetune：用 RRT 生成的避障轨迹微调单独 VLA；动态场景加 wait primitive；在多个 demo 预算中选最佳，峰值 1,500 demos，2,000 下降。论文称其为每个任务-场景单独微调，但正文未明确其初始化 checkpoint 的全部细节，此处标注待原文补充。
- VLSA-EE / VLSA-ARM：CBF-based 安全层，用同一个 π_0.5 checkpoint 和 ground-truth 障碍物信息；VLSA-EE 只约束末端执行器椭圆体，VLSA-ARM 额外约束 5 个臂链接（panda_link3–panda_link7），共 6 个机器人椭圆体；CBF 增益、几何尺度、优化权重在验证集上调，报告最高 SUCC 配置。

**主要数字**（论文 Table I）：
- 六个约束设置平均 SUCC：VLA-Stem 52.8%，VLSA-EE 约 23.7%（按 Table I 六项约束设置平均计算；论文摘要称最强安全基线 23.7%，未点名具体方法；VLSA-ARM 平均约 23.3%）。
- PickCube-Static：VLA-Stem SUCC 0.5219，COLL 0.2316；π_0.5 SUCC 0.0325，COLL 0.8781；VLSA-ARM SUCC 0.1516，COLL 0.2253。
- PickCube-Dynamic：VLA-Stem SUCC 0.4153，COLL 0.3122；π_0.5 SUCC 0.0131，COLL 0.9328。
- Object Stowing-Static：VLA-Stem SUCC 0.5784，COLL 0.1756。
- Object Stowing-Dynamic：VLA-Stem SUCC 0.5950，COLL 0.1203。
- StackCube-Static：VLA-Stem SUCC 0.5141，COLL 0.3353。
- StackCube-Dynamic：VLA-Stem SUCC 0.5419，COLL 0.0784。
- Normal 场景：VLA-Stem 0.7325、0.7061、0.7521，对比 π_0.5 0.7166、0.6138、0.7450；论文称没有降低任务成功率。注意提升幅度小，论文未给置信区间。

**消融**（论文 Table II–IV）：
- 去掉 VLA reference 输入和 reference-based guidance：PickCube 三个场景 SUCC 全为 0.0000（Table II）。
- Step-wise action alignment 替代 trajectory-level guidance：Object Stowing 三个场景平均 SUCC 从 63% 降到 30%（Table III）；static 的 COLL 更低（0.0366 vs 0.1756），但 SUCC 更低（0.4778 vs 0.5784），作者归因于严格时间索引匹配导致任务未完成。
- 去掉 teacher-student distillation：Object Stowing 三场景平均 SUCC 从 63% 降到 14%，约束场景平均 COLL 从 15% 升到 37%（Table IV）。

**Reference 干预实验**（Fig. 4）：
- StackCube 上选一个运动幅度较大的 VLA chunk，向 left/right/up 三个方向平滑形变，位移 15/17.5/20 cm。
- 每个方向 30 对 rollouts，每个幅度 10 对；同一对内干预前执行相同，只修改选定的 reference chunk，后续 VLA chunk 正常从更新观测重新生成。
- D_mod^norm 平均 0.230，D_ori^norm 平均 0.894；88/90（97.8%）更接近修改后的 reference；任务成功率 60.0%–70.0%。

## 6. 能力与失败模式

**能做什么**：
- 在静态障碍物靠近目标或挡在转移路径上时，Stem 能局部绕行，保持任务成功率。例如 PickCube-Static SUCC 0.5219，远高于 π_0.5 的 0.0325 和 VLSA-ARM 的 0.1516。
- 在动态障碍物穿越时，Stem 能等待或调整时机；Fig. 3 展示等待障碍物通过后继续任务。
- 在无障碍场景中，Stem 不降低 base policy 的成功率；三个任务 normal SUCC 略高于 π_0.5（0.7325 vs 0.7166 等），但幅度小，论文没有给置信区间。
- 对 VLA reference 的空间变化敏感：干预实验显示 97.8% rollouts 更接近修改后的参考，说明 Stem 确实在条件化 VLA 的运动意图，而不是忽略它。
- sim-to-real：Stem 只在仿真训练，直接部署到 UR7e；真实世界静态与动态障碍下碰撞率下降、成功率上升（范围见 §5）。

**不能做什么 / 未验证**：
- 不处理接触力、力矩、柔顺性等接触安全；作者在结论中明确把 contact/force-related safety 列为未来工作。
- 不验证长程任务；论文任务是桌面 pick-and-place / stacking / stowing，horizon 较短。
- 不验证复杂障碍物形状：障碍物用中心 + 尺寸表示，VLSA 基线用椭圆体近似；真实世界用 AprilTag 标记的障碍物。非凸、可变形、快速运动障碍物未测试。
- 不验证多机器人或人机共享空间；只有单臂 UR7e。
- 没有开源代码或数据集链接（candidate repo_url 为空）；复现需要自行实现 Stem 训练和感知接口。
- 真实世界样本量小：每个 task-scenario 15 trials；47–60% 成功率范围只对应静态/动态障碍，normal 仅报告保持 base-policy 成功率，不能据此做细粒度统计比较。
- 没有报告推理延迟、控制频率、动作抖动；实时性需要外部测量。

### 6.1 隐含假设

- **低维障碍物表示足够**：假设最多 3 个障碍物、每个用中心 + 尺寸 + 朝向 + 存在指示就能捕捉安全关键信息。这对结构化桌面场景可能成立，对杂乱或非刚性环境不一定。
- **VLA action chunk 在 h 步内仍然有效**：假设 VLA 每 8 步更新一次参考，期间运动意图不会剧烈变化。如果任务需要快速反应或 VLA 的 chunk 本身质量差，这个假设会限制 Stem。
- **运动学映射可靠**：把 VLA 动作映射成末端位姿依赖机器人的运动学模型和动作空间定义；论文没有详细讨论映射误差。
- **特权信息只在训练时可用**：教师用目标物体位置，学生不用；这假设特权信息能显著加速恢复行为学习，且蒸馏能保留大部分收益。消融支持这一点，但只在 Object Stowing 上做了蒸馏消融。
- **仿真障碍物分布覆盖真实世界**：Stem 直接 sim-to-real，没有真实世界微调；真实世界的障碍物布局、感知噪声、动力学差异是否在训练分布内，论文没有系统分析。
- **每个 execution interval 独立**：Stem 没有显式跨 interval 记忆；它依赖 VLA 重新查询时更新的观测来传递信息。这假设 VLA 的观测足够及时，且 Stem 不需要记住之前的障碍物运动。

## 7. 与相关工作对比

| 方法 | 关注点 | 架构 | 训练方式 | 适用场景 | 关键差异 |
|------|--------|------|----------|----------|----------|
| π_0 / π_0.5（base） | 端到端 VLA 操作 | 大模型 VLA（论文未展开内部架构） | 大规模数据预训练 + 任务微调 | 无约束静态操作 | 无显式安全机制；约束场景 SUCC 极低 |
| VLA-finetune | 用避障数据微调 VLA | VLA + RRT 数据 | 监督微调 | 静态/动态障碍 | 表现不一致；可能损害原任务精细操作；需要大量避障数据 |
| VLSA-EE / VLSA-ARM | 即插即用安全层 | 冻结 VLA + CBF QP | 无需训练 VLA；调 CBF 参数 | 静态/动态障碍 | 降低碰撞率但任务成功率低；局部几何修正可能破坏 VLA 动作连续性 |
| VLA-Reasoner / V-GPS（test-time VLA） | 推理时调整 VLA 动作 | 候选搜索 / value function | 预训练 value function 或在线搜索 | 通用操作 | 推理开销大；需要候选评估 |
| VLA-Stem（本文） | VLA 与安全执行的耦合 | 冻结 VLA + 小型 RL Stem policy | PPO + 教师-学生蒸馏 + 课程 | 静态/动态障碍的桌面操作 | 用 action chunk 做运动参考；轨迹级引导；Stem 每控制步运行；需要低维障碍物输入 |

**面试 Tip**：如果被问“VLA-Stem 和 VLSA 有什么区别”，一句话答：VLSA 是在动作空间做几何安全修正，容易为了避障牺牲任务连续性；VLA-Stem 把 VLA 的 action chunk 当成轨迹级意图参考，让一个小 RL policy 在保持空间走向的前提下做局部调整，所以它优化的是“无碰撞任务成功”，而不只是“降低碰撞率”。

## 8. 精读建议

- **值得精读原文的人**：
  - 做 VLA 部署侧安全、test-time 干预、模块化控制的研究者：重点看 §III-A 到 §III-D，理解 action chunk 如何转参考、前向走廊如何工作、蒸馏如何去掉特权信息。
  - 评估 sim-to-real 安全模块可行性的工程师：看 §IV-A 的真实世界设置和 §IV-C 的结果范围，注意 15 trials 的样本量限制。
  - 做 RL + 机器人操作的人：看 §III-D 的课程设计和 Table V 的奖励权重，以及 §IV-B2 的消融，理解去掉 reference 或蒸馏后的性能崩塌。

- **建议章节路径**：先读 §III-A 和 §III-B（核心机制）→ 再看 §III-C 和 §III-D（训练框架）→ 然后 §IV-B 的 Table I 和 §IV-B2 的消融 → 最后 §IV-C 真实世界和 §V 结论（局限）。可以跳过 §II 的相关工作细读，除非你要写综述。

- **不值得精读的理由**：如果你不做机器人操作、不关心 VLA 部署安全，或者你只关心端到端 VLA 的预训练配方，这篇的边际收益有限；读摘要和 §1 即可。如果你已经熟悉 CBF 安全层和 test-time VLA，本文的新意主要在“轨迹级参考 + RL Stem”的组合，而不是全新的数学工具。
